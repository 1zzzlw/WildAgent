## 一、总流程：动笔前的六步

### ① 提示词解析与分流（决定走哪条铁律）

拿到用户提示词，**第一件事是判定输入形态**，因为它决定后续走哪条流程（v2.0 §0）：

| 输入形态 | 走哪条 | 关键动作 |
|---|---|---|
| **一张 / 一组参考图片**（"照图造"） | **铁律零（§0.1）** | 第一步是**读图识别** |
| **只是建筑类型的文字名**（"按名造"） | **铁律一（§0.2）** | 第一步是**调大模型自身通用知识** |
| 对**已存在蓝图**的任一改动 | **铁律二（§0.3）** | 第一步是**列牵连清单** |
| **任何两构件 / 组件的空间关系** | **铁律三（§0.4）** | 恒适用：先判"分离 / 贴接 / 穿插" |

**同时抽取提示词里的硬指标**（缺则按行业常规假设并**显式标注**，或向用户提问）：

- 建筑**类型 / 等级 / 规制**（如"二进四合院""官帽主屋顶"）；
- **层数**、**轴网总长 × 总深**、**各层层高**；
- **朝向与主立面**（默认主立面朝南、主门开南墙）；
- **特殊要求**（如"某处不设栏杆"——属硬语义⑨的合法例外，须记录）。

> **禁止**：跳过分流、拿提示词直接产几何（"看像就写"）。

### ② 大模型内置知识检索（先取通用建筑知识）

> **★ 口径（务必分清）**：这里的"**内置知识库**"指 **AI 大模型自身参数中已掌握的通用建筑知识**（模型训练时习得的建筑学常识 —— 形制、外形、构件做法），**不是**用户编写的那套规则 / 知识文档。**AI 大模型先自动检索自身的通用知识**，取得形制与构件清单；**规则文档只在 ⑤ 书写阶段进场**。

**只给类型名时不得凭"一闪而过的印象"直接动笔**（v2.0 §0.2 铁律一）。**第一步 = 调模型自身的通用知识**，产出**三张清单**：

1. **形制** —— 类型 / 等级 / 规制（如四合院"一进 / 二进"、塔"楼阁式 / 密檐式"、殿顶"庑殿 / 歇山 / 攒尖"）；
2. **建筑外形** —— 体量段数与层数、**屋顶形制与正脊走向**、开间进深、对称性、门廊·露台·栏杆·台阶、立面分带、主色调与材质关系；
3. **所需构件清单** —— **骨架**（地坪 / 墙 / 柱 / 梁 / 楼梯 / 屋顶 / 台基）与**组件**（门 / 窗 / 栏杆 / 台阶 / 雨棚 / 脊饰）。

**★ 两条信息源的职责分工（本流程的核心分界）**：

| 阶段 | 信息源 | 作用 |
|---|---|---|
| **取知识（本步 ②）** | **AI 大模型自身的内置知识**（通用建筑学） | 定 **形制 / 外形 / 构件清单** |
| **定约束（③ 设计 → ⑤ 书写）** | **规则文档**：通用层 v2.0 + 实例层《××蓝图书写规则及蓝图示范》 | 约束"**怎么写**"（引擎语义 / 该类型实值） |
| **落笔（⑤）** | 上述两者 | 产出 `.wild` |

⇒ **一句话：知识来自模型，约束来自文档。** 规则文档**不是** ② 的知识来源 —— **禁**在 ② 就先去翻用户写的文档来找形制。
⇒ 类型**无**专属规则文档时：按模型通用知识 + **v2.0 通用条款**书写，并**显式标注为推断**；两份文档冲突时（③ / ⑤ 阶段）**以 v2.0（引擎硬语义）为准**。

> **模型不确定 / 给不出的关键信息不得写死**：取 v2.0 默认值并标注，或向用户提问（"形制定性存疑，先问清"优于写错重来）。
> **图片任务额外一步**：读图只提取**图上可判定**的要素（含**正脊走向**），不可判定项同上处理。

### ③ 建筑样式设计（把清单变成可推导的尺寸链）

**据 ② 的形制与构件清单做设计，先场地与坐标、再体块与落位**（v2.0 §0.2 第 2 步、§2）：

1. **定轴网**（唯一自由的数值来源）：`层数 / 轴网总长 X × 总深 Z / 各层层高`，按 **0.3m 模数**取值（§2.1）；
2. **定标高**：按 ±0.000 口径（§2.3）+ 水平板四分类（§2.4）排出**标高谱**；
3. **排体块**：逐层轮廓（退台净宽 ∈[1.5,3.0]，§6 公式六d）；
4. **列构件落位**：先骨架后组件，形成**逐级可推导**的尺寸链（§2.5）。
5. **风格配方落位**：把 ② 的"外形"映射到 §3 / §4 的具体构件与参数。

**产出物 = 一份"设计稿"**：轴网 / 标高谱 / 体块轮廓 / 构件清单表（含每件的定位依据）。**它是 ⑤ 书写工序的唯一输入。**

> **禁止**：跳过设计、从类型名直接堆几何。

### ④ 记忆（读 / 写）

| 时点 | 动作 | 载体 |
|---|---|---|
| **写前（读）** | 加载项目长期约定 + 本类型已沉淀铁律 + 最近工作日志，避免重犯已记录缺陷 | 项目 `MEMORY.md` / 当日日志 / 类型《书写规则》 |
| **写后（写）** | 本轮**新确立的判据 / 踩坑 / 参数**回写：① v2.0 §9 错误速查表 + 对应章节；② 该类型《书写规则》自检清单；③ 项目记忆 | 同上 |

**回写判据（何时必须写）**：出现**新缺陷类型**、**新判据公式**、**新实值闭式**、或**对既有规则的修正** ⇒ 必写。纯照抄既有规则完成的任务 ⇒ 不写。

### ⑤ 按规则文档书写

**规则文档在本步进场**——据 **v2.0（通用层）+ 该类型《书写规则》（实例层）** 约束书写全部几何。

进入 **第二部分「五道工序」** 执行。工序顺序**固定**：场地与坐标 → 骨架 → 组件 → 材质 → 序列化。**禁跳步、禁调序**。

### ⑥ 交付前自检 + 三关验证（v2.0 §8）

**三关（顺序固定，缺一不可）**：

| 关 | 工具 | 通过判据 |
|---|---|---|
| **第 1 关：写盘前断言** | 生成器内联断言（v2.0 §1.5-7） | ① 字符串以外无全角标点；② 无超 3 位小数；③ `elements`/`components` **双查**精度 |
| **第 2 关：独立校验** | `蓝图生成器/verify_<type>.cjs` **重读磁盘** | 按蓝图文件本身数值交叉核验，**全过** |
| **第 3 关：真实编译器** | 真实编译管线 | **0 诊断**收口 |

**辅助关（按需）**：`check_wild_integrity.cjs`（语法 / 结构 / 几何三层体检）、`check_profile_winding.cjs`（剖面绕向 0 错）。

**再对照 §8 自检表逐条打勾**，重点：板分层、**转角完整性三层**、门窗 from 口径、屋顶显式 position、护栏完整性、搭接共面、多拷贝全库普查。

### ⑦ 修改轮（用户报缺陷时）

**联动修改律（铁律二，§0.3）**——只按所报缺陷改、但**该缺陷牵动的构件属缺陷范围本身，必须一并改**：

1. **列牵连清单**（三类逐项）：
   - **① 被依附侧**（宿主变 ⇒ 依附件必变）：墙移动 / 改高 ⇒ 门窗 `from`、腰线勒脚、窗台；
   - **② 派生尺寸侧**（自变量变 ⇒ 派生量必重算）：轴网 / 跨度变 ⇒ 屋顶 `span/depth/position`、正脊半长；
   - **③ 同拷贝侧**（同构造其余拷贝）：多层同门楼、成组栏杆、博风板 —— **一处改，全库逐实例改**。
2. **一律"由宿主几何重解"**，**禁照抄旧值 + 目测微调**；
3. **改后重跑三关 + 回读盘实测值比对**（**不得只信编辑动作"成功"的返回**）。

## 二、蓝图书写的五道工序

> 工序顺序 = v2.0 结构（§2 → §3 → §4），先骨架后组件；材质（§5）、公式（§6）、序列化（§1.3/§1.5）并行支撑。

### 工序 1 · 场地与坐标（v2.0 §2）

| 子步 | 做什么 | 输出 |
|---|---|---|
| 1.1 模数 | 重要尺寸取 **0.3m / 0.15m** 整数倍；构造厚度不循模（外 0.24 / 内 0.12 / 板 0.20） | 轴线、标高的取值表 |
| 1.2 轴网 | 定 **X × Z** 总长、开间进深、层高 | 轴网号 ← 唯一自由数值 |
| 1.3 坐标系 | 右手系；**北 = +Z / 南 = −Z / 东 = +X / 西 = −X**；**原点 = 建筑西南角外墙角点**；**±0.000 = 首层地坪顶面** | 原点与基准面 |
| 1.4 标高体系 | 按"**地坪 / 楼板 / 露台面 / 休息平台**"四分类排标高谱；**地坪仅一层、楼板 = 下层外轮廓、顶层不写 floor** | 标高谱 |
| 1.5 推导链 | `轴网间距 → 墙长（轴长 ± 墙厚/2）→ 构件沿墙距离 → 洞口尺寸` | 所有定位的推导式 |

**专项（按类型触发）**：四合院**方位相反**（南=−Z、北=+Z、东=−X、西=+X，§2.3）；大台基 / 住宅 **±0.000 = 室外地面**；超尺度建筑用**等比例缩放法**（§2.6，`meta.scale` 声明 + 回算断言）。

### 工序 2 · 骨架构件（v2.0 §3）

按 **板 → 墙 → 柱梁 → 楼梯 → 屋顶 → primitive** 顺序落位（§1.4 ⑧ 便于自检）：

| 构件 | 一句话要点 | 易错点（→ §9 速查） |
|---|---|---|
| `floor` | `from[1] = to[1] =` **板顶**；板体向下 `thickness` | 写成板底 ⇒ 地面与墙脱开 |
| `wall` | `from[1]/to[1] =` **墙底 / 墙顶**（墙高 = 两端 Y 差）；**禁两端同值**（否则 0 高平板墙、组件全丢） | 普通墙**不写 `height`**；**正交转角端点须与邻墙严格重合**（引擎才斜接成 90° 阳角；**禁手工满长/内缩**） |
| `column` | `base` = 柱底中心；`height`；收分用 `bottomRadius/topRadius` | 引擎统一渲染截锥体，`style` 为声明 |
| `beam` | `from/to` = 梁**底**；顶宜与墙顶齐平 | **`beam` 不被引擎斜接** ⇒ 折线分段转角须由竖向构件（立杆/柱）覆盖 |
| `stair` | **`stepHeight × stepCount = 目标高差`**；步参数显式写全 | 目标高差 ≠ 高差 ⇒ 悬空 / 穿板；转向平台处上下跑踏步边线须对齐 |
| `roof` | **六形制**（flat/gable/hip/dome/chinese_curved/chinese_pagoda）；**`position` 必须显式写**（= 檐口平面中心） | 漏写 ⇒ 引擎扩到全楼；**`roof/flat` 面板不被斜接** ⇒ 边缘护板改写为 4 段 `wall` 环 |
| `primitive` | `shape` ∈ box/sphere/cylinder/profile_sweep；**position = 形体中心** | cylinder 按"底面圆心"写 ⇒ 半截插地；`profile_sweep` 剖面须 **CW**；**入口台阶（box 叠写）朝向：末级（最高）踏面贴建筑墙、标高 = 室内地坪顶（门洞底 = 首层墙底），向远离建筑方向逐级降至室外地面**（住宅三级 0.15 = 0.45；与实心地基配套） |

**屋顶专项（v2.0 §3.6，最易错）**：

- **官帽 / 庑殿 = 一条引擎原生 `roof/hip`**（矩形平面**原生带短正脊**）⇒ **禁自绘坡板、禁写 `soffit`**（自带封底）、**禁 `gable_*`**；**要正脊∥X 就令 `span > depth`**；戗脊占比见 §6；
- **双坡屋顶**：**先锁正脊走向**（它决定坡向 / `rotation` 分量 / 山墙位置 / 山墙 `path` 走向四件事）；需要真实坡面时用**两斜板法**；
- **山墙三角 = `primitive` + `shape:"profile_sweep"` 三棱柱**，**必须弃用 `roof/gable`**（幽灵端墙劫持，§3.6 步骤 6）；`profile` 必须 **CW**（`shoelace<0`），**必须 `closedProfile:true`**；
- **屋面 / 大面结构一律走引擎原生类型**（渲染器对大块 `profile_sweep` 板兼容差）。

### 工序 3 · 装饰组件（v2.0 §4）

**组件依附宿主，由编译器自动展开洞口 / 框扇 / 栏杆**——**组件外禁补玻璃 / 框 / 栏杆**（§1.4 ⑥）：

| 组件 | 关键字段 | 要点 |
|---|---|---|
| `door` | `parentWall` / `from` / `width` / `height` | **双开古建木门用 `doorStyle:"double"`**，**禁拆成 N 件 `single`**；**★ 除首层外，门外侧无「楼板 + 该向栏板」者禁写门**（防坠落，门的下方/外侧须为露台板，v2.0 §4.0 第 5 条） |
| `window` | 同上 + `verticalMullions`/`horizontalMullions` | 外窗 `frameWidth` **显式 0.09**（缺省 0.06 过细）；**框梃×横档十字交接须"一者通长、一者内缩至对方外皮"**（组件内部构件转角律） |
| `balcony` | `width`/`depth`/`slabThickness` | 与阳台门同墙同轴 |
| `canopy` | `width`/`depth`/`thickness` | 棚底高 2.4–2.6 |
| `railing` | `path`（世界坐标折线）/ `height` | 台阶栏板**上端止于附着体台基外皮**（非墙轴线）；**★ `path` 折点即转角 ⇒ 折点处必有立杆落点**（两段横杆端点同抵立杆），**禁两段各止折点留三角空档** |

**组件级转角（v2.0 §0.4 三层总律 ②）**：组件**整体**与宿主 / 相邻组件的转角（如**四面栏杆在露台四角相会**、阳台栏杆与侧向栏杆相会）须**共用同一世界点 + 该点有转角柱**；组件挂载定位按"世界坐标重合"复算，**禁各自按轴线端点各写一半**。

**其余按需**：`ramp` / `bay_window` / `cornice` / `chimney` / `light`。
**硬语义⑨**：**除用户特殊要求，所有坡道 / 台阶 / 楼梯必须配护栏。**

### 工序 4 · 材质（v2.0 §5）

- `materials` 只放**被引用的**材质，每项**五件套必填**（`baseColor / roughness / metallic / albedo / lightingCondition`）；
- **玻璃分两种，严禁混用**：
  - `glass`（**普通窗玻璃**）：`transmission` 高（0.9+）、近无色 —— **透明**，用于家窗 / 门扇玻璃 / 落地窗；
  - `glass_curtain`（**幕墙玻璃**）：`transmission` **0**、带色 `baseColor`、低粗糙度 + `clearcoat` —— **带色反光**，用于幕墙 / 球幕；
- 玻璃**必须补全特殊四件**（`materialClass` / `side` / `transmission` / `ior`），缺则渲染成不透明色块；
- **全楼外墙统一一种材质**，可见材质 ≤ 4–5 种。

### 工序 5 · 文件装配与序列化（v2.0 §1.3 / §1.5）

- **文件骨架**：五顶层键（`meta` / `geometry` / `materials` / `behaviors` / `editor`）；
- **严格 JSON**：无注释、无尾逗号；`id` 全局唯一、**禁 `__` 前缀**（引擎保留）；每次修改 `revision +1`；
- **元素数 > 300 必须参数化生成**（Node `.cjs`）：参数表置顶 `const P`、派生量写公式、`id` 规整、留痕 `editor.generator/params`；
- **体积红线 ≤100KB**：**紧凑 JSON（无缩进无换行）**，坐标 ≤3 位小数；
- **序列化前**：`round_all(obj, 3)` 统一取整 + 两条断言（禁全角标点 / 禁超 3 位小数）→ **然后**写盘（见 ⑥ 三关第 1 关）。

## 三、蓝图书写必备条目（最小语法）

> 书写一份 `.wild`，**必须交代清楚"容器 / 身份 / 类型 / 位置"四件事**。本节 = 这四件事的最小语法。

### 3.1 容器：文件骨架（五个顶层键）

```json
{
  "meta":     { "version": "1.1", "type": "building", "name": "建筑名", "style": "modern", "author": "书写者" },
  "geometry": { "elements": [], "components": [] },
  "materials": {},
  "behaviors": {},
  "editor":   { "revision": 1 }
}
```

| 键 | 语义 | 硬性 |
|---|---|---|
| `meta` | 元信息 | `version` 书写用 `"1.1"`；缩尺建筑加 `meta.scale` |
| `geometry.elements[]` | **骨架元素**（产实体几何） | 每个元素独立写全几何参数 |
| `geometry.components[]` | **装饰组件**（依附宿主、自动展开） | 组件外**禁补**重复几何 |
| `materials` | 材质库 | 只放被引用的 |
| `editor` | 编辑留痕 | `revision` 递增；脚本生成写 `generator`/`params` |

**元素 / 组件分居两条通道，二者不重复**（v2.0 §1.2）。

### 3.2 身份：`id` 规则

| 规则 | 内容 | 依据 |
|---|---|---|
| **唯一性** | `id` **全局唯一**（`elements` + `components` 同一命名空间） | §1.3 |
| **禁用前缀** | **禁 `__` 开头**（引擎内部子构件保留，如 `__leaf_left`） | §1.3 |
| **命名法（阵列）** | `名称_层号_序号`（序号 `padStart(2,"0")`） | §1.5-3 |
| **命名法（板）** | `ground` / `slab_l<上层号>[_方位]` / `terrace_*` / `landing_*` | §2.4 |
| **禁拼浮点** | id 中的数值必须**取整后格式化再拼**（禁 `belt_s_5.8500000000000005`） | §1.5-8 |
| **材质名 ≠ 元素名** | `floor_terrace` 是**材质名**，元素板叫 `terrace_l<n>` | §5 |

### 3.3 类型：`type` 与枚举清单

**骨架元素 `type`（8 类 + opening）**：

| `type` | 说明 | 关键字段 |
|---|---|---|
| `floor` | 水平板（地坪 / 楼板 / 露台面 / 休息平台） | `from`/`to`（Y=板顶）/`thickness` |
| `wall` | 墙体（含女儿墙） | `from`/`to`（Y=墙底/顶）/`thickness`/`curve` |
| `column` | 柱 | `base`/`height`/`bottomRadius`/`topRadius`/`style` |
| `beam` | 梁（含枋） | `from`/`to`（梁底）/`crossSection`/`width`/`height` |
| `stair` | 楼梯 | `from`/`to`/`width`/`stepCount`/`stepDepth`/`stepHeight` |
| `roof` | 屋顶（六形制） | `roofType`/`span`/`depth`/`height`/`thickness`/`position` |
| `primitive` | 附属形体 | `shape`/`position`/`dimensions`/`radius*` |
| `furniture` | 家具 | `subtype`/`position`/`dimensions{}` |
| `opening` | 洞口（**引擎原生元素**，非组件） | `parentWall`/`from`/`width`/`height`/`style` |

**装饰组件 `type`（5 主 + 5 按需）**：`door` / `window` / `balcony` / `canopy` / `railing`；按需 `ramp` / `bay_window` / `cornice` / `chimney` / `light`。

**枚举速查**：

| 字段 | 取值 |
|---|---|
| `roof.roofType` | `flat` / `gable` / `hip` / `dome` / `chinese_curved` / `chinese_pagoda` |
| `primitive.shape` | `box` / `sphere` / `cylinder` / `profile_sweep` |
| `wall.curve` | `arc` / `ellipse` / `catenary`（缺省直线）；可数组多段 |
| `beam.crossSection` | `rect` / `circular` / `i-beam` |
| `opening.style` | `rectangular` / `arched` / `gothic` / `circular` |
| `column.style` | `modern` / `chinese_wooden` / `doric` / `ionic` / `corinthian` |
| `door.doorStyle` | `single` / `double`；`openingStyle`：`rectangular` / `arched` |
| `furniture.subtype` | `table` / `chair` / `bookshelf` / `bed` / `lamp` / `tile` |

> **禁自造 `type`**；**禁非法枚举**（v2.0 §8 自检 9）。

### 3.4 位置：坐标的表示

**基本约定**

| 项 | 规定 |
|---|---|
| **单位** | **米**（角度用**度**，**唯 `primitive.rotation` 用弧度**） |
| **精度** | **保留 3 位小数、禁超**（写盘前 `round_all(3)`） |
| **手系** | 右手系：X 向右、Y 向上、Z 向后 |
| **方位** | **北 = +Z / 南 = −Z / 东 = +X / 西 = −X**（四合院类型例外，见 §2.3） |
| **原点** | **建筑西南角外墙角点**（禁丢在建筑中部）；圆形 / 大场地 = 场地西南角 |
| **基准面** | **±0.000 = 首层地坪顶面**（大台基 / 住宅类型 = 室外地面） |
| **Vec3** | `[x, y, z]`；尺寸 > 0 |
| **rotation** | **弧度**；Euler XYZ（`R = Rx·Ry·Rz`，作用序 = 先 Rz、再 Ry、最后 Rx） |

**★★★ 四类构件 `from` 的 Y 口径对照（最高频错误源）**

同一套坐标，**四种 `from[1]` 语义完全不同**——混写必错：

| 构件 | `from[1]` 语义 | `from[0]` 语义 | 实例 |
|---|---|---|---|
| **`floor`** | **板顶标高**（`from[1] = to[1]`） | `[x1, z1]` 矩形角 | `from:[0,0,0] to:[8,0,6]` ⇒ 板顶 ±0.000 |
| **`wall`** | **墙底标高**（`to[1]` = 墙顶） | `[x, z]` 轴端点 | `from:[−0.12,0,0] to:[8.12,3,0]` ⇒ 高 3 |
| **组件**（door/window…） | **世界 Y**（窗 = 世界窗台标高，非层内相对值） | **洞口左边缘**到墙起点距离 | `from:[3.52,0,0]` = 洞左缘距墙起点 3.52 |
| **`opening`** | **墙底相对高度**（`墙底Y + from[1]`） | **洞口中心**沿墙距离 | 与组件**正好相反** |

> **口诀**：**板看顶、墙看底、组件看世界、opening 反着来**。
> **易错后果**：二层门窗写层内相对值 ⇒ **下沉一个层高**；`opening` 写世界标高 ⇒ **洞口陷入地基**。
>
> ⚠️ **`opening.from` 的两引擎语义差异（v2.0 §3.8 如实标注）**：上表为**分发版 `wild-core`** 口径；**`wild-web`（在线渲染实际使用）** 中 `opening.from[0]` = 开口**左边缘**、`from[1]` = 开口**底部【世界 Y】**（与组件同口径）。⇒ **写入蓝图前必须确认目标引擎并按其语义换算**（面向 wild-web：`from[0] = 洞心沿墙 − 半宽`、`from[1] = 世界标高`）。

**`primitive` 的位置语义**

| `shape` | `position` 指代 | 备注 |
|---|---|---|
| `box` | **几何中心** | `dimensions = [宽, 高, 深]` |
| `sphere` | **球心**（不是底面） | `radius` = 直径/2 |
| `cylinder` | **几何中心**（顶点 y∈[−h/2,+h/2]） | 按"底面圆心"写 ⇒ 半截插地 |
| `profile_sweep` | **省略 `position`**（path 即世界坐标） | 写 position ⇒ 二次偏移 |

**`rotation` 符号约定（§1.4，实测）**：

- `rotation[0]`（绕 X）：正角使 **+Z 端下沉、−Z 端上抬**；
- `rotation[2]`（绕 Z）：正角使 **+X 端上抬**；
- ⇒ 登高朝 +Z 的梯坡 / 坡面板用 **−α**，登高朝 −Z 用 **+α**；写反 ⇒ 坡向翻转（"翘裙边"）。
- ⚠️ **对轴向为 +Y 的形体（cylinder / 长轴 Y 的 box），`rotation[1]` 只是自转、不能改轴向** ⇒ 任意倾斜杆件**首选 `profile_sweep` 世界路径**（§6 公式十一）。

## 四、速查卡

### 4.1 全流程一句话

```
分流 → 大模型内置知识检索(形制/外形/构件清单) → 设计(轴网/标高/体块/落位) → 记忆
     → 按规则文档书写[场地坐标 → 骨架 → 组件 → 材质 → 序列化]
     → 断言 → 独立verify → 真实编译器0诊断 → 回写规则
```

### 4.2 五条通则（全类型强制，v2.0 文首）

| # | 通则 | 判据 |
|---|---|---|
| 1 | **数字可推导** | 逐级推导、**禁拍数**；重要尺寸循 0.3m 模数 |
| 2 | **引擎硬语义高于建筑直觉** | 以 §1.4 硬语义 / 源码事实为准；禁"看像就写" |
| 3 | **骨架产几何、组件产洞口** | 两通道**不重复**，组件外禁补玻璃 / 框 / 栏杆 |
| 4 | **精度 = 米制 3 位小数** | `round_all(3)` + 双查（elements + components） |
| 5 | **依附不悬空** | 相邻构件**共面搭接**或**嵌入宿主**；禁缝、禁可见偏移 |
| 6 | **★ 转角必完整（三层）** | **一切转角必完整、零缺口、外侧 90° 阳角**——**① 构件级**（`wall` 端点重合·引擎斜接；`roof`/`floor` 面板不斜接⇒护板改写为 4 段 `wall` 环）**② 组件级**（组件与宿主/邻组件转角**共用世界点 + 转角柱**；`path` 折点有立杆）**③ 组件内部构件级**（组件展开出的子几何不被引擎斜接 ⇒ 同轴折线**折点由立杆覆盖**、十字/丁字**一者通长一者内缩至对方外皮**）。**禁两段各缩一半（缺口）、禁双通长（超叠 ≥ `t×t`）**。详见 v2.0 §0.4「转角完整性三层总律」 |

### 4.3 四条流程铁律（v2.0 §0，互相并列、优先级最高）

| 铁律 | 触发 | 第一步 |
|---|---|---|
| **零（§0.1）** | 输入 = **参考图片** | **读图识别**（含正脊走向，不可判定项标注 / 问询） |
| **一（§0.2）** | 输入 = **类型文字名** | **调大模型自身通用知识**取形制 / 外形 / 构件清单（**非**先翻用户文档） |
| **二（§0.3）** | 对**已有蓝图**做改动 | **列牵连清单**（被依附侧 / 派生尺寸侧 / 同拷贝侧） |
| **三（§0.4）** | **任意两构件 / 组件 / 组件内部构件**的空间关系 | 判 **分离 / 贴接 / 穿插** ⇒ 只有前两者合法；**转角另按「三层总律」保完整** |

> **两条信息源的分界（再强调一次）**：**知识来自模型**（② 取形制 / 外形 / 构件清单）、**约束来自文档**（⑤ 按 v2.0 + 类型《书写规则》写）。**禁**把用户编写的文档当 ② 的知识来源。

### 4.4 交付前必过（最小集）

**三关**：① 写盘前断言（全角标点 / 3 位小数）→ ② 独立 `verify_<type>.cjs` 重读盘 → ③ 真实编译器 **0 诊断**。
**辅助**：`check_wild_integrity.cjs`（三层体检）、`check_profile_winding.cjs`（绕向 0 错）。
**自检表**：v2.0 §8 共 23 条，逐条打勾。

### 4.5 书写时最易踩的 11 个坑（→ v2.0 §9）

1. `floor.from[1]` 写成板底 ⇒ 地面与墙脱开；
2. `wall.from[1] = to[1]` ⇒ 0 高平板墙、**组件整批丢失**；
3. 上层门窗 `from[1]` 写层内相对值 ⇒ 下沉一层高；
4. `opening.from[1]` 写世界标高 ⇒ 洞口陷入地基；
5. 屋顶漏写 `position` ⇒ 撑到全楼、盖住露台；
6. `profile_sweep` 剖面绕向写成 CCW ⇒ 渲染**空心管**；
7. 正交两墙**端点未严格重合**（相距 `h`）⇒ 引擎配不上 ⇒ 墙角"消失"（0.12×0.12 缺口）；**禁手工满长—内缩**（手工值与引擎外延双重作用必错）；
8. **组件内部构件转角缺口**（栏杆 `path` 折点无立杆 ⇒ 横杆分段留三角空档；门窗框梃横档双缩进/双通长）——**组件展开出的子几何不被引擎斜接**；
9. 放大屋面不抬高墙体 ⇒ **墙从坡面里戳出来**（硬碰撞）；
10. 结构位混入**全角标点** ⇒ 引擎完全打不开文件（报错不指向真因）；
11. 派生值漏取整 ⇒ 出现 `6.000000000000001`。
