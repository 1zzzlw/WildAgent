## 1. 一进形制的定义与引擎映射总表

**一进四合院 = 单一院落**：四面院墙围成一个矩形庭院，南侧开大门，院内北面建正房、东西两侧建厢房、大门东侧（东南角）建倒座房。**没有二道墙、没有垂花门、没有抄手游廊、没有后院**——这是与"二进"的全部结构差异。

| 四合院真实形制 | 本蓝图表达 | 依据 |
|---|---|---|
| 四面院墙围合单个矩形院落 | 4 段 `wall`（th 0.4）+ 每段顶 `profile_sweep` 双坡墙帽；**南墙拆为「西段院墙 + 大门段 + 倒座南墙」三段** | §3.2 / §3.9 |
| 院墙双坡墙帽（脊 ∥ 墙身） | `primitive profile_sweep`，path = 墙顶线，截面双坡（半跨 0.55 / 高 0.42） | §3.9 |
| 东南角大门（门楼） | 木墙段 `gate_wall_mid`（`wood_frame` th 0.4）+ 4 根角柱 + 2 道额枋 + **双开门（原生 `doorStyle:"double"`：2 扇 + 1 共用门框，正中无构件）** + 横披花窗 + 内外各 1 级台阶（含护栏）+ 双坡屋面 + 两端山墙三角实体 | §3.9 / §4.1 |
| 大门内影壁（一进无二道墙，改设于倒座北侧、**按通行净距反解定位**） | 独立片墙 `zhaobi_wall`（th 0.36，正对门洞 X 中心）+ 石座 + 双坡压顶 + **两端山墙三棱柱** | §3.6 第 6 条 / §5.2 / §3.4 |
| 倒座房（南侧，东段一栋） | 4 面 `wall`（th 0.4，**南墙与院墙共用**）+ 双坡屋面 + 两端山墙三角实体 + 朝院（北）直面三段式隔扇 + 南街面少量常规窗 | §3.9 / §5.2 |
| 东厢 / 西厢（3 开间） | 4 面 `wall`（h 3.0）+ 台基 + 檐柱 + 双坡屋面（脊高 1.35）+ 两端山墙三角实体 + 朝院一面隔扇 | §3.9 / §5.2 |
| 正房（北居中，最高最大，5 开间） | 4 面 `wall`（th 0.24，h 3.9）+ 台基 + 6 根檐柱 + 双坡屋面（脊高 1.70）+ 两端山墙三角实体 + 朝院（南）直面三段式隔扇 + 踏跺（含护栏） | §3.9 / §5.2 |
| 庭院甬路（大门 → 正房中轴） | `floor` 浅色铺装条（`court_path`，顶面 +0.02）叠于院地之上 | §3.1 |
| 青砖 / 木构材质分制 | 砖墙 `brick_grey` / 木框 `wood_frame` / 柱 `wood_column` / 瓦 `roof_grey` / 石作 `stone_base` / 山墙 `gable_brick` | §5 |
| 每栋独立双坡屋顶 | 一律 `primitive profile_sweep`（**脊 ∥ 长边**），**不用** engine `roof` | §3.6 |

> **⚠ 一进院的三条硬性差异（与二进的分水岭）**
> 1. **南侧只有一栋倒座房**（东段），**西段是院墙**——二进院南侧是"西段院墙 + 大门 + 倒座（西段）"的镜像布局，一进院倒座在东段；
> 2. **无二道墙** ⇒ 无垂花门、无前院/内院之分 ⇒ **单一庭院**；
> 3. **影壁改位**：二进院影壁嵌在二道墙上（Z = 10.0）；一进院无二道墙，影壁改作**独立片墙设于倒座北侧**，仍满足"正对门洞"的礼制要求。★ **一进院进深小，影壁位置须由「门楼内皮 → 影壁石座南皮 ≥ 3.00m 通行净距」反解**（见 §3.4）。

## 2. 坐标与场地约定

- **场地 30 × 30**（建议值；本蓝图院墙净宽 25.0 × 净深 26.0）；原点 = **院落西南角**（0, 0, 0）；
- **方位约定（本节沿用《四合院蓝图设计语言》）**：**南 = −Z、北 = +Z、东 = −X、西 = +X**；东南角 = 低 X + 低 Z；
  > ⚠️ 注意：本约定与《WILD 蓝图设计语言 v1.2》（北=+Z，东=+X）的**东西向相反**。本文档与蓝图统一采用四合院类型约定，跨类型拼装时须显式换算。
- **±0.000 = 院外地面**；院地铺装顶面 = **0**（`court_paving`，th 0.12，板底 −0.120）；
- **单体台基顶 = +0.35**（`PLAT`）；单体墙底 = 台基顶；院墙/门楼墙/影壁墙底 = 0；
- **标高链**：院地 0 → 单体台基顶 +0.35 → 墙顶 **+3.35**（厢房）/ **+4.25**（正房）/ +2.85（倒座，含大门同高）→ 屋脊 **+4.70**（厢房）/ **+5.95**（正房，全楼最高）/ +4.20（倒座）/ +3.80（大门）；
- 墙厚：院墙 0.4 / 单体砖墙 0.24 / 影壁与门楼木墙 0.36 / 门楼院墙段 0.4。

## 5. 关键构件书写规则

### 5.1 双坡屋面（`profile_sweep` 墙帽式，非 engine `roof`）

四合院每栋独立双坡屋顶，一律用 `primitive profile_sweep`：**脊 ∥ 长边**，path 沿脊线、截面为"双坡 + 下沿折边"闭合多边形。

```json
{ "type": "primitive", "id": "roof_A", "shape": "profile_sweep",
  "path": [[6.4, 4.25, 25.0], [23.6, 4.25, 25.0]],
  "profile": [[-3.1, 0], [0, 1.7], [3.1, 0], [3.1, -0.14], [0, 1.56], [-3.1, -0.14]],
  "closedProfile": true, "material": "roof_grey" }
```

**截面读法**（6 点）：`[-hw, 0]` 檐口外缘 → `[0, H]` 屋脊顶 → `[hw, 0]` 另一檐口外缘 → `[hw, -th]` → `[0, H-th]` → `[-hw, -th]` 回起点。即**外皮沿坡上行，内皮平行下移 th**，形成有厚度的双坡壳；下沿折边模拟瓦口滴水。

**各栋参数表**（hw = 半跨含出檐，H = 屋脊高，th = 瓦厚）：

| 单体 | path（脊线） | hw | H | th | 出檐 | 坡度 |
|---|---|---|---|---|---|---|
| 影壁压顶 | [3.2, 2.75, 5.08] → [9.6, 2.75, 5.08] | 0.50 | 0.45 | 0.10 | 0.50 | 42.0° |
| 大门门楼 | [3.65, 2.95, 1.5] → [9.15, 2.95, 1.5] | 1.85 | 0.85 | 0.12 | 0.55 | 24.7° |
| 倒座 D | [8.05, 2.85, 2.8] → [28.05, 2.85, 2.8] | 1.85 | 1.35 | 0.12 | 0.55 | 36.1° |
| 东 / 西厢 | [5.6, 3.35, 12.0] → [5.6, 3.35, 22.0] | 3.20 | 1.35 | 0.12 | 0.55 | 22.9° |
| 正房 A | [6.4, 4.25, 25.0] → [23.6, 4.25, 25.0] | 3.10 | 1.70 | 0.14 | 0.60 | 28.7° |

**正脊**：沿脊线贴 `primitive box`，`dimensions = [脊长 + 0.2, 0.12, 0.2]`，中心 y = 搁置标高 + H − 0.04（坐脊略压顶）。

> **正房出檐收敛说明**：一进院正房贴北院墙，故只**朝院一侧出檐 0.6**、背侧靠墙；屋面 `hw = 进深/2 + 0.6 = 3.1`。二进院正房两侧均出檐 0.6 ⇒ `hw = 3.6`。

### 5.2 山墙三角实体（**统一 `primitive/profile_sweep` 三棱柱** ★ 铁律 · rev8 定案）

**每栋双坡两端各一件**，语义是**墙体在墙顶以上的三角延续**（不是屋顶、不是装饰件）。

**★ 定义（用户原话，最权威）**：
> "这个三角形墙体只作用于**双坡屋顶**建筑中，**垂直于双坡屋顶屋脊线**的两侧墙体，
> 墙体**厚度与屋顶下面的普通矩形墙体厚度一致**，三角形也是**属于普通墙体**，只是形状为三角形，
> 三角形墙体的**下沿与普通墙体对齐并对应**，**上沿刚好与双坡屋顶相接**，
> 他只是一个普通三角形状的墙体而已。"

四条硬性口径：
1. **只用于双坡屋顶**建筑，位于**垂直于屋脊线**的两侧端墙；
2. **厚度 = 下部矩形墙厚**（同轴线、同厚度，`|Δ| < 0.06`）；
3. **下沿与下部普通墙对齐**（端墙轴线重合）；
4. **上沿与双坡屋面斜面相切**（`height` 严格 = 屋面高）。

#### ★★★ 必须弃用 `roof/gable`：幽灵端墙事故（rev8 源码级实证）★★★

用户反复报告"**三角形墙体与下部普通墙体垂直交叉**"。本轮用**真实引擎代码**跑通
`resolveSpatialRelations()` + `buildRoof()` 后，定位到**架构性根因**——**不是山墙参数写错，而是 `roof/gable` 这种类型本身被引擎劫持**：

`resolver.ts → resolveRoofBoundary()` 对**每一件** `type:"roof"` 元素**无条件**执行：

```
gableEnds = effectiveWalls.filter(|dx| > |dz|)   // 全院「沿 X 走向的墙」
        → roof._gableEnds = gableEnds            // 注入
```

`effectiveWalls` 取的是「**全院墙顶最高的那批墙**」——与"这件 roof 属于哪栋建筑"**毫无关系**。

随后 `geometry/roof.ts → buildGableRoof()`：

```
const autoGableOk = Math.abs(rot[1]) < 1e-6;     // 只认「屋脊∥Z」
for (const end of (autoGableOk ? gableEnds : undefined) ?? []) { ...生成三角山墙面... }
```

**实测证据（本蓝图，修复前）**：

| 事实 | 数据 |
|---|---|
| 每件山墙被注入的端墙数 | **6 件**（全部 12 件山墙无一幸免） |
| 注入的端墙来源 | `z=12.5 x[2.9,8.3]`（**东厢**）、`z=21.5 x[2.9,8.3]`、`z=12.5 x[21.7,27.1]`（**西厢**）、`z=22.5 x[7,23]`（**正房**）… |
| 后果 | 正房西端山墙在 `Z=12.5 / 21.5 / 22.5 / 27.5` 处**各长出一对立面三角**，横跨整个院子，**垂直贯穿**沿途每一道墙 |

三重致命缺陷：
1. **清单与建筑无关**——`effectiveWalls` 是全院集合，一件山墙被喂进别的建筑的端墙；
2. **两条生成路径**——`autoGableOk` 只认 `rot[1]≈0`；转 90° 时跳过自动补墙，但**显式几何仍在**（`buildSlopeBoard` 照常构造坡板）⇒ 同一件 `roof/gable` 在两种朝向下产生**完全不同**的网格；
3. **位置错配**——自动补墙的三角面落在 `z = 端墙.z`，而显式几何落在 `z = position[2] ± depth/2`，两者普遍不等（正房相差 0.58 m）⇒ 三角面**悬空于墙角之外**。

> ⇒ **结论：`roof/gable` 不能被"借用"为山墙实体。** 它只在「屋脊∥Z + 屋面与承托墙同轴」这一种原生场景下语义正确；一旦用于屋脊∥X（必须转 90°），就会被引擎错误注入。

#### ★ 正解：`primitive/profile_sweep` 三棱柱

山墙 = **`primitive` + `shape:"profile_sweep"` 的三棱柱**。`primitive` 不进 `resolveRoofBoundary` 的 roof 分支，**从根上规避**。

```
path    = 沿「墙厚方向」两点，长度 = th，以端墙轴为中心（±th/2 对称）
profile = 三角形 [(-u, 0), (u, 0), (0, H)]，closedProfile: true
          u = 底边半宽 = 屋面坡度向全跨/2 − 0.02（GABLE_INSET）
          H = 三角高，严格 = 屋面高
```

- **三角面天然 ⊥ 墙厚方向** ⇒ **零 `rotation`**（彻底避开 Euler 序陷阱）；
- **`path` 用世界坐标** ⇒ **禁写 `position`**（写了会造成二次偏移，引擎三红线①）；
- `path` 走向直接决定朝向，规则只有两条：

| 屋脊向 | 端墙（山墙）位于 | 三角面须 ⊥ | **`path` 沿** | 实例 |
|---|---|---|---|---|
| **∥X** | x 两端 | **X** | **X**（长度 = 墙厚） | 正房 A / 倒座 D / 大门 gate / 影壁 zhaobi |
| **∥Z** | z 两端 | **Z** | **Z**（长度 = 墙厚） | 东厢 B / 西厢 C |

**两个实例（本蓝图实际产出，照抄即可）**：

```json

  "path": [[6.88, 4.25, 25], [7.12, 4.25, 25]],
  "profile": [[-3.08, 0], [3.08, 0], [0, 1.7]],
  "closedProfile": true, "material": "gable_brick" }

// 路径 B：屋脊∥Z（东厢南端山墙）—— path 沿 Z，长度 = 墙厚 0.24
{ "type": "primitive", "id": "gable_B_s", "shape": "profile_sweep",
  "path": [[5.6, 3.35, 12.38], [5.6, 3.35, 12.62]],
```

> **路径 A 读法**：`path` X 向两点 `6.88 → 7.12`，中点 = **7.0** = `wall_west_A` 轴线 ✓（下沿对齐），
> 长度 `0.24` = 正房墙厚 ✓；`profile` 底边半宽 `3.08 = 2·3.1/2 − 0.02`（屋面坡度向全跨 − 内缩），
> 顶点高 `1.7` **严格 = 屋面高**；`path` 的 `y = 4.25` = 檐口标高 ⇒ 三角底面落于檐口 ✓。
> **`profile` 在垂直于 `path` 的平面内展开**：`path` 沿 X ⇒ 三角面在 YZ 平面（u 沿 Z、H 沿 Y）。

**六条硬规则**：
1. ★★ **山墙一律 `primitive` + `shape:"profile_sweep"`；全蓝图禁出现 `roof/gable`**（生成器 `assert_no_roof_gable()` 强制拦截）。
2. ★ **禁写 `rotation`**——朝向由 `path` 走向决定（屋脊∥X ⇒ `path` 沿 X；屋脊∥Z ⇒ `path` 沿 Z）。
3. ★ **禁写 `position`**——`profile_sweep` 用世界坐标 `path`，写 `position` 会二次偏移（引擎三红线①）。
4. ★ **`path` 以端墙轴为中心、长度 = 下部墙厚**（`±th/2` 对称）；`path` 中点坐标**必须等于下部端墙轴线坐标**（`|Δ| < 0.06`）。
5. ★ **`profile` 顶点高 `H` 必须严格 = 屋面高**（±0.01）；**禁竖向沉降**，唯一防闪手段 = **底边水平内缩 0.02**（`u = 全跨/2 − 0.02`）。
6. ★ **`closedProfile: true`**（三角端面须封闭，否则成开口棱柱）。

**★ 相切断言**：生成器 `assert_gable_apex_fit()` 逐点斜边比对：

```

山墙：y_wall(u) = H · (1 − |u| / u_max)
相切 ⟺ 脊同高（H == roofH）且底边全跨同长（u_max ≈ roofHalf − 0.02）
判据：max_u |y_wall − y_roof| ≤ 0.05
```

> 　· 栏板沿踏跺两侧**临空边**随坡上行，全程落在「踏跺 → 台基」投影范围内。
> **真实编译器复算（修复后）**：一进 / 二进 **0 处干涉**；上端立柱底 = 台基顶、下端立柱底 = 踏跺顶，`x` 与踏跺边逐点对齐。
>
> **通用判据（可迁移到任何「台基 + 踏跺 + 栏板」组合）**：栏板任何杆件被墙/柱**吞没的深度不得超过其自身半径**（`embed ≤ R`）——**贴面收头合法**（如大门台阶栏板北端抵院墙内皮 `gate_wall_mid`，吞没 = `R = 0.045`），**越过附着体外缘扎入墙体则必错**（正房旧值吞没 `0.090` > `R`）。
> 　生成器已落 `assert_step_railing_clear()`（写盘前强拦截，禁止静默产出）；校验器已落 `verify_siheyuan_yijin.cjs → E19`。

```text
   东皮 = 院墙东端（27.5）；Z 向宽 = 门屋 Z 向宽（2.6）→ 对齐
```

## 12. 错误速查

| 现象 | 原因 | 处理 |
|---|---|---|
| **坡屋顶下两侧山墙呈矩形、超出坡屋顶** | `wall + gableTop` 是 `wild-web` 私有扩展，分发版引擎未实现 → 三键被静默忽略 | **弃用 `wall + gableTop`**，山墙统一走 §5.2 的 `primitive/profile_sweep` 三棱柱 |
| **★★★ 三角形墙体与下部普通墙垂直交叉 / 山墙面横跨全院** | **山墙用了 `roof/gable`**——引擎 `resolveRoofBoundary()` 对每件 roof **无条件**注入全院「沿 X 走向的墙」为 `_gableEnds`（与建筑归属无关），`buildGableRoof()` 再为每件端墙生成三角面 | **山墙改为 `primitive` + `shape:"profile_sweep"` 三棱柱**（不进 roof 分支）；生成器 `assert_no_roof_gable()` 强制拦截 |
| **★★ 山墙三角面转 90°、横躺并冲出屋面** | `roof/gable` 原生轴向恒 ⊥Z，`rotation` 又不被透传/被 Euler 序干扰 | **改用 `primitive/profile_sweep`，朝向由 `path` 走向决定**，彻底避开 `rotation`（§5.2） |
| **★★ 山墙"消失"不见** | 误用 `primitive` 但漏写 `closedProfile` 或 `path` 退化成一点 | `closedProfile: true` + `path` 长度 = 墙厚 > 0.05 且首末不重合 |
