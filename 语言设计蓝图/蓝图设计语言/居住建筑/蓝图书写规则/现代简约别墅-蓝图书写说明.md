# 现代简约别墅 · .wild 蓝图书写说明书
### WILD Blueprint Authoring Spec for Modern Minimalist Villa — v1.1（引擎逻辑版）

> **文档性质**：`.wild` 蓝图的**书写说明书**（不是设计意图文档）。按"引擎怎么执行 → 元素怎么写 → 字段填什么值"的顺序组织，目标读者是**生成蓝图的智能体**。
> **使用方式**：写完蓝图前逐节核对。凡本说明书与直觉冲突处，**以引擎行为为准**；凡涉及枚举/材质的通用规则，以《WILD建筑形式设计语言-v1.0》（下称"通用协议"）§1.3/§1.4 为准。
> **设计意图层**：类型气质、体块策略、形式特征见《现代简约别墅-建筑类型设计语言》。本文只回答"**这行 JSON 该怎么写**"。
> **实测基准**：`三层现代别墅.wild`（3 层平顶）与 `现代双坡屋顶别墅.wild`（2 层双坡），二者均已通过引擎级校验并渲染验证。
> **v1.1 修订**：确立**水平板分层术语**——地坪（首层落地板）/ 楼板（层顶板，归属下层、兼上层地板）/ 露台面 / 休息平台，见 §3.1、§5.4；两份蓝图 id 同步为 `ground`/`slab_l<n>`/`terrace_l<n>`。

## 1. 引擎执行模型（写之前必须知道的 7 件事）

### 1.1 流水线（你的文件如何变成 3D）

```
.wild(1.1) ──wild-compiler──▶ 组件展开为 base elements ──▶ 解析/校验 ──▶ resolver 空间适配 ──▶ builders 生成网格 ──▶ Three.js
                (components)        (elements 原样保留)      (opening 语义)    (角部/屋顶/板补全)   (wall/floor/roof/stair…)
```

**推论 1**：`geometry.components` 里的门/窗/阳台/雨棚/栏杆**不是最终几何**——编译器把它们展开成墙洞（opening）+ 框料 + 玻璃/门扇。你**不要**再手写玻璃板或门扇几何（会形成双层透明面）。
**推论 2**：`geometry.elements` 里的元素**原样进入引擎**，本说明书 §3 的每条硬语义都直接作用于它们。

### 1.2 坐标系（书写基准）

| 项 | 规定 |
|---|---|
| 单位 | 米；角度字段用度；`primitive.rotation` 用**弧度** |
| 轴向 | X 向东（+）、Y 向上、Z 向北（+）；原点 = 建筑西南角；**±0.000 = 室外地面；首层室内地坪顶 = +0.45 = 首层墙底**（住宅标高口径，见 §3.5-3 与 v2.0 §2.3） |
| 手性提示 | 该轴向标注下，相机**朝北（+Z）看时屏幕右 = 西**。核对截图时按"屏幕右 = forward × up"推算，勿凭直觉判断东西 |
| 坐标层级 | 轴网（Z/X 间距）→ 墙长 → 构件沿墙距离，逐层推导，禁止跳级拍数 |

### 1.3 元素与构件（两条书写通道）

| 通道 | 位置 | 成员 | 写法 |
|---|---|---|---|
| 直写元素 | `geometry.elements[]` | `floor` `wall` `stair` `column` `beam` `roof` `primitive` `furniture`（+`opening` 仅部署层） | 每个元素独立写全几何参数 |
| 组合构件 | `geometry.components[]` | `door` `window` `balcony` `canopy` `railing` `bay_window` `ramp` `cornice` `chimney` `light` | 依附父墙/父板，只写定位与规格，几何由编译器生成 |

**推论**：所有**承重与围护几何**必须直写为 elements；**门窗阳台**一律走 components。

### 1.4 五条硬语义（写错即物理错误）

| # | 引擎行为 | 正确写法 | 错误写法的表现 |
|---|---|---|---|
| ① | `buildFloor`：`from[1]` = **板顶**，板体向下延伸 `thickness` | 板顶 = **本层墙顶 = 上一层地面**：一层楼板 `from[1] = 3.6`（占 3.4–3.6）；首层地面（**地坪**）`from[1] = 0` | 写成板底 → 整板下沉 0.2m → 地面与墙分离 |
| ② | `buildWall`：`from/to` 为**轴线中线**，thickness 法向对称；旋转角 `atan2(-dz,dx)` | 外墙写中线，靠 §5.2 处理角部 | 用 `atan2(dz,dx)`（自研引擎）→ 东西墙洞口镜像 → "有洞无门窗" |
| ③ | `buildOpening`：旧引擎 `from[0]` = 洞口**中心**、`from[1]` = **相对墙底高度**；填充板尺寸 = 洞口 + 0.08 | 源码写 1.1 语义（左边缘 + 世界 Y），由 flatten 转换 | 源码直接写中心 → 门窗整体偏半个宽 |
| ④ | `buildStair`：**升高 = stepHeight × stepCount**，`from/to` 的 Y 不参与；末步距 `to` 少一个 stepDepth | 每跑 `stepHeight × stepCount = 半层高`，两跑和 = 层高 | 层高 3.0 写 20×0.18 → 楼梯顶悬空 0.6m |
| ⑤ | `resolveRoofBoundary`：**无 `position` 的屋顶**会被扩到全楼墙包围盒 +1.0；**有 `position` 的尊重作者值**（已修引擎） | 屋顶**必须显式写** `span/depth/position` | 漏写 position → 屋顶撑到整栋、盖住露台 |

### 1.5 引擎兜底行为（知道即可，**正式蓝图不得依赖**）

- 完全无 floor 且墙 ≥3 面 → 引擎自动补 0.2m 板；
- 梁端 XZ 距柱顶 < `bottomRadius+0.05` → 自动吸附柱顶；
- `buildGable` 的 `thickness` 字段**不参与**计算（输出封闭棱柱：两端三角面 + 两坡面 + 底面）；
- `primitive.profile_sweep` **不生成端盖**（开放管状）——需要封闭形体时不要用它；
- 阳台朝向由编译器按父墙与整体包围盒中心关系推断，与墙书写顺序无关。

## 2. 文件骨架写法

### 2.1 顶层结构（严格 JSON：无注释、无尾逗号、无 Markdown 包装）

```json
{
  "meta": { "version": "1.1", "type": "building", "name": "现代简约别墅", "style": "modern", "author": "WildAgent" },
  "geometry": { "elements": [], "components": [] },
  "materials": {},
  "behaviors": {},
  "editor": { "revision": 1 }
}
```

### 2.2 各节书写要求

| 节 | 要求 |
|---|---|
| `meta.version` | 固定 `"1.1"`（部署副本由脚本降为 `"1.0"`，不要手改源文件） |
| `meta.style` | `"modern"` → 决定材质方案与屋顶倾向；`meta.name` 用中文建筑名 |
| `geometry.elements` | 必须存在（可为空数组），ID 全局唯一、禁 `__` 前缀 |
| `geometry.components` | 可为空数组；每项必须有 `parentWall`（railing 用 `path` 世界坐标可无父级） |
| `materials` | 只放**被引用**的材质；每项五件套必填（§6.4） |
| `behaviors` | 无行为需求写 `{}` |
| `editor.revision` | 每次修改 +1（部署脚本可据此判断新鲜度） |

## 3. 直写元素书写规范

> 通用要求：所有 Vec3 = 三个有限数字；所有尺寸 > 0；ID 唯一。

### 3.1 `floor`（地坪 / 楼板 / 露台面 / 休息平台）

**先分清四类板（术语与归属，最容易写错的一节）**：

| 名称 | 是什么 | 板顶标高 | 归属 | 数量 |
|---|---|---|---|---|
| **地坪** | 首层落地地面（slab-on-grade，坐在台基顶） | **+0.45**（= 首层墙底 = 室内地坪顶） | 一层 | 恒 1 块 |
| **楼板** | 某层**顶板**，也就是上一层的**地板** | 上一层地面标高 | **下层**（它封顶的那层） | N 层共 **N−1** 块 |
| **露台面** | 层顶板暴露于室外的部分 | 同该层顶板 | 该层顶板 | 每个露台 1 块 |
| **休息平台** | 双跑楼梯半层转台 | 首层墙底 + 半层高 | — | 每层 1 块 |

> **标高口径（住宅，务必先定）**：**±0.000 = 室外地面**、**首层室内地坪顶 = +0.45 = 首层墙底**（三级 0.15 台阶消化）。故本类型两层的标高谱为 **0（室外地面）/ +0.45（地坪顶 = 首层墙底）/ 4.05（一层楼板 = 二层地板）/ 7.05（顶层屋面）**。整栋坐落于**实心地基 `foundation`**（顶 +0.45 / 底 −0.02 / 四面出挑 0.06）之上。

> **两个易错点**：① "一层楼板"与"二层地板"是**同一块板**，只写一次，不要写成两遍；② 首层地面叫**地坪**不叫楼板，顶层顶板由**屋面**承担、不另写 `floor`。

**字段**：`from[3]` `to[3]` `thickness` `material`。`from/to` 取**轴网中线包络矩形**，`from[1] == to[1] ==` 板顶标高。

```json
{ "type": "floor", "id": "ground",    "from": [0, 0.45, 0], "to": [11, 0.45, 9], "thickness": 0.2, "material": "floor_stone" }
{ "type": "floor", "id": "slab_l1_a", "from": [0, 4.05, 0], "to": [9, 4.05, 2.34], "thickness": 0.2, "material": "floor_wood" }
```

**书写规则**：
1. `from[1]` = **板顶 = 本层墙顶 = 上一层地面**（硬语义 ①）——地坪写 `0.45`（= 首层墙底）、一层楼板写 `4.05`、顶层屋面写 `7.05`；
2. 平面范围取外墙**中线**；板边**严禁**与外墙皮齐平（±0.12），也不得取内皮——否则产生共面灰缝（§5.3）；
3. 楼梯间必须**拆板**：洞口四周拆成 2–3 块（§5.5），拆板边界优先落在墙厚带内；
4. 露台面与休息平台同样用 `floor` 直写：露台面板顶 = 其所在层顶板标高（材料 `floor_terrace`）；休息平台板顶 = 半层高、`thickness 0.15`（材料 `floor_wood`）；
5. **命名约定**：`ground` / `slab_l<封顶层>` / `terrace_l<封顶层>[_方位]` / `landing_l12`（"一二层之间"即封顶层语义）。

### 3.2 `wall`（墙）

**字段**：`from[3]` `to[3]` `thickness` `material`；`from/to` 为墙**轴线两端**（Y 分别为墙底/墙顶标高）。

```json
{ "type": "wall", "id": "wall_l1_s", "from": [-0.12, 0, 0], "to": [11.12, 3.6, 0], "thickness": 0.24, "material": "wall_white" }
```

**书写规则**：
1. **外圈四墙端点严格重合**（§5.2）：四段墙端点同点，引擎 `adjustWallJoint()` 各向外延对方半厚 ⇒ 外角 90° 阳角、零缺口、重叠恒为 `t×h`；**禁手工写满长/内缩坐标**；
2. 同层相邻墙端点 XZ 必须**完全一致**（引擎角部延伸阈值 <0.01m）；
3. 内墙 0.12：与外墙相交的端点必须对齐外墙**内皮**（非中心线/外皮），且不得超出外墙；改外墙轮廓时必须同步改该层全部内墙；
4. 墙同时是**洞口的宿主**——`opening.parentWall` / 组件 `parentWall` 只能引用真实存在的墙 ID；
5. **墙体是所有"参考面"的来源**：楼板边、女儿墙定位、洞口对齐都以墙中线/外皮为基准，改墙必须连带改依附构件（§5.2 连带平移）。

### 3.3 `stair`（梯段）

**字段**：`from[3]` `to[3]` `width` `stepCount` `stepDepth` `stepHeight` `material`。

```json
{ "type": "stair", "id": "stair_f1", "from": [0.72, 0.45, 2.34], "to": [0.72, 2.25, 4.74], "width": 1.2, "stepCount": 10, "stepDepth": 0.24, "stepHeight": 0.18, "material": "floor_wood" }
```

**书写规则**：
1. **升高 = stepHeight × stepCount**（硬语义 ④）。双跑时每跑 = 半层高：层高 3.6 → `10 × 0.18`；层高 3.0 → `10 × 0.15`；
2. `from` = 起步点（含 Y = 起步标高），`to` = 该跑**水平终点**（Y 随意但建议写合理值便于人读）；
3. 步进方向由 `to - from` 的 XZ 决定，支持任意方向；踏步实体从 `from` 起逐级排布，**末步边缘距 `to` 少一个 stepDepth**——计算到达板边时按此反推（§5.5）；
4. 踏步宽 = `width`，沿墙/梯井中线布置：梯井宽 = width，两跑并排净距 0。

### 3.4 `roof`（屋顶）

**字段**：`roofType` `span` `depth` `height` `thickness` `position[3]` `material`。

```json
{ "type": "roof", "id": "roof_gable", "roofType": "gable", "span": 9.8, "depth": 7, "height": 2.6, "thickness": 0.2, "position": [4.5, 7.05, 3.5], "material": "roof_dark" }
```

**书写规则**：
1. **必须显式写 `position`**（= 屋顶底面中心 = 墙顶平面中心），否则 resolver 会按全楼墙包围盒扩张（硬语义 ⑤）；
2. `span` = X 向总宽（含出檐）、`depth` = Z 向总深；
3. **`gable` 语义**：屋脊沿 **Z**（depth 方向），山墙三角面朝**南北（±Z）**，坡面朝东西降落；想"山墙朝主立面"，让体块长边沿 Z 即可。`depth` 取体块进深 → 山墙与墙外皮贴合；X 向出檐写进 `span`（轴长 + 2×0.4）；
4. `height` = 1/4–1/3 × span（坡角 25°–35°）；屋脊标高 = `position[1] + height`；
5. **`flat`（平屋面）**：`height` 取 0.3 左右；**屋面板只作"内衬顶面"**——`span/depth` 退到**女儿墙内皮内侧**（`span = BX + 2h − 2(TE+δ)`，`δ = 0.03` 不可见量），**禁与外皮共面**。**"边缘护板"必须另写成 4 段 `wall` 环**（见 §5.2b）：轴线 = 女儿墙环轴线内移 `EMB = 0.03`、壁厚 = `TE`、端点严格重合 ⇒ 引擎斜接出**四角 90° 阳角**。**禁写「轴线 + 固定出檐 0.6」**（凸唇），**亦禁只改 `span` 了事**（箱体四角不斜接）；
6. **多体块建筑**：屋顶只覆盖顶部体块，不要试图用一个屋顶盖全楼——露台区域不设屋顶。

### 3.5 `primitive`（组合件：女儿墙 / 台阶 / 雨棚柱 / 玻璃板）

**字段**：`shape`（`box`/`sphere`/`cylinder`/`profile_sweep`）`position[3]` `dimensions[3]`（box）`material`；可选 `rotation[3]`（**弧度**）`scale[3]`。

```json
{ "type": "primitive", "id": "parapet_n", "shape": "box", "position": [5.5, 3.9, 9], "dimensions": [11.24, 0.6, 0.24], "material": "wall_white" }
```

**书写规则**：
1. `position` = **几何中心**（不是角点）；`dimensions = [X宽, Y高, Z深]`；
2. 女儿墙：**本质是 `wall`**（非 primitive；`type:"wall"`），高 0.90–1.20、厚=墙厚，坐本层墙顶；**转角按 §5.2 转角铁律**（端点严格重合、引擎斜接、外角 90° 阳角、无缺口）；仅布最外圈暴露段；
3. 台阶：每级高 0.15、深 0.4–0.6，逐级叠写；**住宅按「台阶数 × 0.15 = 室内外高差」定级数**（本项目正典：**三级 0.15 = 0.45**）。
   - **★ 标高口径（住宅）**：**±0.000 = 室外地面**、**首层室内地坪顶 = +0.45 = 首层墙底**；整栋坐落于**实心地基 `foundation`**（primitive box，顶 +0.45 / 底 −0.02 / 四面出挑 0.06 / 南面出挑至 −0.18）。⚠️ **禁只写一块 0.2 厚地坪板**（y 0→0.45 悬空 ⇒ 楼飘着、台阶贴墙侧无倚靠）。
   - **★★★ 朝向铁律（高的一侧贴建筑墙）**：台阶消化「建筑 > 室外」的高差 ⇒ **末级（最高）踏面紧贴建筑墙外皮、标高 = 首层室内地坪顶（= 门洞底 = 首层墙底 = +0.45）**，向**远离建筑**方向逐级下降至室外地坪（±0.000 = 0）。
   - **通式（南入口，沿 −Z 向外）**：设墙外皮 `z_w`、级数 `n`、步深 `d`、步高 `h`、室内地坪 `Y_in` ⇒ 第 `i` 级（`i = n` 最贴墙、最高）**踏面** `y_i = Y_in − (n−i)·h`、**中心** `y = y_i − h/2`、沿 z 区间 `[z_w − (n−i+1)·d, z_w − (n−i)·d]`；且 **`n·h == Y_in`**。**正典实例**：`z_w=−0.12, n=3, h=0.15, d=0.6` ⇒ `step_1` 中心 y=0.075 z 中心 −1.62 / `step_2` y=0.225 z −1.02 / `step_3` y=0.375 z −0.42（末级 z 端 = −0.12 = 墙外皮）。
   - **★ 反例**：把最高一级放远端、最低级贴墙 ⇒ 台阶反向、与门洞悬空一大段高差。**判据**：最贴墙一级的踏面标高必须 **>** 最外一级（`0.45 > 0.15`）。
   - **★ 双跑中分（配落地方柱门廊时，§4.5）**：台阶须**中部留空**、分作**东西两跑**（镜像对称、同级同高），**中央走道净宽 ≥ 门洞宽 + 1.2** 且**正对门洞投影**；**判据** = 两跑关于门廊中心对称、中央走道区间 ⊇ 门洞投影、**柱底与任一踏步『零正体积穿插』**。单跑会与柱底打架（穿模）⇒ 禁。
   - **与门洞对齐**：门 `from[1]` = 室内地坪世界 Y（**首层 = +0.45，不是 0**）；末级踏面标高与之相等、端面恰抵墙外皮（贴接不穿插）。
4. **禁用 `profile_sweep` 做封闭形体**（无端盖）；
5. 需要斜面时用 `rotation`（弧度，绕对应轴）；矩形柱用 box：`dimensions:[0.4, 层高, 0.4]`。

### 3.6 `beam` / `column`

| 元素 | 写法 | 关键点 |
|---|---|---|
| `column` | `style` 五枚举（modern 等）+ `bottomRadius/topRadius` + `height` | **矩形柱用 primitive box**，column 只有圆柱体 |
| `beam` | `from/to` + `crossSection:"rect"` + 截面尺寸 | 梁顶贴墙顶；梁端落在柱位上可自动吸附 |

### 3.7 `opening`（洞口）——**仅部署层使用**

源码蓝图**不要手写 opening**：门窗洞口由 `components` 编译产生。若确需裸洞（无门窗），才在 elements 写 `opening`（`parentWall` + `from`(左边缘+世界Y) + `width/height` + `material`）。旧引擎会为洞口**原生渲染填充板**（尺寸 +0.08），`material` 决定填充物（glass → 透明玻璃板）。

## 4. 组合构件书写规范

### 4.0 组件通用规则

| 规则 | 内容 |
|---|---|
| 坐标三语义 | `from = [沿墙距离, 世界Y, 法向偏移]`；**from[0] = 左边缘**距墙**起点**的距离（源码 1.1 语义）；`from[1]` = **世界 Y**（不是本层相对高度！）；**`from[2]` = 0（硬性）**——它是**沿墙法线方向**的偏移、以**宿主墙中心线**为零点，**必须写 0**；写非 0（或误填墙面 / 世界 z，如北墙写 10、内墙写 2）⇒ 引擎按 `\|from[2]\| ≥ (墙厚+框深)/2 − 1e-6` 判定「**门窗框深度与父墙没有实体交叠**」并**编译失败**（`COMPONENT_COMPILE_FAILED`）。墙中心线已是默认基准、无需补偿 |
| 墙起点定义 | 墙 `from/to` 为**轴线端点**（四角严格重合，§5.2）；因引擎两端各外延 `h`，**组件局部原点 = 实际渲染起点 = 轴线起点 − h** ⇒ `from[0] = 中心 − 宽/2 + h`（换算：洞左缘世界坐标 = 墙轴线起点世界坐标 + `from[0]` − `h`） |
| 安装深度 | 外门窗 `frameDepth = 墙厚−0.08 = 0.16`；内门 `= 0.06`；框/扇/玻璃任一表面距墙饰面 ≥0.03 |
| 框宽 | 外窗显式 `frameWidth: 0.09`（默认 0.06 远观读成空洞） |
| 不重叠 | 同墙开口区间 `[from0, from0+width]` 不得重叠；相邻开口净距 ≥0.4；距墙端 ≥0.24 |
| 不重复画 | 组件已含的几何（玻璃、门扇、阳台板、栏杆）禁止再用 elements 补（双层透明面 / 重复构件） |

### 4.1 `door`

```json
{ "type": "door", "id": "door_main", "parentWall": "wall_l1_s", "from": [5.32, 0.45, 0],
  "width": 1.2, "height": 2.2, "frameDepth": 0.16, "leafDepth": 0.05, "doorStyle": "single",
  "frameMaterial": "frame_dark", "leafMaterial": "door_wood",
  "interaction": { "mode": "swing", "hingeSide": "left", "openAngle": 90 } }
```

- 尺寸：主入口 1.2×2.2；内门/楼梯间门 0.9×2.1；`from[1]` = 本层地面**世界 Y**（首层写 **0.45** = 室内地坪顶，L2 门写 **4.05**，**不是 0**）；**门洞底 = 台阶末级踏面标高**；
- `interaction` 建议显式写全（viewer 点击开门依赖它）。

### 4.2 `window`

```json
{ "type": "window", "id": "win_l1_n1", "parentWall": "wall_l1_n", "from": [7.37, 0.9, 0],
  "width": 1.5, "height": 1.5, "frameWidth": 0.09, "frameDepth": 0.16, "glassDepth": 0.012,
  "verticalMullions": 1, "horizontalMullions": 1, "frameMaterial": "frame_dark", "glassMaterial": "glass" }
```

- 标准窗 1.5×1.5 或 1.8×1.5 @0.9，四分格（竖/横梃各 1）；大玻璃 3.6–4.0×2.7 @0.3（竖梃 2–3、横梃 0）；
- 同一立面**同轴同型号**：尺寸/窗台/分格全同，逐层对位。

**★ 多面窗「上下对齐 · 均匀分布」配方**（北 / 西 / 东三面，见类型文档 §7.3e）：

```
① 定「世界坐标中心集」（该面唯一网格，逐层共用）
   北面 z=10 ：x 网格 {3.0, 6.0, 11.5}   （左块 0–9 取 3/6；右块 9–14 取 11.5）
   西/东面   ：z 网格 {4.0, 7.0}
② 按各父墙方向反解 from[0]
   墙 +轴：from[0] = 中心 − 宽/2
   墙 −轴：from[0] = 墙起点坐标 − 中心 − 宽/2
③ 分段均布（L 形 / 退台处按段：段内等距、单窗居中）—— 禁跨段"全宽等距"
④ 逐件核 from[0] + width ≤ 墙长（退台墙更短，网格点须落在每道墙段内）
```

> **反例**：北面 L1 写 `from=[4.5,…]`（→ 世界 x=8.75）、L2 写 `from=[4.0,…]`（→ 世界 x=4.25）⇒ 上下错位。**根因 = 父墙方向不同，同一 `from[0]` 落不同世界位置**。正解 = 世界网格反解。

```json
  "width": 3.6, "depth": 1.5, "slabThickness": 0.15, "railingHeight": 1.05, "postSpacing": 0.9,
```

- balcony **自带板 + U 形栏杆**（含 railingHeight/postSpacing），禁止补板补栏；`from[1]` = 阳台板顶（= 本层地面，二层 = 4.05）；
- railing 用**世界坐标 path**（≥2 点），用于楼梯洞口临空边、露台无墙边缘。

#### ★★★ 入口门廊必须直写「四件套」（**禁 `canopy` 组件**）

> **机理**：`canopy` 组件的支柱由 `compileCanopy` 生成，**截面仅 0.06（细杆）**、高度依附宿主墙墙底
> ⇒ 做落地门廊时**读作"细支杆"而非柱**（用户观感 = "两端柱子并没有落地"）；且其安装高受限（须 ≥ 墙底 +
> 板厚/2 + 净高），无法精确控标高。**凡要"落地方柱门廊" ⇒ 一律不用 `canopy`，改直写 4 个元素**：

```json
{ "type": "primitive", "id": "porch_col_w", "shape": "box",
  "position": [4.0, 1.70, -1.57], "dimensions": [0.30, 2.50, 0.30], "material": "frame_dark" }
{ "type": "primitive", "id": "porch_col_e", "shape": "box",
  "position": [7.0, 1.70, -1.57], "dimensions": [0.30, 2.50, 0.30], "material": "frame_dark" }
{ "type": "beam", "id": "porch_beam",
  "from": [3.85, 2.95, -1.57], "to": [7.15, 2.95, -1.57],
  "crossSection": "rect", "width": 0.30, "height": 0.28, "material": "frame_dark" }
{ "type": "primitive", "id": "porch_slab", "shape": "box",
  "position": [5.50, 3.01, -0.89], "dimensions": [3.30, 0.12, 1.66], "material": "roof_dark" }
```

**四条硬判据**（细则与形制见 类型设计语言 §7.3b）：

1. **柱落地**：柱底 = 台基顶 = 室内地坪顶（+0.45）；柱底竖直投影内必有台基实体 ⇒ 台基南皮外扩到**棚板南端面**。
2. **口径唯一**：`柱顶 == 棚板底 == 梁顶`（三点同标高，偏移恒 **0**）。
   **★ 陷阱**：若柱顶按「`Y0 + 净挑高`」、过梁顶按「柱顶 + 梁高」**两套口径混写** ⇒ 柱顶与梁底之间凭空多出**一个梁高的悬空缝**（读作"柱子没过梁"）。`beam.from[1]` = **梁顶**（引擎自梁顶**向下**挂 `height`）。
3. **柱位由棚板派生**：柱中心 z = 棚板南端面 + 柱半径；柱外皮与棚板端面齐平（棚板宽 = 柱外皮跨 = `门廊净宽 + 柱截面`）。
4. **柱底避挡台阶**：台阶**中部留空**、双跑分列（中央走道正对门洞），柱底与任一踏步**零正体积穿插**。

**三条硬性比例**：棚底净挑高 ≥ 2.35（且高于门洞顶 ≥ 0.30）；棚板外挑进深 1.5–2.2；方柱截面 0.24–0.40。

#### ★★★ 阳台通行铁律（`balcony` 的硬性配套，缺一即错）

> **`balcony` 组件只产「悬挑板 + U 形栏杆」，不产洞口**（源码 `compileBalcony` 只输出 slab + railing）。
> ⇒ 若只在墙上写一个 `balcony`，则该阳台**三面栏杆 + 一面实墙**，**无门可出**，等于一个永远走不进去的装饰凸台。
> **阳台作为人的休闲 / 功能区，必须满足通行原则** ⇒ 其所依附墙体**必须另写一樘门或落地窗**，与阳台跨度对齐。

| 判据 | 要求 |
|---|---|
| **① 必有洞口** | 阳台 `parentWall` 上必须存在 `window`（落地窗）或 `door`，**禁**该墙在阳台跨内为纯实体 |
| **② 跨内重叠** | 该洞口沿墙区间 `[from0, from0+width]` 与阳台区间 `[bfrom0, bfrom0+bwidth]` **有重叠**（人须能正对走进） |
| **③ 必须落地** | 洞口底 `from[1]` ≈ **阳台板顶**（容差 ±0.05）——落地推拉门 / 落地窗 |
| **④ 通行净高** | 洞口顶 − 阳台板顶 **≥ 2.0m**（门 ≥2.1、落地窗 ≥2.4 为宜），且顶 ≤ 该层墙顶 |
| **⑤ 不重复** | 落地洞口由该 `window` / `door` 表达，**禁**再补玻璃板（§4.0 不重复画） |

**落地推拉门的写法（引擎无 `sliding` 型，用落地窗近似）**：引擎 `doorStyle` 只有 `single` / `double`（平开），无推拉型 ⇒ 现代别墅的**落地推拉门**以 **低窗台 `window`** 表达最稳妥：`from[1]` = 阳台板顶（3.6）、`height 2.4`、`verticalMullions 3`（三扇观感）、`horizontalMullions 0`（通高玻璃）。若坚持用 `door`，用 `doorStyle:"double"`（两扇）落地表达。
**注意**：阳台宽 3.6、落地门宽宜 2.4–2.8（两侧留 0.4–0.6 墙垛），且**与同墙其它窗区间不得重叠**（§4.0 不重叠）。

#### ★★★ 4.6 无框玻璃栏板 & 悬挑雨棚带（**直写薄板，不用组件**）

> 现代 / 新中式**退台、露台、平屋面**的临空护栏与**无柱入口雨棚**都属「**薄板环带**」——`railing` 是**杆件型**（立柱 + 横杆）、`canopy` 带支柱时是**细杆**，都不合用 ⇒ **直写 `primitive` `box`**，角部走 §5.2b 的「**通长—内缩**」配对。

**① 无框玻璃栏板**（见玻璃、不见柱）：

| 件 | 类型 / 材质 | 关键量 |
|---|---|---|
| 玻璃面板 | `primitive` `box` / `glass`（`materialClass:"glass"`、`transmission ≥ 0.9`） | 厚 **0.05**、高 **1.10**；**底 = 所在板顶**（落地不悬空）；`position[1] = 板顶 + GB_H/2` |
| 金属压顶扶手 | `primitive` `box` / `frame_dark` | 截面 0.08×0.05；**底 = 玻璃顶**（`position[1] = 板顶 + GB_H + 0.04`）；同路径通长 |

**★ 角部「通长—内缩」（§3.7 ① / §5.2b）**：取**南片通长**（跨满东西两角）、**东西片内缩**且端面恰抵南片北侧面：

```
南片长 = WBX − 2×(bi − 0.06)      // 盖满两转角，两端外皮与露台外皮齐平
东西片北端 = 南片北侧面            // 端面贴接（重叠 0、缝 0）
```
判据：`|南片长 − 目标| ≤ 2e-3`；四角玻璃外皮拼成**连续直角**（无缺口、无叠出）。

**② 悬挑雨棚带**（形制② 整体悬挑**无立柱**）：仅一块厚挑板、靠**后缘嵌墙**支承。

| 项 | 取值 |
|---|---|
| 棚底净挑高（棚板底 − 室内地坪顶） | **≥ 2.35** 且**高于门洞顶 ≥ 0.30** |
| 棚板外挑进深（自南墙外皮量至棚板南端面） | **1.5 – 2.2** |
| 后缘嵌入量 `EMB` | **≥ 0.03**（异材质不可见插入量，入墙不穿透；可见外沿齐平） |
| 棚板厚度 | 0.15 – 0.20 |

```

棚板底  = max(室内地坪顶 + 净挑高, 门洞顶 + 0.30)     // ★ 两条下界取大者
```

## 5. 坐标计算规则（公式区）

### 5.1 构件沿墙定位公式（门窗对齐）

```
开间内偏移量 s（墙起点 → 洞口左边缘）= Σ(前面开间) + 开间内偏移 − width/2
from[0] = s（源码 1.1：左边缘距离）
若墙为反向书写（如北墙 from X=轴长+0.12 向西）：from[0] = 墙起点X − 洞口右边缘X
```
自检：`from[0] ≥ 0` 且 `from[0]+width ≤ 墙长`；同墙区间不重叠。

### 5.2 转角完整性「三层总律」（一切转角必完整、零缺口；**禁手工派坐标**）

> **★★★ 三层总律**：蓝图中**任何**两段**正交相会**的实体，角部**必须完整**——**外角块满实、外侧 90° 阳角、零缺口**。**不分层级**：**① 构件**（`wall`/`roof`/`floor`）、**② 组件**（`railing`/`balcony`/`stair`/门窗…作为整体）、**③ 组件内部构件**（组件展开出的子几何）**一律适用**。
>
> **为何分三层**：引擎自动斜接**只覆盖"元素级 `wall`"**（`resolveWallJoints()` 筛选 `filter(e => e.type === 'wall')`）。组件被展开（`wild-compiler/components/*.ts`）后生成的子几何多为 `beam`/`primitive`/`cylinder`/`profile_sweep`，**全部不在斜接范围**（`buildBeam` 实测：仅按 `from→to` 生成一段盒/柱，**零转角处理**）。

**① 构件级（`wall`）**：任两段**正交相会**的沿轴实体（外墙 / 女儿墙 / 屋面侧板 / 勒脚 / 腰线 / 栏板 / 环带）在角部必须满足：**① 外角块满实、外侧呈 90° 阳角（零缺口）；② 两段体积重叠恰为理论下界 `t×h`**（`t`=厚度、`h=t/2`；0.24 厚 ⇒ **288 cm² × 段高**）。

**写法（唯一）**：令两段**端点严格重合于同一点**，其余交给引擎。

```
引擎 `wild-core/src/primitive/resolver.ts → adjustWallJoint()`：
  判两端点距 < 0.01（joinXZ 吸附）且竖向相交 → 再判正交 → **两墙各沿其轴向对方外延 `对方厚度/2`**
  （`_jointExtensions`；`geometry/wall.ts` 加进 renderLength、并同步平移洞口局部坐标）
  ⇒ 两墙实体**各达对方外皮**，外角天然 90° 阳角、零缺口。
```

**环写法（四段端点严格重合于轴线矩形四角）**（`AX`/`BX` = 轴长，`AY`/`BY` = 轴深）：

```
南墙 wall_*_s ：from [0, y0, 0]      → to [AX, y1, 0]
东墙 wall_*_e ：from [AX, y0, 0]     → to [AX, y1, AY]
北墙 wall_*_n ：from [AX, y0, AY]    → to [0,  y1, AY]
西墙 wall_*_w ：from [0, y0, AY]     → to [0,  y1, 0]
```
**女儿墙同理**；退台露台女儿墙**只布暴露段**（被二层全高墙覆盖处归零、端点取全高墙外皮）。

**★ 禁：手工书写"满长端 / 内缩端"坐标**（如内缩端写 `对方轴线 + h`）。两个必错原因——
① 内缩端令两端点相距 `h`（0.24 墙 ⇒ 0.12）**远超 0.01 容差** ⇒ 引擎配不上 ⇒ **不外延 ⇒ 外角缺口**；
② 手工留下的超长端又会被引擎**再叠加一次 `+h`** ⇒ 端点恰落到对方**轴线**（而非外皮）⇒ 缺口照旧。
**即"手工配对"与"引擎配对"双重作用，必然全错。**

**组件连带**：外墙两端各外延 `h` ⇒ 组件局部原点 = **实际渲染起点 = 轴线起点 − h** ⇒ 沿墙定位 `from[0] = 中心 − 宽/2 + h`（引擎按同一局部系切洞，口径一致）。

**`wall`×`profile_sweep` 交角**：外延只对 `wall` 生效 ⇒ 须手工让 `profile_sweep` 从其覆盖面**外皮**起、`wall` 沿轴端与之对齐（并同步改挂墙洞口 `from[0]`；断言若用 `from[0]+半宽` 反推中心须改**两端端点中点**）。

**自检（双通道）**：生成器断言 + 校验器各一条 —— 逐环逐角检验**引擎斜接后并集**对 `t×t` 外角块的**覆盖率 ≥ 99.9%**。**审计锚点须取"外尖点"（环外接矩形角 ± h）再向内采样**——锚在轴线交点/包围盒角会产生假 0%。

**② 组件级**（组件整体与宿主 / 相邻组件的转角）
- 转角处两段**共用同一个世界坐标点**，并由**转角柱（立杆恰落于该点）**收头——**禁两段各自缩回、中间留空档**（典型：四面栏杆在露台四角相会、阳台栏杆与侧向栏杆相会）。
- 挂载定位按"**世界坐标重合**"复算（组件局部原点 = 宿主实际渲染起点 = 轴线起点 − `h`），**禁各按轴线端点各写一半**。
- **`path` 布局型组件（`railing`）**：**折点即转角** ⇒ 折点位置须显式为路径顶点且有**立杆落点**，两段横杆端点同抵该立杆。

**③ 组件内部构件级**（组件展开出的子几何）
- **同轴折线分段**（栏杆横杆沿 `path` 分段）：**折点由竖向构件（立杆）覆盖**，两端点同抵该立杆（端面被吞没 ≤ 自身截面尺寸）⇒ 外角无缺口、无三角空档。
- **十字 / 丁字交接**（窗框竖梃×横档）：**一者通长、一者内缩至其外皮**（缩进 = 对方截面半宽）⇒ 角部外皮交汇成直角；**禁双缩进（缺角）、禁双通长（超叠 ≥ `t×t`）**。
- **楼梯**：转向平台处**上下跑踏步边线对齐**、梯段斜板与平台板共面收头。

**三层统一判据**：① 外角块（取**外尖点**再向内采样）被参与构件并集覆盖 **≥ 99.9%**；② 正交两段体积重叠**恰为 `t×h`**（< `t×h` = 缺口；≥ `t×t` = 超叠）；③ 转角处相邻两段（含组件与组件）**共用同一世界点**。

### 5.2b 屋面 / 露台板的边缘（**护板必写为 `wall` 环：面归板、角归墙**）

角部完整、外侧 90° 阳角这条律**不限墙体与屋顶**——**一切构件的角落搭接**均不得出现缺口。但**机制只有一条**：**端点重合 · 交给引擎斜接**（`adjustWallJoint()` 只处理 `type === 'wall'`）。⇒ 凡承担"角"的构件**必须是 `wall`**（组件级 / 组件内部构件级见 §5.2 三层总律 ② / ③）。

**① 沿轴实体**（`wall`：外墙 / 女儿墙 / 栏板 / 勒脚 / 腰线 / 环带，以及坡屋顶的**屋檐封边 / 山墙三角 / 戗脊收头**）⇒ 走 §5.2「**端点重合 · 引擎斜接**」，端点严格重合即可，引擎自会外延成 90° 阳角。

**② 屋面 / 露台的一圈"边缘护板" ⇒ 显式写成 4 段 `wall` 环**（**不要**把护板职责留在 `roof` / `floor` 盒的侧面上）：

```
轴线矩形 X[0,BX]×Z[0,BY]，外墙厚 TE，h = TE/2，EMB = 0.03（不可见内缩）：
  ① 屋面板（内衬顶面，roof/flat）： span = BX + 2h − 2(TE+EMB) 、 depth = BY + 2h − 2(TE+EMB)
                                     position = [BX/2, 所坐墙顶, BY/2]
  ② 护板环（4 段 wall）： 轴线 = 女儿墙环轴线整体内移 EMB（X[EMB, BX−EMB] × Z[EMB, BY−EMB]）
                          thickness = TE（与女儿墙同厚 ⇒ 斜接外延量一致）
                          下沿 = 屋面板顶、顶 = 屋面板顶 + 护板高
  例（BX 9 / BY 7 / TE 0.24 ⇒ h 0.12 / EMB 0.03）：
     屋面板 span 8.70 、 depth 6.70 、 position [4.5, 7.05, 3.5]  ⇒ 外沿 X[0.15, 8.85] × Z[0.15, 6.85]
     护板环轴 X[0.03, 8.97] × Z[0.03, 6.97] ⇒ 外皮 X[−0.09, 9.09] × Z[−0.09, 7.09]
  ⇒ 护板环外皮 = 女儿墙外皮 ∓ EMB ⇒ **不共面**（消 z-fight）、**不悬挑**（EMB 不可见）；
     四角相邻段端点重合 ⇒ 引擎斜接成**完整 90° 阳角**（与女儿墙环同源）。
```

- **★ 三条都治不好，故必须换语言**：① **外沿 == 女儿墙外皮** ⇒ 严格**共面**，渲染器无 `polygonOffset` ⇒ 掠射角 z-fight / 发丝缝，四角读作"护板角落有缺口"；② **「轴线 + 固定出檐 0.6」** ⇒ 凸出外皮成**悬挑凸唇**；③ **只改 `roof` 的 `span/depth`（内缩一段）** ⇒ 箱体四角**平直不斜接**，与女儿墙环**不同源**，角部仍留台阶缝。**修复 = 把这一圈护板重写为 4 段 `wall` 环**（整圈换语言）。
- **护板环壁厚取 `TE`**：引擎斜接外延量 = `对方.thickness / 2`；同厚 ⇒ 二者外延量相同 ⇒ 转角并集**恰好盖满 `TE×TE` 外角块**。
- **自检（双通道）**：① 护板环 = 4 段且 `type === 'wall'`；② 环轴端点两两重合 < 0.01 + 相邻段 `|dot| ≤ sin5°`；③ 环外皮 = 女儿墙外皮 ∓ `EMB`；④ 四角外角块（半厚 `h` 象限）被环并集**完全覆盖**。生成器与校验器各一条。


### 5.3 藏带规则（所有"边"的处理）

楼板边、洞口边、拆板缝——凡不必暴露的边，**收进墙厚带**（墙中线 ± 0.12 内）即不可见。
**禁止**：板边/洞边坐标等于 ±0.12、轴长±0.12 等**任何墙面坐标**（共面 → 灰缝/z-fighting）。
唯一例外：到达边（楼梯）、露台临空边——这两处必须与踏步或女儿墙精确对齐并设栏杆。

## 7. 书写顺序（推荐，且修改必须增量）

```
1 地坪 + 各层楼板（标高基准，N 层 = 1 + N−1 块）→ 2 外墙（端点重合、引擎斜接）→ 3 内墙/楼梯间墙 → 4 楼梯 + 平台 + 拆板
→ 5 屋顶（显式 position）→ 6 女儿墙/台阶等 primitives → 7 门窗组件（先算 from[0] 再写）
→ 8 阳台/雨棚/栏杆组件 → 9 materials → 10 自检（§9）
```
**修改协议**：既有蓝图只做增量（增/改/删指定元素），**同文件修改必须串行**（并行编辑互相覆盖）；改墙必查依附构件（§5.2）。

**外墙轮廓修改 → 内墙联动（硬性）**：改任一层外墙（退让/凸出/共线）时，必须同步改该层全部内墙（含梯井墙），禁止只动外墙+门窗/阳台。内墙只依附外墙；端点=外墙内皮（南 z=zc+th/2，北 z=zc−th/2，西 x=xc+th/2，东 x=xc−th/2）；端点不得超出外墙内皮区间；不得悬空/穿墙。组件 from 随父墙重算，内门随父内墙重算。重推：外墙轮廓 → 内皮 → 内墙端点 → 组件 from → 自检。

**地坪 / 楼板轮廓与标高（硬性）**：地坪只在一层，轮廓=一层外建筑轮廓。层间楼板=下层屋顶楼板≡上层地板（只写一次），**轮廓=下层外轮廓**；**板顶=`from[1]`=下层墙顶=上层墙底（与墙体顶面同一平面）**；板体向下 thickness。暴露部分 terrace 分块，并集仍=下层外轮廓。顶层不写 floor，由 roof 承担（搁置=顶层墙顶）。

**女儿墙（硬性）**：**只布一圈**——仅沿当层屋顶/露台板的**最外边缘轮廓**；中间（同层露台共边、退台内凹分界）**禁止**设女儿墙。书写同 `wall`，坐在本层墙顶，厚=墙厚，高 0.90–1.20，端点与墙面齐平（外皮/内皮）不嵌入。

**★ 女儿墙「同层级·遇全高墙即平齐」铁律（硬性，防嵌套）**：**女儿墙与普通全高墙属同一层级，二者不得形成嵌套**——凡外圈某边上**已有本层全高外墙**（如退台上层外墙共线）之处，女儿墙**必须在该段归零**（由全高墙延续收头），**禁**让女儿墙沿整条外轮廓"通铺"而**穿进**全高墙内部（同平面体积重叠 = 硬碰撞）。
- **写法 = 分段**：把该边拆成「暴露段」与「被全高墙覆盖段」，**只写暴露段**；分段端点取**全高墙的外皮面**（与全高墙端面平齐，不重叠不留缝）。
- **判据**：同平面（法向坐标相等）的两段墙，其**沿轴区间 × Y 区间**不得双重叠；若重叠 ⇒ 女儿墙穿墙（本类型校验器 C10 / D6）。
- **典型错误**：L1 11×9、L2 9×7 时，南/西两边各有半段与 L2 外墙共线 ⇒ 南边女儿墙**只写 X[9.12,11.12]**（而非 −0.12→11.12）、西边**只写 Z[7.12,8.88]**（而非 0.12→8.88）；东/北两边全暴露，可整条写。
  - **否则后果**：女儿墙（底 3.6、顶 4.2）与 L2 外墙（底 3.6、顶 6.6）在 Y[3.6,4.2] 全面重叠 ⇒ 挂在该墙上的**落地门窗下部 0.6m 被女儿墙吞没**（"门窗有一部分嵌进墙里"）。

**楼板板顶（硬性）**：**所有楼板板顶 = 本层墙体顶面**（=上层墙底）；`floor.from[1]=to[1]`=该 Y。
