### 1. 新增 `blueprint_normalizer.py` ✅

**文件位置：** `wild-server/app/utils/blueprint_normalizer.py`

**功能：**
- 以前端 `wild_schema.json` 为单一事实源
- 剥离未知字段（如 `parentFloor`、`frameMaterial`、`role` 等）
- 修复已知漂移模式：
  - `interaction.openAngle` 必须 > 0
  - `interaction.hingeSide` 只能是 left/right
  - `railLevels` 钳位到 (0, 1]
  - `from[2]` 归一化到 ≈ 0（贴墙）
  - 旧版 `column` style 枚举映射
  - 旧版 `column` 结构转换（dimensions/radius → base/height/radii）
  - 填充安全默认值（balcony/canopy/bay_window）
- 双墙去重
- 复用 `fix_wall_junctions` 和 `fix_opening_fit`
- 无法修复则丢弃单个构件
- 返回详细修复报告

**核心函数：**
```python
def normalize_blueprint_for_delivery(bp: Dict[str, Any]) -> Tuple[Dict[str, Any], NormalizeReport]
```

**特性：**
- ✅ 纯函数、无 LLM
- ✅ 幂等：`normalize(normalize(x)) == normalize(x)`
- ✅ 详细报告：剥离字段、修复字段、丢弃构件
- ✅ 最终 jsonschema 校验

### 3. 修复 `fix_opening_fit` 负宽 bug ✅

**文件位置：** `wild-server/app/tools/spatial_tools.py`

**问题：** 原逻辑在 `from[0]` 已越墙时会把 `width` 算成负值。

**修复：** 
```python
# 修复前
max_width = wl - max(along, 0)  # along > wl 时产生负值

# 修复后
clamped_along = min(along, wl - 0.1)  # 先钳位 along
max_width = wl - clamped_along  # 再计算 width
if max_width < 0.1:
    max_width = 0.1
```

确保 `0 <= along <= wl - width` 且 `width > 0`。

## 三、核心修复逻辑

### Schema 漂移修复流程
```
LLM 生成 Blueprint（可能包含旧字段/非法值）
              ↓
normalize_blueprint_input（现有基础归一化）
              ↓
normalize_blueprint_for_delivery（新增）
  ├─ 剥离未知字段
  ├─ 修复 interaction/railLevels/from[2]
  ├─ 填充安全默认值
  ├─ 旧版 column 转换
  ├─ 双墙去重
  ├─ 复用 fix_wall_junctions/fix_opening_fit
  └─ jsonschema 严格校验
              ↓
validate_blueprint_schema（现有预检）
              ↓
run_validation_pipeline（现有流水线）
              ↓
前端解析 + 渲染 ✅
```

### 关键设计原则
1. **单一事实源**：前端 `wild_schema.json` 是唯一标准
2. **确定性修复**：纯函数、无 LLM、幂等
3. **渐进式降级**：无法修复则丢弃单个构件，不阻止整体交付
4. **详细报告**：每次修复都记录，便于调试和追踪
5. **双重保险**：merge_node 和 agent_service 两条路径都接入
