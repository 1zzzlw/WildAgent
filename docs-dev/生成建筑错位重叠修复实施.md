# 生成建筑错位/重叠 —— 修复实施记录

日期：2026-08-17
前置诊断：`docs-dev/生成建筑错位重叠根因诊断.md`

## 一、根因结论（一句话）

**不是渲染器、也不是单纯提示词，而是后端与前端各自维护了一套 schema，且没有一层
在交付前把蓝图确定性收敛到 `wild-web/wild-lang/schema.json` 这一单一事实源。**

- 渲染器（wild-core）是确定性的：115 个蓝图重建错误为 0。
- 但 **29/108（27%）的 .wild 在前端 `parseBlueprint` 被严格 JSON Schema 拒绝**，
  整栋建筑因此渲染为空。
- 后端 `validate_blueprint_schema` 是比前端**更宽松、且已漂移**的独立副本，因此
  "后端校验通过 → 前端拒绝 → 建筑变空" 这一断层长期未被发现。

## 二、具体漂移样例（从历史文件实测提取）

| 失败类型 | 样例字段 | 修复 |
|---|---|---|
| light 携带 `parentFloor`/`behaviors` | 未知字段 | 剥离 |
| canopy 携带 `frameMaterial` | 未知字段 | 剥离 |
| door 携带 `role` | 未知字段 | 剥离 |
| window `interaction.openAngle=0` / `hingeSide="bottom"` | 枚举/数值越界 | 剥离非法子字段 |
| 旧版 column `style="classical"` | 非法枚举 | 映射为 `corinthian` |
| 旧版 column（`dimensions`/`radius`） | 旧结构 | 转换为 `base`/`height`/`radii` |
| 旧版 `body`（avatar） | 非建筑 | 丢弃 |
| 负宽 window（`width=-2.0`） | 尺寸非法 | 丢弃 + 修 `fix_opening_fit` 根因 |
| railing `railLevels=[0.5, 1.1]` | 越界 | 钳到 (0,1] |

## 三、实施内容

### 1. 新增 `app/utils/blueprint_normalizer.py`（纯函数、无 LLM）

- 以 `wild_schema.json`（vendored 自 `wild-web/wild-lang/schema.json`）为单一事实源，
  惰性派生每类型"允许字段/必填字段"白名单；
- `normalize_blueprint_for_delivery(bp) -> (bp, report)`：
  1. 复用既有 `normalize_blueprint_input`；
  2. `_repair_components`：剥离未知字段、修复 interaction、railLevels 钳位、
     回填安全默认值（balcony/canopy/bay_window）、`from[2]≈0`，无法判定则丢弃单个构件；
  3. `_repair_elements`：旧版 column/body 转换、style 枚举修复、必填字段校验；
  4. `_normalize_geometry`：双墙去重 + 复用 `fix_wall_junctions`/`fix_opening_fit`/
     `_resolve_wall_opening_component_conflicts`；
  5. 二次收敛兜底（避免几何修复引入负宽等新非法值）；
  6. 用 `jsonschema` 做与前端同源的严格校验，返回剩余错误数。
- 幂等：`normalize(normalize(x)) == normalize(x)`。

### 2. 接入管线

- `app/agent/nodes/merge_node.py`：合并完成后、返回前调用归一化（LangGraph 主路径）。
  `final_validate` 因指纹变化会自动复检归一化后的蓝图。
- `app/services/agent_service.py`：旧单体路径在结构预检前同样归一化。

### 3. 修复 `fix_opening_fit` 负宽 bug（`app/tools/spatial_tools.py`）

原逻辑在 `from[0]` 已越墙时会把 `width` 算成负值（`max_width = wl - along`，along>wl 时为负）。
改为先钳位 `along`、再钳位 `width`，保证 `0 <= along <= wl - width` 且 `width > 0`。

### 4. 测试

- 新增 `tests/test_blueprint_normalizer.py`（6 用例：漂移修复/from[2]/双墙/旧列/幂等/不误伤）。

## 四、回归结果（同一 108 个历史文件，前端分析器 `analyze-batch.mjs`）

| 指标 | 修复前 | 修复后 | 说明 |
|---|---|---|---|
| **解析失败** | **29** | **0** | 29 栋"渲染为空"的建筑恢复渲染 |
| 重建错误 | 0 | 0 | 渲染器始终稳健 |
| from[2] 法向偏移 | 1 | 0 | 错位根因消除 |
| 开口墙角 | 10 | 19* | 见下 |
| 同墙组件重叠 | 12 | 19* | 见下 |
| 双墙 | 2 | 4* | 见下 |

\* 上升项为**预期现象**：那 29 个原本"解析失败→被跳过分析"的文件，归一化后可解析，
其内部本就存在的几何问题（多为室内隔墙自由端、不同标高开口）才首次被统计进来，
并非归一化引入新问题。其中"开口角"多为 `wall_core_partition` 这类合法的室内隔墙
自由端（`fix_wall_junctions` 用 `_is_structural_wall` 已正确跳过非结构墙）。

## 五、验证

- `pytest`：归一化单测 6/6、空间校验/合并精度/交付/提交/回调/路由等 85+ 用例全通过。
- 前端分析器对归一化输出：解析失败 0、重建错误 0、from[2] 0。

## 六、后续建议（未在本次实施）

1. 把 `wild_schema.json` 的 vendored 副本与前端做 CI 一致性校验，防止再次漂移；
2. 对"同墙开口重叠"补充一个更强的确定性重排/裁剪（当前依赖
   `_resolve_wall_opening_component_conflicts`，已能处理门>凸窗>普通窗优先级）；
3. 归一化丢弃动作可在 UI 上以 warning 呈现，便于用户感知被丢弃的坏构件。
