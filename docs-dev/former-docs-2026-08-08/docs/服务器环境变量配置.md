# 服务器环境变量配置

本文档说明 WildAgent 部署到远程服务器时，后端容器需要的 `.env` 文件应该放在哪里、写什么内容、如何设置权限。

## 1. 文件路径

当前 `Jenkinsfile` 默认读取远程服务器上的：

```text
/opt/wild-agent/.env
```

对应 Jenkins 参数：

```text
DEPLOY_ENV_FILE=/opt/wild-agent/.env
```

如果以后想换路径，需要同时修改 Jenkins 构建参数 `DEPLOY_ENV_FILE`。

## 2. 创建目录和文件

在远程 Linux 服务器执行：

```bash
mkdir -p /opt/wild-agent
nano /opt/wild-agent/.env
```

写入后保存，并设置权限：

```bash
chmod 600 /opt/wild-agent/.env
```

## 3. 推荐 `.env` 内容

```env
# Chat Model：负责理解用户请求，并结合 RAG 召回内容生成结果
CHAT__NAME=qwen3.7-max
CHAT__API_KEY=替换成轮换后的 API Key
CHAT__BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# Embedding Model：负责知识库向量化和语义检索，不能替换为 Chat Model
EMBEDDING__NAME=text-embedding-v4
EMBEDDING__API_KEY=替换成轮换后的 API Key
EMBEDDING__BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# Rerank Model：当前代码尚未接入，以下字段仅预留
RERANK__NAME=
RERANK__API_KEY=
RERANK__BASE_URL=

# RAG 检索与文档分块
RAG__ENABLED=true
RAG__PERSIST_DIR=storage/chroma
RAG__COLLECTION_NAME=wild_knowledge_base
RAG__TOP_K=6
RAG__CHUNK_SIZE=900
RAG__CHUNK_OVERLAP=150
RAG__MAX_CONTEXT_CHARS=18000

# 生产环境建议关闭；true 仅适合无 Embedding API 时的本地 smoke test
RAG__ALLOW_HASH_FALLBACK=false
```

仓库同时提供了可复制的模板：

```text
wild-server/.env.example
```

### 3.1 模型职责

| 配置 | 当前用途 | 推荐模型 |
| --- | --- | --- |
| `CHAT__*` | 最终理解、推理和生成 `.wild` 内容 | `qwen3.7-max`，也可使用有效快照名 |
| `EMBEDDING__*` | 将知识库和查询转换为向量，供 Chroma 检索 | `text-embedding-v4` |
| `RERANK__*` | 预留的二次排序配置 | 当前不生效，暂时留空 |

Chat Model 和 Embedding Model 是两个不同接口。`qwen3.7-max`、`qwen3.7-plus`
不能代替 `text-embedding-v4` 完成向量化。三组配置可以使用同一把百炼 API Key，
前提是该 Key 对相应模型都有调用权限。

不要增加 `RAG_MODEL`、`RAG_TOP_K`、`CHUNK_MAX_SIZE` 这类字段。当前项目使用
Pydantic 嵌套环境变量，代码实际读取的是：

```text
EMBEDDING__NAME
RAG__TOP_K
RAG__CHUNK_SIZE
RAG__CHUNK_OVERLAP
```

### 3.2 RAG 参数说明

| 配置 | 作用 | 当前推荐值 |
| --- | --- | --- |
| `RAG__TOP_K` | 最终注入提示词的召回片段数量 | `6` |
| `RAG__CHUNK_SIZE` | 单个 Markdown 分片的目标字符数 | `900` |
| `RAG__CHUNK_OVERLAP` | 相邻分片的重叠字符数 | `150` |
| `RAG__MAX_CONTEXT_CHARS` | 基础规范和召回内容的总字符上限 | `18000` |
| `RAG__ALLOW_HASH_FALLBACK` | 缺少 Embedding 配置时使用低质量本地 hash 向量 | 生产环境 `false` |

`TOP_K=3`、`CHUNK_SIZE=800`、`CHUNK_OVERLAP=100` 也是合法值，但不建议在没有
检索评估结果时随意缩小。当前知识库规模不大，先使用 `6/900/150` 更稳妥。

## 4. 当前 RAG 已实现与未实现的范围

已实现：

- 读取镜像内 `/app/storage/knowledge_base/` 的 Markdown 规范。
- 使用 `EMBEDDING__*` 调用 OpenAI Compatible Embedding API。
- 对文档分块并写入 Chroma。
- 根据每次用户请求检索相关片段。
- 将基础规范和召回片段一起注入 Chat Model。
- 将 Chroma 数据持久化到 `/app/storage/chroma`。
- 容器再次启动时增量同步索引；知识库未变化时不会重复调用 Embedding API。

尚未实现：

- `RERANK__*` 二次排序。
- 用户上传、删除和管理知识库文档。
- 知识库管理 UI。
- 运行中监听文档变化并热更新索引。

服务器部署时，知识库文档已经打包在后端镜像内；不需要在服务器手工创建知识库
文件。Jenkinsfile 会把服务器目录 `/opt/wild-agent/storage/chroma` 挂载到容器的
`/app/storage/chroma`，用于持久化向量索引。

## 5. Jenkins 部署时如何使用

部署阶段会把这个文件传给后端容器：

```bash
docker run ... --env-file /opt/wild-agent/.env wild-agent/wild-server:xxx
```

所以 `.env` 不需要提交到 GitHub，也不需要放进镜像。

创建或修改 `.env` 后，需要重新运行 Jenkins 部署，让 Jenkins 重新创建
`wild-server` 容器。单独执行 `docker restart wild-server` 不会更新容器环境变量。

## 6. 部署后验证

在远程服务器执行：

```bash
docker logs --tail=100 wild-server
```

正常启用 RAG 时，日志应包含类似信息：

```text
RAGSpecLoader: 已启用 Chroma
SpecLoader: RAGSpecLoader
```

如果看到以下日志，说明 RAG 初始化失败，系统已经退回只读取最小规范：

```text
RAGSpecLoader 初始化失败，退回 FileSpecLoader
```

常见原因包括 Embedding 模型名错误、API Key 无权限、Base URL 与 Key 所属区域不一致。

## 7. 注意事项

- 不要把真实 `.env` 提交到 GitHub，即使是私有仓库也不建议。
- 仓库里最多放 `.env.example`，不要放真实 API Key。
- 如果 `.env` 不存在，Jenkinsfile 当前会继续启动后端容器，但后端只能使用默认空配置，模型调用大概率不可用。
- 更换 Embedding 模型或分块参数后，后端会根据索引签名自动重建 Chroma collection。
