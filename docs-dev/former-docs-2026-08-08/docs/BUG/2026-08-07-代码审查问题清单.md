## 二、前端功能 BUG（🔴 / 🟡）

### BUG-05：场景摘要 bbox 只统计 column，其他构件全部忽略

- **位置**：`wild-web/src/wild/sceneSummary.ts` `generateSceneSummary()`
- **问题**：bbox 计算分支只处理 `element.type === 'column'`，wall/floor/roof/opening/stair 等基础构件和全部组合构件（components）都不参与 bbox 计算
- **影响**：发送给 Agent 的 `scene_summary.bbox` 严重不完整。场景里只有墙没有柱时 bbox 为 `undefined`，Agent 无法获知场景真实范围，可能生成坐标越界的构件
- **严重度**：🔴（直接影响 Agent 生成质量）

### BUG-06：loadBlueprint 硬编码 revision=1，破坏 patch 版本控制

- **位置**：`wild-web/src/stores/sceneStore.ts` `loadBlueprint()`（第 66 行 `revision: 1`）
- **问题**：AI 生成蓝图（`blueprint_generated` → `sceneStore.loadBlueprint()`）和导入文件都会把 revision 重置为 1。而用户在画布上的任何 patch 会使 revision 递增（+1）
- **影响**：
  - 场景加载后 revision 回退到 1，Agent 后续 `patch_proposal` 的 `base_revision`（后端取 `scene_revision`）与前端当前 revision 可能不匹配，`applyPatch` 直接拒绝（"Patch revision 不匹配"）
  - 具体触发：用户先手动编辑（revision 涨到 N），再让 AI 重新生成覆盖 → revision 回到 1 → 后续修改类 patch 全部失败
- **严重度**：🔴

### BUG-07：前后端场景保存路径时区不一致（UTC vs 本地）

- **位置**：
  - 前端：`wild-web/src/agent/agentBridge.ts` `buildSceneRelPath()` 用 `new Date().toISOString().slice(0,10)`（**UTC** 日期）
  - 后端：`wild-server/app/api/ws_agent.py`、`blueprint_parser.py` 用 `datetime.date.today()`（**服务器本地**日期）
- **问题**：在中国时区（UTC+8），每天 0:00–8:00 之间，前端 PUT 保存会落到"昨天"的日期目录，后端生成的文件却在"今天"目录
- **影响**：同一会话可能在不同日期目录各存一份 .wild，`sessions.py` 扫描 `rglob("*.wild")` 用 `startswith(session_id)` 匹配可能命中两份或旧的那份，导致加载到过期蓝图
- **严重度**：🟡

### BUG-08：deleteSessionBlueprint 依赖 session.filename，草稿会话删除失败静默

- **位置**：`wild-web/src/agent/agentBridge.ts` `deleteSessionBlueprint()`
- **问题**：`relPath = session?.filename ?? \`${sessionId}.wild\``，草稿会话（无后端文件、filename 为空）DELETE 返回 404 视为成功——逻辑上 OK。但已保存会话若 `session.filename` 含日期目录而前端用旧缓存列表（filename 缺失）时会回退到根目录 `{sessionId}.wild`，删除错文件/找不到文件
- **影响**：会话列表刷新后删除可能删不到正确文件，残留孤儿 .wild
- **严重度**：🟡

## 三、后端功能 / 安全问题（🟡）

### BUG-09：CORS 配置允许所有来源且带凭据

- **位置**：`wild-server/main.py`
  ```python
  allow_origins=["*"],
  allow_credentials=True,
  ```
- **问题**：`allow_origins="*"` 与 `allow_credentials=True` 组合违反浏览器 CORS 规范，且在生产环境等于放开任意站点跨域调用后端 API（含删除场景、读写 .wild）
- **影响**：任何网站脚本都能对后端发起跨域 DELETE /api/scenes、POST /api/sessions 等操作（若攻击者先构造出用户已认证的连接状态则更严重）。至少应改为明确的前端域名白名单
- **严重度**：🟡（安全）

### BUG-10：sessions.py 用 startswith 匹配 session_id，存在前缀碰撞误删/误载

- **位置**：`wild-server/app/api/sessions.py`
  - `_find_blueprint_for_session()`：`if basename.startswith(session_id)`
  - `delete_session()`：`if wild_file.stem.startswith(session_id)`
- **问题**：`session_123` 会匹配 `session_1234_xxx.wild`。删除 `session_123` 时可能连带删除 `session_1234` 的蓝图文件
- **影响**：session_id 前缀重叠时误删/误关联其他会话文件
- **严重度**：🟡（删除为不可恢复操作，建议改为 `stem == session_id` 或 `stem.startswith(session_id + "_")`）

### BUG-11：scenes.py 旧格式 PUT /{filename} 路径穿越防护依赖 FastAPI 单段参数

- **位置**：`wild-server/app/api/scenes.py` 旧格式路由 `PUT /{filename}`、`DELETE /{filename}`
- **问题**：`{filename}` 是单段路径参数，FastAPI 默认不匹配含 `/` 的 URL（除非声明 `{filename:path}`），所以 `../../evil.wild` 这类带斜杠穿越 URL 无法进入该路由——这一点是安全的。但 `_resolve_file_path` 用 `str(file_path).startswith(str(SCENES_DIR.resolve()))` 做前缀判断，若存在与 SCENES_DIR 同前缀的兄弟目录（如 `.../scenes_backup`），可被前缀绕过
- **影响**：当前路由形态下穿越风险较低，但 `_resolve_file_path` 的前缀比较应改用 `Path.is_relative_to()`（Python 3.9+）更严谨
- **严重度**：🟢（防御性建议）

### BUG-12：syncMessagesToServer 只 POST 追加、无去重，刷新后消息可能翻倍

- **位置**：
  - 前端：`wild-web/src/agent/agentBridge.ts` `syncMessagesToServer()`（POST `/api/sessions/{id}/messages` 传整个 messages 数组）
  - 后端：`sessions.py` `add_messages()`（`messages.extend(new_messages)`，`MAX_MESSAGES_PER_SESSION=200`）
- **问题**：前端每次生成后把当前全部消息数组 POST 上去，后端是纯追加（extend），不做去重/幂等。同一会话重复刷新、重复生成，消息会重复累积（200 条截断兜底）
- **影响**：消息历史存在重复条目，前端 `get_messages` 恢复后可能出现同一句话多遍
- **严重度**：🟡

### BUG-13：`_safe_name_slug`（前端）与 `_slug`（后端）中文正则不一致

- **位置**：
  - 前端 `agentBridge.ts`：`name.replace(/[^\w\u4e00-\u9fff]/g, '_')`
  - 后端 `ws_agent.py`：`re.sub(r"[^\w一-鿿]", "_", name, flags=re.UNICODE)`（`一-鿿` 即 U+4E00–U+9FFF，两者等价）
- **问题**：实际两者覆盖范围一致，文件名 slug 可对齐。但前端用 `toISOString`（UTC）日期、后端用本地日期，两者拼接出的 `sessionId_nameSlug.wild` 路径在凌晨时段日期段不同（见 BUG-07）
- **影响**：与 BUG-07 联动，非独立问题
- **严重度**：🟢（记录供 BUG-07 修复时统一）
