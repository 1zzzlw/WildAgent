# 阶段十二：双窗扇、灯光交互与组件拖动总结

## 本阶段目标

本阶段补齐三项编辑体验：窗户右键命中哪一扇就开合哪一扇；构件库提供真正发光的灯泡；组合构件的拖动与门窗交互一样由用户显式开关控制。

自动吸附、自动对齐、碰撞校验和依附面候选推荐不在本阶段实现，统一进入后续规划。

## 已完成内容

### 1. 双窗扇独立开合

- 可交互窗口仍编译为左右两块独立窗扇。
- 左窗扇使用左铰链，右窗扇使用右铰链，两扇分别持有运行时交互元数据。
- 视口不再把任意窗框点击转发到固定的一扇；右键实际命中的窗面只控制对应窗扇。
- 两扇可以先后打开，也可以分别关闭；平开和推拉继续复用统一门窗动画。
- 属性面板对窗户隐藏无意义的单一“开启方向”选择，保留开合方式、最大角度/距离和初始状态。

### 2. 通用灯光交互

- 新增 `light` 组合构件，当前外观由灯泡球体和灯座圆柱组成，未向 Core 增加专用几何 builder。
- 支持 `point` 和 `spot` 两类运行时光源；灯光颜色、弱光强度、强光强度、照射距离和聚光角度写入 Blueprint。
- 右键灯泡按“关闭 → 弱光 → 强光 → 关闭”循环，亮度使用约 220ms 的平滑过渡。
- renderer 为灯泡创建真实 Three.js 光源，同时调整灯泡自发光；灯具交互协议可供后续吊灯、壁灯等外观复用。
- 构件库新增“灯泡”，默认允许拖动；默认点光源位置为 `[0, 2.4, 0]`。

### 3. 显式拖动开关

- 所有组合构件 Schema 都支持可选字段 `draggable`，旧 Blueprint 未设置时保持不可拖动。
- 属性面板使用 Element Plus `el-switch` 显示“允许拖动”开关；开关、说明卡片、颜色选择器和数值控件采用统一样式。
- 开启后，单选组件显示 Three.js 三轴平移控件；拖动期间暂时关闭相机轨道控制，避免事件竞争。
- 拖动时整体移动该组件编译出的所有子网格；松开后通过 `update_component` Patch 回写 Blueprint，因此支持历史记录和重建。
- 墙挂组件的世界位移会换算为父墙的“沿墙距离 / 世界 Y / 法向偏移”；路径、坡道和自由坐标组件更新其对应坐标字段。
- 拖动关闭时不显示三轴控件，也不会改变既有场景的编辑行为。

## 分层结果

```text
Blueprint: light 参数、opening interaction、draggable 开关
wild-compiler: 双窗扇/灯具展开，向子元素附加运行时元数据
wild-core: 只透传 interaction 与 draggable，不新增灯泡几何类型
renderer: 门窗动画、灯光实例与亮度动画
Vue 编辑器: Element Plus 属性控件、右键拾取、三轴拖动和 Patch 回写
```

这种划分保持“语义组件由编译层展开，renderer 只执行通用行为”的既有边界。以后新增灯具外观时，只要继续生成带 `kind: light` 的灯泡网格，就不需要复制一套开关和调光逻辑。

## 回归验证

- `vue-tsc -b`：通过。
- `node scripts/check-component-compiler.mjs`：通过，能力列表扩展为 10 类组件；覆盖双窗扇铰链方向、灯光三态循环、真实点光源、拖动元数据和坐标换算。
- `node scripts/check-wild-core.mjs`：通过，6 个样例、11 项 Core 能力无回归。
- 浏览器内人工测试：当前内置浏览器不可用，仍需在本地页面强制刷新后验证鼠标命中、三轴控件手感和实际光照效果。

## 当前边界

- 拖动只做确定性的坐标变换，仍会经过现有 Blueprint/组件边界校验；越出父墙等非法结果会拒绝写回并恢复重建结果。
- 当前没有吸附网格、面吸附、锚点、碰撞检测、间距约束或自动纠偏。
- 当前灯具运行时亮度状态不持久化；Blueprint 只保存 `initiallyOn` 和两档亮度参数。
- 灯泡是低成本参数化占位外观，高细节灯具资产仍属于后续资产系统。
