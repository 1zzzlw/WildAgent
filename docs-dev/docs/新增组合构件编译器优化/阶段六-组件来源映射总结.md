# 阶段六：组件来源映射总结

## 阶段目标

让编译后的门框、窗棂、洞口和栏杆子网格能够回溯到语义级源组件，为 3D 拾取、整体高亮和属性编辑提供稳定依据。

## 实现结果

组合编译结果新增双向映射：

```text
generatedElementIdsByComponentId
  源组件 ID → 全部临时元素 ID

componentIdByGeneratedElementId
  临时元素 ID → 源组件 ID
```

例如点击 `front_door__frame_left` 时，前端可以确定真正需要编辑的是 `front_door`；选中 `front_door` 时，也能找到洞口和三段门框进行整体高亮。

## 数据边界

- 映射只存在于 `ReconstructedEntity.componentMapping`。
- 源 `.wild` 文件仍只保存 `geometry.components`。
- 没有组合构件的旧蓝图返回空映射。
- 编译失败的组件不会产生虚假的子元素映射。
- 原生元素仍按自己的 `elementId` 选择，不改变既有选择语义。

## 新增辅助函数

- `resolveSelectableId()`：把拾取到的临时元素 ID 转为源组件 ID。
- `getRenderedElementIds()`：把源组件 ID 展开为需要高亮的全部渲染元素 ID。

## 验证结果

- TypeScript 与 Vite 构建通过。
- 组件专项测试通过。
- 测试覆盖门组件完整映射、临时元素反向回溯、原生元素直通和渲染结果携带映射。

## 阶段结论

组件编辑不再依赖解析子元素 ID 前缀，也不需要让 renderer 理解 `door/window/railing`。下一阶段可以在这一映射上实现视口点击、整体边框高亮和源组件属性面板。
