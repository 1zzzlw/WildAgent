# 阶段七：组件选择、高亮与编辑界面总结

## 阶段目标

让用户不编辑 JSON 也能新增、选择、查看、修改和删除第一批组合构件，并让这些操作进入现有 ScenePatch、校验、撤销/重做和保存链路。

## 3D 视口拾取

视口新增 Three.js Raycaster 拾取：

- 单击普通网格时选择对应基础元素。
- 单击门框、窗棂、洞口或栏杆子网格时，通过阶段六映射选择源组件。
- 单击 InstancedMesh 中的栏杆立柱时按 `instanceId` 找到准确子元素。
- 鼠标移动超过 5 像素时按轨道控制拖动处理，不误触发选择。
- 单击空白处清空选择；按住 Shift 可以追加选择。

## 整体高亮边框

选中组合构件后，前端收集它的全部编译子元素，并计算统一世界坐标包围盒。高亮使用独立 `Box3Helper`：

- 门的洞口和三段门框共同高亮。
- 窗的洞口、四边窗框和所有窗棂共同高亮。
- 栏杆的横杆和立柱共同高亮。
- 对实例化网格只计算属于当前组件的实例，不把其他栏杆一起框入。
- 场景重建、撤销或重做后会按最新映射重新生成高亮，不保存到 Blueprint。

## 场景树

场景树现在分为“组合构件”和“基础构件”两组。门、窗、栏杆可以直接在树中选择，选中后自动打开右侧属性面板。

## 组件新增

构件库新增门、窗、栏杆入口：

- 门窗默认依附第一面墙，并根据墙长、墙高计算不会立即越界的初始尺寸。
- 场景中没有墙时会提示先创建墙体。
- 栏杆创建一条可继续编辑的默认路径。
- 新增成功后立即选中源组件并打开属性面板。

## 属性编辑

属性面板覆盖三个受支持组件的全部公开字段：

- 门：父墙、局部位置、宽高、门框尺寸、门框材质、门扇材质。
- 窗：门窗公共字段、竖向/横向窗棂数量、玻璃材质。
- 栏杆：高度、立杆间距/半径、横杆半径、材质、全部路径点和横杆高度比例。

栏杆支持增删路径点和横杆层。组件也可以从属性面板删除；删除需要确认，但可以通过撤销恢复。

所有修改都生成 `update_component` 或 `remove_component` ScenePatch。非法尺寸、父墙越界或重复栏杆高度会被现有校验拒绝，不会污染当前场景。

## 撤销、重做与 Agent 上下文

本阶段同时修复了既有历史 Store 未接入 `sceneStore.applyPatch` 的断链：

- 每次成功 Patch 保存修改前后 Blueprint 快照。
- 撤销/重做恢复快照但不会制造新的历史项。
- 恢复后 revision 继续递增，后续 Patch 不会使用过期版本。
- 保存与导出仍输出语义级 `geometry.components`。
- 当前选择 ID 会发送给 Agent，支持后续“修改这个门/窗/栏杆”的指代。

## 验证结果

- TypeScript 类型检查和 Vite 构建通过。
- 组件专项测试覆盖属性修改、撤销和重做。
- 本地开发服务器返回 HTTP 200，应用入口可正常加载。
- 当前运行环境未提供可用的内置浏览器标签页，因此没有伪造截图或声称完成可视化点击验收；最终仍建议在实际浏览器中做一次点击与边框颜色 smoke test。

## 阶段结论

第一批组合构件已经具备完整的界面编辑闭环：新增、树选择、3D 选择、整体高亮、属性修改、删除、撤销、重做、保存和 Agent 指代都操作同一个源组件。
