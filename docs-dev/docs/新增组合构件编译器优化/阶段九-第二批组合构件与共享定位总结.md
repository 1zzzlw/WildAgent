# 阶段九：第二批组合构件与共享定位总结

## 阶段目标

在不继续扩充 renderer 建筑名词分支的前提下，把第二批常用建筑构件实现为 `geometry.components` 语义组件，并从真实复用需求中抽取墙面、楼板、屋面和路径定位能力。

## 完成内容

组合构件类型从 3 类扩展到 9 类：

- 第一批：`door`、`window`、`railing`。
- 第二批：`canopy`、`balcony`、`ramp`、`bay_window`、`cornice`、`chimney`。

新增组件均由 `wild-compiler` 确定性展开为 Core 已支持的 `wall`、`floor`、`beam`、`opening`、`primitive` 和 `profile_sweep`，没有给 renderer 增加雨棚、阳台或烟囱等业务类型。

## 共享依附与定位

| 能力 | 当前用途 | 能力边界 |
|---|---|---|
| `attachToWall` | 门、窗、凸窗、雨棚、阳台 | 沿墙弧长、世界高度、切线/法线；形成开口的组件仅允许直线墙或单段圆弧墙 |
| `attachToFloor` | 坡道、栏杆 | 支持矩形和圆形楼板的局部平面定位 |
| `attachToPath` | 栏杆、坡道、檐口 | 路径校验、采样与直线路径偏移 |
| `attachToRoof` | 檐口、烟囱 | 支持平屋顶、双坡和四坡屋顶的基础表面定位；不执行屋面布尔穿透 |

这些模块只抽取已有两个或以上真实调用方需要的最小能力，没有引入通用约束求解器。

## 编辑与协议配套

- 构件库能够新增六类组件。
- 场景树、3D 选择来源映射和属性面板能够识别九类组件。
- 第二批组件有各自的业务字段编辑区，并继续通过 ScenePatch 修改、撤销和重做。
- Schema、TypeScript 类型、场景摘要与校验器同步更新，保存结果仍只保留语义组件。

## 验证结果

- 固定几何评测从 6 个扩展到 12 个。
- 组件编译回归通过：9 类组件、共享依附、来源映射、缓存和交互字段均通过。
- 第二批组件经过 Schema 解析和真实 Core 重建，未发现缺件、重复 ID 或编译异常。

## 阶段结论

第二批构件已经证明“业务构件进入编译层、通用几何留在 Core”的扩展路线可行。后续新增建筑构件时，应优先组合现有底层几何；只有多个构件共同缺少同一项通用几何能力时，才扩展 Core。

## 坡道与檐口几何修正补充

- 坡道主体由矩形 `beam` 改为上表面严格经过 `from/to` 的 `profile_sweep` 连续斜板，并增加随坡侧缘挡台、从挡台顶面起算的立柱和上下两道扶手。
- 修复 Core `beam` 的三维欧拉朝向公式；斜扶手的局部长度轴现在严格对齐 `from → to`，沿 X 延伸时也不会丢失 Y 高差。
- 构件库默认坡道调整为 5.4m 水平长度、0.45m 高差和 1.5m 宽度，避免默认样例过短、过陡。
- 构件库不再创建无依附的悬空檐口；必须先存在屋顶，默认沿屋顶边界生成分层线脚截面。
- 屋顶未显式设置 `position` 时，编译器会按结构墙包围盒推导与 Core 一致的屋顶原点，避免依附檐口和最终屋顶错位。
