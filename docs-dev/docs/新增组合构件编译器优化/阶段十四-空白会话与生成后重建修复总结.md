# 阶段十四：空白会话与生成后重建修复总结

## 问题现象

新建会话后，即使用户只测试构件且没有点击保存，服务端仍会出现一个空 `.wild`。同一会话随后由 Agent 生成完整 Blueprint 时，文件内容已经正确更新，但前端偶尔仍停留在空画布。

## 根因

1. 新建会话会立即把空 Blueprint 写入 `storage/scenes`，绕过了“显式保存”边界。
2. Agent 完整生成后复用同一个文件 URL 拉取 Blueprint，请求没有禁用缓存，可能读取先前的空内容。
3. 前端调用 `loadBlueprint` 后没有等待 Worker 重建完成，就提前显示加载成功；真实重建失败只能在控制台看到。
4. 生成期间若用户切换会话，迟到的生成结果可能覆盖当前画布。

## 已完成修复

1. 新建会话只创建浏览器草稿，不再自动向服务端写入空文件。生成完整建筑或用户点击顶部“保存”后，才会创建对应 `.wild`。
2. `blueprint_generated` 事件增加 `session_id`，前端以请求 ID 增加缓存隔离参数，并同时设置 `fetch cache: no-store`。
3. scenes 列表和文件读取接口返回 `Cache-Control: no-store, max-age=0`，服务端与浏览器两端共同禁止旧文件缓存。
4. `loadBlueprint` 现在返回 Worker 重建结果；只有重建成功后才提示“Blueprint 已加载”，失败时给出明确错误。
5. 生成结果只允许更新所属会话；用户已经切换会话时，仅更新对应会话摘要，不覆盖当前画布。
6. 未保存的新会话没有服务端文件，删除接口遇到 404 时前端仍可正常移除本地会话。

## 数据边界

- 手动添加组件、拖动、属性修改和应用 ScenePatch：只修改当前草稿，点击“保存”才覆盖服务器文件。
- Agent 生成一份完整新建筑：生成流水线落盘后立即加载该文件并重建画布。
- 本次不会自动删除历史版本遗留的空 `.wild`，避免误删用户主动保存的空场景；这些文件可以从会话列表中人工确认后删除。

## 回归验收

1. 新建会话不产生服务器 PUT 请求。
2. 生成事件只执行一次禁用缓存的 GET，并携带请求级缓存隔离参数。
3. 最新 Blueprint 加载完成后必须存在重建实体。
4. WebSocket 生成事件同时携带正确的 `session_id` 与会话文件地址。
5. 前端类型检查、组件回归、后端 WebSocket 测试与生产构建全部通过。
