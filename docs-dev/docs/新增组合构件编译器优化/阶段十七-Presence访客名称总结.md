# 阶段十七：Presence 访客名称总结

## 本阶段目标

在进入编辑器前收集一个仅用于展示的访客名称，让在线列表可以区分不同同事，同时保持该名称与账号、会话、Agent、RAG 和蓝图数据完全分离。

## 完成内容

- 首次进入编辑器前展示访客名称输入页，空名称不能进入。
- 名称最长 24 个字符，前后端都会去除首尾空白并合并连续空白。
- 名称保存在当前浏览器本地，刷新页面后不需要重复输入。
- WebSocket 建连时通过 Presence 连接参数提交名称。
- 在线列表展示访客名称、地区、脱敏 IP 和连接时间。
- 在线列表提供名称修改入口；修改后通过 `presence_identify` 消息实时更新在线快照，不会重建 Agent 会话。
- 旧客户端或异常名称统一降级显示为“访客”。

## 数据边界

- 访客名称不是账号，不提供身份认证能力。
- 允许不同连接使用相同名称。
- 名称只存在于浏览器本地存储和后端内存中的当前在线连接快照。
- 名称不会写入 `.wild`、会话文件或知识库，也不会发送给大模型。
- Presence 扩展关闭后，名称不会参与任何核心编辑器流程。

## 后续边界

如果以后需要按用户隔离会话，应引入不可伪造的用户 ID 和登录认证，不能把当前访客名称当作权限标识。
