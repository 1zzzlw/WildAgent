# 现代别墅生成结果问题分析报告

> 分析对象：`D:/Backup/Downloads/现代别墅.wild` + 3 张渲染截图
> 建筑规格：两层现代别墅，占地 8m × 6m，层高 3m

## 一、总体印象

从三张截图和蓝图数据来看，这个“现代别墅”已经具备了**基本的建筑轮廓**（墙体、楼板、屋顶、门窗开口），但存在明显的**建筑合理性不足**和**组件布局机械化**问题。整体更像一个“自动排布的方盒子”，而不是经过设计思考的住宅。主要问题集中在：**屋顶比例失衡、窗户过多过密、栏杆位置不合常理、雨棚与门错位、缺少楼梯** 等。

---

## 二、按类别列出的具体问题

### 1. 屋顶：尺寸过大、高度过高、类型与描述不符

**蓝图数据：**
```json
{
  "type": "roof",
  "roofType": "gable",
  "span": 9,
  "depth": 7,
  "height": 2.5,
  "position": [4, 6.5, 3]
}
```

**问题：**
- **屋顶比建筑主体还大**：建筑 footprint 是 8m × 6m，但屋顶 span=9m、depth=7m，四个方向都会飘出墙体外侧，形成“飞檐过大”的违和感。截图中屋顶明显比一层墙体外扩一圈。
- **屋顶基准高度过高**：墙体到二层顶部是 y=6m，屋顶从 y=6.5m 开始，中间留出 0.5m 的空隙；加上 2.5m 的屋顶高度，屋脊高达 9m。对两层别墅来说，这个高度比例失调，屋顶显得异常高耸。
- **屋顶类型与描述不符**：描述说“四坡屋顶”，但 `roofType` 是 `gable`（双坡屋顶）。

**建议：**
- 屋顶 span/depth 应 ≤ 8m/6m，或仅略出挑 0.2~0.3m。
- 屋顶基准高度应与二层墙顶对齐（y=6m），高度控制在 1.5~2m。
- 若描述为四坡屋顶，应使用 `hip` 类型。

---

### 2. 窗户：数量过多、排列机械、缺乏主次

**蓝图数据：**
- 共 **24 个窗户**（一层 12 个 + 二层 12 个）。
- 每面墙 3 个窗户，尺寸几乎相同（宽 1.0m 或 0.8m，高 1.2m），间距均匀。

**问题：**
- **密度过高**：8m × 6m 的两层小别墅，24 个窗户平均到四面墙 × 两层，每面 3 个。实际住宅设计不会在所有墙面上均匀开窗，尤其是侧墙和后墙。
- **没有考虑门的位置**：正面一层主入口在 x≈2.52~3.72m，但窗户仍按均匀间距分布。右侧窗户（x=4.48~5.48m）距离门边仅约 0.76m，视觉上太挤；左侧窗户（x=0.76~1.76m）与门也不成比例。
- **现代别墅应有的“大面宽落地窗”完全没有体现**：描述中提到“大面积落地窗”，但实际生成的是小尺寸、机械排列的普通窗。
- **窗户离地高度过低**：一层窗户 from[1]=0.9m，二层 from[1]=3.9m（相对于世界坐标，实际上二层窗户底边距二层地面也是 0.9m），高度合理；但尺寸偏小，且没有高窗、飘窗等变化。

**建议：**
- 正面可适当放大窗户尺寸（例如 1.5m × 1.8m），侧面/背面减少数量。
- 主入口附近留出完整的墙面缓冲，不要在门边紧挨着放窗。
- 根据 wall length 动态计算窗户数量，而不是固定每面墙 3 个。

---

### 3. 栏杆：位置完全不合理（最严重问题之一）

**蓝图数据：**
```json
{
  "type": "railing",
  "parentFloor": "floor_second",
  "path": [[0.5, 3, 0.5], [7.5, 3, 0.5]],
  "height": 1.1
}
```

**问题：**
- **栏杆被放在二层墙体内部**：`parentFloor` 是 `floor_second`，y=3m，高度 1.1m，因此栏杆从 y=3m 到 y=4.1m。但二层墙体是从 y=3m 到 y=6m，所以栏杆**嵌在二层墙的中间**，而不是露台边缘或屋顶边缘。
- **四面墙都有栏杆**：但二层四面都有墙，说明二层不是开放露台，四面都加栏杆没有意义，只会造成“墙上长了一圈栅栏”的违和效果。
- **视觉上像屋顶下方悬浮的女儿墙**：截图中屋顶和墙体之间有一圈栅栏状结构，正是这些栏杆。它们既不像露台护栏，也不像屋顶女儿墙，位置尴尬。

**建议：**
- 栏杆只应出现在有高低差或开放边缘的位置（如真正的露台、阳台、楼梯口、屋顶平台边缘）。
- 若二层是封闭空间，不应生成四面栏杆。
- 若需要屋顶女儿墙，应作为 roof 组件的附属结构，或在屋顶层单独生成 parapet，而不是用 `parentFloor=floor_second` 的栏杆。

---

### 4. 门：数量尚可，但后门坐标错误、雨棚错位

**蓝图数据：**
```json
{
  "type": "door",
  "id": "door_back_service",
  "parentWall": "wall_back_1",
  "from": [2.52, 0, 0]
}
```

**问题：**
- **后门位置错误**：`parentWall` 是 `wall_back_1`，该墙位于 z=6m。但后门的 `from[2]=0`，说明它被放在了 z=0 处，而不是 z=6 的背墙上。这是一个明显的坐标错误。
- **雨棚与门错位**：
  - 前门位置：x=2.52~3.72m，中心约 x=3.12m。
  - 前雨棚 `canopy_front_main`：from=[4, 2.8, 0]，宽 1.2m，中心 x=4m。
  - 两者重叠仅约 0.32m，雨棚大部分悬在门右侧，没有完全覆盖入口。
  - 后门雨棚同理错位。

**建议：**
- 门组件生成时应根据 `parentWall` 的平面坐标正确设置第三维（z 或 x）。
- 雨棚应根据门的 `from` 和 `width` 自动计算中心位置，确保覆盖门洞。

---

### 5. 柱子：数量过多、层级错误

**蓝图数据：**
- 8 根柱子，每层 4 根，位于四个角。
- 一层柱子：base y=0，高 3m。
- 二层柱子：base y=3.2m，高 3m。

**问题：**
- **现代别墅不需要这么多外露角柱**：8m × 6m 的混凝土/砖混住宅通常不需要外置装饰柱。8 根柱子让建筑看起来像公共建筑或门廊结构。
- **二层柱穿透屋顶**：二层柱子从 y=3.2m 到 y=6.2m，而屋顶从 y=6.5m 开始。柱子顶端正好顶到屋顶下方，但视觉上容易与屋顶冲突。
- **没有结构逻辑**：这些柱子没有支撑雨棚、阳台或屋檐，纯粹是装饰性的角柱，显得多余。

**建议：**
- 现代别墅可去掉外露柱，或仅在主入口门廊处保留少量门柱。
- 若保留柱子，应确保其顶部支撑某个构件（雨棚、阳台、屋顶），并与被支撑构件底边对齐。

---

### 6. 缺少楼梯

**描述中说**：“预留大面积落地窗、四坡屋顶及室内楼梯位置。”

**问题：**
- `geometry.elements` 和 `geometry.components` 中均没有任何楼梯（stair/ramp）元素。
- 两层别墅没有楼梯，功能不完整。

**建议：**
- 在 skeleton 阶段或 component 阶段根据楼层数自动建议楼梯组件。
- 在内部墙体上预留楼梯洞口，或生成楼梯构件。

---

### 7. 视觉层面：整体像“拼凑的方块”

- **材质单一**：只有几种灰色调，缺少现代别墅常见的玻璃幕墙、木饰面、石材等材质变化。
- **缺少细节**：没有屋檐线条、没有基座、没有排水管、没有台阶。
- **窗户看起来不透明**：`glass` 材质设置了 `opacity: 0.35`，但渲染中窗户是白色/灰色，没有通透感。可能是渲染器未读取 opacity，或玻璃材质未正确应用。

## 四、根本原因推测

1. **LLM 对“现代别墅”的理解停留在“方盒子+门窗”**：没有形成“主立面、服务流线、露台、屋顶出挑”等设计概念。
2. **组件数量规则过于简单**：每面墙固定 3 个窗、4 面墙都加栏杆、4 个角都加柱子，说明 prompt/规则中缺少“按需生成”的约束。
3. **坐标校验不足**：后门 `from[2]` 与 `parentWall` 的 z 坐标不一致，说明组件节点生成后没有进行严格的 `opening_coords` / `wall_junctions` 校验，或者校验只检查了碰撞没有检查归属。
4. **RAG / prompt 没有提供现代住宅设计常识**：比如“雨棚应覆盖门洞”“栏杆只应在开放边缘”“小别墅不需要外露柱”等常识未被编码进生成逻辑。

---

## 五、修复方向建议

1. **prompt 层面**：在 `build_component_prompt` 中加入更强的“现代住宅设计常识”约束：
   - 窗户：根据 wall length 和 facade 重要性决定数量，避免所有墙面均匀分布。
   - 栏杆：必须确认 `parentFloor` 上方没有墙包围，只在开放边缘生成。
   - 门：每个主要朝向最多 1~2 个门，服务入口不要在视觉上破坏主立面。
   - 雨棚：必须根据门洞位置精确计算 from。

2. **校验层面**：
   - 修复 `validate_opening_coords`：门的 from 坐标必须在 parentWall 所在平面上。
   - 增加“栏杆不应被墙体包围”的校验规则。
   - 增加“雨棚必须覆盖门洞”的校验规则。

3. **骨架层面**：
   - skeleton 节点应明确区分“主立面”“背立面”“侧立面”，并给出各立面开窗密度的建议。
   - 根据楼层数自动建议楼梯位置。
   - 根据建筑 footprint 限制屋顶 span/depth，不应超过墙体轮廓太多。

4. **模型路由层面**：这个问题属于**后端生成质量**，应由 **deepseek-pro** 负责修改 prompt 和校验逻辑。

---

## 六、结论

当前生成的别墅虽然结构完整，但明显缺乏建筑设计常识：**屋顶过大、窗户过密、栏杆嵌在墙中、雨棚错位、缺少楼梯**。这些问题不是渲染 bug，而是**生成逻辑和校验规则不足**导致的。修复重点应放在：

1. 强化组件布局 prompt 约束；
2. 补齐 opening/栏杆/雨棚 的位置校验；
3. 在骨架阶段引入主立面/服务流线的概念；
4. 根据楼层功能自动添加必要构件（如楼梯）。

修改完成后，应重新生成同一句 prompt（“一个现代别墅”）进行回归验证。
