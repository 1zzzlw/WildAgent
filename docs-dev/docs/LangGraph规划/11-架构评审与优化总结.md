# LangGraph Agent 架构评审与优化总结

> 日期：2026-08-06  
> 范围：`wild-server/app/agent/` 全链路 + `ws_agent.py` 精密模式  
> 状态：评审完成，Phase A 优化已落地

---

## 一、总体结论

**架构方向正确，节点划分基本合理。** 从单体 Agent 拆成「骨架 → 动态并行组件 → 合并 → 校验 → 回调」符合 WildAgent「AI 只填参数、引擎负责几何」的核心理念。

| 维度 | 评分 | 说明 |
|------|------|------|
| 架构方向 | ★★★★☆ | 分片并行 + 骨架驱动是正确的工程选择 |
| 节点划分 | ★★★★☆ | gen/val 分离、工厂模式好；merge/validate 有重叠 |
| 图拓扑完整性 | ★★★☆☆ → ★★★★☆ | 已补 EDIT 路径；组件依赖去重已落地 |
| 状态管理 | ★★★☆☆ | 字段膨胀、Callable 不可序列化（待 Phase B） |
| 错误处理/重试 | ★★★☆☆ | callback 已有 current_params + tool_data，结构化错误待补 |
| 可扩展性 | ★★★★☆ | 注册表驱动扩展性好 |

## 二、当前图结构

```
classifier
  ├─ GENERATE → skeleton → Send(组件 gen→val 链，并行) → merge → final_validate
  │                                                      ↓ partial
  │                                                   callback → merge (循环)
  ├─ EDIT     → patch → END                    ← Phase A 新增
  └─ CHAT     → chat → END
```

### 设计亮点

1. **注册表驱动**（`COMPONENT_REGISTRY`）：新增组件主要改配置，符合开闭原则
2. **gen → val 两段式**：LLM 生成与工具校验职责分离，诊断字段完善
3. **Send 动态派发**：骨架未建议的组件零成本跳过
4. **design_brief**：骨架输出 facade_plan + component_quota，组件节点按配额执行
5. **双模式并存**：LangGraph 精密 + LangChain 快速，便于渐进迁移

## 四、节点职责速查

| 节点 | 输入 | 输出 | 是否调 LLM |
|------|------|------|-----------|
| classifier | user_message, current_blueprint | intent | 是（轻量） |
| chat | user_message | chat_reply | 是 |
| patch | user_message, current_blueprint | scene_patch | 是 |
| skeleton | user_message | skeleton_blueprint, design_brief, suggested_components | 是 |
| {type}_gen | skeleton_*, design_brief | {type}_fragments | 是 |
| {type}_val | fragments, skeleton_blueprint | 校验后 fragments | 否（工具） |
| merge | 所有 fragments, skeleton | merged_blueprint | 否 |
| final_validate | merged_blueprint | failed_components, status | 否 |
| callback | failed_components | 修正后 fragments | 是 |

## 五、与 LangChain 快速模式对比

| 维度 | LangGraph 精密 | LangChain 快速 |
|------|----------------|----------------|
| 新建建筑 | skeleton → 并行组件 → 合并校验 | 单次 Agent 输出完整 Blueprint |
| 增量修改 | patch 节点（Phase A） | query_structured ScenePatch |
| 知识问答 | chat 节点 + 多角度 RAG | 同一 Agent 纯文本 |
| 校验 | 多层（per-component val + merge + final） | 单次 15 步 pipeline |
| 重试 | 组件级 callback | 无细粒度重试 |

## 六、测试建议

### 关键词 fallback
- 「生成现代别墅，不要门」→ 不应派发 door_gen
- 「中式庭院，要有飞檐和烟囱」→ 应派发 cornice + chimney

### EDIT 路径
- 有 current_blueprint + 「把门加宽到 1.2m」→ 走 patch 节点，返回 patch_proposal
- 无 current_blueprint + 「把门加宽」→ 降级为 generate 或报错

### 组件依赖
- skeleton 建议 `balcony, railing` → 应只派发 balcony（railing 被 embed 去重）
