# 生成建筑「错位 / 偏移 / 重叠」根因诊断报告

- 诊断日期：2026-08-06
- 范围：115 个 `.wild` 蓝图（`wild-server/storage/scenes/**` + `wild-web/lantu/**`）
- 工具：复用真实编译器/重建器（`wild-core` + `wild-compiler`）做的批量扫描脚本 `wild-web/scripts/analyze-batch.mjs`

---

## 0. 结论先行（直接回答你的问题）

> **不是渲染引擎的问题，也不是单纯提示词的问题，而是「管线设计缺陷」。**

三个判断的依据：

1. **渲染引擎（Compiler / Renderer）是正确且确定性的**——115 个文件里**重建错误 = 0**。只要喂给它合法、闭合、坐标自洽的蓝图，它就 100% 正确渲染。手绘参考图 `generated_modern_villa.wild` 就是证明（0 错误）。
2. **提示词无法从结构上杜绝这类问题**——提示词只能影响 LLM 输出概率，而「墙体端点精确共享」「组件绝对世界 Y 正确」「同墙开口不重叠」这些是**几何坐标不变量**，不是语义，LLM 每代一次都有概率算错。
3. **真正的缺失是：LangGraph 各节点（skeleton / component / merge）自由生成坐标，但管线里没有任何确定性环节去强制『WILD schema 合规 + 几何坐标不变量』。** 你手绘的那份参考图之所以没问题，是因为**有人工逐条保证不变量**；AI 管线缺的就是这个「守门人」。

所以你感觉「不是提示词的问题」是对的；但它也不是渲染 bug——**是生成的数据（蓝图 JSON）不合规、不自洽，而管线没有在渲染前把数据修合规。**

## 2. 失败模式分类与根因

### A. Schema 不合规 → 整图无法解析（29 个，25%）
LLM 产出的 JSON 不符合 WILD schema，解析阶段直接抛错，整栋建筑渲染成空/崩。典型错误：
- `parentFloor 是未知字段；path 为必填字段` —— **旧 schema 残留**（构件用 `parentFloor` 而非 `parentWall`+`path`）。
- `interaction.openAngle 必须大于 0；type 必须为 "door"` —— door 构件字段畸形。
- `elements[33].height 必须大于 0；from 为必填字段` —— column 等元素缺字段。
- `components[0].frameMaterial 是未知字段；slabThickness 为必填字段` —— balcony/canopy 字段畸形。
- `column style 必须是 doric/ionic/...`、`stair build 必须是 lean/athletic/stout` —— **旧枚举 schema 残留**。
- `meta.type 必须是 building/avatar/asset/scene`。

**根因**：LLM 产出「自由 JSON」，管线只在最后用严格 parser 校验，却没有**生成后 → 渲染前的 schema 修复门**。一旦 LLM 偏离当前 schema（或用了训练里的旧 schema），整图报废。

### B. 墙体未闭合（12 个）→ 墙角缝隙 / 错位
复杂轮廓（L 形、U 形、退台）里，内墙/隔墙的端点没有和其他墙共享同一角点（距离 > 6cm）。例如：`wall_int_h@(-7.87,0)`、`wall_stair_L_1@(10,5)` 等悬空端点。渲染后这些墙之间出现可见缝隙或错位。

**根因**：skeleton 节点**独立生成每一面墙**，没有把「相邻墙端点必须重合」作为硬约束，也没有事后 snap。

### C. 双墙 / 重叠墙（2 个，严重）→ 视觉偏移 / 重叠
例如 `wall_base_l_front <> wall_repair_1 (4m)`、`新中式退台别墅` 中 13 对墙体互相重叠数米（翼墙直接画在基座墙上方）。两个 Box 共面叠加 → z-fighting / 看起来像「墙偏移了一截」。

**根因**：退台、翼体量分别建模，没有墙体**去重 / 避让 / 裁剪**逻辑。

### D. 同墙真实组件重叠（12 个）→ 视觉重叠
同一 `parentWall` 上，两个构件水平区间和竖向区间都重叠，例如：
`window_left_f1_02(4.6-5.8) X door_left_f1_far(5-6) ov=0.8m yov=1.3m`
（窗和门在同一面墙、同一高度段重叠了 0.8m）。

**根因**：component 节点按 `parentWall` + `from[0]`（沿墙弧长）放置构件，但**没有同墙开口排布 / 最小间距校验**，也没有跨节点去重。这正是此前「24 扇窗」数量问题的坐标版——数量修好了，但**位置仍可能重叠**。

### E. 组件编译错误（3 个）→ 构件被静默丢弃
`compileBlueprintComponents` 把单个构件错误吞进 `diagnostics`（不抛），导致该构件干脆不出现。例如某个文件 32 个构件全部编译失败 → 那面墙空了。

**根因**：字段缺失（如缺 `frameDepth`）触发 `assertWallDepthAlignment` 抛错被吞。这本身是「合法但字段不全」的数据问题。

### F. 竖向缝隙（10 个，保守）→ 楼板/墙竖向不连续
楼层高度与墙体 Y 由不同节点分别给出，未对齐，出现悬浮楼板或墙顶悬空。（注：本指标为保守启发式，含部分良性楼板厚度偏移，置信度低于 A–E。）

## 3. 「我的设计」（参考图）vs AI 管线的本质差异

**参考图 `generated_modern_villa.wild`（手绘，0 错误）**
- 4 面墙端点**精确共享角点**：`(0,0)-(11,0)-(11,8)-(0,8)`，闭合矩形。
- 组件 `from = [沿墙弧长, 绝对世界 Y, 法向 ≈ 0]`：`door_front` `from:[4.6,0,0]`、`window_front_l1_l` `from:[1.0,0.9,0]`。
- 门窗带完整 `frameWidth / frameDepth / glassDepth / openingStyle / doorStyle`。
- 所有不变量由人工逐条保证。

**AI 管线**
- 每个节点「独立想象」坐标；坐标契约（① `from[1]` = 绝对世界 Y，② 选对 `parentWall`，③ 墙端点共享）对 LLM 是**隐含且易错**的。
- 编译器只对「越界」（如 `from[0]+width>length`、`from[1]` 超出墙体竖向范围、`|from[2]|` 过大）**抛错 → 静默丢构件**；对「**合法但坐标错**」（墙没闭合、构件贴错墙、构件重叠）则**照渲染 → 错位 / 重叠**。

> 一句话：渲染器是「照单全收」的确定性机器；AI 给的「单子」经常算错坐标却不越界，于是就被忠实渲染成了错位/重叠。

---

## 4. 根因（一句话）

> 渲染引擎正确；问题 100% 在 **AI 生成的蓝图数据**；根因是管线**缺少介于 `merge` 节点与渲染器之间的「确定性蓝图归一化 / 修复层」**——既不做 schema 合规修复，也不强制几何坐标不变量。

这也解释了为什么你之前修过的 `design_brief / component_quota`（数量配额）只解决了「24 扇窗」的**数量**问题，却没解决**位置重叠 / 墙错位**：那一层只管数量，没管坐标。

---

## 5. 修复建议（设计层，非提示词层）

新增 **`blueprint_normalizer`**（建议在 `merge_node` / `final_validate` 之后、渲染之前调用，或在 `wild-server` 侧加一道确定性关卡）：

1. **Schema 修复门**：`parentFloor → parentWall + path`；补全缺失 `height / from / thickness / slabThickness`；枚举值白名单修复（column style、stair build、meta.type）；类型字段补全。
2. **墙体端点 snap**：把距离 < TOL（如 6cm）的端点合并为同一角点 → 强制闭合。
3. **墙体去重 / 避让**：同向重叠 > 阈值的两段墙合并或裁剪，消除双墙 z-fighting。
4. **同墙组件排布**：按 `parentWall` 聚合，按 `from[0]` 排序，重叠或间距不足则重排 / 丢弃多余；强制 `from[0] + width <= length`。
5. **竖向连续性对齐**：由 `floor` 列表推导每层世界 Y，反推组件 `from[1]` 与墙体 Y 范围，修正错层 / 错墙附件。
6. **`from[2]` 归一**（贴墙，≈0）。
7. **严格回滚**：修复后仍不合规 → 降级或显式报错，**不要静默**。

## 6. 验证方式（回归闸门）

- 把 `scripts/analyze-batch.mjs` 作为 CI / 生成后闸门：期望 **解析失败 = 0、开口角 = 0、双墙 = 0、真实组件重叠 = 0**。
- 对手绘参考图必须始终保持 0 问题（已验证通过）——它既是「正确样板」，也是「回归基线」。
