## 方案 A 落地：修 wild-core 迁移后 Jenkins 前端部署必挂

**背景**：用户把渲染引擎从 `wild-web/src/wild-compiler|wild-core` 迁移成根级 `wild-core/` 包（`wild-web/package.json` 加 `"wild-core": "file:../wild-core"`，lock 里 `link:true` 软链）。这个迁移**未 commit**（`git status` 一排 `RM` rename），HEAD(`4bc9645`) 里仍是旧布局（`wild-core/` 0 文件、package.json 无 wild-core 依赖）。

**根因（确定性失败，非偶发）**：`file:../wild-core` 要求 wild-core 在 wild-web 的父目录，但 Jenkins 构建环境只给 wild-web 目录本身：
- `Jenkinsfile` 旧 `docker build -f wild-web/Dockerfile wild-web` → build context 只有 wild-web，wild-core 进不去。
- `Dockerfile` `npm ci` 解析 `file:../wild-core` → 容器 `/wild-core` 不存在 → ENOENT。
- 编译检查 stage `-v $PWD:/app`（$PWD=wild-web）同样找不到 `../wild-core`。

**方案 A 改动（4 处）**：
1. 新建仓库根 `.dockerignore`（context 改根后 Docker 只读根 .dockerignore；排除 `**/node_modules`、`**/dist`、`.git` 等，否则 `COPY wild-web/ ./` 会把 node_modules 带进去）。
2. `wild-web/Dockerfile`：COPY 路径加 `wild-web/` 前缀；新增 `COPY wild-core/ /wild-core/`（在 `npm ci` 之前，复刻本地"wild-core 在父目录"布局）；`nginx.conf` → `wild-web/nginx.conf`。
3. `Jenkinsfile` 编译检查 stage：`-v "$REMOTE_RELEASE_DIR:/repo"` + `-w /repo/wild-web`（替代 `cd wild-web` + `-v $PWD:/app`）。
4. `Jenkinsfile` Docker 构建 stage：context `wild-web` → `.`。

**验证**：本地 `wild-web/node_modules/wild-core` 是 symlink → `../wild-core`（证明 file: 依赖靠父目录解析，Dockerfile 已复刻）；diff review 无笔误；docker 本机不可用未真跑 build。

**⚠️ 待办**：这批改动 + wild-core 迁移**须一起 commit** 才生效（`git archive HEAD` 只导出已提交内容；迁移不 commit 则 Jenkins 仍部署旧代码）。commit 后建议在远程跑一次 `REMOTE_VALIDATE_ENABLED=true` 的编译检查验证。
