# WildAgent RAG 文档模板

先从 `metadata-schema.md` 复制 frontmatter，再按文档类型选择模板。删除空章节，不为了统一外观保留无内容标题。

## WILD Schema / 蓝图规范

```md
# WILD `<type>` 规范

## `<type>` 定义与能力边界

## `<type>` 最小字段集合

## `<type>` 字段说明

## `<type>` 坐标与引用规则

## `<type>` 约束与校验

## `<type>` 最小有效 JSON

## `<type>` 常见错误

## `<type>` 与其他构件的关系
```

字段表、坐标规则、正确示例和错误示例回答不同问题；内容较长时使用独立真实标题，不放进同一个超长章节。

## 构件族

```md
# `<构件族>` 分类与组装规则

## `<构件族>` 定义

## `<构件族>` 当前引擎能力边界

## `<具体变体>`

<!-- rag-meta

-->

### `<具体变体>` 定义与适用场景

### `<具体变体>` 所需 WILD 构件

### `<具体变体>` 参数与空间约束

### `<具体变体>` 最小有效 JSON

### `<具体变体>` 常见错误
```

每个具体变体使用真实标题。多个变体不得依靠粗体编号区分。

## Pattern / 已确认案例

```md
# `<模式名称>`

## `<模式名称>` 用户目标

## `<模式名称>` 可复用决策

## `<模式名称>` 蓝图摘要

## `<模式名称>` 不应泛化的内容

## `<模式名称>` 已验证结果
```

Pattern 必须能够追踪到用户确认或已验证项目，不得把单次偶然参数包装成通用规则。

## JSON 示例

有效示例使用：

````md
### `<实体>` 最小有效 JSON

以下是 `geometry.elements` 片段，不是完整 `.wild` 文件。

```json
{
  "id": "example",
  "type": "supported_type"
}
```
````

错误示例放在单独标题和代码块中，并在代码块前明确说明错误原因。若需要展示非严格 JSON 的注释说明，代码语言使用 `text`，不得标成 `json`。
