# 来源保真与条件关系

先拆分声明，再决定是否进入生成上下文。按 identity、program_space、massing、structure、envelope、opening、circulation、auxiliary、assembly、repetition、material、parameter、unsupported、example 分类；没有的类别不补写。

## 处置记录

| disposition | 含义 |
|---|---|
| preserved | 有依据的事实保留 |
| normalized | 保留语义，按当前字段或条件关系重写 |
| routed | 原文或参考内容转到明确目标，说明是否参与生成 |
| downgraded | 保留目标语义，说明当前近似表达 |
| deferred_conflict | 证据不足或冲突，隔离且不生成 |
| rejected | 重复、无关或错误，记录原因 |

记录来源位置、原始声明、状态、理由、活动目标。全量迁移可保留逐节原文快照与哈希，同时明确活动文档保留了什么、哪些仅在档案中；不能把一份档案宣称成所有语义已进入 RAG。

## 必要性与自由度

“必须”用于 WILD 合法性或本次已选择系统的必需关系。“类型特征”是按请求保留的身份，不代表附属系统全部必选。“条件”写明触发需求。“可选”属于方案选择，不能改名为 required。

保留有来源的关键空间、系统角色、依附和重复关系；不要把详细建筑只压成百科名词。但不为每类建筑强制十栏、最小回退或完整 JSON，也不保留没有价值的百科篇幅来满足形式。

错误字段与建筑语义分别处理。没有 curtain_wall 类型不等于删掉幕墙需求，应映射到 wall+window 或显式骨架玻璃。对没有通用受支持映射的专业系统，说明限制，不编造字段。

## 参数

Schema 范围与引擎阈值保留源码依据；运行配置先查实际解析器。普通建筑尺寸、配色、柱数与开窗节奏只有在用户明确指定或任务有证据时才形成约束。不要把来源数字机械改成范围、比例或固定模数，也不要用“禁止照抄”让完整布局继续占据生成上下文。
