# 阶段十：Core 几何与门窗右键行为总结

## 阶段目标

补齐第二批组件真正需要的 Core 通用能力，并建立门窗行为层。交互约定按当前编辑器习惯固定为：左键选中高亮，右键开合门窗。

## Core 几何改动

- 墙上开口解析支持单段圆弧墙，统一采用沿墙弧长和世界高度定位。
- `profile_sweep` 增加路径点、截面点、有限数值和重复路径点校验，为檐口等沿路径截面提供稳定兜底。
- Blueprint 读取时增加显式 `1.0 → 1.1` 迁移器，并返回迁移报告，避免旧数据兼容逻辑继续散落。
- 保留 `opening` 作为墙体开口和填充面的 Core 类型；交互行为不写进 opening builder，而随门窗组件编译结果传递到 renderer。

当前边界：曲线开口只支持直线墙或单段圆弧墙；复杂屋面真实穿透、稳定布尔/CSG 和地形贴合没有伪装成已完成能力。

## 门窗行为系统

门和窗可选配置 `interaction`：

- `swing`：铰链侧、开合角度、初始状态。
- `slide`：滑动方向、距离、初始状态。

编译器把行为转换为带闭合位置、旋转轴或滑动向量的内部数据。renderer 只负责播放约 220ms 的缓动动画，不反向修改 Blueprint，也不把运行时动画状态混入静态几何编译。

## 鼠标职责

- 左键：继续执行 Raycaster 选择、组件来源映射和高亮，不触发开关。
- 右键：命中带 opening 行为的门扇或窗扇时阻止浏览器菜单并切换开合。
- 右键命中普通构件或空白处时不执行门窗行为。

属性面板提供交互启用、平开/推拉、铰链方向、角度/距离和初始状态编辑，并明确提示“左键选中，右键开合”。

## 验证结果

- 交互字段已通过 Schema、组件编译、Core MeshData 和 renderer 数据链路检查。
- Vue 类型检查与生产构建通过。
- 当前 Codex 会话没有可用的内置浏览器实例，因此未完成真实鼠标点击自动化；仍需开发者在页面上做一次左键/右键人工验收。

## 阶段结论

`opening` 的预留足以继续承担门窗开口几何，但开合动画属于独立行为层。这个分层避免了每增加一种开启方式就扩大 Core 几何分支，也不会和左键编辑交互冲突。

## 交互缺陷修复补充

- `pointerdown` / `pointerup` 选择链路现在只接受鼠标左键，右键不会改变构件选中或高亮状态。
- 可交互窗编译为固定窗扇与活动窗扇，开合时只移动铰链所在窗扇，另一半保持原位。
- 活动窗扇打开后，右键固定窗扇或窗框仍会通过组件来源映射找到活动窗扇，因此开启和关闭都只需一次右键。
- 开合动画每一帧都会主动标记按需渲染视口重绘，不再依赖相机控制事件偶然刷新；完整开合约 300ms，动画中途反向切换按剩余路程调整时长。
