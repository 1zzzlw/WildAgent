## 本次具体做了什么

1. 先保存编写计划，审计既有设计、作者脚本、流程、WILD与报告，重写主语言与创作方法。
2. 原样复制Core与必要前端依赖闭包，添加相对依赖运行包装；没有复制整个Agent/后端、node_modules、浏览器或密钥。
3. 编写26元素/6组件教学茶室和标准库展开脚本，将完整JSON同步进主语言。
4. 把核心资料、工具和教学例复制到项目外的系统临时目录，在那里安装随包Node依赖；随后使用该目录的Core和渲染模块编译、重建、真实WebGL出四视图。
5. 实际查看正面与透视图；其他出图和专项的边界见教学例README。执行静态工具的反例检查、包内链接和指纹核对，结果保存在对应JSON。
6. 在第二个新临时目录按lock执行npm ci，运行整个资料包自检与Core，重放教学WILD；命令全部返回0，逐字节一致。两份项目Schema当前指纹相同：`a445ebb4442a30ad574fba51696815dffe30fed15fa54a10cf93bef6322e567f`。

独立运行的“独立”指源码/脚本/示例的路径不依赖原项目；当时使用机器已有的Node、Python和Chromium，Python的jsonschema也来自已安装环境，并非在无任何软件的裸机离线安装。首次npm安装需要网络/缓存，浏览器本体不随包。

## 能力与验收层级

教学例在复制出去的资料包里完成Core和真渲染，不能据此声明十二例已全部在新包重新出图。十二例本次做来源/文件指纹/已有图输入绑定和静态检查，旧后端报告的误判仍原样保留。资料包没有执行新的外部模型生成或模型对照实验。

原项目后端全流水线与前端额外重建诊断不是同一套检查；包内两份原始Node脚本只执行其声明的Core/基础显示范围。L0/L1/L2/L4成功不自动代表完整后端关系检查或空间/审美成功。

案例中不同相机/太阳/天空/后期设置各有清单，不能把随包固定基线与图片复建参考方向混成相同条件。裁切、去顶、相机靠近和调曝光不能用于隐藏建筑缺陷。图像hash只是证明复制一致，不是审美评价。

## 如何重新核对资料包

在包根目录安装Python依赖后执行：

```powershell
python "工具/核对资料包.py" --report "验证结果/本机资料包自检.json"
```

该工具会核对主语言完整例子与独立WILD的语义一致性，解析JSON代码块，验证包内文件链接、源码/案例/记录hash、已有实图与输入绑定，并检查重复ID、缺宿主/材质、楼梯尺寸链、洞口越界、非法Schema/JSON、非有限数字的反例。它不调用新模型，不自动修文件，不重新渲染，也不能以这组有限反例推断所有几何检查完整。

资料包修改后应重新运行；源码快照或案例一旦改变，也必须更新并说明来源，不可沿用旧hash。需要真正验证新建筑，按工具README对新WILD另跑静态、Core、渲染和人工查看。
