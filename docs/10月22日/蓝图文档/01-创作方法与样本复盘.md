# 创作方法与十二例复盘

这里总结可以审查的设计依据、实际使用的资料和修订原因，不记录或还原模型的私有内部思维过程。来源是既有设计文件、作者源码、流程记录、正式 WILD 和真实渲染清单；不是根据最终图片倒编一条“一次生成成功”的过程。

## 1. 十二例到底包含什么

本日有11栋独立作品：01、02、04、05、06、07～12。03是前端与门窗优化，不是建筑。加上用户指定的质量参照“汀院别墅”，本包以12例审计。去顶、分层、木构等查看副本不重复计数。

正式文件的来源路径、字节数、元素/组件/材质数量和 SHA-256 见 [十二例来源索引](验证与来源/十二例来源索引.json)。数量用来核对文件身份，不用于评判精美程度。完整WILD与每例一张已有实图收在 [案例目录](案例/README.md)，可以单独打开；原工程的完整修订历史不在本包中重复复制。

## 3. 创作时实际考虑的方面

### 3.1 先解释“这栋建筑为什么这样组织”

别墅考虑公共/私密/服务空间，凉亭考虑柱网和开敞方向，办公楼考虑重复使用与交通核心，咖啡馆考虑点单/出品/座位，超市考虑货架通道和收银。先定使用顺序和相邻关系，立面与屋面才有依据。

对每个体量，明确它服务什么空间、与其他体量在哪里相接、是否跨层、屋顶是否可达。体量不是随意堆叠的盒子：低翼可以承托露台，凹口可以形成入口，退台必须带来真实室外空间，而非只是立面形状变化。

### 3.2 用一套设计事实派生全部坐标

完成面决定门底、家具底、踏步起终；板厚决定墙顶、孔边和净空；墙轴决定门窗沿墙距离；屋面方程决定瓦垄/檩条/天窗框。把这些共享值当事实，避免一处修3.7、另一处仍留3.5。

特别检查三维关系：看似连上的梯口是否全宽接板；回转平台是否能接门；窗洞是否被另一层饰面盖住；悬挑下面是否有真实支承；水池是否真的有深度；图书馆内庭是否被另一块楼板封住。

### 3.3 让风格落到比例和构造，而非标签

中式的院落与檐下层次、欧式的柱式与窗套、现代的深窗/框架/材料交接，各有不同的构造逻辑。一个`meta.style`或颜色并不能实现风格。关键节点先建成，再用可控的重复细部建立秩序。

同一风格允许多种空间策略。例如现代别墅可以向院子、景观、内街或高差展开；“现代”不强制两层L形、泳池和木格棚。特定历史作品的组合不能固化为所有新作品的配方。

### 3.4 在可见尺度上分配细节和资源

优先细化入口、近人尺度窗洞、檐口、露台边、主要室内家具和类型专属设施。细节有基底、主体、边框和收口，大小受主体约束。远处植物可以概括，不用上千叶片遮建筑；超市商品可以有分组变化，不需要逐个商品标签。

输出容量也是设计条件。纯聊天模型尽量选择能完整展开的规模；有脚本工具时可增加重复细节，但仍控制几何、渲染与检查成本。原语组合让形态开放，不能等同于无限复杂模型都能可靠生成。

### 3.5 依靠不同视图找不同错误

透视看整体、入口、主次与遮挡；正立面看节奏和招牌；侧面看进退与闭合；俯视看场地、屋面和轮廓；剖切看梯井、房间、家具和门。水需环境近景，真实光源需夜景，门窗动画需实际交互专项检查。某一张好看的图不覆盖其他层面。

## 5. 旧写法需要改进的部分

| 问题 | v3.0的改进 |
| --- | --- |
| 流程很长，纯文本AI容易被仓库命令淹没 | 主语言自足；工具安装与原项目集成移到包内说明 |
| 例子容易被当默认建筑 | 示例明确为语法教学；给出设计轴、相互联动与同类型对比任务 |
| 风格词和“精致”缺少可执行内容 | 由用途→空间/剖面→围护→构造节点→材质/光景逐层展开 |
| 实现边界隐藏在失败记录里 | 正文直接说明梁吸附、roof语义、sweep端盖、世界Y、灯body坐标等 |
| 字段正确但空间/画面错 | 加入完整交通链、遮挡、家具全脚、池体和侧墙检查 |
| 普通用户不知道给AI哪些文件 | README区分单文档、设计增强、带工具三种发送方法 |
| 把几何数量、静态通过或过程脚本当最终效果 | 分层报告，保留误判，明确真实图/人审和未覆盖范围 |

## 6. 仍然不能许诺什么

语言能减少字段错误、固定套路和遗漏，不能代替模型的空间推导与输出容量，也不能代替真实看图。当前资料包验证的是契约、工具与实例可运行；没有测量多个外部模型在全新会话中的一次生成成功率，没有证明任何模型都会达到本批精度。

下一次真正评估语言质量，应在相同模型/输出预算下比较旧文档和v3：各选住宅、公共建筑、商铺和木构任务，使用未在案例中出现的条件；比较硬条件满足、几何关系、类型特征、视觉层次和修订成本。同类差异化另测，不把换色当新方案，也不通过降低任务难度来宣布进步。
