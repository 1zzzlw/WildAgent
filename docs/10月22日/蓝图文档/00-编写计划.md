# 蓝图创作资料包编写计划

本计划先于正文编写。目标是把本批建筑中可以复用的设计方法、WILD 几何契约和验收方法整理成可交给其他 AI 的资料包，而不是把现有建筑脚本改名为通用生成器。所有新增产物限于本目录，保留原建筑、旧语言文档和应用代码。

## 1. 样本与来源审计

核对建筑文件、设计说明、作者脚本、修订记录和校验报告；区分创作资料、生成工具、验收工具和显示环境。目录编号不直接当作建筑数量；剖切副本不重复计数。输出样本清单和可核查的设计经验。

验收：每个样本都能定位到正式 WILD、设计/过程和已有渲染证据；不把离线校验写成视觉成功，不把手工作者脚本写成 Agent/RAG 生成。

## 2. 重新组织主语言

编写自足的 `WILD蓝图设计语言-v3.0.md`：任务解释、场地与标高、体量和交通、空间与立面、材质与细部、WILD 输出契约、灯/字/水、差异化设计、文本自检与实际验收。明确哪些是格式要求、哪些是设计建议、哪些是引擎边界。

验收：纯文本模型只收到主文档也能知道如何输出完整 WILD；不依赖固定建筑名称、构件配额或历史布局；包含一个完整而简短的有效示例。

## 3. 随包核心资料与工具

提供当前 Schema、必要类型/编译实现的只读快照、来源指纹及使用说明。必要时编写小型独立检查工具和结构化设计记录示例；以相对路径定位包内资源。项目完整后端和渲染器作为可选集成，不伪称已打包为独立引擎。

验收：随包工具可以在没有项目源码的另一个目录运行；依赖和能力边界明示；不复制密钥、运行数据库、依赖缓存或整套 Agent。

## 4. 创作方法与差异化任务

总结可公开审查的设计依据、约束计算和修订原因。给出不同类型的提示词及同类型不同方案的对照，规定固定需求、可变设计轴和变化理由；提供少量可复用构件例，而非默认套用十二栋成品。

验收：同类差异来自布局、剖面、交通、屋面或围护策略，不能仅换颜色/名称/随机种子；风格与功能保持一致。

## 5. 验证与交付

解析全部 JSON 示例，使用当前 Schema 检查随包 WILD；验证独立工具和错误样本，必要时用项目 Core 与真实渲染检查新示例。核对内部链接、源码快照指纹和示例同步关系。把未执行的视觉/运行验证单独列出。

验收：形成入口 README、主语言、设计方法、核心资料、提示词/示例和验证来源记录；写清各层验证证明什么。最终更新本计划的执行结果，不改写历史建筑的验收结论。

## 预定产物

- `README.md`：给不同 AI 的使用入口与资料选择。
- `WILD蓝图设计语言-v3.0.md`：可单独发送的主语言。
- `01-创作方法与样本复盘.md`：样本范围、设计依据、工作空间用法与修订经验。
- `02-提示词与差异化设计.md`：任务协议、同类异构设计与迭代方式。
- `核心资料/`：Schema、必要源码快照、能力边界与来源清单。
- `工具/`：包内独立检查工具及依赖说明。
- `示例/`：经校验的完整最小建筑和设计记录。
- `验证与来源/`：审计清单、指纹、执行结果及边界。

## 执行结果

已按计划完成：

1. 样本口径为11栋当日作品加汀院参照，共12例；正式WILD、已有实图、原始设计/流程/校验证据已建立索引与副本，不重复计剖切。
2. 重写自足v3.0主语言，另写创作复盘、工作空间使用表、提示词和同类差异化方法，旧语言与应用源码保持原样。
3. 提供79个原项目核心/必要渲染/设计参考文件的只读快照，新增Python检查器、有限反例核对工具、Node依赖包装和教学例展开脚本；不引入通用建筑生成器或新Agent。
4. 教学例已通过原始Schema、引用/尺寸检查、Core编译/重建；在项目外临时目录安装随包依赖并真实WebGL出四视图，76网格、错误0、材质缺失0，实际查看正面/透视。
5. 自检工具对12例与教学例做静态检查、核对来源指纹与已有实图输入绑定，检查8个有意错误反例；首次自检发现尚未创建的自检报告链接，保留原结果后复查。最终机器结果见验证目录，不将历史后端误判改写为全图通过。

未做多模型盲测、同预算旧版/v3对照、其他操作系统运行、教学例夜景/逐帧交互或施工相关验收。全部产物集中在本目录，资料包可整体带走。
