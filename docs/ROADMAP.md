# 优化路线

最后核对：2026-10-13。

本文只写**当前状态与后续优先级**。已完成的阶段性实施记录、Bug 复盘和方案原文不在本目录，见 [`docs/README.md`](README.md) 的分类规则与 `docs-dev/` 归档。代码位置见 [项目索引](项目索引.md)。

## 结论

项目的核心设计是合理的：参数化 Blueprint 把模型与几何隔离，设计文档（DesignDocument）把「设计」与「实现」分离，确定性编译器负责图纸到蓝图的映射，校验流水线负责拦截，ScenePatch 保留用户决策权，LangGraph 只负责节点编排。

当前架构的三条硬约束，任何改动都不能破坏：

1. **`app/agent/compiler/compile.py` 是纯函数** —— 无 IO、无 LLM、无全局状态，同输入逐字节相同输出；它**不产生设计**，图纸该改什么只以 `defects` 报出。
2. **能力缺失只标记，不阻断** —— 引擎做不到的构件转成 `unsupported` 条目进入交付清单，而不是让整轮生成失败（见 `app/agent/plan/capability.py`）。
3. **工具循环必须在条目内部** —— 提到图层会让 `recursion_limit` 失去意义（见 `app/agent/plan/tool_loop.py`）。

当前重心已从「多加校验」转为「**图纸驱动的确定性落地质量**」：设计质量由模型决定，落地质量由编译器和校验器决定，两者要分别度量。

## 当前链路

```text
classifier
  → architecture      产出 DesignDocument（完整图纸，含体积、立面、屋顶、材质意图）
  → material_plan     受控归一化的材质方案
  → design_review     ★ 唯一的人工暂停点：批准 / 要求修改
  → plan              建筑走图纸标记确定性展开（零模型调用）；物件走策略
  → execute ⇄ replanner   唯一循环；失败条目经有界 replan 收尾
  → compile           图纸驱动装配，把分片合并为蓝图
  → final_validate    完整校验流水线 + 交付门禁
  → callback          有界白名单修复（可选）
```

节点与路由的完整对照见 [项目索引 · 当前生成主链](项目索引.md#3-当前生成主链)。

## 已闭环的底线

1. **协议可判定**：每个 WebSocket 消息都可按 `protocol_version` 与结构化字段解析，不依赖展示文案。
2. **产物可阻断**：最终校验未通过时，保存函数不执行；前端不会把有错误的蓝图当作成功加载。
3. **状态有归属**：消息、步骤、思考、诊断、产物都绑定 `request_id + session_id`；迟到的迟到结果不覆盖已切换的画布。
4. **刷新可解释**：历史 Turn 可恢复；无法继续的运行态明确显示为中断。
5. **修改需确认**：Agent 提议的 ScenePatch 一律经用户确认才应用；应用失败回滚 Blueprint 并恢复上一版网格。
6. **失败可定位**：校验错误结构化为逐实体 `ValidationIssue`，RAGTrace 落盘，LangSmith 可观测节点状态。

## P1：落地质量与可观测性

当前最高优先级。图纸驱动链路的每个环节都可能静默丢失信息。

1. **编译缺陷闭环**：把 `CompileDefect` 按四类输出分别建立统计，量化「图纸写了但编译不出来」的比例。这是图纸质量最直接的度量。
2. **设计履约量化**：`app/design/fulfillment.py` 已产出履约报告但**不参与保存门禁**。先长期观测它与最终渲染质量的相关系数，再决定是否升为门禁。
3. **固定评测集扩容**：把不同建筑类型（别墅、公共建筑、塔类、传统形制）的合格蓝图纳入回归样本，统计结构成功率、最终校验通过率、平均重试次数与 token 成本。
4. **检索质量闭环**：`RAG__RETRIEVAL_GATE__*` 目前默认 `observe` 只记结论。用正负样本校准 `max_distance` 后再评估是否切 `enforce`，避免误拦。
5. **节点耗时归因**：`tests/misc/` 已有诊断 Schema 基础，补齐每节点开始/结束时间与错误码聚合。

## P2：交互与容错

1. **单组件人工重试**：在自动定向修复之外，允许用户对单个失败构件发起重试，而不是重跑整份计划。
2. **真正的请求取消**：前端已有停止按钮，需要后端真正取消 LangGraph/LLM 任务而非仅丢弃结果。
3. **审核意见的再利用**：`design_review` 的 `design_feedback` 目前只回到图纸修订，可评估是否也影响材质方案，避免图纸改了材质没跟上。
4. **诊断可复制**：为运行步骤增加「复制本轮诊断」，便于用户反馈与问题复现。
5. **前端大包拆分**：Three.js、Element Plus 与编辑器重模块按路由或功能动态加载。

## P3：能力扩展

按「先用现有构件组合，确实需要新的成形方式再补规范、构建器和校验」的顺序推进。

1. **室内与家具**：当前有提示词闸门与最小区件要求，但完整室内布局能力缺失。缺口应先表达为 `unsupported` 条目，而不是让模型自由发挥。
2. **对象存储/CDN 迁移**：把 `ASSETS__PUBLIC_BASE_URL` 切到公开 HTTPS 前缀，WILD 协议无需变更。资产仓库当前 20MB/文件、80MB/总量上限，迁移前需重估。
3. **材质世界化**：`materials/GLOBAL_MATERIAL_WORLD_ARCHITECTURE.md` 提出的长期架构尚未落地，程序化材质仍以 `renderer_only` 方式扩展。
4. **照片级渲染**：路线见 [渲染引擎现状评估与照片级路线](渲染引擎优化/渲染引擎现状评估与照片级路线.md)。注意字段数量不是精细度的瓶颈（实测 169 份蓝图），瓶颈在几何构建器与材质资源。

## 明确不做的事

避免把以下内容当作本阶段目标：

- 为每个审美问题新增一个 LLM 节点。审美判断属于设计文档与模型职责，不属于编排层。
- 让外部适配器（Blender 烘焙、AI 贴图生成、对象存储 SDK）进入渲染器运行时。
- 在同步阻塞问题未定位前，用 `--allow-blocking` 长期掩盖。
- 用跳过测试来让流水线变绿。发布门禁应保持确定性检查，移除的只能是依赖外部额度的真实模型调用。
