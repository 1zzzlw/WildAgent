# 优化路线

最后核对：2026-08-10。

## 结论

项目的核心 Agent 设计是合理的：参数化 Blueprint 把模型与几何隔离，RAG 提供领域知识，确定性工具负责校验和修正，ScenePatch 保留用户决策权，LangGraph 适合拆解复杂生成任务。可靠性底线已基本补齐，当前重心从“多加校验”转为“建筑方案先行、程序计算易错坐标、用固定样本量化质量”。

## 本轮已完成

- 精密模式补齐 `GENERATE / EDIT / CHAT` 三意图路由，新增真实 Patch 节点。
- 组件建议统一过滤未知类型、否定需求和阳台栏杆重复生成。
- 修复骨架节点 JSON 序列化变量错误。
- 问答正式回复与 thinking 流分离，避免重复显示。
- 精密模式最终校验未通过时阻止保存和自动加载。
- 快速模式保存失败不再发送无效蓝图事件。
- 前端引入 request/session 级 `AgentTurn`，修复全局过程状态串会话。
- 对话改为单一时间线和内联折叠执行过程，保留自然阅读顺序。
- 迟到产物不会覆盖当前画布；蓝图加载完成后才同步正式回复。
- 会话切换恢复服务端消息；用户上滚后不再被强制拉回底部。
- 增加 Agent 路由回归测试，并通过相关 WebSocket/思考流测试与前端生产构建。
- WebSocket envelope 升级到 `protocol_version=1.0`；步骤事件改为结构化字段，前端不再解析展示字符串。
- 新增统一生成出口，快速/精密模式共享最终复检摘要、错误门禁、文件命名、保存和成功回复。
- Agent Turn 写入服务端会话文件；支持按 `request_id` 合并、串行同步以及页面刷新/服务重启后的中断恢复。
- 增加真实编译图三分支测试、统一生成出口测试、协议版本测试和 Turn 持久化测试。
- 修正门窗局部坐标提示词与 Core 契约冲突；门窗组合构件不再被 opening 空列表提前跳过。
- 合并阶段新增设计数量、立面最大开口数、同墙门窗重叠与材质引用硬门禁；移除会静默改动整面立面位置的门窗均匀重排，无有效修复时停止无意义循环。
- 用现代别墅问题蓝图建立回归：背墙后门从 6 米法向漂移投影回父墙中心面。
- 修复零高度骨架墙导致门窗回调无解的问题：组件派发前按楼板标高补墙高，并取消引用/几何校验的重复报错。
- AI 时间线改为单一滚动面；流式内容按渲染帧贴底，用户上滚暂停，移除执行步骤内部嵌套滚动和生产控制台刷屏。
- 兼容模型把最终 Blueprint 放入 reasoning 且不加 JSON 代码围栏的响应；草稿会话不再请求猜测场景路径制造 404，并增加唯一材质别名修复。
- 建立分级定向修复闭环：校验文本结构化为逐实体 `ValidationIssue`；模型只选择白名单修复工具，程序在副本执行；错误没有严格减少或出现新错误时自动回滚，不再让模型重新生成完整组件。设计配额缺失通过受限 `add_entity` 补齐，因此“门/窗根本没有生成”也能进入定向修复，而不是直接终止。
- 修复动作协议保持模型供应商无关：普通 `content` 与 `reasoning_content` 均可提取，规划过程中的其他数组不会被误当成动作；以后可把不同角色映射到不同模型，目前也能全部复用同一模型。
- 修复知识库问答的 OpenAI SDK 版本兼容：非流式 `ChatCompletion` Pydantic 对象不再被当成字典调用 `.get()`；字典/Pydantic 响应和 reasoning 字段均由模型适配层统一处理。
- Phase 3A 空间约束闭环：骨架节点把结构墙包围盒、墙体局部方向/法向和楼层标高写入 LangGraph 状态，各组件 Prompt 直接消费这些确定性不变量，不再要求模型从长文本中重复猜坐标系。
- 组件工具修复后强制调用同一校验器复检；只有复检通过才显示“已修复并通过复检”，仍有错误时节点明确标红并交给全局定向修复。
- RAG 节点诊断增加命中文档来源与标题，执行面板可以展开查看本轮究竟使用了哪些知识片段。
- wild-core 适配层增加结构化重建报告，把源构件、展开后的元素 ID、网格数量、宿主关系、预期/实际包围盒和空间间距关联起来；缺失网格、脱离宿主和屋顶覆盖不足会进入校验面板。
- `sceneStore` 不再把“返回了重建实体”等同于成功：存在重建级错误时加载返回失败；ScenePatch 会回滚 Blueprint 并恢复上一版网格，不会提交错误构件。
- 固定评测入口增加 `npm run eval:phase3a`，覆盖门窗宿主映射、实际网格包围盒及缺失网格识别。
- Phase 3B PBR 最短闭环完成：新增独立资产 LangGraph，按“意图提取 → 文件校验 → 内容寻址入库 → 资产/材质 ScenePatch”运行，不让主建筑生成图直接处理二进制图片。
- PBR 图片本体写入 `storage/assets/{assetId}`，`.wild` 只保存不可变 `assetId`、SHA-256、来源、授权和 URL；不再把新图片编码为 Base64。`ASSETS__PUBLIC_BASE_URL` 可从当前站内路径切换到对象存储/CDN，而不改变 WILD 协议。
- WILD 增加可选顶层 `assets` 与 `materials.*.textureSet`；前后端结构校验、ScenePatch 预检和 Core 重建均会阻止悬空资产引用，`upsert_asset` 必须先于引用它的 `upsert_material`。
- 前端右侧增加“素材”面板，可上传 Base Color/Normal/Roughness/Metalness/AO、记录授权并绑定当前选中构件；Three.js 异步加载 URL 纹理，失败会进入“校验”面板而不是静默丢失。
- Jenkins 增加生产 `storage/assets` 持久化目录和容器挂载；重启、重新部署或镜像回滚不会删除已入库纹理。
- 当前文本模型已接入“现有材质质感优化”，但不修改图片：检测到纹理/材质优化请求时必须有选中构件，并且只能输出 `tune_material`。程序克隆原材质后仅覆盖白名单 PBR 数值，自动保留 URL、Base64 兼容字段、纹理通道和 `textureSet`，因此共享旧材质的其他构件不受影响。
- 材质提案会稳定显示材质名和参数前值→后值；粗糙度/金属度等限制为 0–1，法线强度限制为 0–4 且必须真实存在 normal 通道，纹理比例限制为两个 0–64 正数。无变化参数、图片/资产修改、未选中目标和几何操作都会被服务端拒绝。
- 精密生成新增 `architecture` 方案节点：同一模型一次输出两个紧凑候选，程序按明确层数、风格、入口与完整度评分选择；调用或解析失败时使用确定性回退方案，不阻断后续生成。
- 骨架节点不再同时承担立面坐标设计。程序根据真实墙体解析 `front/back/left/right` 和门窗 `opening_slots`；组件 Prompt 使用精确槽位，合并阶段二次吸附、补齐最低配额并剔除无槽位开口，直接降低漏门窗、世界/局部坐标混用和重叠概率。
- wild-core 为直墙各表面和门窗洞口侧壁生成硬边法线与按米展开 UV，曲墙补齐沿弧长 UV；Three.js 同时提供 AO 的 `uv1/uv2`、按 GPU 能力设置纹理各向异性，并优化包围盒取景、动态阴影覆盖范围和地面接触阴影标高。
- 直角墙角增加非破坏式渲染闭合：只处理竖向范围重叠、端点相接的近 90° 直线墙，按相邻墙半厚延伸端部并补偿洞口切口，不修改 `.wild` 墙体中心线；相邻楼层、斜墙和曲墙保持原语义。
- 门窗深度统一：框深默认继承父墙厚度，门扇与玻璃生成真实封闭厚度并校验父墙交叠；Schema、后端白名单、属性面板、Agent 组件规则和 RAG 规范已同步。
- 修复阳台内翻与重复造型：组件编译器按宿主墙相对建筑中心的位置确定室外方向；合并阶段把 `balcony` 作为悬挑板和 U 形栏杆的唯一表达，自动删除重合楼板、附属重复栏杆和首层入口栏杆。实际问题蓝图已验证会删除 `floor_balcony`、三段阳台重复栏杆和三段门廊地面栏杆，同时保留楼梯栏杆与门廊楼板。
- 使用真实 RAG 分块契约整合《建筑类型分类体系_1.1_居住建筑_蓝图整合版》：旧版 `wal/elements` 蓝图和不受支持字段未直接入库；20 个扩展住宅类型拆为独立、自包含的 assembly 实体，块内同时保留类型定义、当前组合和能力边界，6 个已有成熟知识的类型只保留路由。住宅文档实际预览 23 个 chunks、0 个分片问题，并完成山地旅居、老年公寓和阳台唯一表达的定向召回验证。
- 修复 Jenkins 生产模型预检对推理模型的误判：移除仅检查字符串 `response.content` 的 16-token 内联命令，改为镜像内可测试脚本；输出预算提高到 128，并复用 `content/reasoning_content` 及多内容块兼容提取。真正双通道空响应仍阻断部署，日志会给出文本来源和 `finish_reason`。

## P0：已闭环的底线

1. 协议可判定：每个新消息都可按版本和结构化字段解析，不依赖 UI 文案。
2. 产物可阻断：最终状态不完整或仍有错误时，保存函数不会执行。
3. 状态有归属：消息、步骤、思考、诊断和产物都绑定 `request_id + session_id`。
4. 刷新可解释：历史 Turn 可以恢复，无法继续的运行态明确显示为中断。

## Phase 3B PBR 人工验收门禁（当前停点）

当前只完成“单材质、本地上传、站内 URL、WILD 绑定、Three.js 展示”的最短生产闭环。请先完成下面的人工视觉验收，再扩展 Poly Haven 搜索、AI 贴图生成、自动通道处理、对象存储上传或 Blender 烘焙；这些外部适配器不应进入渲染器运行时。

1. 打开已有建筑，选中一面墙，在“素材”面板上传一张 PNG/JPEG/WebP Base Color，填写素材名称、材质 ID 和授权，点击“入库并写入场景”。
2. 确认选中墙面出现贴图；保存并重新加载 `.wild` 后贴图仍存在，文件内应包含 `assets`、`textureSet` 和 URL，但不包含新上传图片的 Base64 数据。
3. 同一组纹理重复上传应返回同一 `assetId`；服务器 `storage/assets/{assetId}` 中只保留一份不可变文件和 `manifest.json`。
4. 暂时把纹理 URL 改成不存在的地址，校验面板必须显示 `PBR 纹理加载失败` 及具体 URL；恢复后不应留下 Blueprint 结构错误。
5. Jenkins 部署后进入容器执行 `ls /app/storage/assets`，应看到宿主机持久化目录中的已有资产；重建容器后资产仍可通过 `/api/assets/{assetId}/files/{filename}` 访问。
6. 选中一面已绑定纹理的墙，在 AI 对话输入“提升这面墙的纹理质感，让石材更真实”。提案必须只包含材质参数前后差异；应用后选中墙使用新材质，其他仍共享旧材质的墙不应变化，`.wild` 中原 `textureSet` 必须保持不变。

自动化复查命令：

```bash
cd wild-server
python -m pytest -q tests

cd ../wild-web
npm run eval:pbr
npm run build
```

进入 PBR 外部生产扩展的条件：上述 6 项通过；至少保存 3 份带 PBR 的 `.wild`；重新加载后纹理无丢失；固定评测集没有新增失败。

## P1：质量与可观测性

1. 统一意图分类器，避免快速模式和精密模式在同一句输入上分流不一致。
2. 继续收口两种模式的事件适配和指标汇总；统一出口已覆盖保存安全，但过程事件仍有两套翻译代码。
3. 在现有 Phase 3A 固定评测入口上继续加入真实 `.wild` 样本，统计结构成功率、最终校验通过率、重试次数和 token 成本。
4. 诊断数据改为稳定 Schema，并增加每节点开始/结束时间、错误码和产物摘要。
5. 将生产展示从依赖原始 `reasoning_content` 调整为可控的过程摘要，确保不同模型能力下降级一致。
6. 会话、消息、Turn 与场景文件建立明确事务关系，避免部分成功。

## P2：体验与性能

1. 允许用户取消请求，并让后端真正取消 LangGraph/LLM 任务。
2. 在已完成自动定向修复的基础上，支持用户对单个失败组件发起人工重试，而不是重新生成整栋建筑。
3. 为运行步骤增加搜索、复制诊断和开发模式开关，默认界面保持简洁。
4. 前端大包拆分：Three.js、Element Plus 与编辑器重模块按路由或功能动态加载。
5. 方案节点之后优先扩展确定性方案编译和质量评分，不再为每个审美问题新增一个 LLM 节点。
