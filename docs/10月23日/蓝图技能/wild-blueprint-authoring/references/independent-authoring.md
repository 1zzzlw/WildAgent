# 独立创作后得到的验证经验

## 来源与使用边界

2026-10-23「棕影水院」由主代理在未读取/使用创建蓝图skill的阶段完成；依据项目当前源码与公开文档设计，正式WILD经Schema、Core和Chromium验证后才更新本技能。完整来源位于原项目`docs/10月23日/17-独立创作-现代热带别墅`。本页自足保留可复用结论，使用技能不必取得该项目目录。

该例随机选中现代热带风格，自主设计单层U形住宅。它证明本次输入在当前引擎中的可运行性，不证明加载技能能改善其他Agent的设计，也不是用户认可的审美标杆。不得把U形、单层、两卧、泳池或本例尺寸变成默认需求。

## 观察到的问题与有效修订

| 观察 | 可复用做法 | 边界 |
| --- | --- | --- |
| 圆柱同时写radius与上下半径，原始Schema拒绝 | 检查原始oneOf，选一组半径；不以类型声明中各字段可选推断它们可同时出现 | 依据当前schema的primitive定义；引擎版本变化时重查 |
| label猜写fontSize | 只写当前支持的text/color/fontFamily；文字占面由实际显示规则决定 | 不用修改Schema让错误参数通过 |
| 树干位于地块内，叶冠仍使X范围超界 | 对最终展开/重建后的世界包络检查完整场地外缘；修改共享摆位后重建 | 整体包络能查越界，不能证明实体无碰撞 |
| 卫浴门洞合法，但紧邻淋浴玻璃阻碍转入 | 从入口检查到房间的通路，将固定玻璃和家具计入；移动门后重新检查 | 门洞合法只是必要条件；二维采样不能代替开门扫掠或完整人体模拟 |
| Node在进入建筑逻辑前报CSPRNG初始化断言 | 检查本进程Windows目录环境；本例补全SystemRoot/WINDIR即可恢复 | 只适用于确认的环境缺失，不据此重写建筑或永久修改系统设置 |

## 本例确认有效的构造关系

- 泳池孔贯穿场地板和露台板，水面下有真实池底与池壁。凡是穿过池体的覆盖层都要纳入检查，透明水面不能隐藏实体地板。
- 深檐按实际上下皮衔接：墙顶等于檐底板底，檐底板顶接坡顶最低处；柱顶抵达承托面。本例的具体标高仅为设计值，不是通用参数。
- 多体量共享通路界面不重复建墙。独立房间通过真实门连接；家具和洁具不能侵占必要转入空间。
- 剖切从最终WILD只删遮挡物，记录源hash/删除ID，逐对象验证保留部分不变。正式日夜图与剖切图各绑定自己的输入hash。
