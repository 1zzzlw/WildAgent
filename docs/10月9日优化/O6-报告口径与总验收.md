# O6：报告口径与总验收

状态：实现完成待验收。实现、能力边界及用户运行清单见 [执行记录](执行记录.md)。前置：O1—O5。以下整份内容可作为执行提示词。

## 目标

将代码改动整合为可交付的一次修复，报告准确，留给用户的验证步骤可执行。不要把“新增字段和模块”当成最终效果。

## 报告修正

1. 核对 `app/design/fulfillment.py::fulfillment_summary / fulfillment_line` 和所有前端、最终消息、报告消费者。15项中3满足必须显示3/15；可判定满足率3/5单独命名，另列可判定覆盖率5/15。当前代码可能已部分支持，禁止重复加同义字段。
2. unsupported表示验收器/表达能力不支持，不等于建筑确定错误；needs_review不等于成功；几何通过与设计兑现分开展示。无分母时显示无可判定项，不能默认100%。
3. 核对 `app/agent/vision/evaluation.py`、validation里的visual_review和离线workflow：proxy只表示测量值，不能根据材质数量、开口等距推断审美“合理”。如保留ok，必须明确是该几何规则通过，不是视觉通过。没有截图评价时complete=false。
4. 检查计划任务done、整体status、最终消息、保存/加载门禁是否一致。单个validate任务执行结束不等于全项目通过；已知阻断不得发成功交付消息。
5. 审核SVG展示O1统一产物的投影，不掩盖未解决问题，不要求本路线额外实现照片级效果或全自动视觉Agent。

## 用户验收矩阵

执行Agent编写必要的参数化测试和最小fixture，但不要运行。不要把12MB trace直接复制到测试目录；抽取脱敏且足以复现的设计/蓝图片段，并记录来源与预期。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A1 | 本次体量坐标冲突 | 明确拒绝/修订，无静默截半 |
| A2 | 原点和平移后的等价建筑 | 尺寸和关系一致，无意外裁剪 |
| A3 | 单体量屋顶、不同宽深/脊轴/出檐 | 屋顶与真实承托对齐 |
| B1 | 原始坏屋顶可被自动修好 | 原始编译诊断仍报告原错误，原输入不变 |
| B2 | 几何通过但批准实体变更 | callback和final均识别同一阻断 |
| B3 | 蓝图或设计版本变化 | 校验缓存失效，报告指纹对应当前产物 |
| C1 | 雨棚与真实入口门 | 修复上下文包含真实关系，不制造假缺门 |
| C2 | 恢复批准值会破坏几何 | 停止局部往返，进入设计修订边界 |
| C3 | 无变化/重复候选/模型故障 | 无假成功、无无限调用、状态可解释 |
| D1 | 四根柱位置错误 | 数量可满足但关系任务不得done |
| D2 | 支撑目标/位置/柱顶正确 | 关系通过，证据对应最终实体 |
| D3 | 正确产物后再挪柱或删目标 | 原履约失效，旧证据不能继续使用 |
| E1 | 设计完善仅改文案/重排 | 不当作有效闭合 |
| E2 | 局部缺口与真实依赖变化 | 最小完整任务组，预算和停止原因准确 |
| F1 | 3满足、2未满足、1待核对、9不支持 | 显示3/15；3/5和5/15分别命名 |
| F2 | 无截图但proxy有数据 | 不声称完成视觉验收 |
| G1 | 一次合法完整生成 | 正常审核、执行、保存，无新增阻断 |
| G2 | 一次需设计修订的生成 | 明确停在审核/修订边界，不成功交付坏产物 |

## 提供给用户的运行方式

根据实际新增测试文件写出精确命令和预期，不给虚构路径。目录层面的初始范围是wild-server/tests/design、compiler、repair、plan、validators，优先列本任务涉及的具体文件。真实生成至少包含简单单体、平移/侧入口、多体量三类；复杂屋面超出当前能力的预期应是明确缺口，而非假成功。

用户运行后比较：完整阻断数、重复修复次数、设计要求兑现/覆盖率、实际LLM调用数、总耗时、最终产物与审核版本一致性。调用次数要扣除/单列不同任务与重试，不把本次32次当通用阈值或保证。
