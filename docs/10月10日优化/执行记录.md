## 1. 当前建筑链

```text
classifier → architecture → material_plan → design_review
                                            ├─ revise → architecture
                                            └─ confirm → plan → execute ↔ replanner
                                                                    ↓
                                                                 compile
                                                                    ↓
                                                             final_validate
                                                                    ↓
                                                            保存并交付 .wild
```

`architecture` 正常情况下请求模型一次，交付完整设计。字段、尺寸、宿主或编译表达检查失败时，带具体证据有界重试，最多三次；失败明确返回原因，不再丢掉失败字段组后用默认建筑替代。模型服务异常立即终止，区别于设计格式错误。

`material_plan` 保留现有材质角色和可信资产解析职责。`design_review` 展示并审核同一 `DesignDocument`；没有另建一个重复设计的 `design` 节点。

建筑 `plan` 从 `resolved_design.component_markers` 确定性展开，不再请求模型重复决定构件种类。按类型分批，任务绑定标记 ID、图纸哈希与宿主依赖。几何投影只供审核与定位，不代表标记已经落实。

`execute` 每批共享一次对应类型的知识检索。已设计的 ID、类型、宿主、位置、尺寸和材料保持只读；只有注册表中尚未声明的可选细节字段可由模型补充。无需生成细节时直接参数化落实；需要时按类型整批请求一次，失败沿现有有界执行状态机处理。

`compile` 在执行结束后装配实际结果。缺失或改变确认字段的标记被列入 `missing_markers`，不会补造实体冒充完成。最终候选门禁重新逐个核对标记与批准实体，失败阻止 `.wild` 保存和加载。

## 3. 接口与几何一致性

门窗显式标记可以写：

```json
{
  "id": "window_second_floor",
  "type": "window",
  "host": "main_L2_front",
  "placement": {"offset": 2.0, "sill_height": 0.85},
  "size": {"width": 1.4, "height": 1.6},
  "form": {}
}
```

`offset` 是沿宿主墙的距离；`sill_height` 相对该墙底部。编译为 WILD 的 `[沿墙距离, 底部世界Y, 局部法向偏移]`，并同步对应设计槽位。没有 `placement` 的历史实例继续使用已有槽位语义。

屋顶显式实例按宿主匹配对应屋面；不再固定取第一块。显式构件改用稳定 ID 后，同场景的宿主引用随之更新。多个显式标记争用同一位置会明确报错。墙宿主采用编译器实际支持的 `<volume_id>_L<楼层>_<方位>`；显式追加门窗和阳台的世界标高由真实宿主墙底确定，移除固定 3.2 米假设。

结果必须只包含图纸字段和允许生成的细节字段。重复 ID、未设计结果、依赖环、图纸哈希或投影版本失效均有明确拒绝路径。审核新版图纸时清空旧版结果，避免几何相似就复用旧细节。

现有协议、材质资源、完整几何校验、批准实体保护和产物指纹证据继续使用。本轮没有重建 Chroma 索引，没有改变环境配置。

## 7. 灯具重复与附属实例编译修复

## 10. 屋顶分体量格式、总体尺寸语义与本地模型日志
