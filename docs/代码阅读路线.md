# 代码阅读路线

按一次请求的执行顺序阅读，每次只追踪一个节点及其字段。历史 trace 中出现的旧字段和旧节点，以当前源码为准。

## 00：先认清三个包

| 包 | 负责什么 | 入口 |
|---|---|---|
| `wild-web` | 发起请求、显示过程、编辑和展示场景 | [main.ts](../wild-web/src/main.ts)、[agentBridge.ts](../wild-web/src/agent/agentBridge.ts) |
| `wild-server` | 理解需求、生成设计、组织任务、检索、校验和保存 | [main.py](../wild-server/main.py) |
| `wild-core` | 从 WILD 数据编译组合构件、重建几何 | [index.ts](../wild-core/src/index.ts) |

后端交付 Blueprint 或 ScenePatch，前端将其交给几何引擎，再用 Three.js 展示。模型不直接生成网格。

## 01：请求怎样到达图

```text
前端 agentBridge.sendUserMessage
  → WebSocket /ws/agent
  → api/ws_agent.py：接收请求和组织事件
  → services/generation_job_service.py：保存任务，处理暂停与恢复
  → agent/graph.py：执行节点与条件路由
```

先读 [graph.py](../wild-server/app/agent/graph.py) 的 `build_generation_graph()`，只看节点名称和边。`nodes/` 是薄入口，逻辑在它导入的业务模块中。

随后读 [state.py](../wild-server/app/agent/state.py)，分清三种数据：

- `GenerationInput`：本轮公开输入。
- `GenerationState`：工作流保存的完整状态；节点通常只返回本次更新的字段。
- WebSocket / `astream_events` 事件：用于观察过程，不等于完整 State。

## 02：classifier，从这里开始追字段

入口：[intent/workflow.py](../wild-server/app/agent/intent/workflow.py) 的 `classifier_node()`。

```text
workflow.py：读取输入 → 调用分类 → 写入 intent_* 字段
  → classify.py：整理近期对话 → 拼接输入 → 调用模型
    → prompt.py：模型的分类要求
    → decision.py：提取 JSON → 校验意图 → 整理分类结果
      → rules.py：识别解释类问题
      → target_kind.py：目标类型缺失或非法时，判断建筑或物件
```

粒度默认值由 [contracts/generation_options.py](../wild-server/app/contracts/generation_options.py) 统一处理，不属于建筑设计算法。

分类后追踪 `intent`、`intent_target_kind`、`intent_profile`，再回到 `graph.py` 的 `_classifier_dispatch()` 看下一站。分类失败会写入终止信息，旧单标签和关键词分类不再接管请求。

## 03：看完 classifier，接着看 architecture

入口：[generation/architecture/workflow.py](../wild-server/app/agent/generation/architecture/workflow.py) 的 `architecture_planner()`。

这一步先回答四个问题：

1. 从 State 读取哪些需求、粒度、形制与修订信息？
2. 检索到的知识怎样进入 Prompt？
3. 模型结果怎样成为 `DesignDocument`？
4. 返回了哪些字段，下一节点读取哪些字段？

只在遇到具体调用时进入 `design_workflow.py`、`planning.py`、`profile.py` 和 `app/design/`。其中 `profile.py` 负责设计参数与物理边界，不再负责入口的目标类型分类。

两个 trace 可以按下面的阶段对照：

| 记录 | 主要阶段 | 下一步关注 |
|---|---|---|
| `trace-01a13e41-7afa-7d90-a9d1-3c2a9882eec5` | 分类、建筑设计、材质、等待审核 | 设计字段的来源与审核内容 |
| `trace-01a13e42-ec81-7e21-a30f-d849a78b5993` | 审核恢复、计划、执行、装配、最终校验 | 批准设计怎样变成最终 Blueprint |

## 04：后面的节点按需阅读

| 节点 | 实现入口 | 先观察什么 |
|---|---|---|
| `material_plan` | [generation/material/workflow.py](../wild-server/app/agent/generation/material/workflow.py) | 材质意图怎样解析并写回设计 |
| `design_review` | [design_flow/review.py](../wild-server/app/agent/design_flow/review.py) | 暂停数据、批准、修订和恢复 |
| `plan` | [plan/workflow.py](../wild-server/app/agent/plan/workflow.py) | 建筑构件标记怎样展开为任务 |
| `execute` | 同上，再按条目进入 `handlers.py` | 当前条目、检索、模型输出与实现结果 |
| `replanner` | 同上，再进入 `replan.py` | 哪些结果被采用，是否继续或结束 |
| `compile` | [design_flow/compile.py](../wild-server/app/agent/design_flow/compile.py) | 已采用片段怎样装配为 Blueprint |
| `final_validate` | [validation/workflow.py](../wild-server/app/agent/validation/workflow.py) | 校验问题、失败目标与最终状态 |

物件请求先进入 `generation/objects/workflow.py`，审核后经过 `generation/skeleton/workflow.py`。它与建筑共享部分执行工具，但不应把物件分支的骨架步骤套进建筑主线。

## 05：共享模块怎样找

| 遇到的问题 | 去哪里读 |
|---|---|
| 公共输入选项、事件协议 | `app/contracts/` |
| 设计文档、图纸投影、宿主和构件关系 | `app/design/` |
| 模型创建、调用、流式响应、服务错误 | `app/llm/` |
| 知识文档加载、索引和检索 | `app/spec/`，以及 `app/rag/` 的检索、门控和引用 |
| 任务、会话、事件保存、最终交付 | `app/services/` |
| 工具和基础 Blueprint 操作 | `app/tools/`、`app/utils/` |

几个名字相近的编译入口承担不同阶段：

- `app/design/compilation.py`：设计投影与通用设计编译入口。
- `app/agent/compiler/`：上述通用设计编译的底层实现。
- `app/agent/design_flow/compile.py`：当前建筑主图中，装配已经实现的构件片段。
- `wild-core/src/compiler/`：前端重建前，将 WILD 组合构件展开为基础元素。

`agent/assets/` 是独立资产流程，`agent/vision/` 是单独调用的视觉评价与修订流程。它们不在当前建筑主图中，不必为了读完一个节点而提前读完这些包。

## 06：结果怎样回到画布

```text
最终 State
  → services/agent_delivery.py：校验交付信息并保存
  → WebSocket 事件
  → agentBridge / agentStore：匹配会话与请求
  → sceneStore：加载 Blueprint 或确认 ScenePatch
  → reconstruction.worker.ts / wildCoreAdapter.ts
  → wild-core 编译与几何重建
  → renderer / Three.js
```

入口：[agent_delivery.py](../wild-server/app/services/agent_delivery.py)、[sceneStore.ts](../wild-web/src/stores/sceneStore.ts)、[reconstruction.worker.ts](../wild-web/src/workers/reconstruction.worker.ts)、[wildCoreAdapter.ts](../wild-web/src/renderer/wildCoreAdapter.ts)。

流程结束、校验通过、保存成功、真实渲染和人工确认是不同的观察结果，需要分别核对。

## 每读一小段，记录四件事

1. 本次真实输入是什么。
2. 哪段代码读取、转换了它。
3. 本节点返回了什么更新。
4. 谁接着读取这个更新。

没有在某次 trace 中执行，不代表方法无用；只被导出或注释提及，也不能证明它正在被调用。用符号搜索定位实际调用，再决定是否继续追踪。
