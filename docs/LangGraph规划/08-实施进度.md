## 三、两种模式对比

| | LangChain（快速模式） | LangGraph（精密模式） |
|---|---|---|
| **触发** | `precision_mode: false`（默认） | `precision_mode: true` |
| **架构** | 单体 Agent 一次生成 | 骨架→10组件并行→合并→校验 |
| **生成质量** | 组件知识可能被挤出上下文 | 每个组件独立 RAG，不竞争 top_k |
| **修复能力** | 整体重来 | 只重试失败组件（最多 3 次） |
| **跳过不必要组件** | 无法识别 | need_keywords 自动跳过（零 Token） |
| **前端进度** | "正在调用 AI..." | "✅ 骨架: 25构件 \| RAG 18000字 200ms \| LLM 15000ms" |
| **RAG 诊断** | ❌ | ✅ 每节点 RAG 字符数/耗时 |
| **LLM 诊断** | ❌ | ✅ 每节点 LLM 字符数/耗时/Token |
| **思考内容** | 流式逐字推送 | 每节点独立展开查看 |
| **性能汇总** | ❌ | ✅ 总 RAG 时间/LLM 时间/Token/组件数 |
| **Token 消耗** | ~20K/次 | ~15-50K/次（按需，跳过则零消耗） |
| **耗时** | ~40s | ~1m40s（并行：≈最慢的1个而非累加） |

## 五、核心设计决策

1. **工厂模式消除重复**：`create_component_node(ComponentConfig)` 封装完整流程，新增组件只需 6 行代码 + 注册表一行
2. **need_keywords 自动跳过**：7 种低频组件（栏杆/雨棚/阳台/灯具/坡道/檐口/烟囱）用户不提就跳过，零 Token 消耗
3. **精确回调修正**：校验失败只修正失败组件，携带精确错误信息（组件ID + 字段 + 范围 + 建议值）
4. **LLM 并发控制**：`asyncio.Semaphore(3)` 限制 10 个并行节点中最多 3 个同时调用 LLM
5. **骨架短路**：骨架失败直接终止，不浪费后续 LLM 调用
6. **诊断数据链**：每节点 → `_diag` → `debug_log` → 前端实时展示
7. **precision_mode 前端切换**：localStorage 持久化，思考模式和精密模式互斥

## 七、使用方式

### 启动

```bash
# 后端
cd wild-server
uv run uvicorn main:app --host 0.0.0.0 --port 8000

# 前端
cd wild-web
npm run dev
```

### 切换模式

前端聊天面板底部连接栏有两个开关：

- **思考**（绿色）→ LangChain 流式思考内容
- **精密**（蓝色）→ LangGraph 分片并行 + 节点诊断面板

两个开关互斥。精密模式开关状态持久化到 localStorage。
