# LangGraph 实施后的前后端影响分析

> 基于实际代码分析：`ws_agent.py` + `agentStore.ts` + `AIChatPanel.vue`

---

## 一、核心结论

### ✅ 你的判断完全正确

1. **后端 LangChain 写法会被替代**：是的，但影响范围有限且可控
2. **前端需要大量修改**：**不需要**，只需调整进度展示逻辑
3. **只改固定动画即可**：对，主要是把假进度改成真实节点进度

## 二、后端影响范围

### 2.1 会被替代的部分

| 当前代码位置 | 功能 | LangGraph 后 | 影响程度 |
|---|---|---|---|
| `agent_service.py:query_structured()` | 单体 Agent 调用 | `graph.ainvoke(state)` | 🟡 中等（核心逻辑） |
| `prompts.py:build_system_prompt()` | 单一 System Prompt | 拆分为 per-node prompts | 🟢 小（拆分复用） |
| `_build_rag_queries()` | 8 路查询统一执行 | 每个节点独立 RAG | 🟡 中等（逻辑分散） |

### 2.2 完全不变的部分（复用）

| 模块 | 复用方式 | 代码位置 |
|---|---|---|
| `run_validation_pipeline()` | Layer 2 直接调用 | `agent_service.py:154-320` |
| 18 个空间工具 | 每个节点可调用 + 回调强制执行 | `spatial_tools.py` |
| `RAGSpecLoader` | 每个节点独立调用 `.retrieve()` | `loader.py:727-900` |
| `normalize_blueprint_input()` | 每个节点输出后归一化 | `blueprint_parser.py` |
| `validate_blueprint_schema()` | 骨架和 merge 后都要校验 | `blueprint_parser.py` |

**复用率约 70%**，核心逻辑不需要重写。

### 2.3 WebSocket 层影响

**当前流程：**
```python
# ws_agent.py:269-415
async def _handle_user_message(ws, data):
    await send_step("analyzing", "正在分析...")
    await send_step("generating", "正在调用 AI...")
    
    result = await agent_service.query_structured(...)  # ← 单体调用
    
    for pr in result.pipeline_results:
        await send_step("validating", f"{status} [{pr.step}] {pr.name}...")
    
    await ws.send_json({"type": "blueprint_generated", ...})
```

**LangGraph 后：**
```python
async def _handle_user_message(ws, data):
    await send_step("analyzing", "正在分析...")
    
    # ← 替换为 LangGraph 调用，但增加实时进度推送
    async for event in graph.astream(initial_state):
        node_name = event.get("node")
        
        # 动态进度展示
        if node_name == "skeleton":
            await send_step("generating", "✅ 正在生成骨架...")
        elif node_name == "doors":
            await send_step("generating", "✅ 正在生成门...")
        elif node_name == "windows":
            await send_step("generating", "✅ 正在生成窗...")
        elif node_name == "validate":
            # 仍然复用原有的流水线展示逻辑
            for pr in event["validation_results"]:
                await send_step("validating", f"{status} [{pr.step}] {pr.name}...")
    
    final_state = event  # 最后一个 event 就是 final_state
    await ws.send_json({"type": "blueprint_generated", ...})
```

**关键变化：**
- `agent_service.query_structured()` 改为 `graph.astream()`
- **增加** 实时节点进度推送（skeleton → doors → windows → ...）
- 校验流水线展示逻辑**完全不变**（仍然是 `send_step("validating", ...)`）

### 3.2 需要调整的部分（只有一处）

**当前的"假进度"：**

```typescript
// agentBridge.ts:339-370
case 'agent_step':
  if (content.startsWith('✅') || content.startsWith('❌') || ...) {
    const status = content.startsWith('❌') ? 'error'
                 : content.startsWith('⚠️') ? 'warn'
                 : content.startsWith('⏭️') ? 'skip'
                 : 'ok'
    agentStore.addPipelineStep(content, status)
  }
  break
```

**LangGraph 后的"真实进度"：**

```typescript
// agentBridge.ts（几乎不变，后端已经区分 stage 了）
case 'agent_step':
  const { stage, content } = data
  
  // 生成阶段：显示节点进度
  if (stage === 'generating') {
    // 后端会发: "✅ 正在生成门..."、"✅ 正在生成窗..."
    // 前端直接展示即可，无需改动
  }
  
  // 校验阶段：仍然解析流水线步骤
  if (stage === 'validating') {
    const status = content.startsWith('❌') ? 'error'
                 : content.startsWith('⚠️') ? 'warn'
                 : content.startsWith('⏭️') ? 'skip'
                 : 'ok'
    agentStore.addPipelineStep(content, status)
  }
  break
```

**实际上连这个都不用改**，因为：
- 后端发送的 `agent_step` 消息格式完全兼容
- `content` 字段仍然是带 emoji 的文本
- 前端只需要按原逻辑解析 emoji 判断状态

```typescript
// agentStore.ts（新增，可选）
const generatingNodes = ref<Array<{
  name: string
  label: string
  status: 'running' | 'done' | 'failed'
  emoji: string
}>>([])

function updateGeneratingNode(name: string, status: 'running' | 'done') {
  const labels = {
    skeleton: '骨架',
    doors: '门',
    windows: '窗',
    roof: '屋顶',
    // ...
  }
  const node = generatingNodes.value.find(n => n.name === name)
  if (node) {
    node.status = status
    node.emoji = status === 'done' ? '✅' : '🔄'
  } else {
    generatingNodes.value.push({
      name,
      label: labels[name] || name,
      status,
      emoji: status === 'done' ? '✅' : '🔄',
    })
  }
}
```

## 四、迁移步骤（最小改动路径）

```python
    await send_step("analyzing", "正在分析...")

        result = await _handle_with_langgraph(ws, data)
    else:
        result = await agent_service.query_structured(...)
```

**此时前端无需任何改动**，因为：
- WebSocket 消息格式完全兼容
- `result` 结构（QueryResult）不变
- 校验流水线展示逻辑不变

### Step 2: 增加实时节点进度（后端推送）

```python
async def _handle_with_langgraph(ws, data):
    async for event in graph.astream(initial_state):
        node_name = event.get("node")
        
        # 推送节点进度（复用现有 agent_step 消息）
```

**前端仍然无需改动**，因为：
- `send_step()` 发送的仍然是 `agent_step` 消息

- 只是从"假进度"变成"真进度"

## 六、你的问题的精确答案

### Q1: 是不是就替代了我目前的 LangChain 的大部分写法？

**A: 是，但影响范围可控。**

- **被替代：** `agent_service.query_structured()` 改为 `graph.ainvoke()`
- **完全复用（70%）：** 校验流水线、工具、RAG、归一化、Schema 校验
- **新增：** 每个组件节点的独立 RAG 查询和 LLM 调用

### Q2: 前端也需要大量的修改，好像也不用？

**A: 对，前端几乎不需要改。**

- WebSocket 消息格式**完全兼容**
- `agentStore.pipelineSteps` 数据结构**完全兼容**
- `AIChatPanel.vue` 的渲染逻辑**完全兼容**

### Q3: 把那个固定动画改了就行了？

**A: 对，而且连前端都不用改。**

- 只需要后端在 `_handle_user_message()` 中增加 `send_step()` 调用
- 前端收到的仍然是 `agent_step` 消息，自动展示
- 从假进度（"正在调用 AI..."）变成真进度（"✅ 正在生成门..."）
