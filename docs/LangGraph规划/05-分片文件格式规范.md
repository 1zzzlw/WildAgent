# 分片文件格式规范

> LangGraph 各节点产出的片段文件格式定义。每个节点产出独立的分片 JSON，最终由 merge 节点组装为完整 Blueprint。

---

## 一、设计目标

1. **独立可校验**：每个分片可以独立跑 Schema 校验
2. **无冲突合并**：各节点输出不互相覆盖
3. **可追溯**：每个 fragment 知道自己来自哪个节点
4. **兼容现格式**：合并后的产物就是标准 Blueprint，无需额外转换

---

**窗分片、屋顶分片和其他组件分片格式相同。**

## 三、合并规则

```python
def merge_fragments(skeleton: dict, fragments: list[dict]) -> dict:
    """
    1. 深拷贝 skeleton 作为基底
    2. 遍历每个 fragment:
       - elements → 追加到 geometry.elements
       - components → 追加到 geometry.components
       - extra_materials → 合并到 materials（同名材质以 skeleton 为准，防止覆盖）
       - diagnostics → 汇总
    3. ID 冲突检测:
       - 所有 elements/components 的 id 取并集
       - 如有冲突 → 记录 diagnostic，后到的加 _dup 后缀
    4. 引用完整性检测:
       - 所有 parentWall 必须在 wall id 列表中
       - 所有 parentFloor 必须在 floor id 列表中
       - 缺失引用 → 记录 diagnostic
    5. 返回合并后的完整 Blueprint
    """
```

### ID 命名空间规则

为避免并行节点之间的 ID 冲突：

| 组件类型 | ID 前缀约定 |
|---|---|
| door | `door_`（如 `door_front`、`door_back`） |
| window | `window_` 或 `win_` |
| roof | `roof_` |
| railing | `rail_` |
| furniture | `furn_` |
| light | `light_` |

编译器随后会确定性派生子元素 ID（如 `door_front__opening`、`door_front__frame_left`），不同组件的子元素不会冲突。

## 四、分片的生命周期

```
Layer 0: skeleton_fragment   ─┐
Layer 1: door_fragment       ─┤
         window_fragment     ─┤
         roof_fragment       ─┼─→ merge_fragments() → merged_blueprint
         railing_fragment    ─┤       │
         furniture_fragment  ─┤       ▼
         light_fragment      ─┘   validate_and_fix()
                                       │
                              ┌────────▼────────┐
                              │  回调修正        │
                              │  只重写失败分片  │
                              │  不重写已通过分片│
                              └────────┬────────┘
                                       │
                                       ▼
                                 final_blueprint
```

**关键**：回调时只重写失败的 component fragment，不重新跑 Layer 0 和已通过的 Layer 1 节点。

---

## 五、分片存储（调试用）

在开发阶段，每个分片在合并前存储到 `wild-server/storage/sessions/{session_id}/fragments/`：

```
fragments/
├── 0_skeleton.json
├── 1_doors.json
├── 1_windows.json
├── 1_roof.json
├── 1_railings.json
├── 1_furniture.json
├── 1_lights.json
├── 2_merged.json          ← merge 后的完整 Blueprint
├── 2_validation.json      ← 校验结果
├── 2_retry_1_doors.json   ← 第一次回调修正后的门
└── 3_final.json           ← 最终产物
```

**用途**：出现 bug 时可以精确追踪是哪个节点生成的哪个 fragment 有问题，而不是在一个巨大的 Blueprint 里大海捞针。
