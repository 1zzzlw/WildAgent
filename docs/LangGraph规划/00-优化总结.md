## 四、关键设计决策与理由

### 决策 1：内存优先，磁盘可选

**理由：**
- LangGraph State 本身就是内存对象
- 单次生成 10-30 秒，无需断点续传
- 磁盘 I/O 仅用于调试，不影响生产性能

**实现：**
```python
# 生产：纯内存
final_state = await graph.ainvoke(initial_state)

# 开发：内存 + 磁盘镜像
if config.SAVE_GENERATION_FRAGMENTS:
    await save_fragment_debug(state, node_name)
```

### 决策 2：严格按编译器依赖排序组件优先级

**理由：**
- `balcony` 编译器内部调用 `railing` 编译逻辑
- 必须先实现 `railing_generator` 才能测试 `balcony_generator`

**实施顺序（P1-P5）：**
```
P0: door, window, roof           (独立，无依赖)
P1: railing                      (被 balcony 依赖)
P2: canopy, balcony              (balcony 依赖 railing)
P3: light                        (生成 behaviors，独立)
P4: ramp, bay_window             (特殊场景)
P5: cornice, chimney             (中式建筑)
```

### 决策 3：每个组件独立的 RAG entity_type 过滤

**理由：**
- 避免 top_k 竞争（当前 8 路查询共享 top_k=6）
- 每个节点只召回自己需要的 chunk

**实现：**
```python
# door_generator
retrieve_many([
    SpecQuery(user_message, {"entity_type": "door"}),
], per_query=2)

# window_generator
retrieve_many([
    SpecQuery(user_message, {"entity_type": "window"}),
], per_query=2)
```
