# WildAgent 项目索引

最后核对：2026-10-13。

按「稳定索引」查代码：本文件的每一项都是**文件路径 + 符号名**。行号会随改动漂移，不作为定位依据；需要精确行号时用符号名搜索。全部路径相对仓库根目录。

## 2. 最短阅读路径

1. `wild-server/app/agent/state.py` —— 先认清中间状态契约，其余一切都在读写它。
2. `wild-server/app/agent/graph.py` —— 看节点拓扑与路由函数，图只有一处定义。
3. `wild-server/app/agent/nodes/` —— 这些文件全是 3–9 行的薄 re-export，**实现不在这里**，顺着导出符号跳到领域包。
4. [架构说明](ARCHITECTURE.md) —— 模块边界与数据流。
5. [Agent 与 AI 对话设计](agent/AGENT_AND_CHAT.md) —— 前后端协议与交互边界。

> `nodes/*_node.py` 的「薄入口」由 `tests/agent/test_agent_module_boundaries.py` 强制：每个入口文件 ≤ 100 行，`nodes/` 之间不得互相 import，领域包不得反向 import `app.agent.nodes`。

| 源 | 路由函数 | 目标 |

节点标签表有两份，必须同批修改：后端 `app/api/ws_agent.py` 的 `_NODE_LABELS` / `_OUR_NODES` / `_NODE_START_DETAILS` 是权威；前端 `wild-web/src/stores/agentStore.ts` 的 `_NODE_LABELS` 是兜底副本，其中仍残留已下线节点名。守卫测试见 `tests/api/test_ws_step_labels.py`。

**Layer -0.5 建筑方案（10）**：`architecture_plan`（DesignDocument 的只读兼容投影）、`architecture_diag`、`design_document`、`drawing_hosts`、`resolved_design`、`design_review_status`、`design_feedback`、`design_material_refresh`、`material_plan`、`material_diag`

**Layer -1 分支输出**：`chat_reply`、`chat_diag`、`scene_patch`、`patch_reply`、`patch_diag`

**Layer 0 骨架（8）**：`skeleton_blueprint`、`skeleton_summary`、`wall_bounding_box`、`spatial_invariants`、`suggested_components`、`design_brief`、`skeleton_diag`、`compile_report`

**Layer 1 组件分片（2，带 reducer）**：`component_fragments`、`component_diagnostics`

**Layer 2 合并与校验（13）**：`merged_blueprint`、`merge_diag`、`validation_results`、`validation_issues`、`validation_error_count`、`validation_warning_count`、`validation_cache_reused`、`validation_snapshot`、`design_fulfillment`、`failed_components`、`passed_component_ids`、`retry_count`、`max_retries`、`component_retry_counts`

## 5. plan 动态执行计划层

`plan` 只描述本次业务目标；**固定节点顺序由 LangGraph 独占**，计划里没有 `steps`，也不存在按 step 调度的执行器。

### 5.1 类型契约

[`app/agent/plan/contracts.py`](../wild-server/app/agent/plan/contracts.py)，`PLAN_SCHEMA_VERSION = "plan/1.0"`。

| 符号 | 说明 |
|---|---|
| `OPS` | `generate` / `merge` / `validate` / `fix` / `repair` |
| `PlanStatus` | `pending` / `ready` / `blocked` / `done` / `abandoned` / `skipped` / `unsupported` |
| `RunState` | `idle` / `running` / `succeeded` / `failed` / `aborted` |
| `PlanItem` | 一条工作项：`id`、`op`、`kind`、`target`、`depends_on`、`origin`（`plan` / `emergent`）、`status`、`run` |
| `ItemRun` | 执行态，**只有 execute 写**：`attempts`、`max_attempts=3`、`evidence`（≤2000） |
| `PlanStrategy` / `PlanKindStrategy` | 模型产出的策略，经程序归一化后使用 |
| `PlanDocument` | 整份计划 + 循环控制计数（`iterations`、`no_progress_rounds`、`llm_calls`） |

### 5.2 模块职责

| 文件 | 职责 |
|---|---|
| [`contracts.py`](../wild-server/app/agent/plan/contracts.py) | 计划态与执行态两个状态机的类型定义 |
| [`store.py`](../wild-server/app/agent/plan/store.py) | **唯一被允许改 plan 对象的确定性数据层**，全为纯函数：`record_result`、`poll_runnable`、`mark_running`、`reset_for_retry`、`terminal_stats` |
| [`expand.py`](../wild-server/app/agent/plan/expand.py) | 把方案/骨架产物**确定性**展开为条目列表，不调模型。建筑走图纸标记，物件走策略 |
| [`workflow.py`](../wild-server/app/agent/plan/workflow.py) | 三个图节点：`plan_node`、`execute_node`、`replanner_node` |
| [`strategy.py`](../wild-server/app/agent/plan/strategy.py) | plan 阶段的**唯一模型调用点**：`request_plan_strategy`，失败降级 `deterministic_strategy` |
| [`capability.py`](../wild-server/app/agent/plan/capability.py) | 能力缺口判定：**能力缺失只标记不阻断**，转成 `unsupported` 条目进交付清单。`CAPABILITY_GAPS`、`detect_capability_gaps` |
| [`reconcile.py`](../wild-server/app/agent/plan/reconcile.py) | 对账：**唯一**能写条目 `status` 的地方 |

| [`handlers.py`](../wild-server/app/agent/plan/handlers.py) | 处理器表 `HANDLERS`：`generate`/`repair` 走模型，`merge`/`validate`/`fix` 纯确定性 |
| [`replan.py`](../wild-server/app/agent/plan/replan.py) | replanner 异常分支，动作限五元闭集，`MAX_REVISION=2`、`MAX_NO_PROGRESS_ROUNDS=2` |
| [`tool_loop.py`](../wild-server/app/agent/plan/tool_loop.py) | **条目内部**的有界工具循环，不是图节点 |
| [`tool_registry.py`](../wild-server/app/agent/plan/tool_registry.py) | `(op, kind)` 工具裁剪，**fail-closed 默认** |
| [`knowledge_tool.py`](../wild-server/app/agent/plan/knowledge_tool.py) | 检索构件知识并保留来源 |
| [`slot_utils.py`](../wild-server/app/agent/plan/slot_utils.py) | 设计清单槽位读取与批次摘要 |
| [`slots.py`](../wild-server/app/agent/plan/slots.py) | `slot_utils` 的兼容 re-export |

### 5.3 关键机制

- **`plan_node` 走两条分支**：建筑分支用 `app.design.compilation.project_drawing` 解析图纸后 `expand_plan` 确定性展开，**零模型调用**（`plan_diag.source="drawing_implementation"`）；物件分支才调 `request_plan_strategy`。
- **`execute_node` 支持安全并发**：`_MAX_PARALLEL_ITEMS = 3`，`asyncio.gather` 后由 `_merge_parallel_updates` 合并局部 state。
- **工具循环必须在条目内部**：若提到图层，`recursion_limit` 就失去意义。

## 10. 空间校验与修复闭环

### 10.1 轻量结构校验

[`app/utils/blueprint_parser.py`](../wild-server/app/utils/blueprint_parser.py) 的 `validate_blueprint_schema(blueprint, *, allow_empty_geometry=False)` 分四个强制阶段：

| 阶段 | 内容 |
|---|---|
| 0 顶层类型 | 必须是 JSON 对象 |
| 1 顶层元数据 | `meta` 存在，且 `version` / `type` / `name` 三个必填 |
| 2 几何与构件身份 | `geometry.elements` 与 `components` 不能同时为空（`allow_empty_geometry=True` 时豁免，仅供物件骨架阶段）；两者**共享 ID 命名空间**；组件 `type` 必须在闭集内；`from` / `to` 必须是 3 个有限数 |
| 3 PBR 资产清单 | `assetId` 须匹配 `pbr_[0-9a-f]{24}`，`contentHash` 须匹配 `sha256:[0-9a-f]{64}`，通道 `colorSpace` 须与通道匹配 |
| 4 材质结构与颜色通道 | 颜色通道 0–1 且显式排除 `bool`；`materialClass` ∈ {standard, glass, clearcoat, fabric}；glass 必须 `transmission>0` |

该函数**不做空间关系校验**，那是 `spatial_tools` 的职责。

### 10.2 真正的强制校验流水线

入口：[`app/services/agent_service.py`](../wild-server/app/services/agent_service.py) 的 `run_validation_pipeline(blueprint, *, log_steps=True, auto_fix=True)`。

校验器在 [`app/tools/spatial_tools.py`](../wild-server/app/tools/spatial_tools.py) 与 [`app/tools/component_tools.py`](../wild-server/app/tools/component_tools.py)。

| 步骤 | 校验器 | 自动修复 |
|---|---|---|
| 1 | `validate_blueprint_structure` | — |
| 2 | `validate_element_required_fields` | — |
| 3 | `validate_reference_integrity` | `fix_material_references` + recheck |
| 4 / 4b | `validate_opening_coords` / `validate_opening_fit` | — |
| 5 | `validate_wall_junctions` | — |
| 6 | `validate_stair_alignment` | — |
| 7 / 7b | `validate_roof_coverage` / `validate_element_dimensions` | — |
| 7c | `validate_model_quality`（重复骨架质量门禁） | — |
| 7d | `validate_stacked_member_containment`（贯通构件逐层收进门禁） | — |
| 7e | `validate_roof_top_coverage` | **只报警告，不参与复检，不阻断交付** |
| 8–8f | — | `fix_opening_coords`、`fix_opening_fit`、`fix_stair_alignment`、`fix_element_dimensions`、`fix_roof_coverage`、`fix_wall_junctions`，每项修复后 recheck |
| 9 / 9b | `validate_collision` | `fix_element_elevations` + recheck |
| 10.x | `validate_{component_type}_placement`（按蓝图内实际组件类型动态展开，排除 `roof`） | `fix_{component_type}_placement` + recheck |

两条必须记住的规则：

- **早退**：步骤 1 有 error 则 2–9 全部 `skip_step`；步骤 2 有 error 则 4–9 全部 skip。
- **尾递归复查**：`auto_fix=True` 时在末尾以 `auto_fix=False` 再跑一遍完整流水线，复查被后续修复改动过的事实。因此**最终错误会覆盖初检结果**，只保留每组最后一条（`_final_errors`）。
