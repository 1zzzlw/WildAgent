# WildAgent 项目索引

本文档记录 WildAgent 当前 Agent 生成工作流、结构化中间状态、确定性装配、空间校验与前端重建链路的代码索引，用于后续持续维护和定位问题。

本文档只描述当前代码的位置、职责和接入状态，不把历史设计、待办方案或未接入实现写成已交付能力。

最后核对：2026-09-08。

## 1. 使用方法

索引中的“接入状态”分为：

| 状态 | 含义 |
|---|---|
| 当前主链 | 当前 LangGraph 生成流程会正常执行 |
| 支撑层 | 被主链节点、校验器或前端调用 |
| 兼容保留 | 仍在代码或图中保留，但不是当前新建筑正常主链 |
| 未接入 | 已有实现或测试，但当前主链未调用 |
| 交付后 | Blueprint 通过服务端校验后，在前端编译、重建和显示阶段执行 |

表格中优先记录稳定的函数、类或节点名。行号仅用于当前版本快速定位，代码变更后应重新核对。

## 2. 最短阅读路径

如果需要快速理解 Agent 建筑生成全链路，建议按以下顺序阅读：

1. [`wild-server/app/agent/graph.py`](../wild-server/app/agent/graph.py)：LangGraph 节点和路由。
2. [`wild-server/app/agent/graph_state.py`](../wild-server/app/agent/graph_state.py)：可持久化中间状态。
3. [`wild-server/app/agent/execution_plan.py`](../wild-server/app/agent/execution_plan.py)：计划模式的结构化任务和能力边界。
4. [`wild-server/app/agent/nodes/architecture_node.py`](../wild-server/app/agent/nodes/architecture_node.py)：总体方案生成与候选选择入口。
5. [`wild-server/app/agent/nodes/skeleton_node.py`](../wild-server/app/agent/nodes/skeleton_node.py)：当前 LLM 主体骨架与组件建议入口。
6. [`wild-server/app/agent/nodes/base_component_node.py`](../wild-server/app/agent/nodes/base_component_node.py)：动态组件生成和校验工厂。
7. [`wild-server/app/services/agent_service.py`](../wild-server/app/services/agent_service.py)：Blueprint 强制校验与修复流水线。
8. [`wild-web/src/renderer/wildCoreAdapter.ts`](../wild-web/src/renderer/wildCoreAdapter.ts)：前端 compiler → core → reconstruction diagnostics 入口。

## 3. 当前生成主链

当前建筑生成主链为：

```text
classifier
  → planning_research / planner / plan_validator / plan_review / plan_executor
  → architecture
  → material_plan
  → skeleton (LLM 主体 + 组件建议)
  → Send(component_gen → component_val) × N
  → merge
  → final_validate
  → callback / END
```

## 15. 维护约定

以后修改 Agent 工作流时，按以下规则同步更新本文档：

1. 新增、删除或重排 LangGraph 节点时，更新第 3 节主链和对应索引。
2. `GenerationState` 字段变更时，更新第 4 节，并标明字段是临时、可持久化还是可交付。
3. Prompt 输出结构变更时，同步核对对应 normalizer、State 回写和测试。
4. fallback、风格包、组件白名单或确定性装配改变时，更新第 7–9 节。
5. 新增校验器或修复器时，必须记录它的调用入口、执行顺序、复检位置和回归测试，不能只记录函数文件。
6. 代码存在但未接入主链时，必须放在第 12 节，不得写成当前能力。
7. 每次核对后更新文档顶部的“最后核对”日期，并检查相对链接和行号。
8. 问题分析、改造方案和实施记录分别放入对应专题文档或 `docs-dev/`；本文档始终保持为“现行索引”。
