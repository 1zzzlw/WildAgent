**体块构成规则（防"三层方盒"，本次迭代核心）**：
1. **上下层不得同轮廓**：相邻两层的实体外轮廓必须有至少一处退让或悬挑，禁止 L1/L2 完全重合的"叠方盒"。
2. **上层支承约束**：任何缩进的上层墙体必须有同轮廓的下层楼板/墙体托底——L2 主块 10×10 与 L3 外轮廓完全对位，保证 L3 全部外墙落在 L2 板上。
3. **退让处成露台**：下层屋面因上层退让暴露的部分，直接升格为屋顶露台（floor + 女儿墙 + 可达门/窗），不得留裸楼板。
4. **翼体收头**：L2 东翼体（5×6.5）顶面即 L3 露台底座，翼体北缘 z=6.5 处设满长女儿墙压边（与主块东墙外皮对齐，不留缺口）。

**楼梯引擎硬语义（本次修正的隐性错误）**：`stair` 的升高 = **stepHeight × stepCount**，`from/to` 的 Y **不参与**计算（to 仅定走向与水平终点），且**末步距 to 沿走向少一个 stepDepth**（末步西缘 = to.x − 0.12…按 from+9×步距 推）。旧 stair_l2_l3 写 20×0.18=3.6m 而层高仅 3.0m，楼梯顶悬空 0.6m——每跑必须满足 `stepHeight × stepCount = 该跑升高`，两跑之和 = 层高。

## 修改规则：外墙轮廓变化时的内墙联动（硬性）

1. 该层全部内墙（含楼梯井墙）随外墙轮廓重算；上层轮廓若变，上层内墙一并重算。
2. 内墙只依附外墙；端点对齐外墙**内皮**（南 z=zc+th/2，北 z=zc−th/2，西 x=xc+th/2，东 x=xc−th/2）。
3. 内墙端点不得超出外墙内皮区间；不得悬空、不得穿墙。
4. 门窗/阳台 from[0] 随父墙起点重算；内门随父内墙端点重算。
5. 重推：外墙轮廓 → 内皮 → 内墙端点 → 组件 from → 校验。

## 附：渲染部署说明（wild-viewer 旧引擎语义降级）

源 `.wild`（1.1 规范）不经修改直接可用于 WildAgent 主程序（workspace wild-web 1.1 引擎）。若要在独立 wild-viewer（v1.0 参考引擎）预览，需做四处**部署侧**语义降级（转换脚本：工作区根目录 `flatten_villa3.ts`）：

| 差异点 | 1.1 规范 | 旧 viewer 引擎 | 部署转换 |
|---|---|---|---|
| 洞口横向定位 | `from[0]` = 左边缘沿墙距离 | `from[0]` = 开口中心 | `from[0] += width/2` |
| 洞口竖向定位 | `from[1]` = 世界 Y | `from[1]` = 相对墙底高度 | `from[1] -= 墙底Y`（否则墙体被撑高、洞口飞出） |
| flat 屋顶 | span/depth 显式、有 thickness | 被 resolver 按全部墙 XZ 包围盒自动扩张、渲染为零厚板 | 移除 roof 元素，改 primitive box 平屋顶 + 女儿墙 |
| 物理玻璃 | materialClass:glass + transmission + ior | 仅支持 opacity | 剥离物理字段，改 `opacity: 0.45` |

**洞内填充说明（修正）**：旧引擎 `buildOpening` **原生渲染洞内填充板**（尺寸=洞口+0.08 边距，位置=resolver 按墙真实方向计算）——窗的 opening 携带 `material:glass` → 渲染为透明玻璃板；门的 opening 携带 `material:leafMaterial` → 渲染为门扇板。**不要**在部署层额外补 `__glass`/`__leaf` 几何（会与引擎填充板形成双层透明面）。

**"洞口无门窗"的真正根因（已修复引擎）**：wild-core `buildWall` 曾用 `angle = atan2(dz, dx)` 旋转墙体，而 Three.js `Ry(θ)` 把局部 +X 映射到 `(cosθ, 0, -sinθ)`，正确值应为 `atan2(-dz, dx)`。旧值导致 **dz≠0 的墙（东/西墙）绕中点首尾翻转，洞口切割位置被镜像**——洞口开在错误位置，而门窗框与填充板按真实坐标放置（埋在墙体内不可见），表现为"只有洞口没有门窗构件"。南北墙（dz=0）不受影响；西墙窗户恰近墙中点（镜像不变），故只有东墙明显暴露。已在 `wild-yuan/wild-core/src/primitive/geometry/wall.ts` 修正并重建 viewer。

教训：**多楼层墙共享角点 XZ 时，洞口竖向坐标一旦按世界 Y 传入旧引擎，墙体会被撑高到洞口顶标高**（表现为"凭空多出灰色墙体"）。任何 Agent 生成蓝图时仍应按 1.1 规范写世界 Y，降级只发生在渲染部署层。

### 部署健康检查（预览前必做）

预览"看不到修改/旧错误复现"时，按序排查——多数是部署层而非蓝图本身：

1. **服务器存活**：`curl -s http://localhost:18901/villa3.wild | wc -c`，返回 <1KB（如 upstream connect failed）说明静态服务器已死，需重启（脚本：`wild-viewer/serve_dist.mjs`）。
2. **内容新鲜**：对比 served 与 `dist/villa3.wild` 的 md5，不一致说明改动未部署或被缓存。
3. **禁用缓存**：服务器必须返回 `Cache-Control: no-store`（serve_dist.mjs 已内置）；预览 URL 追加 `&t=<时间戳>` 兜底。
4. **数据审计**：`check_components_complete.mjs`（逐组件核对洞口/框/玻璃/门扇齐全）+ `audit_openings_world.mjs`（模拟旧引擎洞口切割语义，验证每个洞与填充板空间重合、无游离板）。
5. **引擎级验证**：`verify_engine_infill.ts`（esbuild 打包后 node 运行）——真实跑 parseBlueprint + reconstructEntity，确认填充板全部产生网格。

### 预览性能（viewer 渲染管线约定）

本场景体量极小（≈5.7k 三角形、≈300 draw calls），卡顿只会来自渲染管线固定开销与显示环境。viewer 已做以下约定（`wild-viewer/src/main.ts`，改引擎后 `vite build` 重建）：

1. **阴影按需更新**：`shadowMap.autoUpdate = false`，仅在蓝图加载后与门扇动画窗口（600ms）内置 `needsUpdate`——静态场景不逐帧重算阴影贴图；
2. **阴影贴图 1024 + 阴影相机紧贴建筑包围盒**（±14），替代默认 2048 + 60×60；
3. **pixelRatio 上限 1.5**：HiDPI/预览面板缩放下填充率是首要开销；
4. `powerPreference: 'high-performance'`：双显卡机器优先独立 GPU；
5. 指南针方位角变化 >0.2° 才写 DOM。

若内嵌预览面板仍卡（面板可能走软件渲染），用系统浏览器打开同一 URL 即可启用 GPU 加速。
