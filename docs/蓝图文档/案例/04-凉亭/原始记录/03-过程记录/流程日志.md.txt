# 听雨水榭创建记录

## 方法与来源

当前对话 Codex 自主设计 → 可复现 Python 展开 JSON → 项目只读 Schema、编译器、重建器、后端流水线 → 原项目 Chromium/WebGL 四视图 → 人工查看 → 修订。没有运行项目 LangGraph/RAG、项目配置模型或外部图片渲染。规则来源为 `docs/Wild蓝图设计语言.md`；`00-公共脚本/构件作者工具.py` 提供无建筑方案参数的原语写入和四坡瓦作函数。

设计先保存在 `01-需求与设计`，最终 `.wild` 在本目录根部。每轮完整输入和当时脚本保存在 `r1`～`r4`，命令、起止时间、退出码和未裁剪输出保存在 `命令记录`。具体命令参数以记录 JSON 为准。

## 实际修订

1. r1：完成新方案并输出 666 个基础构件。柱字段误用了 primitive cylinder 的 radiusBottom/radiusTop，Schema 拒绝。保留原稿和失败报告，没有声称初稿通过。
2. r2：改为文档规定的 bottomRadius/topRadius，修正圆柱细分字段为 segments。Schema 通过；引擎报 10 条梁退化错误。检查源码发现 beam 端点仅按 XZ 吸附柱顶，低位竖木格两端会被拉到同一点。实际失败图和报告保留。
3. r3：装饰杆件改为明确旋转的实体 box，避免吸附；补短柱与屋下檩条。踏步改为不重叠的独立踏面段，池底不再与场地板穿插。编译/重建清零，后端碰撞警告清零。
4. r4：通长檩条使用端部挑过柱线的原生 beam；修正自定义悬灯 body 的世界坐标。灯体不再错误生成于世界原点。规则文档同步补充这两项已确认的坐标/吸附边界。
5. 最终四视图：实际查看正面和透视图，入口通畅，台阶连续，坐凳不封正面，灯体位置正确，瓦垄和角脊可辨。去屋面副本只删除 roof/roof_detail 层，保留木构、茶席及场地的原始坐标与材料；实际查看透视图。
6. 参考汀院使用当前源码重新出图，保存在 `00-质量参考/凉亭写字楼同条件参考`，不覆盖先前两栋别墅的历史比较证据。

## 结果与限制

最终文件：676 个基础构件、2 个组合灯具、20 种材质，120601 字节。最终 SHA256 为 `164f8428ca97f5d91399b638cf6debf189c90e3e0ac92d3eb2be4fbbc90513e4`。引擎真实重建 694 网格，编译/重建错误 0、缺失材质映射 0。

后端 `validate_roof_coverage` 仍报 1 项：外檐面 +4.05 与最近柱顶 +3.56 的比较不能识别多段木构承托，也没有按 hip 坡面内侧接触标高判断。保留完整原始失败；另用屋面实际函数核对 6 个檩条接触点，屋面下表面与檩条顶均 +4.54，柱头—叠涩—短柱—檩条连续。没有更改项目校验代码、删掉屋顶、降低标准或用局部通过冒充全图通过。

水池有当前水材质；本次是静态外观与空间检查，不额外声称逐帧水动画或灯具交互已在此建筑上专项测试。模型不是施工图。

初次 shell 命令误用了根目录 `.venv` 路径，未启动生成；改用实际的 `wild-server/.venv` 后执行。首轮命令记录器在打印 emoji 时遇到 GBK 编码错误，原始子进程输出已完整落盘；记录器随后显式使用 UTF-8，失败记录保留。
