# 提示词、自由设计与同类型变化

本文件给任务组织方法，不增加WILD字段。以下方案是可以继续发展的设计方向，不是承诺已经生成、校验或渲染的新作品。主语言的格式/坐标/计算规则始终有效。

## 1. 最少需要告诉 AI 什么

```text
用途：
硬条件：地块、层数、必须功能、必须文字、禁用项
风格或环境：可留空，由AI确定
设计倾向：可留空，例如安静内院、面向街角、开敞木构
变化要求：首次创作/同类新方案/复建参考图
输出模式：完整WILD JSON / 有工具的文件交付
质量重点：空间、构造、室内、材料、光景中的优先项
```

不要要求用户填写几十个几何参数才能开始。把不可变条件与可自由决定项分开即可。缺失层数和规模时由AI合理选择并保持一致；如果地块容不下所有必须功能，先说明具体冲突，再寻求调整，不能输出暗中越界的成品。

## 2. 三种可复制的启动提示词

### A. 只发一个文档，直接输出文件内容

> 严格按附件《WILD蓝图设计语言-v3.0》生成一份完整WILD。设计一座两层现代住宅，地块24×20米，三间卧室、书房、家庭起居和餐厨，有院子，不要泳池。招牌写“松间居”。布局与立面由你重新设计，注重入口、深窗、屋面收边和室内可使用空间。只输出完整JSON，不输出脚本/解释/省略号。

A模式只发送主语言即可。输出能力不足时减小细节展开规模，保留要求的全部功能和关系；不能把未生成的部分写成注释。

### B. 发主语言与本文件，强调同类不同方案

> 按附件设计另一栋咖啡馆。硬条件：16×16米地块，两层，吧台、后场、卫生间、室内外座位，招牌“暮野咖啡”。保持暖色砖木风格。上一方案是矩形主楼、侧外梯、层层退台；本稿避开这三项组合。请从平面拓扑、楼梯位置、剖面和屋面选择另一套连贯策略。最终输出一份完整WILD，不只改颜色与名称。

### C. 发整个资料包给有工具的智能体

> 先读README与主语言，按当前能力独立设计一座32×32米地块的小型社区图书馆，两层，有阅览、书架、咨询、卫生间、内部楼梯与室外阅读区，招牌“林间书屋”。先保存设计事实，再生成自足WILD。允许脚本展开，禁止把固定案例改名当新设计。运行静态检查、Core和真实四视图，实际看图，必要时做剖切；保持需求、记录失败与修订，明确保留问题。只写我指定的交付目录。

有工具不代表必须用Agent/RAG、远程模型或某个建筑生成器。先确认已具备的Python/Node/浏览器，再选择能够完成的验证层级。

## 3. 同一需求可以怎样设计出三种不同住宅

共同任务：24×20米地块，两层、三卧、餐厨/起居/书房，无泳池、现代暖色材料。下表展示**设计方向**，不是三个已通过的建筑。

| 方面 | A 内院住宅 | B 线性景观住宅 | C 双体量连廊住宅 |
| --- | --- | --- | --- |
| 主命题 | 公共空间围绕小院，安静内向 | 较窄体量沿长边布置，朝庭园展开 | 公共/私密分别成体，通过入口厅/连廊联系 |
| 平面 | U形或折院，院子作为组织中心 | 条形加局部端部书房，保留连续大庭园 | 错接双矩形，入口落在两者间 |
| 垂直交通 | 一侧内梯，层层廊道明确 | 中部内梯缩短到卧室的路径 | 相接处核心梯，上层桥廊留真实孔和防护 |
| 剖面/屋面 | 局部露台，围院低檐口 | 局部挑高起居+分段坡/平屋面择一 | 高低两顶，上层连接区明确支承 |
| 立面 | 院侧大开口、外侧深窗 | 面景宽窗与连续遮阳，背面控制开口 | 两翼材料比例有主次，连接体较轻 |
| 必须复算 | 院廊、屋面分块、门窗宿主 | 挑高板孔、屋面端墙、房间净宽 | 连廊洞口、桥侧护栏、两翼标高与墙体连接 |

三方案功能相同，空间拓扑与剖面已经不同。不能直接把三种策略叠在一个地块上，更不能因“自由”增加用户禁用的泳池或多一层。

## 4. 把“随机”改成有条件的选择

推荐顺序：

1. 固定硬条件，写出功能邻接与不能堵塞的交通线。
2. 提出少量相容方向，以场地、采光、使用、风格和预算取舍选定一个。
3. 锁定体量/标高/交通，完成门窗与屋面后再细化；局部细节可以变化，但不能不断改变共享尺寸。
4. 色差、植物簇、书本/商品等低风险重复细节可使用固定seed复现，记录seed及其影响范围。
5. 用户要同类新稿时，改变至少一组核心空间关系并联动重算；随机seed只负责细节纹理不能承担此任务。

有连续会话的智能体可以保留一份“已用方案摘要”，记录平面、剖面、交通、屋面、围护、材料六项。没有历史时不承诺与所有过去作品绝不重复；让用户提供想避开的特征即可。

## 5. 设计事实记录示范

工程化模式可按下面组织另存的设计说明，**不要把这个结构塞入WILD，也不要称它为项目正式DesignDocument**：

```text
用户硬条件：用途、地块、层数、功能、名称、禁用项
本稿主命题：一句话
与旧稿的实质差异：平面/剖面/交通/屋面及原因
体量表：id、起点x/z、宽/深、跨层、角色
标高表：各层完成面、板厚、墙顶、屋面上下皮
功能与通路：公共/私密/服务；楼梯到达与平台
围护与细部：开间、洞口、材料角色、主节点
关键计算：孔范围/面积、梯段尺寸、支承/净空、池深
输出预算：主体/主要细节/次要细节，容量不足时减哪里
验证状态：执行工具、文件hash、原始报告、实际看过的视图、保留问题
```

接入原项目正式工作流时，应按 [当前DesignDocument契约](核心资料/wild-server/app/design/contracts.py) 编写，并由完整后端验证。体量x/z是平面起点而非中心；massing控制总体范围，不是世界原点边界；facade pattern长度对应bays；每一建模楼层和标高必须完整。作者专用`authoring`扩展不能被其他工具自动理解，不能宣传成通用自然语言DSL。

## 6. 其他类型的任务例

| 类型 | 任务示范 | 应避免的固定套路 |
| --- | --- | --- |
| 木构亭 | 临水休憩亭，入口朝步道，坐凳不封路，展示柱梁檩与屋顶接触；可自行选择平面与屋面 | 不强制六柱/四坡/中置茶桌；先看使用和柱网 |
| 写字楼 | 五层、社区尺度、首层公共接待、上层办公与会议、内部梯/电梯、局部露台 | 不默认完整玻璃盒；连续交通比统一窗数量更重要 |
| 图书馆 | 两层，安静阅览与儿童阅读分开，内外阅读场所、咨询和服务可达 | 不默认中庭；若有中庭必须真实留洞和防护 |
| 超市 | 单层16×16，鲜食/冷柜/日用分区，补货后场、收银排队、明确店名 | 不只摆整齐空盒；双面货架和顾客/补货流线不同 |
| 图片复建 | 按可见体量、左右、开口和代表节点复建，尺寸自行推定并说明，隐蔽侧合理补全 | 不把图片色调/景深当作几何成果，不复制水印和按钮 |

## 7. 精细度不够时怎样反馈

| 笼统反馈 | 更容易执行和核验的反馈 |
| --- | --- |
| 再精致一点 | 保留平面，补入口门套、窗台深度、屋顶压顶及材料接缝；控制新增几何规模 |
| 再丰富一点 | 补齐该用途缺少的实际功能物件，并给主要节点增加基底/框架/收边，而非增加窗数 |
| 和上一栋太像 | 改变交通位置与屋面策略，重新组织房间/院子，保留硬条件与风格 |
| 水不真实 | 看池底是否被地面遮，核池深/水面/压顶，再在环境近景调透射与粗糙度 |
| 夜景不亮 | 检查发光原语是否有lightSource和initiallyOn，别只增emissive |
| 招牌看不到 | 核文字面朝向与牌面尺寸，再从主要到达方向检查雨棚/墙/柱遮挡 |

## 8. 日后语言/skill评估的验收维度

评估任务应覆盖未见过的用途/场地组合。把硬条件、JSON/Schema、引用/几何关系、空间完整性、类型特征、构造细部、材料/光景、同类差异和修订成本分别记录。单次平均分不能掩盖必须功能缺失；高构件数量不能补偿堵路和封井。

同模型、同输出预算、不同提示词进行对照；至少保留原始输出与失败稿。视觉最好使用同一引擎/相机/灯光比较，并由人看图。是否迁移成skill取决于真实瓶颈：重复查字段可结构化查表，重复算洞可工具化，重复漏功能可检查设计事实；不能仅因为文档变长就加入更多Agent节点或重试次数。
