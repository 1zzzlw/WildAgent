# P2：统一审核预览与编译解析

状态：代码已完成，运行验收由用户负责。见 [P2-P2A-P2B-执行记录.md](P2-P2A-P2B-执行记录.md)。前置：P1。目标：用户审核的可执行设计与实际生成使用同一份几何解释。

## 可直接使用的提示词

```text
请实施 WildAgent 建筑生成优化 P2。先读 docs/10月7日优化/03-Agent执行总约束.md，并核对 P1 的实例往返与修订结果。

已知现象：app/design/resolver.py::resolve_design 与 app/agent/generation/architecture/facade.py::resolve_facade_layout 各自计算门窗。历史样本的审核门宽 3.72m，成品门宽 1.1m。不能仅把两个常量改成相同值。

实施步骤：
1. 画出 document → resolve → preview 与 approved document → plan → skeleton/facade → compile 的调用路径，找出尺寸、宿主、标高和槽位被重复计算的位置。
2. 确定共享解析入口：优先抽取现有可复用纯函数，或让预览投影当前编译解析结果。不要在 resolver 和 compiler 间制造循环依赖，也不要仅为了统一而新增大型 IR 框架。
3. 解析结果至少能标识 design revision/hash、实际宿主、槽位 ID、局部尺寸和位置、必要的派生来源。仅存确有消费者的数据。
4. 审核 SVG 从同一解析结果投影；编译消费同一结果，不能再次按另一公式决定门窗大小。透视/投影差异允许，物理尺寸和实体选择不能不同。
5. 明确 architecture_plan、resolved_design、design_brief 的权威关系。旧调用点可通过适配读取共享结果，逐步去掉重复计算；不要一次删除所有旧字段。
6. 设计变化后使依赖解析结果失效；不能把新文档与旧 resolved_design 一起使用。历史 checkpoint 的缺版本处理必须明确，禁止默认为有效缓存。
7. 保证编译无网络、无模型调用，重复输入产生稳定结果。若需要解析版本，只引入实际用于一致性校验的最小版本字段。
8. 检查 merge、repair 和最终 normalizer 是否重新改变已解析尺寸；有变化时记录并触发对应一致性验收，不允许在末端再次漂移。

测试矩阵：
- 矩形、L 形、逐层不同体量，门窗槽位与最终实体逐一匹配。
- 检验坐标系转换，不能直接拿墙局部坐标与世界坐标比较。
- 审核解析与成品宽高、宿主、层标高一致；容差使用项目已有定义。
- 显式实例与默认槽位分别覆盖，不让“默认正确”掩盖“实例被覆盖”。
- 改一处立面后旧解析被拒绝或重新计算。
- 连续编译两次一致；旧设计文档和物件链可读取。

相关入口：app/design/resolver.py、compilation.py、preview.py、repository.py、review_outcome.py，app/agent/nodes/compile_node.py（薄入口），app/agent/design_flow/compile.py、review.py，app/agent/compiler/compile.py，generation/architecture/facade.py、skeleton.py，generation/assembly/workflow.py，validation/workflow.py。路径以当前重构后的源码为准。
若涉及前端类型或 SVG 消费，追踪实际消费者并更新，不只修改后端快照。
验收时展示同一个门窗的“设计 → 审核解析 → Blueprint”数值对照，不以截图大致相似替代数值验证。
```

## 与新增阶段的交接

本阶段仍是 P1 后的下一步，不新增设计规划循环，不以 SVG 美化为目标。交付共享解析入口、设计版本和实体/宿主映射，供 P2A 的缺口检查使用。暴露可定位到设计路径的解析缺陷；不要在 P2 中另建需求账本。测试由用户运行，提供同一实体的数值对照方法。
