## 做了什么

**核心判断**：`evaluate_design`（P2A）判的是**设计层字段**（`/decisions/massing/floors` 写了 2
就判 satisfied），它证明"设计文档里这么写了"，**不证明蓝图里真的长出两层**。编译降级、修复环改动、
宿主解析失败都会让实体偏离设计。所以同一条要求需要两份证据，且设计层通过**不能**复制成最终通过。

## 关键设计决定

1. **履约不进几何门禁**。`pipeline_results` 喂的是 `prepare_blueprint_delivery` 的保存门禁
   （含 `WARNING_GATE_MAX=20`）。多塞一条就可能把"合法但不完整"变成"不许保存"，与 P4
   「合法但不完整的产物可按既有政策交付并展示缺口」相反。所以履约只进快照、State、诊断与回复文案，
   `geometry_blocking` 字段恒 `False`。
2. **不新建要求系统**。要求集合就是 `DesignDocument.constraints`（P2A），状态枚举复用 `DesignGap`，
   缺口 id 用 `gap.impl.*` 与设计层 `gap.*` 区分。
3. **`superseded` 不计入缺口，只单独计数**。显式取代（有 `source_quote` + 修订原文校验）不是
   "默默删掉"，混进缺口会虚高未兑现率；完全不记又会让取代不可见 ⇒ 进 `superseded` 计数。
4. **满足率只统计"能判定"的条目**：`satisfied_ratio` 分母是 `satisfied + open`，
   `needs_review` / `unsupported` 单列，不混进分母也不混进分子。

## 实体侧判据（逐路径）

| 设计路径 | 判据 | 说明 |
|---|---|---|
| `massing/floors` | 楼板实体标高数 | `representation_mode != full`（示意）时 `needs_review` |
| `massing/width` `depth` | **墙体**包围盒跨度 | 🔴 屋顶/阳台**不参与**：出檐本来就外扩，算进去会让该要求永远不满足 |
| `massing/floor_height` | 相邻楼板标高差 | 少于两层时 `needs_review` |
| `roof/type` | 所有 roof 实体的 `roofType` 集合 | 无屋顶实体 ⇒ `open`；其余字段（如 `overhang`）`unsupported`，注明属 P5-A |
| `facades/<面>/bays` | **逐层**开口计数 | `bays` 是每层槽位数；层高取宿主墙底标高（开口自身 `from[1]` 带窗台高，取整会漂）。面的朝向由几何推导（轴对齐墙 + 包围盒中心），推不出时 `needs_review` |
| `circulation/vertical_strategy` | stair 实体有无 | |
| `component_quota/<类型>/min\|max` | 该类型实体计数 | |
| `required_components` | 逐类型实体存在 | |
| `components/<i>/*` | — | 🔴 `needs_review`：实例级宿主/位置证据需要**实例→实体 ID 映射**（`compile_report.instance_entities`），当前只有类型级证据，不足以判定 |
| `volumes` / `structural_grid` / `materials` | — | `needs_review`，理由写明依赖尚未建立的映射；**按红线不做文案关键词匹配** |
| `check="manual"` / `adoption="proposed"` | — | `needs_review`，与设计层同口径 |

## 验证

- 新增 14 条用例（`tests/design/test_fulfillment.py`）全绿，**全部用真实 `compile_document` 产物**：
  - 设计层 satisfied、实体被改（roofType gable→flat）⇒ 履约 `open`，`actual == ["flat"]`；
  - 合法几何 + 屋型不符 ⇒ `open` 但 `geometry_blocking is False`；
  - 修复环把宽度腰斩 ⇒ `open`，`actual == 9.0`；
  - 出檐不破坏 width 要求（`_bbox` 只取墙）；
  - 两层住宅 front 每层 3 槽位判 satisfied，拆掉一层一个开口后判 open；
  - 实例级要求 `needs_review`（不冒充通过）、`manual` → `needs_review`、未知字段 → `unsupported`；
  - 无要求 ⇒ `total == 0` 且回复不出现履约字样；
  - `superseded` 单独计数、不进缺口；
  - 交付文案含"设计履约 1/2 已兑现"与具体缺口，但 `validation.errors` 仍为 0。
