## P7 使用入口

以下命令由用户按需执行，本次没有执行。工作目录为 `wild-server`，使用项目 Python 环境；截图脚本还需要 wild-web 已安装依赖、支持全局 WebSocket 的 Node 版本，以及 Chromium。

```powershell
# document.json 为导出的 DesignDocument，不是 .wild 蓝图。
python -m app.agent.vision.workflow document.json .workbuddy/vision --chromium "C:\path\chrome.exe"
```

每次命令创建独立运行目录，保留文档、编译诊断、蓝图、四张截图、render_manifest、proxy 和 human_review 模板。模板逐项填写 `status`、`issues`、`viewEvidence`（front / side / top / perspective）、`relatedFields`（例如 decisions.facades）、`confidence`、`suggestion`，完成后设置 `complete=true`。不要修改 render 中的输入和源码摘要。

```powershell
python -m app.agent.vision.workflow document.json .workbuddy/vision --review "上次输出目录/human_review.json" --chromium "C:\path\chrome.exe"
```

该入口一次最多请求一轮候选。候选图纸、蓝图、截图和评价模板单独留档；**原图的人工意见不会套用到新候选上**，新候选待再次看图。候选通过后还需走现有设计审核/批准入口，命令不写会话、不批准、不覆盖场景。自动修订函数自身最多两轮、四次设计块调用，模型等待受时间预算限制；离线渲染子进程另有 90 秒上限。

```powershell
# 生成固定任务、三个组、每项三次的记录模板。
python -m app.agent.vision.report .workbuddy/vision/records.json
# 填写实际运行的结果、证据、成本和截图路径后汇总。
python -m app.agent.vision.report .workbuddy/vision/report.json --records .workbuddy/vision/records.json
```

模板中的 `failureType=not_run` 表示未运行，不算样本。实际运行后填写失败类型，成功可设为 null。判据在 `requirements.*.criterion`，只有附带证据的 satisfied/open 参与可判定项满足率；unsupported/needs_review 单列。三组使用相同需求、WILD 协议与能力资料、渲染配置和验收口径；通用 Agent 的产物由真正的外部通用 Agent 提供。汇总程序不替人证明证据真实性，也不生成通用 Agent 的替代样本。

## 第二轮：代码质量与职责复核（2026-10-09）

结论：既有分层可以保留，但补丁规则重复、完成状态误判、重复编译与可变缓存不符合可靠性要求；本轮直接重构这些实际调用路径。

- **P3 / P7 共用补丁入口**：新增 `architecture/revision_patch.py::apply_design_patch`，统一块权限、约束保护、归一化越权检查、锁定字段和无变化拒绝。返回候选及归一化/派生记录，不修改调用方 patch，也不承担编译和采纳决策。两个流程删除各自重复实现。
- **P3 完成证据**：缺口只有明确变为 satisfied 才算关闭；变为 unsupported / needs_review 或消失不算完成。原先满足的要求若消失同样拒绝候选；历史任务在后续版本失去证据时标记 invalidated。
- **P4 判据一致**：required_components 的 contains 使用单个类型成员，与设计侧检查一致；空数组不能虚报成功。数量上限检查拒绝非数值、非有限值和不支持的判据；min 表达下限而非精确数量。
- **P5 迁移边界**：旧文档迁移先检查 decisions、facades、pattern 和 rule_trace 的数据形状；畸形输入交给契约校验，不在迁移中因直接调用 items/get/append 而崩溃。逐体量屋面仍仅支持现有可分段屋型，修正文案与实际回退行为不一致之处；复杂局部屋面不是本轮已新增能力。
- **P6 缓存所有权**：schema 和能力查询返回独立副本；能力快照一次加载同时返回数据与失败状态。合法空能力面可缓存，刷新失败清空旧能力，失败不缓存，下一次查询重试；不通过第二次 schema 加载猜测第一次查询是否失败。
- **P7 每版本编译一次**：渲染、编译错误统计和履约检查复用同一次编译；基准履约结果只在采纳候选时更新。候选缺少完整评价时留档并返回 review_required，不继续重复生成待审核候选。预算先收紧再进入流程，提前返回的诊断也采用实际预算。

本轮未运行测试、语法/类型检查或真实渲染，只做源码复核和定向 diff 空白检查。运行效果仍由用户验收，不能据此宣称 P3—P7 已经全部通过验收。优先验收：跨块越权补丁、满足项消失、缺口从 open 变 needs_review、能力刷新失败后恢复，以及候选缺少评价时的停止行为。
