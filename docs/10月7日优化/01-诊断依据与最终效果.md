- **当前源码事实**：2026-10-07 工作区中可定位的数据路径、字段和规则。
- **待验证判断**：对最终视觉效果、发生频率和性能改善的推断。

## 2. 历史 trace 确认的问题

用户只输入“生成一个别墅”。不能将模型自行选择的退台、平屋顶称为用户明确要求；但这些选择一旦作为方案展示和批准，就应与后续产物保持一致。

| 阶段 | 数据 | 意义 |
|---|---|---|
| 原始模型输出 | 主楼、底层侧翼、上层收缩侧翼；两块 flat 屋顶 | 模型提出了体量层次 |
| 归一化后 | 两个均覆盖两层的 L 形体量；统一 gable | 退台和屋顶意图发生变化 |
| 设计说明 | 仍声称有侧翼退台、屋顶露台和两块平屋顶 | 文案与结构化决策不一致 |
| 审核解析 | 主入口门宽 3.72m、高 2.4m | 审核视图中的尺寸 |
| 实际槽位与最终门 | 宽 1.1m、高 2.318m | 同一设计被再次解释 |
| 最终状态 | complete，0 个校验错误、1 个警告 | 当前检查通过，不等于设计完整实现 |

原始输出并不正确：同层体量存在重叠，roof 数组也与接收协议不一致。优化目标不是照单全收错误输出，而是带证据修订，不要静默替换设计之后继续展示旧说明。

## 3. 当前代码确认的问题

以下路径均相对仓库根目录；实施前重新核对，避免把此快照当成永久事实。

### 3.1 实例设计通路没有贯通

- `wild-server/app/design/contracts.py` 的 `ArchitectureDecisions.components` 已有实例表达，包括 host、size、form、material_role。
- `wild-server/app/agent/generation/architecture/design_blocks.py` 的 components 块只声明 `component_quota`。
- `design_workflow.py::_pick_block_fields` 丢弃块字段之外的内容。
- `app/design/resolver.py::build_design_document` 未传入 components。
- 同文件 `architecture_plan_from_document` 未返回 components。
- `app/agent/compiler/compile.py` 已有实例覆盖相关实现。

结论：不能只看 Schema 或编译器宣称“已经支持具体构件设计”；正常生成与审核往返没有完整接线。

### 3.2 修订上下文缺失

`generation/architecture/convergence.py` 调用 `draft_design_blocks` 时没有传入现有草稿；后者内部从空 dict 起步。只修屋顶或立面时，缺陷说明不能替代原始体量、宿主和尺寸。事后合并旧草稿无法弥补模型起草时的上下文缺失。

### 3.3 审核和编译各算一套

`app/design/resolver.py::resolve_design` 按开间比例算抽象槽位；`generation/architecture/facade.py::resolve_facade_layout` 又计算实际门窗。普通窗存在宽度上限 2.2m、高度上限 1.55m，门采用另一套默认尺寸逻辑。两个阶段均有合理局部目的，但缺少共享的最终解析结果。

### 3.4 默认规则承担了部分设计职责

`RoofDecision` 主要提供 type、ridge_axis、overhang；`FacadeDecision` 主要提供 bays、ground_pattern、upper_pattern。代码中另行决定部分尺寸与比例。

分块契约把某层全 empty 同时用来表达“开敞无墙”，混合了“无开口”和“无围护墙”的含义。层次丰富的建筑因此难以被准确表达。

### 3.5 验收目标不足

`app/agent/validation/workflow.py` 基于几何与设计清单检查决定 complete/partial。它不能直接证明自然语言设计意图全部实现，也没有完整的视觉质量评价闭环。

### 3.6 材质设计受资产目录影响

`generation/material_workflow.py` 在没有可匹配 PBR 资产时跳过材质模型调用。历史 trace 中也确实发生。此策略节约时间，但把无贴图情况下的颜色、粗糙度与角色组合设计一并弱化了。

## 4. 已有改进不能忽略

当前建筑主链已经增加设计分块、块级检索、编译试算、设计收敛、审核后的确定性编译；旧的建筑类型档案已收缩为 custom。因此不能按旧 trace 推断“目前每扇门窗仍必须模型生成”，也不能把恢复旧 FloorPlanIR 架构作为默认方案。

正式 docs、README、skill 中可能存在过时拓扑。以当前 `app/agent/graph.py` 的实际连线和调用实现为准。

## 5. 最终期望效果

| 方面 | 当前风险 | 优化后可观察行为 |
|---|---|---|
| 设计保真 | 文字丰富、结构化输出退化 | 明确选择的退台、屋顶、开口在成品中有实体证据 |
| 审核可信度 | 审核尺寸与成品不同 | 审核预览和编译使用同一解析结果 |
| 差异化 | 多数细节取相同默认值 | 不同设计决策带来相应几何差异，而非随机扰动 |
| State | 多份对象各自解释设计 | 权威设计、派生视图、实际产物、验收结果职责清晰 |
| 修订能力 | 局部修订缺上下文或改动其他部分 | 修改目标明确，依赖重算，无关决策保持 |
| 材质 | 无资产时退回固定组合 | 无贴图也可落实明确的材质角色与参数 |
| 交付 | complete 容易被理解为需求全满足 | 几何有效、设计履约、视觉评价分开报告 |
| Agent 优势 | 无公平基线 | 在相同约束下比较符合度、效果、成本和稳定性 |

不能预先承诺“全面超过通用 Agent”。第一目标是在 WILD 约束下更稳定、更忠实、更可编辑；视觉质量通过真实对照决定。新协议无法创造引擎尚未实现的几何能力，缺失能力应明确记录。
