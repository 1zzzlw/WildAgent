# P3：归一化来源与批准边界执行记录

日期：2026-10-08。代码实现完成，运行验收由用户负责。未运行 pytest、语法检查、构建、类型检查、真实生成或渲染。仅做源码调用链和 Git 差异核对；没有提交、推送或部署。

基线为结构重构后的工作区，包含用户正在进行的形制标签、实例宿主、材质角色、JSON 提取等修改。本阶段在现有修改之上实施，未回退这些修改。

## 1. 行为变化

- `planning.py` 保留现有契约允许的显式尺寸及精度、建模层数、tiers、最多 8 个体量、最多 32 个立面/结构开间。没有扩展 Schema；修正的是归一化比契约更窄的范围。一个字段非法时不会因此丢掉其他合法 massing 字段。
- 显式立面 pattern 不再被幕墙默认分格替换，也不因默认入口策略插入门；各面显式入口索引保留。显式细部清单不再因为幕墙条件把 bay_window 替换成 light；沿用契约的 20 项边界。缺失值仍有默认，关系不合法的降级仍留证据。
- 正交体量保留原坐标，复用骨架既有 `_resolve_union_wall_segments` 联合外轮廓。没有自动推移、删除重叠体量。楼板、屋顶、宿主等是否有效仍由编译与校验决定；不把外轮廓可求并集等同于整个建筑等价。无法证明等价时保留原设计并交有界修订，不另造通用体量分解器。
- 单项 roof 数组可无损迁移为对象。多项数组、未知屋顶类型先由设计块契约反馈给已有重试；裸计划仍需降级时保存 before/after，不假装支持逐体量多屋顶。
- 设计说明增加从当前结构化值生成的 `[决策事实]` 摘要。语义变化未解决时，原理由与概念标记 `[待核对]`，不继续作为成品事实宣传。
- `compile_document` 明确传入已解析文档；编译器和骨架不再对文档重跑归一化、不再按原请求覆盖批准尺寸。历史裸 plan 入口保留一次归一化及诊断。
- 解析版本升级为 `compiler-projection/2`，旧版本批准结果走既有重新审核路径。归一化证据纳入设计 hash，避免同一决定内容搭配过期缺口证据。

## 2. 规则分类与处理

| 位置/字段 | 触发与来源 | 分类 | 结果与证据 |
|---|---|---|---|
| planning：shape/type 大小写、单项 roof 数组 | 已有值存在等价协议表达 | 协议规范化 | 等价大小写/单项包装转换记 protocol；未知类型不归此类 |
| planning：massing、roof、facades 等缺失字段 | 模型未提供，读取现有 fallback/profile | 缺失值默认 | default；before_exists=false，after 为实际补值 |
| planning：非法尺寸、楼层关系、pattern | 显式值不满足契约或关系 | 设计语义变更 | 优先块级重试；必要降级记原值、结果、字段和规则；进入缺口检查 |
| planning：请求尺寸/形状覆盖模型值 | 现有请求解析规则 | 设计语义变更 | 不称为几何必需；仅能与已核对原文的采用约束对上时标 user，否则保持 model/unknown |
| planning：门窗配额、required_components、representation_mode | 立面 pattern、屋顶与建模层数 | 程序派生 | derived；若覆盖显式值仍 semantic_change=true，不能用分类掩盖冲突 |
| planning：楼层缺口修复、重复 ID/非法体量回退 | 当前文档要求楼层覆盖、ID 唯一 | 设计语义变更 | 局部或整组 before/after；不把修复后的方案冒充原始意图 |
| skeleton：联合外轮廓、楼层到标高 | 既有正交体量与层高 | 确定性几何派生 | 保留输入体量；仍受同一编译/预览及最终校验约束 |
| facade：槽位门窗默认宽高、阳台尺寸、屋顶范围 | 现有宿主、pattern 和槽位算法 | 派生与默认设计选择 | 不宣称全部是物理必要。实际实体由 P2 展示；模板无法落实显式实例 size 时新增字段级 implementation/unsupported 缺口，扩展能力留 P5 |
| compiler：实例 form/host/size | 既有实例覆盖层 | 协议映射或有损实现 | 沿用 form_ignored/dropped/host_fallback；增加 size_changes，保留期望值、实际值和实体 ID |
| resolver：materialId → role | 当前材质方案同一绑定 | 协议规范化 | 同材质别名转换为 protocol；不存在的角色清空为语义变化并留证据 |
| blueprint_normalizer：字段剥离、厚度/位置修复、材料补值、实体删除 | 当前交付修复函数 | 缺省或潜在语义变化 | NormalizeReport.changes 提供实体/字段 before/after；未经等价性证明的显式改写按语义变化保守记录 |
| validation：批准后的实体/材质变动 | 当前文档的共享编译结果与待交付产物对比 | 批准边界检查 | 已有字段变化或实体缺失产生 error；新执行实体/新字段不作为改写，数值容差 0.001 |

分类描述的是规则责任，不声称全部旧规则已被删除。保留规则一旦改变显式设计必须有证据。

## 3. 数据传递与消费者

没有新建 State 真相对象，复用现有诊断及 RuleTrace：

1. `normalize_architecture_plan(..., normalization_changes=...)` 输出字段变化。architecture_diag 同时保存 raw_plan、normalized_plan、used_fallback、used_local_fallback；整案 fallback 不再清空原始草稿。
2. 文档 `rule_trace[].changes` 归档证据并关联既有 constraint ID；`design_revision` 指出证据产生版本。字段包含 path、before/after、存在标记、rule、category、input_source/output_source、semantic_change、reason、constraint_ids。
3. `evaluate_design` 按当前版本重查证据。仍保留降级值且有可写路径的语义变化形成 open 缺口，进入 P2B；派生冲突/不能定位的变化保留 needs_review。后续设计改变原降级值时旧事件不再作为当前未解决问题；原 constraints 独立检查，expected 不被降低。
4. 完善循环每轮及被拒绝补丁记录 normalization_changes，文档保留历史证据；probe 回执也显示变化，不能只显示“可编译”。
5. 编译 `summary.instance_size_changes`、解析的 implementation/unsupported 缺口展示当前模板忽略的实例尺寸。它们不通过伪造目标完成来消失。
6. `merge_diag.normalization_changes` 记录交付归一化；`merge_diag.approved_design_changes` 保存批准后差异。最终检查位于几何缓存之外，错误仍走现有禁止交付规则。

字段记录示例（说明结构，并非真实运行结果）：

```json
{
  "path": "/decisions/massing/floor_height",
  "before": -1,
  "after": 2.4,
  "before_exists": true,
  "after_exists": true,
  "rule": "architecture.normalize.massing",
  "category": "semantic_change",
  "input_source": "model",
  "output_source": "program",
  "semantic_change": true,
  "reason": "尺寸、楼层或形状的显式值不符合约束，或与请求解析冲突",
  "constraint_ids": ["choice.massing.floor_height"]
}
```

设计路径采用 JSON Pointer；Blueprint 诊断中的 elements/components 使用实体 ID 定位，而不是可直接提交为 JSON Patch 的数组下标。

## 4. 用户验收

新增 `tests/design/test_normalization_evidence.py`：缺失/非法/合法维度、无损屋顶迁移、非法屋顶块反馈、合法值与 tiers 保留、显式立面、重叠体量保留、重复归一化、关联决定和缺口、逐实体修复证据、批准后删改与材质变化、数值容差、新实体、文档编译边界、实例尺寸缺口展示。

用户可在 wild-server 执行（Agent 未运行）：

```powershell
uv run --no-sync pytest tests/design/test_normalization_evidence.py tests/design tests/agent/test_design_blocks.py tests/agent/test_design_completion.py tests/agent/test_design_convergence.py tests/agent/test_design_review_version.py tests/components/test_architecture_plan.py tests/compiler
```

前端有 RuleTrace 类型增加，用户另在 wild-web 执行 `npm run build`。

真实生成重点看：

- 给合法小数尺寸，观察 raw_plan → normalized_plan → document 是否保持；原请求与修订尺寸不同的审核文档，编译不得改回原请求。
- 给非法屋顶/层高，观察块重试证据；降级后审核必须可见问题，不能只出现 used_fallback=false。
- 局部改屋顶，其他尚未解决的归一化证据仍保留；关联 expected 不改变。
- 有重叠体量时，确认联合轮廓、楼板和屋顶实际几何；归一化不通过移动体量“消错”。
- 已批准实体被末端修复改变时，检查 approved_design_changes 及 error 状态；不允许直接加载为成功产物。

## 5. 限制与后续

批准后检查是保守的已有编译实体变更守卫，不是完整 P4 履约系统。合法拆分、实体改名等拓扑替换，当前没有等价性证明时也可能被报告；需要实际样本决定是否补通用等价判断，不能直接关掉检查。新构件是否满足所有需求、自然语言含义与视觉质量仍由后续阶段覆盖。

tiers 保留不等于引擎新增收分能力；某些模板实例尺寸仍不能覆盖实际槽位，现已显式报告 unsupported，P5 再扩展端到端表达。无资产材质设计仍属于 P6。
