# P2B：审核前设计完善循环

状态：代码已完成，运行验收由用户负责。见 [P2-P2A-P2B-执行记录.md](P2-P2A-P2B-执行记录.md)。前置：P2、P2A 代码与接口已具备，用户测试结果单独记录。目标：发现设计遗漏后，动态安排有依据的设计任务并修订当前图纸；不靠增加构件数量体现“精细”。

## 目标职责图（待实现）

```text
用户意图 → architecture 初始方案 → 材质初稿
                                  ↓
                 评价设计缺口与编译可行性
                    ↓ 有可处理缺口
                 规划设计任务 → 局部修订
                    ↑____________↓
                                  ↓ 无缺口或达到停止条件
                         展示当前图纸与剩余缺口
                                  ↓
                              人工审核
                                  ↓
                         确定性编译 → 执行规划/修复
                                  ↓
                              最终履约验收
```

SVG 只是当前设计的展示，不承担规划。最终履约完整能力由 P4 接入；本阶段沿用现有最终校验并保留缺口，不宣称已经实现 P4。

## 可直接使用的提示词

```text
请实施 WildAgent 建筑生成优化 P2B。
先读 docs/10月7日优化/03-Agent执行总约束.md、P2A-设计决策与缺口契约.md 和对应执行记录。P1 已完成，测试由用户负责，不运行测试、真实生成或构建。

步骤 1：核对职责并选择最小接入点
阅读 graph.py、nodes/design_convergence_node.py、generation/architecture/convergence.py、design_workflow.py、workflow.py、design_review、plan/workflow.py、expand.py、replan.py。
优先扩展现有审核前收敛入口，用内部任务循环复用块修订，不默认新增多个图节点。说明编译错误修订和设计补全各自的触发与终止条件。
保留审核后的 plan/execute/replanner 作为实现已批准设计的执行机制；不能简单移动旧 plan，也不能让它静默改批准方案。

步骤 2：从缺口规划任务
读取 P2A 当前版本的设计缺口、有效决定、现有能力、当前设计和预算。
仅为可处理缺口创建任务；任务关联 gap/decision ID、目标块、允许写字段、依赖和可验证完成条件。
用户未要求且没有采用决定的装饰，不作为必补项。模型可以提出有依据的设计完善建议，但不能无限扩张需求；模糊意图标待审，不自行制造硬要求。
同一缺口去重；依赖体量的宿主与立面任务排在体量修订之后。对同一块/字段的并发写冲突串行处理。
新增任务按设计问题拆分，例如“修正上层体量关系”，不局限于“再生成 window 类型”。能力不足保留 unsupported，不派发注定无法执行的任务。

步骤 3：执行设计补丁
复用 P1 的 current_plan、批次快照与块级合并。执行器读取当前有效设计和相关决定，返回限定写入范围的增量。
校验任务基准版本与写入范围，越权或过期补丁拒绝并重新评价；不把整份模型输出无条件覆盖当前图纸。
编译修错沿用保守修订边界；设计补全允许在当前契约和用户范围内修改相应体量/立面等，不能沿用“禁止任何新增体量”的提示词又宣称支持补全。两类任务明确分开。
任务引起材料角色或宿主变化时，使相关解析/材质绑定失效并刷新受影响内容。复用现有材质工作流，不在此提前实现 P6 的完整材质策略。

步骤 4：重新评价后才能关闭任务
每批有效补丁合入后更新设计版本，刷新 P2 解析，运行现有编译试算及 P2A 设计缺口评价。
工具成功或模型返回 completed 只表示执行返回；完成条件满足且证据属于当前版本才关闭缺口。
新发现的、可定位的关联缺口可以新增任务。旧缺口关闭后若关联设计变化必须重新检查。
同类构件已经存在，不证明全部设计目标满足；不要把 expand.py 按类型过滤结果作为设计补全依据。批准后类型过滤的完善只针对明确实现缺口，避免重复生成与本阶段越界。

步骤 5：有界停止、故障与恢复
沿用现有预算机制并明确最大轮数、模型调用、任务数与连续无进展限制，避免多个预算互不计账。可先复用现有修订轮数默认值，记录调整理由。
进展依据具体缺口的解决和有效设计变化，不能仅按任务 done 数量或缺陷总数减少判断。相同缺口反复出现应停止或报告待审，不无限重建同一任务。
模型故障、非法补丁、无能力、预算耗尽都保留最后有效设计、未解决缺口与停止原因。
没有可执行任务不等于设计全满足。延续当前审核策略，允许携带问题进入人工审核，不偷偷新增一律阻断流程；最终几何错误仍遵守不保存/自动加载的既有边界。
持久化足够的版本/任务状态支持现有 checkpoint 恢复，已合入补丁不重复应用；不建设新的通用事件存储。

步骤 6：审核与批准后的边界
审核展示本轮最终设计和未解决项，修改设计后旧审核版本不能直接批准为新版本。
用户要求修订时回到有效设计与缺口，不恢复过期 raw_plan。
批准后发现实现缺口由执行任务处理；若解决必须改变批准设计，则接回既有重新审核流程，不能在修复时偷偷改图纸。
同步正式 Agent 文档、节点说明和 trace 事件，能回答为什么创建任务、修改了什么、什么证据关闭了缺口。

交付：真实职责图、设计任务样例、预算/停止条件表、恢复与审核边界说明、必要回归用例、用户运行观察点。本阶段不美化 SVG，不扩展 P5 几何能力，不执行测试。
```

## 用户验收场景

| 场景 | 期望行为 |
|---|---|
| 可编译但遗漏可表达的明确设计要求 | 审核前发现，派发设计任务，修改后重评 |
| 编译错误且伴有设计遗漏 | 两类问题分别定位，不只修到“能编译”便全部通过 |
| 体量修订使开口宿主失效 | 下游解析和相关任务重建，不复用旧版本完成证据 |
| 模型输出无关字段或过期补丁 | 拒绝覆盖，记录原因，保留有效设计 |
| 缺口反复出现或模型故障 | 有界停止，展示剩余缺口，不伪称设计完成 |
| 中断恢复 | 不重复应用已合入补丁，不混用设计版本 |
| 用户明确不要阳台 | 不为增加精细度创建阳台任务 |
| 批准后才发现需要改变体量 | 进入既有重新审核路径，不由执行器静默修改 |

实现完成不等于建筑更美观；本阶段的核心观察点是缺口是否被正确发现、任务是否真正改进当前设计、完成证据是否可靠。实际运行与视觉结论由用户测试后填写。
