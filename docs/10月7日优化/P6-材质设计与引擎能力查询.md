## 可直接使用的提示词

```text
请执行 WildAgent 建筑生成优化 P6 的指定批次；未指定时先做 P6-A。读取 docs/10月7日优化/03-Agent执行总约束.md，核对已有材质角色与能力注册表。

P6-A：把材质设计与资产匹配分开
1. 检查 generation/material_workflow.py、material_plan.py、materials.py、prompts/planning.py 中材质提示词，以及真实素材目录加载路径。
2. 当前无 catalog 时跳过材质模型调用。改为“是否需要设计决策”和“是否有纹理资源可匹配”分别判断，不能因缺资产就无视用户材质要求。
3. 有明确合法颜色/PBR 参数可确定处理时直接处理；需要材质组合设计时在现有预算内进行一次紧凑规划。避免为没有变化的材质每次重复调用。
4. 合法参数材质可独立存在；有资源时再绑定白名单资产。禁止编造 assetId、URL 或纹理文件。
5. procedural_materials_enabled=false 必须继续生效；不要通过另一个入口绕开用户开关。
6. 复用已批准材质的条件必须与设计依赖一致：改变相关表面、材质角色或用户反馈时重新评估；纯屋顶坐标修复不能无故换全楼颜色。
7. 保留模型失败时可交付的确定性回退，但履约/诊断明确哪些材质意图未实现。
8. 将角色和分区绑定跟踪到最终实体，检验 merge/apply_resolved_material_plan 不覆盖用户显式选择。

测试：空目录+明确材质要求、空目录+组合设计、有资源匹配、非法资源 ID、程序化关闭、材质复用、反馈修改、模型失败。必须检查最终实体参数，不只看“调用了 LLM”。

P6-B：可查询的引擎能力
1. 从现有 schema、组件注册表、编译器和能力知识整理一个最小查询面。查询内容包括：类型、必要字段、可选设计参数、宿主约束、坐标语义、有效示例、已知不支持项、来源版本。
2. 可机械提取的字段从事实源生成；不能机械提取的语义保留人工维护并给来源，不要建第二份无人同步的字段白名单。
3. 优先给设计阶段提供按任务裁剪的能力信息，与现有 compile probe 共用版本和语义。不是把全部源码或整个 Schema 塞进提示词。
4. RAG 保留为协议解释、组装关系和设计知识补充。查询失败、无命中、引擎不支持是三个不同状态。
5. 若修改知识文件，先读取项目 wild-knowledge-ingest skill；复用检索评测和分片验证。没有授权不删除生产索引或更换 embedding。
6. 默认不让线上模型执行 shell 或改引擎。需要调查新能力时提供明确的开发期入口，不成为每次生成固定步骤。

测试：查询返回字段与真实注册表一致；示例能编译；不存在的能力明确返回 unsupported；知识文档版本漂移能被发现；少量用户任务能命中正确能力。
交付实际效果对照、模型调用成本变化和能力查询示例。不以 RAG 文本长度增加证明质量提升。
```

## 新增设计循环的接入要求

新增能力同时接入 P2A 的设计决定/缺口评价、P2B 的任务写入与依赖失效，以及 P4 的实体履约。原 unsupported 项只有在能力实际实现且有证据时才能重新判定；不批量改为 satisfied。代码前置需包含 P2A/P2B，用户尚未反馈的测试保留待测记录，Agent 不运行测试。
