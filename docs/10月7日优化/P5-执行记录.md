## 一、P4 缺口收尾：实例 → 实体 ID 映射

P4 主体（设计履约验收）已交付，但 `/decisions/components/<i>/*` 只能判
`needs_review`：履约层拿不到"图纸第 i 条实例落到了哪个实体"。原因是**宿主解析规则
只存在于编译器里**（`slot_*` / `wall_*_L<n>_<face>` / `roof:<volume>` / `railing:main:2`
…），履约层不该重新实现一遍——那正是"同一件事两处解析必然分叉"。

| 改动 | 位置 | 语义 |
|---|---|---|
| 编译期产出映射 | `compiler/compile.py::_compile_from_instances` | 每条实例记 `{index, declared_type, declared_host, outcome, host_intent, host_sequence, entity_id, entity_type, entity_host, entity_host_field}`，按 `index` 排序（编译循环按类型分组，原序不可用） |
| `host_intent` 判据 | 同上 | `none` / `resolved`（按原意解析到）/ `fallback`（退用第 N 条派生模板，记 `host_fallback`）。**编译器出的结论，下游只读** |
| 投影 | `compiler/diagnostics.py::CompileResult.summary()` | `instance_entities` 进摘要 |
| 履约消费 | `design/fulfillment.py::_instance_check` | `type` 比 `entity_type`；`host` 按 `host_intent` 判 `satisfied`/`open`；`size/<field>` 比实体字段；映射缺失/过期 → `needs_review` |
| 接线 | `agent/validation/workflow.py:153` | 从**同一次 compile** 的 stats 取映射与 `roof_slots` |

判据（`tests/design/test_fulfillment.py` +9 条）：

- 实例被丢弃 ⇒ `open`（不是 `needs_review`）："没做到"与"没查"必须长得不一样；
- 映射过期（entity_id 不在最终蓝图里）⇒ `needs_review`；
- 无映射 ⇒ 保留原来诚实的 `needs_review`。

## 二、P5-A：逐体量屋顶

设计层 `decisions.roof` 仍是**单块风格模板**（`type` / `ridge_axis` / `overhang`），
逐体量差异作为**可选数组 `volumes[]`** 加在同一个对象内 —— 不回到"roof 必须写成
数组"的旧形状（那个形状曾导致 3 轮重试后整块作废）。

| 改动 | 位置 | 语义 |
|---|---|---|
| 契约 | `design/contracts.py::RoofVolumeOverride` | `volume` / `type`（可空，继承模板）/ `overhang`（可空）。只允许**引擎能实现的差异**（脊高是派生量，不可表态）；体量引用完整性**不在契约层校验** |
| 逐体量解析 | `generation/architecture/facade.py::_roof_overrides_by_volume` | 同体量重复覆盖 → 记 `override_conflict`（后者生效），不静默取第一个 |
| 拆分判定 | `facade.py::_planned_roof_slots` | 逐体量解析类型后，**任一体量**落在不可拆分形制（`dome` / `chinese_pagoda` / `chinese_curved`）就整体拒绝拆分、退回单块 |
| 逐槽位形态 | `facade.py::conform_roofs_to_slots` | 槽位带 `roofType` 时覆盖模板形态；没带的沿用模板 ⇒ 与引入本特性前的产物逐字节相同 |
| 缺陷 | `compiler/compile.py::_roof_override_defects` | 未知体量 / 冲突覆盖各记一条 **warn**（编译器有兜底，按「只标记不阻断」+「契约层不能比编译器严」不得阻断） |
| 履约 | `design/fulfillment.py::_roof_volume_check` | 按槽位 `volume` 定位（不按序号约定）；`overhang` 在实体上没有独立字段 ⇒ 恒 `needs_review`（诚实不判） |

三条通道必须分清（`tests/design/test_roof_per_volume.py`）：

- `roof.type` 在声明了 `volumes` 时是**模板**；覆盖集能解释其余roofType ⇒ `satisfied`；
  出现**无法解释的第三种**形态 ⇒ `open`（测试真的注入 `hip` 来钉这条，不是比计数）。

### 四态实测（同一方案，只改一个设计变量）

| 输入 | 结果 |
|---|---|
| 主楼 `gable` + 侧翼 `flat` | `['gable','flat']`，逐槽位跨度 12.6 / 8.3 |
| 无覆盖 | `['gable','gable']`，跨度 12.6 / 8.6 |
| 覆盖写错体量 id | 1 条 `roof_override_unknown_volume`(warn)，退回模板，`ok=True` |
| 覆盖写 `dome` | 拒绝拆分，退回单块 |

pydantic `le=2` 拒收越界值 → 整条覆盖被丢；编译器0.15–0.8 的钳制只在这个区间内生效。

## 三、P5-B：围护与开口分离

`empty` 原来同时承担"有墙、这一格没洞"与"这一面这层没有墙"两件事。拆成两个 token：

| token | 语义 |
|---|---|
| `empty` | 有墙、这一格不开洞 |
| `open` | 开敞、这一面这一层不生成墙 |

| 改动 | 位置 | 语义 |
|---|---|---|
| 词表与判定 | `design/openings.py` | `OPENING_KINDS = ("door","window","empty","open")`；新增**唯一判定函数** `is_open_side(pattern)`：含 `open`，或整面全是 `empty`/`open` |
| 骨架 | `generation/architecture/skeleton.py::_open_facade_sides` | 改调`is_open_side`，不再自己重推"全空" |
| 归一化 | `generation/architecture/planning.py::model_declared_front_open` | 同上；主入口豁免也走它 |
| 迁移留痕 | 同上立面装配循环 | 整面全 `empty` 仍按开敞解释（**旧文档不能突然被封墙**），并往 `normalize_notes` 写一条说明两者语义不同 |
| 契约 | `design/contracts.py::FacadeDecision.patterns_use_legal_tokens` | 校验 **token 的类型头**（`window:swing` / `window:casement` 合法），但 `empty:` / `open:` 带形态后缀**拒收**（它们没有形态，悄悄丢掉后缀会让作者以为表达生效了） |
| 并行校验 | `generation/architecture/design_workflow.py::check_block_contract` | 同一套两条规则，证据文案同时点出两种 token |
| 履约 | `design/fulfillment.py::_envelope_check` | 只判**开敞面**（该面该层确实没有墙）；声明实墙恒 `needs_review`（"哪一格没洞"在实体上没有字段） |

### 四态实测（同一方案，只改立面声明）

| 输入 | 墙数 |
|---|---|
| 常规（每面有实墙槽位） | 8 |
| 旧写法：整面全 `empty` | 4（开敞语义保留 + `normalize_notes` 留痕） |
| 显式四面 `open` | 4 |
| **部分 `empty`**（同面混`empty` 与 `door`） | **8** ← 这条就是拆分恢复出来的行为 |

## 四、P5-C：构件实例与材质分区

### 4.1 区域/构件材质绑定

引入前材质角色**只按元素类型**分配（`ELEMENT_ROLE`），同类型的墙/柱/灯具必然共用
一个材质。引入后可按"这一类实体"单独换引用。

| 改动 | 位置 | 语义 |
|---|---|---|
| 契约 | `design/contracts.py::MaterialRegion` / `MaterialIntent.regions` | `{role, type, note}`。`type` 是**目标实体类型**（元素类或构件类） |
| 落引用 | `generation/material/plan.py::apply_material_regions` | 只改 `geometry.elements` / `geometry.components` 里 `type` 匹配的实体的 `material`，**不新增材质实体** |
| 接线 | `compiler/compile.py::_compose` 末尾 | 绑定放在**全部派生之后**（早绑会漏掉后派生的构件），结果进 `stats["material_regions"]` |
| 往返 | `design/resolver.py::architecture_plan_from_document` | 用 `exclude_defaults=True`，空`note` 不进方案 |
| 归一化 | `generation/architecture/planning.py` | 只做**形状过滤**（必须有 `role`），不解释角色闭集；**键只在非空时写入**（否则"有没有表达过绑定"变成不可判） |

两种"未生效"都只记录不阻断：`role` 不在材质方案里 / 蓝图里没有该类型实体。

### 4.2 补齐canopy / railing 的设计控制（P5-C 第一条）

引擎早已实现这两类，但图纸侧**没有任何一条通路**：

- `canopy` 分支要求派生结果带 `parentOpening` 字段，而派生链从不写⇒
  提示词教的任何宿主写法都落空，实例被静默丢弃（`outcome: dropped`）；
- `railing` 分支只按出现序取派生模板，没有派生就丢弃，且**宿主语义在提示词与
  契约里完全没有定义** —— 模型无从知道该写什么。

这就是「能力已实现却无人派发」这条独立缺陷。改动：

| 改动 | 位置 | 语义 |
|---|---|---|
| 槽位 id 解析 | `compiler/compile.py::_opening_expression` | 补 `wall_front_1:floor_1:door:1` 形式（`rpartition(":")` 会把 `:door:1` 一起吃掉，剩下的不是墙 id） |
| canopy 宿主宽容 | `_compile_from_instances` | 三种写法都认：门窗实体 id、开口槽位 id、墙 id / `<volume>_L<n>_<face>`；墙 id 走 `_opening_expression` 再取该墙上**真实存在的**门窗当遮蔽对象（注册表：雨棚必须有真实遮蔽物，否则是漂浮废构件） |
| railing 通道 | `_railing_instance_defaults`（新） | 宿主认`<volume_id>` / `<volume_id>_L<floor>` / `railing:<volume_id>[:<floor>]`，按体量边界算闭合 `path`。**世界坐标只由体量决定，图纸不写 path**（模型算不出体量边界，写出来必飘） |
| 教给模型 | `generation/architecture/design_blocks.py`（components 块契约）+ KB（`composite-components-second-batch.md` 的 canopy 段、`capability-boundaries.md` 的 3.7 栏杆段） | 宿主写法表 + "不要自己写 path" |

实测（同一方案只改一个设计变量）：

| 改动 | 实体差异 |
|---|---|
| canopy `size.depth` 1.2 → 2.4 | 只有 `depth` 变，其余字段逐字段相同 |
| railing `size.height` 1.1 → 1.4 | 只有 `height` 变，`path` 不变 |
| railing `host` `main` → `main_L1` | 路径 Y 从 6.6 → 3.4（层号真的生效） |
| 坏宿主 `no_such_wall` | `outcome: dropped` + `summary()["instance_dropped"]` 有留痕，`entity_id` 为 None |

`floor_height` 只在 `brief["realization"]` 里（brief 顶层是槽位表）—— 读错位置会静默退回 3.2默认值。
