# P0：建立基线与数据契约地图

状态：历史/静态基线完成，真实生成基线待环境恢复。见 [P0-基线记录.md](P0-基线记录.md)。前置：无。

## 可直接使用的提示词

```text
请执行 WildAgent 建筑生成优化 P0，只建立诊断与验收基线，不改变生产生成行为。

先读 docs/10月7日优化/03-Agent执行总约束.md、01-诊断依据与最终效果.md、02-实施路线与验收.md。

任务 A：核对当前实现
1. 读取 app/agent/graph.py、state.py，定位 architecture、material_plan、design_convergence、design_review、compile、plan、execute、replanner、final_validate 的实际函数。
2. 沿函数调用追踪 architecture_plan、design_document、resolved_design、design_brief、components、material_plan、compile_report、final_blueprint。
3. 为每个字段记录生产者、直接消费者、传入模型/计算函数的实际内容、覆盖点、权威版本、验收者。
4. 特别区分节点返回的局部更新、合并后的 State、事件和模型上下文；不要因节点没有返回某字段就断言字段丢失。

任务 B：核对已发现的断点
1. 检查 components 块字段、_pick_block_fields、build_design_document、architecture_plan_from_document。
2. 检查 converge_design → draft_design_blocks 的现有方案上下文。
3. 比较 resolve_design 与 resolve_facade_layout 的门窗计算。
4. 检查默认屋顶、体量回退、材质无资产分支、final_validate 的成功条件。
5. 每个问题给出当前函数证据；已修复的问题只记录验证结果。

任务 C：建立最小样本
1. 从两份用户 trace 提取必要的 raw_plan、normalized_plan、review slots、实际 slots 和最终门/屋顶，不复制整份 7MB trace 入仓库。
2. 验证它们属于同一线程的审核前后，不当作两个实验样本。
3. 建立合法的最小实例设计样本、局部修订样本和预览/编译一致性样本。历史 raw_plan 不合法的部分不能直接当作期望输出。
4. 在现有 tests/fixtures 或相关测试模块中放置必要的小样本。阶段输出可以记录当前失败，不要写永远断言“错误行为应该存在”的永久测试。

任务 D：留下后续能复用的证据
1. 记录 commit、dirty 状态、测试环境、模型/引擎版本可用信息，不泄露凭据。
2. 按路线文档选择首批 3 个真实生成任务；环境不可运行时将运行列为 pending，不伪造结果。
3. 生成 docs/10月7日优化/P0-基线记录.md，附字段表、问题列表、最小样本位置、实际命令和结果。

验收：每个已确认缺陷都有输入、发生位置、输出变化和影响；历史事实与当前事实分开；后续 P1 可以直接使用这些夹具。
本阶段不重命名 State，不改节点路由，不增加 RAG 文档，不调整模型。
```
