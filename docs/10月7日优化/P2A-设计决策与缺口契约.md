# P2A：设计决策与缺口契约

状态：代码已完成，运行验收由用户负责。见 [P2-P2A-P2B-执行记录.md](P2-P2A-P2B-执行记录.md)。前置：P2 的共享解析入口与版本映射。P1 已完成，不重复实现。目标：让设计想法成为可追踪、可判定、可交给任务处理的决定。本阶段不启动自动设计循环。

## 可直接使用的提示词

```text
请实施 WildAgent 建筑生成优化 P2A。
先读 docs/10月7日优化/03-Agent执行总约束.md、01-诊断依据与最终效果.md、P2 执行记录和本文件；核对当前源码，不按旧 trace 复原旧架构。测试由用户执行，不运行测试或构建。

步骤 1：先建立字段责任表
沿 graph_state.py、app/design/contracts.py、resolver.py、architecture/workflow.py、design_workflow.py、design_blocks.py、design_review 和 plan 路径扫描。对需求、决定、设计文档、派生解析、缺口和任务列出：现有字段、唯一写入方、读取方、持久化位置、版本和失效条件。
复用 requirements/constraints/locks 和已有诊断结构。不要创建第二份独立设计真相；State 只持有实际需要跨节点传递的数据或引用。

步骤 2：保存可执行决定
architecture 输出初始结构化设计时，同时关联需求与采用的设计决定。
最小信息：稳定 ID、来源（用户明确要求/模型设计选择/默认或未知）、目标对象与设计路径、期望值或关系、采用状态、验证方式。字段名以现有契约为准，别为每个概念增加一个顶层对象。
保留简短依据，不保存模型原始思维链。模型提出的露台不能伪称用户硬要求。
“待定”“已采用”“被明确替换”必须可区分；被替换的决定保留关联原因，不能直接消失。用户要求不允许模型自行撤销。批准后的选择遵守现有冻结边界。
说明文本根据当前有效决定生成或标记已失效，避免结构化设计变化而旧文案继续承诺。

步骤 3：实现最小设计缺口评价
输入用户要求/采用决定、当前 DesignDocument、P2 共享解析及现有能力信息；输出可定位的缺口。
至少区分：设计未明确或关系冲突、设计已明确但实现缺失、执行失败；本阶段只实现审核前设计评价所需部分，最终实体检查留给 P4。
每条缺口包含稳定身份、关联 requirement/decision ID、当前设计版本、expected、actual、设计路径/对象证据、可处理状态与原因。
先覆盖现有协议支持的明确层数、体量关系、屋顶类型、开口/实例宿主和材质角色，按实际能力选出能可靠判断的最小集合，不在本阶段扩展新几何 Schema。
确定性关系由代码判定；语义提取或难以确定的关系可由模型提出候选，但无可靠证据的项目标 needs_review，不冒充机器判定。
不支持标 unsupported，未知不等于 satisfied；完整性检查不等于审美评分。

步骤 4：定义任务契约与写入边界
设计任务最少说明：解决哪个缺口、依据的设计版本、目标块/允许写入字段、依赖、完成条件和状态。复用现有任务机制中适用的字段，但先核对 PlanDocument 的 op/状态/执行器假设，不能直接塞入未知 op。
本阶段只定义后续 P2B 实际需要的契约和检查接口，不启动执行器。若复用旧执行计划会混淆批准边界，采用最小独立设计任务结构并说明原因，不建立通用任务平台。
明确修改体量后宿主、开口、材质关联及解析结果的失效关系；旧版本任务补丁不得无条件覆盖新文档。

步骤 5：兼容与可观测性
旧文档没有决定记录时保留读取能力：仅从已有可靠结构化数据生成派生记录并标来源，不回填成“用户明确要求”。缺少可靠意图标待审。
复用当前事件/trace 机制，展示需求 ID → 决定 → 缺口 → 后续任务的关联；不在每次调用里复制完整 State。
列明每个新增字段的真实消费者；本阶段缺口评价实际接入审核前诊断/展示，但不自动修改设计。不能仅定义类而不接线。
同步正式 Agent 文档中的新契约；区分已实施和后续计划。

交付：字段责任表、最小契约、接入的设计检查入口、旧文档迁移说明、一个机器可读缺口样例、必要回归用例和用户验收步骤。报告代码完成与运行待测，不运行测试。
```

## 用户验收样本与观察点

1. 用户明确两层，当前设计一层但可编译：报告设计缺口，关联原要求，不改 expected。
2. 模型提出某种屋顶并采用，设计字段缺失或不同：能关联到决定；不能仅因文案提及就判满足。
3. 只说“别墅”：不自动判“没有露台”是用户要求失败。
4. 明确要求暂不支持的逐体量屋顶：记录 unsupported，不静默改成统一屋顶后宣称满足。
5. 修订生成新版本：旧缺口证据和任务基准不能继续作为当前完成证据。
6. 旧 checkpoint：能读取，未知来源不被升级为用户硬约束。

## 退出与下一阶段

实现退出：上述数据通路有写入和消费，最小设计检查能返回定位明确的结果，P2B 可据此构建任务。运行验收由用户填写。P3 后续补全归一化审计，P4 扩展最终产物验收；本阶段不得依赖二者全部完成。
