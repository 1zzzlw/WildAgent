# P7：视觉反馈与效果对照

状态：未实施。前置：P1—P6 中本次评测能力已验收；有可用的真实渲染环境。

## 可直接使用的提示词

```text
请实施 WildAgent 建筑生成优化 P7。先读 docs/10月7日优化/03-Agent执行总约束.md 和 02-实施路线与验收.md。先建立可重复渲染与评价，再增加自动视觉修订。

任务 A：真实渲染基线
1. 追踪 wild-web 实际加载 Blueprint、wild-core 编译重建、材质完成和场景稳定的入口，复用现有 check:rendering 等工具。
2. 固定引擎版本、灯光、背景、相机和输出尺寸；为尺度不同建筑确定可复现的取景规则。
3. 输出正面、侧面、俯视和一个透视视角。截图必须来自实际引擎渲染，不允许使用图像生成工具代替。
4. 记录 Blueprint/设计版本、相机参数、加载错误和截图路径。截不到图必须标失败，不给空白图打质量分。

任务 B：先评价再自动改
1. 把真实截图、批准设计摘要、P4 履约结果交给评价器；模型没有图像输入能力时先使用人工评价，不假装做视觉判断。
2. 评价项限定为可见问题：体量层次、入口识别、立面节奏、材质协调，以及设计中明确的视觉要求是否体现。
3. 不凭截图推断精确结构尺寸或不可见关系；这部分以 Blueprint/几何校验为准。
4. 输出问题、视角证据、关联设计字段/实体、置信度和建议。找不到字段映射的意见只记录，不自动猜测并修改。

任务 C：有界修订
1. 首版最多自动尝试 2 轮，使用明确调用/时间预算；达到上限、无进展或模型失败时停止并保留最佳有效版本。
2. 修订通过现有设计块/受控变更接口，不直接让视觉模型写 Three.js 或绕过编译器改场景。
3. 批准后涉及设计变化的建议进入既有确认流程；保持设计语义的确定性几何修复才可直接执行。
4. 每次候选必须重新运行共享解析、几何校验和履约验收；不能靠牺牲用户硬要求让画面看起来更好。
5. 将候选与基准比较，变差就回退。旧 Blueprint、截图和验收结果保留可追踪引用，不覆盖掉唯一证据。

任务 D：对照评测
1. 按路线文档的任务集和公平预算比较 P0、优化版与通用 Agent，记录模型、工具权限与实际消耗。
2. 使用相同 WILD 输出约束，若通用 Agent 修改了引擎则另设探索组。
3. 用户要求满足率、设计保真率、几何有效率、人工视觉偏好、耗时和成本分开报告。
4. 失败样本不能从统计中删除；模型自评不能替代匿名人工比较。没有通用 Agent 运行条件时明确缺该组，不编造结论。
5. 输出可复核的评测报告：任务、版本、结果、截图索引、数值指标、失败类型、限制。小样本只给观察，不宣称统计显著。

验收：视觉反馈确实来自真实截图；至少一个可控问题完成发现→建议→候选→校验→采纳/回退的闭环；预算停止与回退测试通过；结论与数据一致。
如果没有视觉改善，报告最常见失败原因和下一步最小实验，不继续堆节点或无限重试。
```
