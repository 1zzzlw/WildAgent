# P1：贯通设计字段与修订上下文

状态：代码优化已完成，运行验收由用户负责；本文件保留为已实施阶段的任务说明，不应再次执行。见 [P1-执行记录.md](P1-执行记录.md)。前置：P0 的字段地图和最小样本。

## 可直接使用的提示词

```text
请实施 WildAgent 建筑生成优化 P1。先读取 docs/10月7日优化/03-Agent执行总约束.md 和 P0-基线记录.md；若基线文件缺失，先核对本阶段必要数据路径。

目标一：已有 components 实例能力在正常生成和人工审核往返中不丢失。

重点入口（相对 wild-server）：
- app/agent/generation/architecture/design_blocks.py
- app/agent/generation/architecture/design_workflow.py
- app/agent/generation/architecture/planning.py
- app/design/contracts.py、resolver.py、review_outcome.py
- app/agent/compiler/compile.py

实施步骤：
1. 列出 components 与 component_quota 的不同职责。配额是数量要求，实例是具体设计，不允许将两者合成含糊字段。
2. 给现有实例字段分配明确的设计块所有者，并使字段过滤器保留合法实例。实例可为空，不因没有装饰实例就强迫模型增加构件。
3. 使用当前 ComponentInstance 契约，不新建同义模型。起草时仅引用当前阶段真实可用的宿主；若编译器只接受尚不存在的墙 ID，先明确最小语义宿主解析，不能要求模型猜将来的实体 ID。
4. 接通 normalize → build_design_document → 保存/读取 → approve → architecture_plan_from_document → compile。逐个检查 host、size、form、material_role。
5. 检查合并和最终 conform_* 是否又覆盖显式实例；如果它们会覆盖，本阶段必须为已经支持的实例保住语义，而不是只让字段在 JSON 中存在。
6. 历史文档没有 components 时按空列表兼容。不要创建虚假实例填满配额。

目标二：局部设计修订有完整的基准上下文。

重点入口：generation/architecture/convergence.py、design_workflow.py、design_plan.py。
1. 给分块起草提供当前有效设计的只读基准；区分供模型读取的完整上下文与本轮允许返回的字段。
2. 只修 roof 时，模型必须能读到真实体量、层数和宿主；只修 facade 时也必须看到相关几何。
3. 后续修订轮基于上一轮接受的版本；不能每轮回到最初 raw_plan。
4. 返回变化按块字段合并，不允许模型覆盖无关字段。缺失字段不要意外清空已有值。
5. 同批并行块使用同一份稳定输入快照，结果按现有依赖表合并，避免读取并行兄弟刚写了一半的 dict。
6. 当前提示词对前序 JSON 使用字符截断时，改成有字段选择的合法 JSON；不能从字符串中间截断必要宿主或生成破损 JSON。保持实现简单，不引入通用上下文平台。

必须新增或补充的测试：
- 含多个实例的 plan → document → approved plan 往返，逐字段相等。
- 审核后真实 compile 结果体现至少一个显式尺寸/形态，不只是检查中间 JSON。
- 只修 roof：捕获实际模型输入，断言存在原体量；未修改的 facade/materials 保持。
- 两轮修订：第二轮看到第一轮已接受的结果。
- 同批执行顺序变化不影响提供给各块的前置上下文。
- 历史空实例文档兼容，物件分支共享转换不被破坏。

不要把 schema 新增的能力一口气全做完；本阶段贯通已经存在的能力。运行相关 tests/design、tests/compiler 和设计块/收敛测试。
验收报告必须展示一个实例从模型可表达字段到最终 Blueprint 的完整证据，以及一次修订的输入/输出差异。
```
