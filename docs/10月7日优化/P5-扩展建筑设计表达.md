# P5：扩展建筑设计表达

状态：未实施。前置：P4。按 P5-A、P5-B、P5-C 顺序分批交付，每批单独验收。

## 可直接使用的提示词

```text
请执行 WildAgent 建筑生成优化 P5 的指定批次；未指定时先做 P5-A。先读 docs/10月7日优化/03-Agent执行总约束.md，确认 P1—P4 已有验收证据。

总目标：让模型能明确表达有意义的建筑差异，并由确定性编译准确实现。不通过随机扰动、增加数量或模型自由写坐标制造差异。

所有批次共同步骤：
1. 先检查 wild-core/schema.json、实际组件编译器和几何实现，列出可用参数。字段存在不代表整个生成链支持，必须追到实体输出。
2. 设计层先表达意图与宿主，解析层计算坐标，编译层实现；不要让模型复制渲染器内部参数大全。
3. 每个新增字段同时更新契约、Schema 导出、生成块/提示词、归一化、文档往返、共享解析、预览、编译、履约检查与相关前端类型。
4. 保持旧文档迁移可解释；设计协议升级不等于必须升级 WILD 协议，后者仅在引擎输出契约变化时修改。

P5-A：逐体量屋顶
- 引入最小的屋顶决策集合，能按稳定体量/承托面引用声明不同 roof type 和已有引擎可实现的比例参数。
- 明确默认屋顶与逐体量覆盖的优先级；旧单 roof 文档能迁移为等价默认，不凭空改变造型。
- 覆盖主楼坡顶+侧翼平顶、不同高度承托、L 形内院不被整块屋顶封住。
- 非法宿主或冲突覆盖明确报错，不能静默换成统一 gable。
- 真实编译后检查屋顶类型、数量、覆盖与标高；做引擎重建验证。

P5-B：围护与开口分离、立面分段
- 显式区分“有墙无洞口”与“开敞无墙”，不要继续让 empty 同时承担两种语义。
- 允许按真实体量边界/楼层范围定位立面段；优先覆盖轴对齐现有体量，不直接引入任意曲线建筑系统。
- 支持显式开口宽高、窗台/底标高和现有合法形态；未指定时才使用默认槽位规则。
- 上层门如用于阳台连通，必须有宿主与通行/防护关系，不能只解除 upper_pattern 的限制。
- 不再依赖全局四方向推测所有 L 形内院立面；共享解析负责可用边界识别。
- 历史 empty 语义按旧版本迁移并留记录，不能将旧开敞建筑突然封墙。

P5-C：构件实例与材质分区
- 基于 P1 已贯通的 ComponentInstance，先选引擎已经支持的 2—3 类构件做完整设计控制，例如栏杆、雨棚、檐口。
- 表达真实宿主、尺寸、形态和材质角色，配额只作汇总要求，不代替实例设计。
- 增加最小的区域/构件材质绑定，避免所有墙强制共用一种效果；无资产也应允许合法参数材质，具体材质规划由 P6 完善。
- 任意显式实例都要经过几何和设计履约验收，不能因为“模型指定”而绕过宿主/碰撞校验。

每批验收：两个只在一个设计变量上不同的方案，应在最终实体上出现对应差异；其它设计保持。重复编译同方案结果稳定。提交数值对照和真实渲染证据；环境无法渲染时明确保留视觉未验收。
不要在本阶段实现完整室内房间系统、结构工程规范引擎或任意自由曲面编辑器。
```
