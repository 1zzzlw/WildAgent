## 六类根因和修复

### 1. 180 个窗超过单次输出容量，却被原批重试

原窗任务三次 `generate / repair_1 / repair_2` 的 `finish_reason` 都是 `length`，每次输出均达到 8192 token。首稿输入 67,676 token，后两稿输入继续增加；原逻辑把截断当作普通 JSON 错误，重复发送全部 180 个标记。

修复位于 `app/agent/plan/expand.py` 和 `implementation.py`：

- 按序列化图纸内容分批，当前每批目标不超过 8000 字符，保留所有标记及依赖。本次原窗任务分成 16 批，每批 9–12 个。
- 8000 字符是经本轮实测的初始图纸负载阈值，不冒充模型 token 上限，也不包括全部系统提示和参考资料。若仍遇输出截断，对独立标记批次二分，后续修订继续沿用拆分边界。
- 单个标记和批内互相依赖的组合保持完整。无法继续拆分的截断明确报告长度问题，不擅自删掉设计内容。
- 中断恢复保留已采用标记和拆分边界；拆分受原任务调用预算约束，没有扩大预算或增加固定修订阶段。

四档复杂度使用同一入口，不按建筑 ID、楼层数或窗数量编写特例。

### 2. 楼梯平台实际连通，却要求两个梯段落在同一块板上

原楼梯第二次修订稿有 32 个实体。楼梯洞口拆板后，相邻两跑的楼面到达点分别落在相接板片上。旧判定要求一块矩形同时包含两个端点，误报七处“平台错开 2m”。后续模型据此修出了实际断开的平台。

`app/tools/spatial_tools.py` 改为判断同标高板片集合的连通性：重叠或共享非零长度边界可以连通，孤立岛、实际间隙、只碰一个角仍不能连通。原有端点完整净宽承托检查和标高容差保留。

原稿回放结果：`repair_2` 通过，拆板涉及 8 块楼板，楼梯问题 0；`repair_1` 的平台标高错误仍拒绝，原 `assembly_revision` 的真实断开仍拒绝。没有修改原稿坐标，也没有放宽间隙容差。

### 3. 屋顶任务越界重复实现女儿墙

图纸把女儿墙独立派发，但屋顶描述也提到女儿墙。屋顶任务不知道同宿主的委派信息，生成了四周围墙，后续女儿墙及压顶与其冲突。

修复：把相关同宿主标记交给任务上下文，明确构件归属；增加平屋面与独立女儿墙的有限共享归属检查，片段采用和最终候选均检查。原稿中的越界围墙现在能提前拒绝。屋面以下支承、其他宿主、坡屋面没有套用这一平屋面判据。

这是有明确适用范围的规则，并不声称能够从任意旋转 primitive 或自由组合中识别所有跨任务重复造型。

### 4. 只拿新增压顶验收整座女儿墙

部分墙段已经采用，修订只返回压顶时，原代码把新增压顶单独当成完整构件比较尺寸，错误报告总高约 0.1m 不符合女儿墙高 1.2m。

`_accept_fragment()` 现在把已采用部分与修订部分组成完整候选验收，返回时只追加新实体。已采用实体仍不可改写；重复 ID、`true` 冒充数值、遗漏必要几何和错误总尺寸继续拒绝。重复回传已采用部分不会产生第二份几何。

### 5. 分批后暴露：自动窗只有中心，没有可用开间约束

第一轮真实回放落实 177/180 个窗，剩下三窗持续与已采用邻窗重叠。复验发现三个先采用的窗宽 5m，但其开间宽只有 4.5m。另一次重叠发生在两个并发批次之间：各批局部看不到对方的新输出。

新增共享 `opening_cell_limits()`：从已批准的开间划分、示意墙长度、开间中心和底标高推导可用沿墙范围及最大高度，传给模型，并由 `opening_design_errors()` 在采用前和最终验收中核对。检查整个洞口组，不能靠多扇窗各自合格绕过整体范围。

此处给的是上限，不强制填满开间；显式实例仍遵守其批准尺寸，不自动缩小、不移动、不减少数量。受影响的原 12 窗批次在新契约下真实重生成，一次全部通过。保留了首次回放的失败证据。

### 6. 后端通过的雨棚，被 Core 编译拒绝

初次 Core 检查发现原入口雨棚 `from[0]=10`、`width=12`，父墙长 20m，沿墙范围达到 22m。原任务把世界板中心当成沿墙起点。后端雨棚校验没有水平范围检查；混合了支撑 primitive 的组合也没有精确核对原生雨棚板的安装位置。

修复：

- `validate_canopy_placement()` 补齐与 Core 一致的沿墙范围检查，接入生成片段采用入口；最终流水线复用同一校验器。
- `canopy_mount_target()` 按真实墙坐标、外表面偏移和批准板中心换算安装起点，作为共享提示事实。
- `canopy_design_errors()` 在片段与最终候选中检查原生雨棚的板中心和显式尺寸，即使组合中还有其他零件也不能绕过。
- 雨棚组合整体采用，避免只保留支撑而丢掉主板。

雨棚在修复后真实重生成一次通过，Core 编译不再丢弃该组件。自定义斜撑的全部接触关系不在上述原生板安装判据内，仍列构造复核。
