# 10 月 14 日：建筑生成稳定性扫描与优化总结

按本文实施后的进展、验证结果与未完成项见 [执行记录](执行记录.md)。以下保留原只读审计结论与历史证据。

审计日期：2026-10-14（北京时间）。本次只读扫描源码、测试、流水线及本地生成记录，仅新增本目录文档，未修改业务代码。

## 1. 核心结论

**项目仍有明显优化空间。低复杂度不稳定的关键，不只是模型不够强或提示词不够长，而是设计中的约束、构件实现的约束、失败后的修订目标和最终成功口径还没有完全闭合。**

四档建筑共用主要生成入口，因此修好这些问题能够同时改善低、中、高、极高复杂度。但高档不仅构件更多，还会增加宿主依赖、跨构件关系、空间组织和上下文规模。不能直接把低档单次成功外推为高档稳定。

建议维持当前主线，在已有入口内收紧契约、减少重复推导、改进修订和验收；不建议重写整套 Agent，也不建议再增加一套规划器、修复图或独立“低复杂度专用系统”。

本次最值得优先做的事情：

1. **审核前检查设计内部可计算的矛盾。** 避免实现阶段被要求同时满足互相冲突的尺寸、楼层和关系。
2. **统一“结束”与“成功”的含义。** 标记舍弃后流程可以结束，但不能计入建筑完整成功率。
3. **按明确的问题归属修订，并识别无进展。** 不让同一错误几何反复消耗调用，也不把无法定位的问题默认交给主体重做。
4. **建立固定样本、固定版本的真实生成基线。** 离线回放、单测、后端交付和浏览器外观分别验收。

失败轮并不是“构件太多，模型预算耗尽”：界面保留的最后一次计划对账显示 6/6 完成、无预算耗尽，却没有楼梯可供交付。随后 compile 已把最终计划中的楼梯任务改为 abandoned，并由最终校验阻止交付；问题在于过程展示与业务成功语义不一致，不是这栋缺楼梯的建筑被错误保存为成功。

该轮图纸声明楼梯连接 1—3 层，真实楼面为 `0.45 / 3.45 / 6.45m`，总连接高差是 `6m`；同时又给出 `size.height=8.85m`、`flights=3`、`rises=18`、`riser_height=0.15`，踏步累计为 `8.1m`。下游一度实现到 `9.45m`，把三层墙顶当成额外到达层，随后又被引导补平台。

**当前工作区已经补入 `stair_span_conflicts()`、真实楼面连接上下文及相关提示词和测试。** 因此本报告不把“缺少楼梯总高检查”当成当前仍未修复的缺陷；这组记录说明的是跨字段设计矛盾必须提前检查，以及修复后还需要新生成验收。本次没有运行这些新增测试或重新生成。

另外，失败轮 `repair_2` 和 `assembly_revision` 返回的楼梯 `geometry` 经解析、排序序列化后摘要完全相同，错误也没有闭合。这是改进无进展判定的直接证据。

以上是两个诊断样本，不是成功率统计。它们不是相同图纸，也没有记录完整的运行源码版本、模型参数和提示词版本，不能当作严格的模型对照实验。

## 3. 优先级总表

| 编号 | 优先级 | 优化点 | 当前判断 | 对复杂度的影响 |
|---|---|---|---|---|
| A1 | P0 | 设计审核前的跨字段一致性 | 已有局部检查，需形成共享关系契约；楼梯已有待验收修复 | 所有档位；多层、多体量更敏感 |
| A2 | P0 | 流程结束、设计完整、交付通过的口径 | 已有分项数据，但任务 `succeeded/done` 会包含舍弃 | 所有档位；标记越多越容易误判 |
| A3 | P0 | 修订归属、重复候选和无进展终止 | 有限次数已存在，失败候选仍可能原样重复 | 所有档位；高档失败传播范围更大 |
| A4 | P1 | 共享设计事实、提示词与组合构件验收 | 部分事实已确定性派生，组合表达的验收仍不均衡 | 所有档位；复杂组合更突出 |
| A5 | P1 | 任务批量、上下文与全局成本边界 | 当前主要按类型分组，缺少按实际上下文负载分批 | 高档放大，低档门窗批次也受影响 |
| A6 | P1 | 可复现运行记录及成本统计 | 输出、检索、checkpoint 已有；逐调用输入和版本链不足 | 全档位，是稳定性测量前提 |
| A7 | P1 | CI、离线回放与真实渲染验收 | 有大量测试及前端诊断，流水线覆盖不一致 | 全档位，防止修一处退化另一处 |
| A8 | P2 | RAG 异步执行与结果归属 | 同步检索及共享 `last_results` 存在性能/串读风险 | 并发请求及高档更多任务时更明显 |

P0 优先恢复可信的设计与结果语义；P1 建立稳定性和扩展能力；P2 在有测量依据后优化。

## 4. 已有基础应当保留

- `DesignDocument`、设计 hash/revision、`resolved_design`、构件标记和实现记录已经提供了可追溯主线。
- 建筑主体先实现、附属任务有界并发、失败局部保留和资源命名隔离已经存在。
- `evaluate_candidate()` 统一最终候选校验；交付会核对蓝图指纹、校验证据和设计版本。不能再简单归因为“没有校验器”。
- 门窗宿主、屋顶覆盖、主体楼板范围、楼梯平台、材质合并等已有共享规则和回归，不应重新复制一套。
- 前端有 Core 编译诊断、重建诊断和部分加载提示；后端也明确记录视觉检查未完成。应把这些证据接成验收链。
- 四档粒度已有统一入口，未知设计形态允许通过原生实体组合表达；优化不能退回固定住宅模板或构件数量套餐。
