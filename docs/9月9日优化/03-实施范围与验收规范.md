# 实施范围与验收规范

## 1. 本次代码范围

### 后端

- `app/design/contracts.py`：DesignDocument、DesignPatch 和 ResolvedDesign 的 Pydantic 类型。
- `app/design/resolver.py`：architecture plan 转换、确定性解析、设计 hash 和 SVG。
- `app/design/repository.py`：原子保存、历史 revision、锁定字段和版本冲突。
- `scripts/design/export_design_schema.py`：从 Pydantic 契约导出并核对正式 JSON Schema。
- `app/api/designs.py`：Schema、查询、Patch、批准和 SVG API；设计初稿只允许由生成链路创建。
- `app/agent/nodes/design_review_node.py`：LangGraph 人工建筑设计审核。
- `app/agent/nodes/architecture_node.py`：方案节点生成正式设计草案；材质节点补齐受控材质后统一持久化设计文档与 SVG。
- `app/agent/graph.py`：骨架前增加强制 `design_review`。
- `app/api/ws_agent.py` 与 `generation_job_service.py`：审核事件、持久化暂停和恢复。
- `merge_node.py`：Blueprint 合并时绑定设计版本和 hash，使最终校验也覆盖这组来源信息。

### 前端

- `types/design.ts`：DesignDocument v1 的 TypeScript 契约。
- `types/agent.ts`：设计审核 WebSocket 协议。
- `agentBridge.ts`：设计批准、自然语言修改和恢复。
- `agentStore.ts`：按会话持久化设计审核状态。
- `AgentExecutionPanel.vue`：SVG、核心参数、约束、配额和审核操作。
- `AIChatPanel.vue`：设计审核期间的对话修改入口。

### 知识维护

- `wild-knowledge-ingest` 增加知识声明到 DesignDocument 的映射要求。
- 硬规则必须声明执行位置；Schema 变更必须同步代码和测试。

## 2. API 契约

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/designs/schema` | 获取 DesignDocument JSON Schema |
| GET | `/api/designs/{session_id}` | 获取当前设计与 ResolvedDesign |
| PATCH | `/api/designs/{session_id}` | 应用版本化 DesignPatch |
| POST | `/api/designs/{session_id}/approve` | 批准指定 revision |
| GET | `/api/designs/{session_id}/preview.svg` | 获取当前 SVG 审阅图 |

WebSocket 新增 `design_review_required` 和客户端 `design_review`；版本冲突使用 `design_review_rejected` 返回并恢复审核按钮。

## 3. 验收矩阵

| 层次 | 验收条件 |
|---|---|
| Schema | 未知字段、非法枚举、立面 pattern 数量错误、越界体量被拒绝 |
| 版本 | Patch 必须匹配当前 revision；成功后 revision 加一并回到 draft |
| 锁定 | 锁定路径及其子路径不能被 Patch 修改 |
| 派生 | 同一 DesignDocument 得到稳定 design hash、标高、槽位和 SVG |
| 审核 | `design_review` 暂停发生在材质解析之后、骨架和组件生成之前 |
| 恢复 | 页面断开、服务重启和事件重放后仍能继续同一审核任务 |
| 编译 | 审核时从存储加载最新 revision，并重新编译回 architecture plan |
| 交付 | Blueprint `meta` 含 designSchemaVersion、designRevision、designHash |
| 前端 | 能查看 SVG、参数、约束和配额；能批准或用对话生成下一版 |
| 知识 | 硬规则有执行映射，活动 generation 库不存在建筑类型卡，参考事实不误召回 |

## 4. 兼容与清理边界

- `ScenePatch` 继续负责 Blueprint 完成后的实体修改，不能删除。
- 当前 `design_brief` 仍承担“骨架墙 ID 到具体开口槽位”的后几何解析，它应逐步并入 ResolvedDesign 的 Blueprint realization 区，当前不能直接删除。
- `architecture_plan` 仍是现有骨架和组件节点的内部编译目标，但不再是用户层权威文档。
- 新拓扑已提升持久化生成流水线版本，旧 checkpoint 会明确退休并要求重新发起，避免在不同图结构间错误恢复。

## 5. 完成定义

本轮达到工程闭环需要同时满足：

1. 文档和类型契约可读取；
2. 后端模块静态编译通过；
3. DesignDocument 单元测试通过；
4. LangGraph 路由和持久审核恢复测试通过；
5. 前端 TypeScript 构建通过；
6. 实际启动后完成一次“生成方案—查看 SVG—修改—批准—生成 Blueprint”；
7. Blueprint 的 design hash 与批准 revision 的 ResolvedDesign 一致。

若运行环境阻止 Python asyncio、Node 加密随机源或真实模型连接，必须分别报告为环境阻断，不得用静态检查冒充完整运行证明。
