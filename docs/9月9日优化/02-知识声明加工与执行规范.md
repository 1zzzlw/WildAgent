# 知识声明加工与执行规范

## 1. 长文不能直接入库

建筑资料、规范摘录和本地模型回答通常混合百科、工程建议、精确数值、风格偏好、系统关系和当前引擎不支持的对象。整篇向量化会让模型无法判断哪些内容必须执行，也会把某一套建筑描述变成固定模板。

所有资料先拆成最小可判断的声明，再逐条决定去向。

## 2. 五类声明

| 分类 | 含义 | 处理方式 |
|---|---|---|
| `engine_hard` | 当前 WILD Schema、组件注册表和编译器的事实 | 必须由 Schema/compiler/validator 执行 |
| `conditional` | 选择某系统后必须成立的关系 | 写明 `applies_when`，由 resolver 或 validator 执行 |
| `preference` | 造型、材质或构图倾向 | 只参与候选生成和评分 |
| `reference` | 当前产品不需要执行的背景知识 | 留在参考区，不进入 generation scope |
| `unsupported` | 当前 WILD 无法表达的对象 | 进入 proposed 或能力缺口清单 |

## 3. 标准声明格式

```yaml
claim_id: envelope.curtain-wall.floor-grid-alignment
claim: 幕墙水平分格与建筑楼层关系协调
classification: conditional
applies_when: /decisions/envelope/system == curtain_wall
schema_targets:
  - /decisions/envelope/curtain_wall/grid_strategy
  - /decisions/facades
enforcement:
  - planner
  - resolver
  - validator
source:
  location: 来源文件或 URL
  status: verified
free_variables:
  - 开间宽度
  - 面板比例
  - 立面节奏
disposition: relation
```

`free_variables` 是防止固定化的必要字段。它说明规则约束了什么关系，也说明本次设计仍可决定什么。

## 4. 玻璃幕墙写字楼资料的处置示例

| 原始声明 | 分类 | 处置 |
|---|---|---|
| 幕墙由玻璃、框架和连接关系组成 | `conditional` | 映射围护系统、宿主关系与幕墙网格 |
| 幕墙网格需要与楼层和开间协调 | `conditional` | 写入 DesignDocument 目标并由 resolver/validator 执行 |
| 写字楼可采用框架、核心筒等结构 | `preference` | 作为候选系统，不强制所有写字楼使用同一种 |
| 办公建筑需要清晰入口和竖向交通 | `conditional` | 由用途和楼层条件触发 |
| 地基、HVAC、配电、喷淋系统细节 | `reference` 或 `unsupported` | 当前 WILD 不表达时不进入生成上下文 |
| 100mm、1.5kPa、成本 30%、节能 40% | 未验证数字 | 没有标准版本、地区和原始证据时不得升级为规则 |
| 银色镀膜、线性灯带、对称幕墙网格 | `preference` | 只在用户选择后写入本次设计 |

## 5. 组织方式

共享规则按系统维护：

```text
structure/frame
structure/core-frame
envelope/curtain-wall
facade/grid-and-opening
circulation/vertical
roof/flat
roof/gable
```

建筑类型卡只保存用途身份、必要差异和系统触发条件。例如 office 类型卡可以说明多层办公需要竖向交通，但不复制幕墙全部字段，也不固定层数、材料、尺寸和体量。

## 6. 硬规则的完成条件

一条知识只有满足以下条件才能称为“已经成为硬规则”：

1. 具有稳定 `claim_id`；
2. 有来源或明确属于当前项目源码事实；
3. 写明适用和不适用条件；
4. 映射到 DesignDocument JSON Pointer；
5. 至少存在 Schema、resolver、compiler 或 validator 执行位置；
6. 有命中与不命中的测试；
7. 不把自由变量一并锁死。

仅被 RAG 召回、仅写在 system prompt 或仅要求模型“必须遵守”，都不能作为硬规则的执行证明。

组件注册表和提示词只保留字段、宿主、编译及已批准槽位等实现约束。门窗数量、固定尺寸、立面对称方式和风格构件套餐不得以“组件专属规则”的名义在代码中重复写死，否则即使知识库已经清理，生成结果仍会再次模板化。
