# 知识库三类内容与执行边界

## 1. 最终内容模型

活动知识库只回答三个项目特有问题。建筑用途、风格和普通建筑常识由模型理解，并在本次 `DesignDocument` 中形成可审核选择。

| 类别 | 回答的问题 | 存放位置 | 运行消费者 |
|---|---|---|---|
| 操作协议 | 当前 Blueprint 的字段怎样读取，ScenePatch 怎样修改，坐标属于世界还是宿主局部 | `BLUEPRINT-PATCH-PROTOCOL.md`、`BLUEPRINT-SPEC-*` | 编辑计划、Agent 系统协议、ScenePatch 校验 |
| 构件能力 | 当前引擎能生成什么，合法字段是什么，复杂构件如何用最小局部 JSON 表达 | `components/` | 各组件节点、compiler、Schema |
| 可执行关系 | 选中构件或系统后，宿主、引用、连接、覆盖和材质必须满足什么关系 | `recipes/` | 方案/骨架/组件节点、resolver、validator |

当前 Blueprint 本身不存入知识库。它由 LangGraph State 注入编辑链；知识文档只解释稳定字段语义。例如 WILD 数组三维顺序是 `[X,Y,Z]`，但门窗 `from[2]` 是父墙法向偏移，不能按世界 Z 直接修改。

## 2. 复杂构件怎样写入知识

构件知识使用“语义名称 → 当前能力 → 最小局部 JSON → 自由变量 → 禁止项”的结构。示例只能包含一个目标构件及理解它所需的宿主关系，不能附带整栋建筑坐标。

规则横竖格窗可以用 `window.verticalMullions` 和 `horizontalMullions` 表达，因此保留有效局部 JSON。菱花窗目前没有斜向窗格字段；在文档里写一组固定 `primitive` 坐标会把案例伪装成能力。正确顺序是先实现参数化窗格组件及校验，再把菱花窗语义映射到它。

玻璃幕墙属于复杂系统。写字楼百科中的基础、暖通、成本和典型尺寸不进入活动库；当前 WILD 的宿主墙、窗格组件、显式骨架、物理玻璃及禁止字段可以进入，因为这些内容能映射到现有字段和代码。

## 3. 固定规则怎样落地

一条“必须”规则至少要有一个程序执行点。活动文档负责解释，Schema、compiler、resolver 或 validator 负责保证。

| 规则 | 当前状态 | 处理 |
|---|---|---|
| 物理玻璃具有正 transmission，opacity 为 1 或省略 | 已校验 | 保留在活动 relation/capability |
| 门窗引用真实父墙并落在墙体范围内 | 已校验 | 保留在活动 relation/capability |
| 楼梯端点落在楼板区域、相邻梯段连接 | 已校验 | 保留在活动 relation/capability |
| 楼梯穿越上层楼板时存在净空洞口 | 尚无完整校验 | 放入 `docs-dev/knowledge-backlog/` |
| 所有必达房间从入口可达 | 当前无房间拓扑 | 放入 `docs-dev/knowledge-backlog/` |

“每面内隔墙必须有门”过于宽泛，应改成“标记为必达的空间具有有效通行路径”。这需要 DesignDocument 保存空间 ID、边界和邻接关系，再由图校验执行。

## 4. 外部资料加工流程

对本地模型或外部资料产生的建筑长文逐条处理：

1. 删除模型已有、且不能映射到当前项目字段的百科说明。
2. 核对 Schema、类型、compiler、resolver 和 validator，纠正不存在的字段与能力。
3. 把已实现字段写成 capability，把跨构件条件写成 relation，把编辑语义写成 protocol。
4. 每个条件写明触发来源。只有用户要求或 DesignDocument 已选择幕墙时，才使用幕墙知识；“写字楼”本身不触发幕墙。
5. 只保留最小局部 JSON，并明确 ID、坐标和尺寸不得复制为默认值。
6. 尚未实现的规则和组件移到 backlog，不放在活动目录中等待 metadata 过滤。
7. 更新检索节点、评测答案和 Skill，随后检查真实分片与索引同步。

## 5. 当前数据流

```mermaid
flowchart LR
    U[用户需求] --> A[方案节点]
    A --> D[DesignDocument]
    D --> R[按已选系统检索 capability/relation]
    R --> G[骨架与组件生成]
    G --> V[Schema/resolver/validator]
    V --> B[Blueprint]
    B --> P[当前 Blueprint + ScenePatch protocol]
    P --> E[对话编辑]
```

活动库不保留 `building_types/`、`patterns/` 或 proposed 文档。未来若确有项目专用设计策略，需要新增显式策略 ID 和独立 reference 检索节点；普通语义查询不会承担这项职责。
