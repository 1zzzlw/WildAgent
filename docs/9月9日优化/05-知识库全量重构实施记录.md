## 3. 消费链调整

- 普通检索由 `rules-v3` 强制限定为 `protocol`、`capability`、`relation`。
- 总体方案、执行计划和骨架节点统一查询 `supported_assembly_relations`，不再请求建筑类型或无执行点的模板。
- 组件节点根据批准方案中的实际系统和组件查询能力文档；`applies_to` 阻止未选择的幕墙等专用系统进入上下文。
- 知识问答节点改为三条受控查询：Blueprint/ScenePatch 协议、构件能力、组装关系；不再宣称知识库覆盖建筑类型学或推荐尺寸。
- 编辑计划原来使用不存在的 `doc_scope=editing`，现改为明确查询 `blueprint_spec + protocol`，因此能够召回 Z 轴和父墙局部坐标说明。
- `AgentService` 直接构造带 metadata 的 `SpecQuery`，删除了根据“查询列表长度和位置”猜测过滤条件的旧适配函数；编辑时分别检索协议、目标构件能力和关系约束。
- Loader 在返回命中前核对来源是否仍属于本次启动扫描到的活动文件清单；即使 Chroma 暂时残留已删除向量，也不会把旧模板注入 Prompt。
- Loader 中已删除旧 `patterns` 路径推断和建筑案例相关注释；旧建筑分类维护脚本与测试已删除。

## 4. 防复发门禁

`wild-knowledge-ingest` Skill、linter、分片预览脚本和 rules-v3 回归现在共同拒绝：

- generation scope 中的 `building_type`；
- generation scope 中的 strategy/example/fallback 角色；
- 活动文档或嵌套分片中的 `status: proposed`；
- 带非空 geometry 的完整 Blueprint 示例；
- 用建筑用途或风格作为专用系统的隐式触发词。

复杂构件示例必须是单个组件和必要宿主的局部 JSON。菱花窗等当前没有参数化构件的对象保存在能力缺口中，不能用一组固定世界坐标冒充复用能力。
