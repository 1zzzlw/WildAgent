# 商业计划书 Vue 页面与工作台主题

## 最终交付

用户最终选择只维护 Vue。已删除独立 HTML 计划书、HTML 导出脚本和中间 HTML/CSS/DOM 脚本，原项目根目录介绍文件保留。

- [BusinessPlanDocument.vue](../../wild-web/src/features/business-plan/BusinessPlanDocument.vue)：纯 Vue 单文件组件，包含模板、响应式试算、作品循环、大图对话框、目录与样式。没有 v-html、iframe 或外部 HTML 模板。
- [BusinessPlanView.vue](../../wild-web/src/views/BusinessPlanView.vue)：计划书路由页面。
- [路由](../../wild-web/src/router/index.ts)：/ 为建筑工作台；/business-plan 为计划书，支持直接打开与刷新。
- [WorkbenchView.vue](../../wild-web/src/views/WorkbenchView.vue)：从原 App 移出的工作台，通过 KeepAlive 保留场景与画布；计划书显示时停止视口循环，返回后恢复。
- [themeStore.ts](../../wild-web/src/stores/themeStore.ts) 与 [style.css](../../wild-web/src/style.css)：亮暗主题与 Element Plus 配色。默认亮色，本地保存选择。暗色采用原工作台底色与表面色；亮色使用米白、深绿与低饱和橙。

工作台顶部及访客入口提供计划书入口，计划书右上角回到主页。公开页面移除了版本、日期、取材来源、仓库路径和文档引用；定价、试算和增长目标仍标为建议或假设。

计划书直接复用工作台的 studio 主题变量与全局 color-scheme，不再固定为浅色。正文、导航、卡片、表格、输入框、强调区域和图片弹窗跟随主页选择；独立刷新同样读取已有主题偏好，不增加第二份主题状态。

## 产品定位

以项目 README、根目录介绍、蓝图语言和用户补充为写作依据，网页不展示内部取材信息。强调成熟智能体可以依据文档、规范与示例编写丰富的小体积 WILD 蓝图；自研参数化几何、编译校验与基于 Three.js 的渲染编辑工作台承接资产。自研 Agent 同步开发，资源有限，目前复杂创作效果和成熟度仍落后于成熟智能体。

没有把显示库全部声称为自研，也没有把本轮截图声称为新完成的 Agent 全链路生成、客户交付或用户验收。

根据 README 与根目录项目介绍进一步补充了蓝图保存的建筑语义、参数化轻量表达、Core/Vue/Three.js 的职责、DesignDocument/Blueprint/ScenePatch 三份契约，以及局部修改示例。应用与路线增加方案交流、设计学习、场景内容、按需检索、预算控制、失败草稿保留、表现层独立迭代和外部服务接入，并区分风格、材质、光影与世界包的现有基础和规划中的产品化工作。

依据根目录项目介绍的“能力边界与发展规划”补充四档自研 Agent 目标范围（minimal、simple、standard、detailed），明确区分蓝图表达、引擎重建与自动生成稳定性。自动房间布局、场地语义规划、专业二维平剖面交付，以及任意有机造型和扫描级细节均列出当前边界，没有把早期文档中的稳定性描述当作本轮实测结论。

发展规划细化为光影扩展包、材质扩展包、扩展制作页面、世界导入与效果预览、建筑编辑增强、生成稳定性收敛六项；每项分别写出现有基础和仍需完成的交付、验收工作。

## README 反思与 Agent 研发目标

从根 README 的“常见问题”提炼三个产品问题：已有规范为何需要 Agent、成熟智能体也能做时的产品差异、模型继续进步时如何积累价值。保留专用流程的成本与收益都需验证的判断，没有沿用“所有通用 Agent 必须通读整个项目”及单轮注入量对比整会话读取量所得的成本倍数。

发展规划增加自研 Agent 的明确目标：提升建筑创作与可靠执行能力，缩小不同底层模型在建筑任务中的成品差距，逐步接近 Codex 等成熟智能体的设计完整度、细节表达和修改质量。目标不代表已达到相应水平，也不承诺消除底层模型的能力差异。

六项提升路径分别覆盖设计判断、知识检索与提示组织、参数化执行、跨阶段约束与局部修订、真实渲染与视觉反馈、运行诊断与质量成本评测，每项列出具体做法和验收重点。依据包括[项目演进记录](../../wildagent%20项目的演进过程.md)中的知识、Trace 与瓶颈反思，以及[参数化执行](../10月24日/Agent参数化执行/README.md)、[构造深化](../10月24日/构造深化与确定性实现/README.md)、[最新两次生成诊断](../10月24日/最新两次生成诊断/README.md)。演进记录的旧节点、旧架构与绝对化模型能力判断不作为当前事实；自动看图修订继续明确为规划，局部回归与历史单次试跑不当作总体质量收益证明。

此次页面补充后完成 vue-tsc、Vite 生产构建及[浏览器核对](../10月28日/商业计划书内容补充/验证.json)：390、768、1440 三种视口分别检查亮暗主题，表格字段标签完整、无整页横向溢出、返回主页按钮可见，浏览器异常列表为空。已查看同目录中的桌面目标、产品反思与手机提升路径截图。此项验证针对页面呈现，没有产生模型调用或新的 Agent 质量评测结论。

## 游戏建筑资产定位与性能边界

按用户补充，将游戏与互动场景中的轻量建筑资产供给提升为主要应用方向，项目摘要和客户章节优先面向独立游戏开发者、小型游戏场景团队及网页互动项目。先验证一个目标引擎中的单体建筑，再推进重复建筑与街区规模。

当前源码依据为 [Core 公开入口](../../wild-core/src/index.ts) 与 [MeshData 契约](../../wild-core/src/primitive/types.ts)：独立 Core 输出实际网格缓冲与材质参数，渲染适配由调用方承担。这能支持游戏适配的方向判断，不能直接证明已有跨游戏引擎插件、完整碰撞导航适配或性能收益。

公开页面区分四种收益：存储与传输、内存与显存、帧率与场景规模、加载与首次呈现。小文件的直接价值是紧凑建筑描述；完整资源还包含运行时、纹理和缓存。相同几何与材质的运行占用不会仅因源文件更小而自动下降，参数化重建也有 CPU 与上传成本。共享几何材质、实例化、按需加载卸载、细节分级均作为游戏交付的待完善工作，不对节省比例作承诺。

技术核对使用 Three.js 官方资料：[网格缓冲](https://threejs.org/docs/pages/BufferGeometry.html)、[纹理内存](https://threejs.org/manual/pages/textures.html)、[实例化](https://threejs.org/docs/pages/InstancedMesh.html)、[细节分级](https://threejs.org/docs/pages/LOD.html)。网页不展示内部取材引用。性能验收规划覆盖完整下载量、重建与首帧、加载峰值和稳定内存、显存资源、绘制次数与帧时间；本次没有实施游戏适配或运行游戏性能对比。

补充后 vue-tsc、Vite 生产构建通过；[游戏定位与性能边界核对](../10月28日/商业计划书内容补充/游戏定位与性能边界核对.json)检查正文边界及 390、768、1440 三种视口的亮暗布局，全部通过，浏览器异常列表为空。已查看同目录 05、06 两张桌面和手机截图。复用已有本地预览服务，没有停止其他进程；未新增游戏性能测试结论。
