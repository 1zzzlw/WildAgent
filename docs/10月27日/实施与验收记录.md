# 材质、遮光、动态构件与新别墅交付

日期：2026-10-27。

## 用户要求

1. 材质库中的材料实际参与渲染，体现纹理、表面起伏、粗糙度、反射和透光差异。
2. 局部光源受到不透明墙体遮挡，玻璃可以透光。
3. 完善现有电梯：专属呼梯/选层与开关门按钮、实际轿厢运动和状态联动。
4. 实现可交互的风扇，并沿现有按需渲染循环驱动动态部件。
5. 完成后原创一栋新别墅，充分使用本次引擎能力，保留设计、作者输入、校验、真实渲染和交互检查。

## 初始源码发现

- 现有材质选择会完整复制配方，但内置材料覆盖较少；默认表面与显式图案需要分别检查，不能把颜色变化当成纹理/反射已经实现。
- `FixtureLightingRuntime` 只给精细档两个灯开启阴影，其他活跃灯直接参与照明，这是局部灯穿墙的明确来源。
- 电梯当前由实心轿厢盒、导轨和单个按钮组成，点击后循环到下一层；缺少真正的选层、层门/轿门、到站状态和搭乘链路。
- 保留前一轮已完成的米制 UV、法线修复、画质恢复与网格复用，以及用户已有的无关工作区改动。

## 验证口径

静态检查、Core 编译、浏览器真实渲染、交互验证、助手看图和用户验收分别记录。未运行的检查不记为通过；不以渲染预览冒充完整 Agent 生成，也不预先宣称达到照片级或覆盖所有场景。

## 材质实现

### 从库到生成结果

`wild-core/material-presets.json` 是 13 种内置表面的源数据，Core 导出、材质面板与后端受控材质计划采用同一内容；后端部署副本位于 `wild-server/storage/knowledge_base/material-presets.json`，由回归校验两份相等。

后端原先主要保留 baseColor / roughness / metallic，表面配方在计划归一化时丢失。本次加入内部计划字段 `surfacePresetId`，按角色白名单解析完整配方；计划复用时读取嵌套 material，保留纹理类型、物理玻璃、清漆、织物光泽和金属各向异性。没有模型选择时，已有角色默认表也能落到适配表面。显式颜色继续生效，纹理资产、砖材配方、普通内置表面按互斥路径处理。

`surfacePresetId` 是生成计划字段；最终 `.wild` 保存展开后的完整材料参数，不依赖模型再次解释这个 ID。现有 PBR 资产路径继续支持；本轮内置表面不需要新增图片、远程 URL 或 GLB。

### 表面与面板

| 类别 | 实际参与渲染的内容 |
| --- | --- |
| 石英石 | 细颗粒、云斑、局部高光与清漆 |
| 橡木 / 胡桃木 | 板块尺度、拼缝、年轮与纤维方向 |
| 石灰抹面 / 清水混凝土 | 抹痕、浇筑云斑、细孔与粗糙度变化 |
| 洞石 | 层理、条带色差和孔隙 |
| 石砖 / 陶土砖 | 米制板块、缝宽、缝下沉法线与逐块色差 |
| 拉丝金属 | 方向微纹和各向异性环境高光 |
| 亚麻 | 经纬交织高度场、粗糙度和 sheen |
| 清透 / 磨砂玻璃 | 透射率、折射率、厚度、粗糙透射与吸收参数 |

显式表面使用构件自身的米制 UV，随电梯或扇叶运动，不在世界空间中“游动”；保留旧默认表面的世界投影兼容行为。材质面板的内置缩略图通过正式 Core / Three.js 管线生成，结束后释放缓存和 GPU 资源。三种既有砖材配方继续可用，并另验真实像素结果。

## 遮光与玻璃

所有进入预算的实时局部灯均投射阴影。流畅 / 均衡 / 精细分别使用 2 / 4 / 8 个灯、256 / 512 / 1024 阴影尺寸，以灯数和分辨率控制开销。其余灯体仍可显示发光外观，不以无阴影光照补亮墙后。

不透明墙体、楼板和构件投影；透射玻璃不写入不透明遮挡阴影。发光面不遮住自身光源，灯壳与周围结构继续参与遮挡。

真实 GPU 隔挡测试包含一个优先灯和一个墙后的次级灯，覆盖三个质量档。墙后测试点为 RGB `[0,0,0]`；更换清透玻璃后分别为 `[183,183,183]`、`[214,214,214]`、`[202,202,202]`。这验证了局部直射光的墙 / 玻璃差异，没有把环境光当成透墙直射光。

## 电梯与动态家具

- 电梯从实心盒改为地板、侧壁、背板、顶板、照明、轿门、各层层门、门框与门槛。
- 各层有独立呼梯按钮；轿内有目的楼层、开门、关门按钮和请求指示。面板用人类楼层 `1/2/3…`，WILD `initialFloor` 按 `0/1/2…` 保存。
- 统一状态机执行关门、行驶、停稳、开门；行驶中开门请求不生效，途中其他楼层请求排队，重复呼梯去重。只有停靠层的层门打开。
- 对开门收进轿厢正面两侧的门袋，不滑出井道；轿厢地板完成面对齐停靠层。`landingWalls` 可逐层引用直线入口墙并自动开洞，引用进入公共关系索引。
- 可动地板携带人物，角色仍通过实际建筑和轿厢几何碰撞；停靠后通过门槛进入楼层。
- 吊扇作为 `fan` 组合构件，电机、吊杆固定，轮毂和扇叶绕电机中心旋转；独立开关循环关闭、低速、高速，带加减速惯性。
- 设备复用视口 RAF，动态阴影按既有节流更新；停机后允许按需渲染休眠。不增加每设备 RAF，不向 WILD 写入运行进度、请求队列或按钮状态。
- 构件库与属性面板支持电梯、吊扇的加入及参数 / 材质编辑；生成侧的类型注册、需求词表和 Schema 同步支持风扇。

人物搭乘进一步暴露两处通用问题并修复：`Capsule.translate()` 返回 void，踏步候选体不能链式赋值；活动 Octree 最大平面在部分高度因包围盒分割舍入丢失，建树前对 bounds 增加 `0.00001m` 余量。没有按别墅 ID 或某个楼层打补丁。

## 新别墅与渲染检查

交付：[岚石光庭-交互材质别墅.wild](./岚石光庭-交互材质别墅.wild)。源文件 49,802 字节，257 个原生元素、19 个组合构件、19 个源材质；编译为 422 个元素、545 个网格，21 个实际材质引用包含两个编译器内置材质。545 是网格材质槽数量，不是 545 种不同材质。

先写[设计事实](./别墅设计事实.md)，再用[确定性作者脚本](./生成岚石光庭.mjs)生成自足文件。两层 L 形体量围合水庭，搭配木格栅、露台、洞石与抹面、玻璃、室内家具和灯光。全部 13 种内置表面均在蓝图中绑定实际构件；三种砖材独立展示验证，避免为凑齐材质而破坏别墅配色。

[别墅渲染](./别墅渲染/)包含四个外景方向 / 俯视、夜景、日夜起居室、卧室、材料近景和电梯开门，共 10 张 1280×960 引擎截图。采用正式精细档、环境反射、阴影、GTAO、水面反射与夜景 Bloom，没有隐藏墙体或屋顶来拍正式视角。每次出图记录输入 SHA-256、渲染源码摘要、相机和时间配置。

助手检查发现并调整了卧室柜体旋转后的宽深、室内取景、天花饰面、吊扇吊杆连接和电梯门袋尺寸。四个外景确认体量、屋面、窗墙和格栅阴影；室内确认材料尺度与灯光；电梯近景确认按钮与可进入轿厢。

## 当前边界

1. 这是实时光栅化渲染。玻璃通过透射材质和跳过不透明阴影实现透光，没有离线焦散、彩色透射阴影或完整路径追踪；IBL / 半球补光不按封闭房间做物理全局照明。
2. 程序表面的高度场改变着色法线，不制造真实石材轮廓或家具软包倒角。家具和植物仍有参数化形体的简化感；本次充分使用当前功能，不等于达到照片级或理论最高写实度。
3. 电梯支持等层高、世界 +Z 入口；井道围合和上层楼板孔洞由蓝图负责。运行队列和运动状态不持久化。风扇目前是吊扇，不宣称任意家具已支持任意运动。
4. 设备和材质已接入现有生成入口，但本轮没有重新入库 / 重建 RAG，也未验证模型对整栋建筑的一次生成成功率。
5. 浏览器没有 Shader 编译失败。仍出现既有 PMREM 样本截断、驱动采样偏置提示及部分 GLSL 转译器告警；不能把这些告警写成零告警。用户审图仍待进行，`visual_review.complete` 保持 false。

本轮保留此前引擎修改和用户无关改动，没有改动 `.env`，没有提交或推送。
