本轮只修已证实的实现缺陷，保留图纸语义、现有节点、三次设计调用上限和原校验标准。并非承诺任意图纸三次内一定生成成功。

## 本轮源码修复

1. `app/utils/json_extractor.py` 为图纸和补丁提供 outer_only 模式，外层 JSON 损坏时不接受内部局部对象。其他调用默认行为保留。
2. `architecture/design_workflow.py` 的完整图纸和 operations 补丁均使用该严格入口，语法错误反馈保留行列及附近文本；保留原始文本用于格式修订，不用局部对象替代整图。修订提示要求保持其他设计及稳定 ID。
3. `architecture/workflow.py::_validation_reason` 不再将普通错误硬截到 300 字，已发现的后续字段和冲突一并交给修订。
4. `coordinates.py` 的 U 梯错误带精确字段路径；中心 Y 错误明确使用 `placement.position[1]` 及完整目标向量，避免模型另造 `placement.y`。这处错误路径遗漏是上一轮优化引入的交接缺陷。
5. 每轮校验后根据当前错误重新计算修订范围；新错误没有可定位字段时明确记录 `repair_scope_missing` 并停止，不沿用上一轮无关权限，不扩大为整图任意修改。失败诊断保留 last_candidate。
6. 缺失门窗宿主时，设计冲突携带当前墙 ID、open 状态与端点，以及来源于 `/facades`、`/volumes` 的围护说明。修订层据实际关系同时开放必要的宿主及围护字段，仍由模型显式修订设计，不自动把 open 改成封墙。
7. 格式修订关闭思考，首次设计沿用用户思考设置。调用上限不变；提示词补充 JSON 数值需已计算、U 梯 rises 表示每跑级数。活动知识说明同步数值协议，未再次同步向量索引。

未改变 plan 的分工、构件配额、坐标容差、设计通过条件或楼梯形式；不通过的图纸仍不能进入生成链。用户端“未命名建筑 0 元素仍被保存”的交付表现已记录，它不是这些设计失败的起因，本轮没有顺带重构保存链。
