## 一、设计输入现在怎样表达

唯一后端类型仍为 [contracts.py](../../wild-server/app/design/contracts.py)。以下是新增或正式类型化的设计数据；其他开放形式仍保存在 components.form，不要求建筑套用矩形造型或固定装饰清单。

| 数据 | 输入含义 | 消费与检查 |
| --- | --- | --- |
| floor_layouts | 每层楼面顶、房间、独立内墙及挑空 | Pydantic 类型、坐标投影、SVG、主体上下文与必要楼面验收 |
| construction | 本次统一板厚、外墙厚 | 板底计算、墙宿主厚度、主体实际板厚与墙厚核对；明确内墙厚度单独保留 |
| circulation.paths | 选定水平通路的楼层、X/Z 折线、净宽、净高 | 设计类型、所有构件上下文、平面图及最终空间复核 |
| components.connections | 两个同轴边界的对齐目标与差值 | 标记依赖、已实现目标坐标、片段检查和最终复核 |
| components.repetition | 等距矩形零件的数量、轴、中心距和截面 | 整组包络与全部单件中心推导，实际数量/位置/尺寸复核 |
| materials.definitions | 已确定的命名材料参数 | 设计版本保存、批准后全局材质准备、局部禁止重定义 |
| components.material_bindings | WILD 材料字段与命名材质 ID 的明确绑定 | 原生字段绑定、材料引用和定义核对 |

新字段只承载本次选择；未选定的路径、连接、重复组和精确材质可以省略。详细粒度由空间联系、虚实、分格、截面、间距和材料分区体现，不以构件配额决定精细程度。

旧房间边界 `x_start/x_end/z_start/z_end` 保留原格式；新设计使用 `x/z/width/depth`。`void:false` 保留，缺省不强行补成 false。内墙继续按 `from/to` 序列化，Python 内部属性名不进入交接数据。

## 二、程序统一计算什么

[coordinates.py](../../wild-server/app/design/coordinates.py) 统一输出 `design_geometry_context`：

- levels：实际楼面顶、墙顶、板底、体量范围、显式及派生挑空、必要铺板矩形。
- volumes：体量边界、平面中心、底部与屋面承托标高。
- rooms / paths：本次房间与通路世界坐标，供局部任务共同避让。
- stair_routes：已完整定位的 U 形双跑梯段、半平台、完整梯井。
- repetitions：等距零件中心、单件尺寸与整组包络。

楼面矩形先做体量并集去重，再扣显式挑空与已能确定的完整梯井。主体按这些分片铺板，不能以完整包围盒填平庭院，也不能只留下第二跑穿板位置而覆盖第一跑与半平台上空。主体拆分后的 delegated_components 也参与同一推导，使片段验收与整栋图纸保留一致梯井。

U 梯推导适用于明确的单组两跑、一个楼层连接、完整世界定位与占地、单跑宽度、平台进深和第一跑方向。支持 +X / -X / +Z / -Z；已明确的 rises/riser_height/tread_depth 必须相容。选择了 max_riser_height 且未固定级数时推导整数级数。其他楼梯形式继续由模型实现，不伪称已有统一精确解；必要挑空仍可在图纸明确声明。

板厚必须小于对应层间高差。输入矛盾返回设计修订，不裁小尺寸、不扩大容差、不改批准设计，也未提高调用或重试预算。

## 三、设计怎样交给实现

主线仍为 `architecture → material_plan → design_review → plan → execute / replanner → compile → final_validate`。

architecture 提示词增加空间构图、室内外联系、围护虚实与本次构造/材料决定的要求，同时说明新字段。设计中的关键分格、截面、间距和颜色应先确定；execute 按图实现与计算，不再次选择整栋建筑的主题。

[resolver.py](../../wild-server/app/design/resolver.py) 与 [planning.py](../../wild-server/app/agent/generation/architecture/planning.py) 都保留 floor_layouts、construction、circulation 的扩展数据以及材料定义，避免图纸在归一化或回传时丢字段。新空间字段纳入原 structure 修订块、补丁越权检查与设计检查根，不新增节点。

[implementation.py](../../wild-server/app/agent/plan/implementation.py) 为任务提供上述几何事实、房间/通路、连接目标坐标和重复零件中心。connections 目标加入标记依赖，并通过落实记录对应到真实实体 ID。已采用片段仍保留，失败反馈继续定位当前标记。

命名材质在批准后的 plan 阶段进入全局材料表；与角色材质重名且参数不同会反馈冲突。局部实现可引用这些定义，但不能重定义已采用的同名材料。其他局部材质仍使用原有内容绑定与并发合并机制。material_bindings 按当前引擎 Schema 中实际存在的字段应用；不能映射的组合列待复核，不发明 WILD 字段。

## 四、验收增加了哪些证据

片段与最终候选共用 [relations.py](../../wild-server/app/design/relations.py) 的几何事实与连接核对：

- 重复矩形组的数量、单件中心、尺寸与整体包络。
- 原生或组合实体可测的世界整体中心，防止相互连接后整体漂移仍被接受。
- 柱、梁、楼板、盒体、门窗洞口和平屋面等可测包络的边界坐标对齐；门底与露台板顶可直接核对。
- 明确材料字段引用对应的命名材质定义。
- 矩形主体必要楼面的实际覆盖、挑空保留及明确构造尺寸。

connections 当前证明同轴边界坐标，不证明投影接触面积或荷载安全。曲面、装饰柱头和未知组合的精确包络缺少判据时保留 needs_review，不用整体数量替代关系证据。

[spatial_review.py](../../wild-server/app/design/spatial_review.py) 在最终装配后检查声明的水平通路。使用连续线段净空与有限实体的相交判据，包含直墙、矩形体、绕 Y 旋转家具的名义占地和现代等半径柱。门与普通 opening 扣除可通行区，窗不作为通道；门框宽度计入净宽。

未知形态有可定位包络时，只影响相交的路线；完全无法定位的形态保持待复核。简单平移实例按引擎模板规则展开，其他变换、局部门窗实例和表面排布保持待复核；柱头、鼓肚等不能以名义半径排除碰撞。此检查不证明完整导航、路面支承、弯角扫掠、门扇开启、渲染器派生线脚或任意网格碰撞。非法实体导致无法解析时报告失败，不签发空间通过。

通路阻挡进入最终错误；未知形态进入逐路线履约缺口。不会缩窄路径、降低净高或自动搬家具。记录写入原 `validation_snapshot.spatial_review` 和履约报告；校验器版本为 1.1，投影版本为 drawing-projection/2，旧结论不能替代本轮证据。

## 五、视觉审核使用哪一个文件

[vision/workflow.py](../../wild-server/app/agent/vision/workflow.py) 现在要求实际装配的 `--blueprint`。它保留输入 WILD 的原始字节、SHA-256、语义指纹和图纸 hash；可用 `--snapshot` 核对设计与产物绑定。没有提供快照时明确标记绑定未提供。

渲染输入不再经旧 `compile_document` 从图纸重建。manifest 必须匹配实际输入字节。填写过的人工评价仍校验截图及上下文指纹；输出 revision_request，交回既有设计修订、审核和标记实现流程。没有重新实现候选与重新渲染，就不自动宣布视觉改善。

原有有界视觉修订库需要调用方提供当前实现/装配函数 realize；缺少入口时保留实际基线，返回 review_required，不默默用旧离线编译器生成替代品。

最终校验继续将真实渲染与人工评价是否完成如实分开报告；没有把几何代理评价伪装成看图。本轮未增加自动浏览器服务、额外 Agent 节点或额外模型调用。
