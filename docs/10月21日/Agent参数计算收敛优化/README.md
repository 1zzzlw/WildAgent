# Agent 参数计算收敛优化

本轮按用户要求减少模型重复填写可计算参数，清理错误驱动的提示词追加，把参数齐全的受支持构件交给程序生成。本轮不运行测试、构建、服务、模型生成、Embedding 或渲染；当前状态是源码与文档交付，运行效果待用户验证。

比较基准为本轮开始时的 [修改前.zip](修改前.zip) 和 [指纹](修改前指纹.json)，保留此前尚未提交的代码。[本轮差异](本轮差异.patch) 与 [增删和静态检查统计](静态检查与增删统计.json) 不把已有脏工作区的全部改动算成本轮成果。

## 模型和程序各负责什么

| 内容 | 本轮职责 |
| --- | --- |
| 布局、形制、用途、层高、构件形式、占地、截面、间距和材料选择 | 模型作设计取舍 |
| 总体宽深 | 缺省时按全部体量计算包络；显式值保留为总体尺寸上限 |
| 建模层数与表达方式 | 缺省时由 floors / modeled_floors 计算；显式不一致继续拒绝 |
| 立面 bays | 两个 pattern 等长且非空时由长度计算；显式不一致继续拒绝 |
| 楼层标高、板底与必要楼板分片 | 沿用统一计算，体量并集减挑空，不填平庭院或梯井 |
| 已定位 U 形双跑 | 由平面中心、连接楼层、占地、梯宽和平台深度计算中心Y、总高、两跑、平台与完整梯井；已选级数、最大级高、级高和踏步进深继续作为约束 |
| 重复矩形构件 | 由数量、中心距、截面与整组中心生成单件坐标 |
| 参数完整的受支持构件 | 程序生成真实 WILD，再走原片段验收与最终校验 |
| 未覆盖的造型或参数不齐 | 保留模型实现通道，不能删掉设计要求以命中程序实现 |

原生屋面可在 roof.height/thickness 选择高度与厚度，程序从宿主体量、出檐和墙顶推导覆盖尺寸与安装标高；参数不足或特殊屋型仍交模型实现。

新增楼梯入口 `placement.plan_position:[X,Z]`，与楼层连接一起推导中心Y。旧三维 position 仍有效，同时填写必须一致。此入口当前只适用于完整定位、单连接的U形双跑，其他形式不能静默忽略它。显式填写的级高或占地若冲突，仍要求修订设计，没有删除约束、扩大容差或自动移动构件。

## 入口改动

- [normalization.py](../../../wild-server/app/design/normalization.py) 增加唯一的缺省参数补算入口，供正式契约、图纸保存和既有归一化共用。保存时记录派生来源，不原地修改输入。
- [contracts.py](../../../wild-server/app/design/contracts.py) 保留完整保存契约，投影模型输入 Schema；去掉复杂度状态、配额和材质解析结果，字段类型与数值边界仍来自正式契约。[输入 Schema](模型设计输入.schema.json) 已导出，不再手写另一份字段示意表。
- [coordinates.py](../../../wild-server/app/design/coordinates.py) 负责统一计算；[compilation.py](../../../wild-server/app/design/compilation.py) 在输入可计算时一起反馈房间和楼梯独立冲突。
- [realization.py](../../../wild-server/app/design/realization.py) 是纯参数实现器，当前覆盖条件明确的承重墙矩形主体、完整U形双跑、等距矩形条板、参数齐全的原生门窗和屋面。额外轮廓、未知字段、独立主体结构、模糊材料和未解析依赖继续保留模型通道。
- [implementation.py](../../../wild-server/app/agent/plan/implementation.py) 在现有 generate 中优先尝试程序实现。两种来源共用宿主安装、共用墙处理、材质绑定和片段验收；落实记录区分 source=program/model。程序失败保留错误、失败稿与已通过片段，不调用模型重算；主体失败继续停止附属生成。
- [relations.py](../../../wild-server/app/design/relations.py) 统一核对已计算的两跑路线、宽度与明确踏步约束，替换执行器中的另一份方向检查。未知组合和没有明确ID映射的描述性材料继续列待复核。

主线节点不增加。投影版本为 drawing-projection/3，校验器为 1.2，能力说明为 p6b.2；旧投影与验收快照不能替代本轮判据。

## 实际删除和收敛的内容

1. 删除 architecture 的手写字段示意表和重复专项注意事项，以契约投影提供类型协议。
2. 删除 execute 按主体、门窗、屋顶、雨棚、栏杆、楼梯逐类追加的长提示，以及已提供 Schema 后再重复列字段的文字。保留真实 WILD 坐标语义和宿主事实。
3. 删除按 roof 数组、size、face、offset、host 等错误种类追加的修订教程；直接反馈契约路径和事实。
4. 删除木、石、金属等材料关键词分类硬拦截函数。明确ID与绑定继续检查，自然语言语义不靠扩充词表判定。
5. 删除每次设计修订时再次检索规则的路径，以及同一知识实体的重复查询。
6. 删除根据错误文字出现 host/facades 等词扩大修订权限的分支，以及 floor_layouts 出错就开放全部 components 的联动。范围来自错误路径及关系上下文的明确可编辑路径。
7. 删除房间冲突反馈中“可以改成哪个尺寸”的示例计算和邻居建议；保留相交墙段、房间边界与路径。
8. 清理旧 layout.shared_footprint 等不适用于当前主线的要求，知识文档同步为同一职责边界。

严格外层 JSON 解析、稳定ID、补丁越权检查、完整候选验收、明确设计冲突和既有调用上限继续保留。语法修订与设计修订分别标记；前者关闭思考，后者沿用用户设置。没有追加节点、配置项或重试次数。
