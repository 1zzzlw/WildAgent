# 组合构件编译器：完整流程实例

> 从一个带门的 Blueprint 出发，追踪每一行源码，展示编译器如何将 `door` 组件变成渲染引擎能消化的基础元素。

---

## 起点：一份带门的 Blueprint

用户在编辑器中拖入一堵墙和一扇门，生成的 Blueprint 如下：

```json
{
  "meta": { "version": "1.1", "type": "building", "name": "测试小屋" },
  "geometry": {
    "elements": [
      {
        "type": "wall", "id": "wall_front",
        "from": [0, 0, 0], "to": [6, 3, 0],
        "thickness": 0.3, "material": "wood"
      }
    ],
    "components": [
      {
        "type": "door", "id": "front_door",
        "parentWall": "wall_front",
        "from": [2.4, 0.0, 0],
        "width": 1.2, "height": 2.2,
        "frameMaterial": "wood",
        "leafMaterial": "door_wood",
        "interaction": { "mode": "swing", "hingeSide": "left", "openAngle": 90 }
      }
    ]
  },
  "materials": {
    "wood": { "baseColor": [0.55, 0.27, 0.07], "roughness": 0.7, "metallic": 0.0, "albedo": 1.0, "lightingCondition": "D65_noon" },
    "door_wood": { "baseColor": [0.38, 0.16, 0.06], "roughness": 0.72, "metallic": 0.0, "albedo": 1.0, "lightingCondition": "D65_noon" }
  },
  "behaviors": {}
}
```

注意：`wall` 在 `geometry.elements` 中，`door` 在 `geometry.components` 中。这是关键区别。

## 第 4 步：compileDoor() — 把门拆成 4 个基础元素

**文件**：[`wild-compiler/components/door.ts:16-68`](wild-web/src/wild-compiler/components/door.ts#L16-L68)

### 4.1 解析父墙，建立局部坐标系

```typescript
const frame = resolveStraightWallFrame(component, context)
// 输入: component = { parentWall: "wall_front", from: [2.4, 0, 0], width: 1.2, ... }
//       context.elements = [wall_front]
// 
// 过程:
//   1. 在 context.elements 中找到 id="wall_front" 的元素
//   2. 确认它是 wall 类型
//   3. 计算墙体路径: from=[0,0,0] → to=[6,3,0]，长度=6m
//   4. 验证门的位置: along=2.4, width=1.2 → 2.4+1.2=3.6 ≤ 6 ✓
//   5. 建立沿墙坐标系:
//      - pointAt(along, worldY, normalOffset): 沿墙某位置的世界坐标
//      - directionAt(along): 沿墙方向向量
//      - normalAt(along): 墙体法线方向
```

这个坐标框架（[`attachedToWall.ts:31-122`](wild-web/src/wild-compiler/components/attachedToWall.ts#L31-L122)）是整个编译器最重要的基础设施。它让所有依附墙体的组件（door/window/canopy/balcony/bay_window）不需要自己处理曲线路径、坐标系转换。

### 4.2 生成 4 个基础元素

```typescript
// ① 墙体洞口（覆盖几何）
const opening = {
  type: 'opening',                    // ← 这是引擎认识的 11 种基础类型之一
  id: 'front_door__opening',         // ← 确定性派生 ID（组件ID + "__opening"）
  parentWall: 'wall_front',
  from: [2.4, 0.0, 0],              // ← 沿墙距离，直接来自组件的 from
  width: 1.2,
  height: 2.2,
  style: 'rectangular',
  material: 'door_wood',
  _interaction: {                     // ← 运行时行为数据，透传给 renderer
    kind: 'opening',
    mode: 'swing',
    pivot: [2.4, 1.1, 0],           // ← 铰链在左侧
    closedPosition: [3.0, 1.1, 0],
    closedRotation: [0, 0, 0],
    openRotation: [0, 1.57, 0],     // ← 90° = π/2 弧度
    initiallyOpen: false,
  }
}

// ② 左边门框
createBox(
  'front_door__frame_left',           // ← ID = 组件ID + "__frame_left"
  frame.pointAt(2.44, 1.1, 0),       // ← 沿墙 2.44m, 高 1.1m, 法向偏移 0
  [0.08, 2.2, 0.34],                 // ← 宽 8cm, 高 2.2m, 深 34cm
  frame.rotationAt(2.44),            // ← 旋转对齐墙体方向
  'wood',                             // ← frameMaterial
)

// ③ 右边门框
createBox(
  'front_door__frame_right',
  frame.pointAt(3.56, 1.1, 0),       // ← 沿墙 3.56m (= 2.4 + 1.2 - 0.04)
  [0.08, 2.2, 0.34],
  frame.rotationAt(3.56),
  'wood',
)

// ④ 顶部门框
createBox(
  'front_door__frame_top',
  frame.pointAt(3.0, 2.16, 0),       // ← 沿墙 3.0m (居中), 高 2.16m
  [1.04, 0.08, 0.34],                // ← 宽 1.04m (内宽), 高 8cm, 深 34cm
  frame.rotationAt(3.0),
  'wood',
)
```

返回值是 `[opening, frame_left, frame_right, frame_top]` — 4 个引擎认识的基础元素。

## 第 5 步：回到主循环 — 校验 + 追加

**文件**：[`wild-compiler/index.ts:80-93`](wild-web/src/wild-compiler/index.ts#L80-L93)

```typescript
// 校验：生成的元素 ID 不能与已有元素冲突
const generatedIds = new Set<string>()
for (const element of generated) {
  if (generatedIds.has(element.id) || usedIds.has(element.id)) {
    throw new Error(`编译结果 element.id 冲突: ${element.id}`)
  }
  generatedIds.add(element.id)
}

// 追加到 elements 数组
elements.push(...generated)
// elements 现在是: [wall_front, front_door__opening, front_door__frame_left, 
//                    front_door__frame_right, front_door__frame_top]

// ★ 记录 ID 双向映射
mapping.generatedElementIdsByComponentId['front_door'] = [
  'front_door__opening',
  'front_door__frame_left',
  'front_door__frame_right',
  'front_door__frame_top',
]
for (const id of generatedIds) {
  mapping.componentIdByGeneratedElementId[id] = 'front_door'
}
```

**进入引擎**：[`wild-core/src/primitive/index.ts:232-279`](wild-web/src/wild-core/src/primitive/index.ts#L232-L279)

```typescript
export async function reconstructEntity(bp: Blueprint): Promise<ReconstructedEntity> {
  bp = normalizeBlueprintInput(bp) as Blueprint  // 归一化（hex→RGB等）

  let elements = expandTemplates(bp, diagnostics)  // 展开模板实例
  elements = resolveSpatialRelations(elements)      // 墙角闭合、梁柱吸附等

  // ★ 逐元素调用 builder
  for (const el of elements) {
    const registration = getElementBuilder(el.type)
    // el.type="wall"      → buildWall()
    // el.type="opening"   → buildOpening()
    // el.type="primitive" → buildPrimitive()  (shape="box")

    const meshes = registration.build(el)
    // 每个 builder 返回 MeshData[]（顶点、法线、索引、材质引用）
  }
}
```

引擎只知道 11 种基础 type。它看到 `"opening"` 和 `"primitive"`，完全不知道这些是从 `"door"` 编译而来的。

**文件**：[`componentSelection.ts:4-8`](wild-web/src/wild/componentSelection.ts#L4-L8)

```typescript
export function resolveSelectableId(elementId: string, mapping: ComponentCompilationMapping): string {
  // 查映射表：如果这个 element 是某个 component 编译出来的，返回 component ID
  return mapping.componentIdByGeneratedElementId[elementId] || elementId
}
```

这一步是关键——用户在 3D 视口里点击门框上的一个 box，编辑器实际选中的是 `"front_door"` 这个组件，属性面板显示的是门的参数（width/height/material），而不是一个 box 的参数。

### 9.2 高亮整个组件

## 总结：编译器的真正价值

从这个实例可以看出，编译器做了三件渲染引擎做不到的事：

1. **坐标计算**：`resolveStraightWallFrame()` 处理了直线墙、圆弧墙、椭圆弧、悬链线的路径采样和坐标系建立。这些逻辑如果放在 11 个 builder 里，要么每个 builder 都复制一遍，要么引擎要引入"父构件依附"的通用抽象——这会让引擎变得非常复杂。

2. **语义保留**：编译后 Blueprint 中的 `"door"` 虽然被删除了，但 ID 映射让前端可以追溯。用户在编辑器中操作的始终是 `"front_door"` 这个门组件，而不是 4 个互相无关的 box。

3. **错误定位**：如果门参数有问题（比如超出了墙体范围），`ComponentCompileError` 能精确指出是 `from` 字段的问题。如果让引擎 builder 来报错，它只能报告 `ELEMENT_BUILD_FAILED`，用户不知道是哪个参数写错了。
