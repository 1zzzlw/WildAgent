## 3. 本地开发环境

### 3.1 前提

- Node.js ≥ 22
- Python ≥ 3.12
- Docker Desktop（可选，本地运行容器用）

### 3.2 启动前端

```bash
cd wild-web
npm install
npm run dev
# → http://localhost:5173
```

### 3.3 启动后端

```bash
cd wild-server
uv sync
uv run uvicorn main:app --host 0.0.0.0 --port 8000
# → http://localhost:8000
```

### 3.4 本地 Docker 验证

确认 Dockerfile 没问题（可选）：

```bash
# 根目录
docker compose up -d
# → 前端 http://localhost
# → 后端 http://localhost:8000

docker compose down    # 停止
```

## 4. 环境变量管理

### 4.1 不提交 .env 到 Git

```bash
# 三步完成
echo ".env" >> .gitignore
git rm --cached wild-server/.env
git commit -m "从仓库移除 .env"
```

> **为什么**：`.gitignore` 只管"还没被追踪的新文件"，对已经被 `git add` 过的文件无效，必须用 `git rm --cached` 移除追踪。

### 4.2 GitLab CI Variables 配置

去 GitLab 项目 → **Settings → CI/CD → Variables**，添加以下变量（勾选 Protected + Masked）：

| Key | 用途 |
|---|---|
| `SSH_PASSWORD` | 服务器 root 密码 |
| `CHAT__NAME` | LLM 模型名 |
| `CHAT__API_KEY` | LLM API Key |
| `CHAT__BASE_URL` | LLM API 地址 |
| `EMBEDDING__NAME` | Embedding 模型名 |
| `EMBEDDING__API_KEY` | Embedding API Key |
| `EMBEDDING__BASE_URL` | Embedding API 地址 |

> `$CI_REGISTRY_USER` 和 `$CI_REGISTRY_PASSWORD` 是 GitLab 内置变量，不需要手动添加。

## 5. 各文件说明

### 5.1 `wild-server/Dockerfile` — 后端镜像

```dockerfile
FROM python:3.12-slim                    # 基础镜像
COPY --from=ghcr.io/astral-sh/uv:latest /uv /usr/local/bin/uv   # 安装 uv
COPY pyproject.toml uv.lock ./           # 先复制依赖文件（利用缓存）
RUN uv sync --frozen --no-dev            # 安装依赖
COPY . .                                 # 复制源码
CMD ["uv", "run", "uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**与 Java 对比**：Python 不需要"先在本地打包 JAR 再复制到 Docker"。Dockerfile 本身就是一份完整的构建菜谱，所有步骤都在容器内完成。

### 5.2 `wild-web/Dockerfile` — 前端镜像（含 nginx）

```dockerfile
# 阶段一：构建 Vue 项目
FROM node:22-alpine AS builder
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build              # → dist/

# 阶段二：nginx 运行
FROM nginx:alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf    # 覆盖默认配置
COPY --from=builder /app/dist /usr/share/nginx/html  # 复制静态文件
EXPOSE 80
```

### 5.3 `wild-web/nginx.conf` — 反向代理规则

| 请求路径 | 处理方式 |
|---|---|
| `/` | 返回 Vue 静态文件（SPA fallback） |
| `/api/*` | 代理到 `wild-server:8000`（HTTP API） |
| `/ws/*` | 代理到 `wild-server:8000`（WebSocket，带 Upgrade 头） |

### 5.4 `.gitlab-ci.yml` — CI/CD 流水线

```
stages: build → deploy

build-server  ┐
              ├─ docker build → docker push（推送镜像到 GitLab Registry）
build-web     ┘

deploy        ── SSH 登录 39.106.183.13 → docker pull → 重启容器
```

#### 关键设计

- **只改前端 = 只构建前端镜像**，反之亦然（`only: changes` 规则）
- **deploy 只在 main 分支触发**，其他分支只构建不部署
- **API Key 不写死在文件里**，通过 `$变量名` 从 GitLab Variables 注入

### 5.5 `docker-compose.yml` — 本地开发

```yaml
services:
  server:
    build: ./wild-server        # 从本地 Dockerfile 构建
    ports: ["8000:8000"]
    env_file: .env              # 读取本地 .env

  web:
    build: ./wild-web
    ports: ["80:80"]
    depends_on: [server]        # 等后端启动完再启动前端
```

## 6. 完整操作流程

### 第一步：本地开发 + 测试

```bash
cd wild-server && uv run uvicorn main:app     # 启动后端
cd wild-web && npm run dev                    # 启动前端
```

### 第二步：提交代码

```bash
git add .
git commit -m "feat: 添加 Dockerfile 和 CI 配置"
git push origin main
```

### 第三步：GitLab 自动执行

1. `.gitlab-ci.yml` 被触发
2. **build 阶段**：构建 Docker 镜像 → 推送到 GitLab Registry
3. **deploy 阶段**：SSH 到服务器 → 拉取镜像 → 停旧启新

### 第四步：验证

```bash
# 浏览器访问
http://39.106.183.13          # 前端
http://39.106.183.13:8000     # 后端 API

# SSH 到服务器查看
ssh root@39.106.183.13
docker ps                     # 应该看到 wild-server 和 wild-web
docker logs wild-server       # 看后端日志
```

### 第五步：后续更新

以后每次改完代码，只需要：

```bash
git add . && git commit -m "xxx" && git push
```

剩下的 GitLab 全自动搞定。

## 7. 常见问题

### Q: Python 有没有像 Java JAR 那样的打包命令？

A: 有 `uv build` 打 wheel 包，但那是给**库/模块**用的。Web 服务不需要——Dockerfile 就是打包方式，所有依赖安装和代码构建都在容器里完成。

### Q: nginx 需要手动在服务器上安装吗？

A: 不需要。`wild-web/Dockerfile` 以 `FROM nginx:alpine` 为基础，nginx 已经内嵌在镜像里了。

### Q: .gitignore 写了 .env 为什么还被提交？

A: `.gitignore` 只管"还没追踪的新文件"。已经被 `git add` 过的文件不受影响，必须用 `git rm --cached` 从索引中移除。

### Q: TypeScript 编译报错但运行没问题是怎么回事？

A: 前端类型定义（`src/types/scene.ts`）与 wild-core 实际输出的字段名不一致（如 `positions` vs `geometry`）。运行时 JS 不检查类型，所以能跑；编译时 TS 严格检查，所以报错。修复方式：让类型定义对齐运行时实际数据。
