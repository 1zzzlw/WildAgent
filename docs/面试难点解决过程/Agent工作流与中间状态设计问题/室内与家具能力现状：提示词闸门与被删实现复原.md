## 二、为什么这 10 处不能现在改（顺序红线）

`docs/面试难点解决过程/Agent工作流与中间状态设计问题/动态节点设计规划.md` §1.5
标题就叫「对既有闸门的影响（**顺序红线**）」，原文：

> - 本能力落地前，`_UNSUPPORTED_INTERIOR_TERMS` 里那四个词条**必须继续标 unsupported**，不得提前放行。
> - 只有在 P2 的房间层通过 §1.4 全部八条之后，才允许把对应词条从 unsupported 表移除。
> - **不得先改闸门再补能力**——那会造成"闸门放行、但没有任何节点能实现"，正是《能力闸门分级》§2 记录过的那类事故。

而房间层**目前尚未实现**（`grep -rn "\broom\b" wild-server/app/` 零命中；
`detail_level` 也还没进 schema）。

**结论**：这 10 处不是遗漏，是刻意留的、且带移除前置条件的。现在改任何一处都会踩自己定的红线。
改动的正确时机是 **P2（"接 LLM 节点 + 房间层 + 档位"）落地并 §1.4 八条全绿之后**。

### 4.2 `dynamic/furniture.py` 的原始设计（从 pyc 复原）

模块 docstring 原文：

> 审核态平面图的家具布置（确定性，纯几何）。
>
> 为什么值得做：一张只有色块的平面图和一张摆着床、沙发、餐桌的平面图，给人的"专业感"差一个量级。
> 家具是让人一眼认出"这是建筑图"的最短路径。
>
> 为什么只放在审核态：**蓝图里没有房间信息（房间只存在于 design schema），所以交付态渲染器拿不到房间类型，无法判断该摆什么**。
>
> 档位如何控制精细度（与 §2.2.2 的"档位 = 精细程度"一致）

#### 公开 API

```python
plan_furniture(
    room_type: str,
    bounds: tuple[float, float, float, float] | None,   # (x1, z1, x2, z2)
    detail_level: str = 'standard',
) -> list[dict[str, Any]]      # 元素含 label / shape / rect
```

反汇编出的局部变量顺序，确认了计算链路：

```
x1, z1, x2, z2 = bounds
room_w, room_d = x2-x1, z2-z1
for tier in FURNITURE_TIERS[detail_level]:
    for (label, width, depth, cx_ratio, cz_ratio, shape) in FURNITURE_BY_ROOM[room_type][tier]:
        cx = x1 + cx_ratio * room_w
        cz = z1 + cz_ratio * room_d
        left, top = cx - width/2, cz - depth/2
        # 越界 → 整件不摆（不做缩放）
```

#### 家具表 `FURNITURE_BY_ROOM`

元素格式：`(标签, 宽, 深, cx_ratio, cz_ratio, 形状)`，
其中 `cx_ratio` / `cz_ratio` 是**相对房间的居中比例**（0~1），形状取 `rect` / `oval` / `dashed`。

| 房间类型 | 家具（标签 / 宽 × 深 / 比例 / 形状） |
|---|---|
| `bedroom` | 床 2.0×1.6 @(0.5, 0.42) rect；床头柜 0.5×0.5 @(0.28,0.12) 与 @(0.72,0.12) rect；衣柜 0.6×1.8 @(0.88,0.62) rect；地毯 1.8×2.4 @(0.5,0.5) **dashed** |
| `living` | 沙发 2.2×0.9 @(0.5,0.18) rect；茶几 1.2×0.6 @(0.5,0.42) rect；电视柜 1.8×0.4 @(0.5,0.88) rect；地毯 2.8×1.8 @(0.5,0.35) **dashed** |
| `kitchen` | 冰箱 0.7×0.7 @(0.12,0.9) rect；餐桌 1.4×0.9 @(0.5,0.5) rect；椅 0.45×0.45 ×4 @(0.36,0.36)/(0.36,0.64)/(0.64,0.36)/(0.64,0.64) rect |
| `bathroom` | 淋浴 1.2×0.9 @(0.5,0.2) rect；洗手盆 0.7×0.5 @(0.25,0.72) rect；坐便 0.45×0.7 @(0.72,0.72) **oval** |
| `garage` | 车位 2.6×5.0 @(0.5,0.5) rect |
| `circulation` | 楼梯示意 1.2×2.6 @(0.5,0.5) **dashed** |

表中仅 6 种房间类型 ⇒ `storage` / `service` 等**无家具表，不猜、不摆**。
（规划 §1.3 的房间类型枚举是 8 种，家具表覆盖其中 6 种。）

#### 档位映射 `FURNITURE_TIERS`

档位名与规划 §2.2 的 `detail_level` 四档**完全一致**：

| 档位 | 启用分级 | 语义（来自已删测试） |
|---|---|---|
| `minimal` | （空） | "低档位不摆家具——档位控制的是精细程度，低档就该是干净的体块" |
| `simple` | `main` | 主体 |
| `standard` | `main, secondary` | 主体 + 配角 |
| `detailed` | `main, secondary, tertiary` | 再加细节 |

#### 已删测试钉住的四条规则

取自 `test_furniture.py` 的用例名与文档字符串：

1. `test_low_granularity_has_no_furniture` —— 低档位不摆；

4. `test_furniture_is_skipped_when_it_does_not_fit` —— **"放不下就整件不摆，不做缩放——缩放的家具尺寸是假的"**；
