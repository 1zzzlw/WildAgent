# Agent 工作流与中间状态设计问题：实施记录（2026-09-06）

> 文档性质：一次已完成工作包的证据记录。按[统一实施路线与验收](../统一实施路线与验收.md)第 7 节口径记录：触发需求、修改范围、同条件前后结果、反例与未处理边界。本文不把目标收益写成已取得效果之外的承诺。

## 1. 触发需求与现象

用户报告两类问题，均与本文档专题对应：

1. **生成建筑错误多**：真实会话（2026-09-06，session_1788606267543）中模型在平面链产出几十个空间与 13 面内墙后，`floor_validate` 后只剩“2 个空间、0 面内墙、0 洞口”，提示 `内墙 spatial_wall_1_wall_L1_A 没有位于两个空间的公共边界上`，整份设计退化为确定性故障预览，且后续 revise 循环“盲跑”不收敛。
2. **启动阻塞**：服务启动（fastapi dev --reload）时 RAG 索引同步在模块导入路径上同步执行，单批 embedding 30s 超时被硬编码、无重试无预算，启动被阻塞 5～15 分钟甚至降级为 FileSpecLoader（日志：APITimeoutError / httpcore.ReadTimeout，37 批拉锯）。

## 2. 根因定位（源码审计结论）

| 现象 | 根因（文件:行） |
|---|---|
| 模型设计整体消失 | `normalize_spatial_plan` 在几何校验残留任一错误时整份替换为 1 空间/层模板（`spatial_plan.py` 原 821-829）；`_repair_plan_geometry` 只修墙不修空间，且贴外轮廓的“内墙”永远过不了两侧探针校验（`spatial_plan.py:996-1029` 语义与 `wall_derivation` 只吸端点的实现不一致） |
| revise 盲跑 | 平面审核失败后回 `floor_space_analysis` 重跑整条链，但新四节点 prompt 均不含 `floor_plan_feedback`/上一轮校验问题（仅旧 `floor_plan_design_node` 消费 feedback） |
| 回退原因不可诊断 | 只把首个几何错误 message 塞进 `fallback_reason` |
| 启动阻塞/超时 | `RAGSpecLoader.__init__(auto_sync=True)` → 同步 `sync_index()`（`loader.py`）；embedding 超时 30s/max_retries=0 硬编码且不消费 `config.embedding.timeout`；3 连超时 raise → agent_service 永久降级 FileSpecLoader，与“部分可用”语义矛盾；无跨进程去重 |
| 图/代码冗余 | graph 中 11 个单组件节点文件 import 不存在的 `create_component_node`（既死且坏）；`graph.py` 的 `skeleton_generator` 重绑定造成“nodes 侧是旧 LLM、graph 侧是确定性装配器”的命名分裂；gen→val 兼容链注释/日志宣称“兼容路径”与实况不符；`web_research_node` 由模块改成函数后测试仍按模块属性打补丁（测试失配） |

## 3. 修改范围（本次工作包，均未改动用户 .env）

### 3.1 生成错误链（spatial_plan.py / floor_validate_node.py / 三个平面节点 / prompts.py）

- `_repair_plan_geometry` 扩展为四步确定性局部修复（新增 `_classify_interior_wall`、`_rebind_opening_host`、`_space_contains`）：
  - 贴组合轮廓的“伪内墙”按外墙归类保留（`kind=exterior`），不再作为内墙报错；
  - 越出轮廓/悬空的模型内墙剔除（需要时从空间公共边界重新推导），不再整份回退；
  - 宿主墙被删的洞口重挂到语义匹配的墙，并限幅 offset/width，消除连锁的 `missing_opening_host`/`opening_outside_host`；
  - 判定与 `validate_spatial_plan` 探针语义保持一致（函数注释标明同步维护）。
- 整包回退仍保留（覆盖缺口/重叠等空间级问题），但 `fallback_reason` 现在合并全部几何问题（去重、≤6 条）而非首条；`floor_validate_node` 的 notice 附带回退原因。
- `prompts.floor_revision_instruction(state)`：revise 循环把上一轮审核反馈+未通过校验问题注入 floor_space_analysis/floor_layout/floor_openings 的用户消息（无修订时返回空串，不增加常规生成成本）。

### 3.2 RAG 启动阻塞（loader.py / config.py / agent_service.py / .env.example）

- `RAGSpecLoader` 构造默认不再同步全量索引（AgentService 显式传 `auto_sync=False`），新增 `start_background_sync()`（守护线程、进程内单飞、有限退避重试）与 `sync_status` 观测；同步失败保留“部分可用”索引，不再整体降级弃用。
- `sync_index` 新增 `raise_on_stall=False`（连续 3 批超时只停止本轮、剩余保留待同步）与 `budget_seconds`（时间预算，默认未用）；默认 `raise_on_stall=True` 保持既有语义，原 sync 单测全部不变通过。
- embedding 网络参数可配：新增 `EmbeddingModelConfig(timeout=90, max_retries=2)`（`config.embedding` 独立于 chat），`create_embedding_function` 透传；`_embed_batch` 对 APITimeoutError/连接错误做指数退避重试。
- 跨进程同步互斥：persist_dir 下 `.wild_rag_sync.lock` 字节锁（Windows msvcrt / POSIX fcntl），dev reload 父/子进程不再并发写同一 Chroma；`RAG__AUTO_SYNC=false` 可关。
- 启动验证：RAG 开启（hash 模式探针）构造 ~4.6s 返回、531 块后台 3.7s 完成，import 不再阻塞。

### 3.3 图与死代码清理（graph.py / nodes/__init__.py / 删除文件 / 测试）

- 删除 11 个单组件死节点文件（door/window/roof/railing/balcony/canopy/bay_window/cornice/chimney/light/ramp _node.py）及对应残留 .pyc；全仓无引用。
- `nodes/__init__` 导出改名 `legacy_skeleton_generator`，消除与 `graph.py` 内 `skeleton_generator=approved_plan_assembler` 的语义分裂；graph 顶部注释与编译日志改为“gen→val 兼容链仅旧骨架/旧 checkpoint 可达”。
- 修复测试失配：`web_research_node` 改为运行期取 `app.agent.web.create_search_client`（可被 monkeypatch），`test_web_research_gate` 同步更新；`test_callback_targeted_repair` 的 `spec_loader.load_many` 补丁加 `create=True`（兼容 RAG 关闭时 FileSpecLoader 环境）。

## 5. 同条件验证结果

运行环境：Windows，wild-server/.venv Python 3.12，`RAG__ENABLED=false`（离线、不产生真实 embedding 调用），pytest 全量可运行组：

- 基线（改动前同一命令范围）：agent/components 组 1 个失败（test_web_research_gate 失配），其余通过；rag/misc/network 中 20+ 项因沙箱不允许系统临时目录写入（`PermissionError: WinError 5 @ %TEMP%`）无法在本环境运行。
- 改动后：**472 passed, 0 failed**（tests/agent、api、blueprint、components、repair、validators + rag 索引/后台同步/缓存/trace/rerank/query_planner + misc 只读类 + ws network 2 组）。原失配的 web_research_gate、callback_targeted_repair（4 例）、新链 45 例、spatial_plan 32 例全部通过。
- 启动行为探针：`AgentService()` + RAG(hash) 构造 4.6s（原来 import 即 5~15 分钟阻塞），后台同步 531 块 3.7s，`sync_status=ok`；embedding 90s/2 次重试配置生效。
- 手工单例验证：贴轮廓伪内墙场景 修改前 source=deterministic_fallback（1 空间）→ 修改后 source=model、外墙 exterior、几何 0 issue。

## 6. 仍失败或不支持的反例（未处理边界）

1. 空间级错误（空间重叠、覆盖缺口、门 connects 与墙两侧不符、跨层不连通）仍走整包 fallback——确定性模板通道（`recover_confirmable_spatial_plan`/`deterministic_baseline_spatial_plan`）仍未接入生产链路，属文档 P1/P2 范围，需要先定义“模板确认”UI 语义再接线。
2. 沙箱环境本身不允许子进程向 `mkdtemp(0o700)` 目录写入（WinError 5），`tests/network/*(job/session/runtime)`, `tests/assets/test_pbr_assets.py`, `tests/rag` 内 chunking/runtime-controls 等依赖系统临时目录的测试在本机命令行回归时需以常规 Windows 环境执行确认（代码路径未改动，属环境限制）。
3. revise 循环本轮只做了“上下文注入”，未把模型上一轮有效空间程序（FloorPlanIR 程序）作为不可变输入重跑布局；该彻底修复（程序化几何/保留候选重规划）仍待文档 P2 的“模型出程序、程序出几何”方案。
4. 后台同步的进程锁按 Windows 字节锁语义实现（跨进程互斥，同进程二次获取不受影响——进程内由线程单飞保护）。
