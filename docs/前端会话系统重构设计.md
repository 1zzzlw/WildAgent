# 前端会话系统重构设计

> 日期：2026-08-05
> 范围：`wild-web/src/stores/agentStore.ts`、`AIChatPanel.vue`、`agentBridge.ts`、`types/agent.ts`
> 关联后端：`wild-server/app/api/scenes.py` → 新增 `sessions.py`

---

## 一、现状问题（10项）

| # | 严重度 | 问题 | 根因 |
|---|--------|------|------|
| 1 | 🔴 | 切换会话丢失全部聊天记录 | `switchToSession()` 重置 `messages = []`，无持久化 |
| 2 | 🔴 | 会话名称几乎全是"新建筑"，下拉框无法区分 | `createSession` 默认名无意义，下拉框信息量极少 |
| 3 | 🔴 | session_id 从文件名正则解析，格式依赖脆弱 | `basename.match(/^(session_\d+)/)` 依赖文件命名约定 |
| 4 | 🟡 | "草稿模式"体验割裂：提示8秒消失，刷新丢失 | 前端本地创建会话，未同步到服务端 |
| 5 | 🟡 | 刷新页面后所有状态丢失 | 消息/进度/thinking 全在内存中 |
| 6 | 🟡 | 会话列表信息严重不足 | 仅显示 `名称 (N 构件)`，无时间/类型/预览 |
| 7 | 🟡 | 删除按钮无视觉层级，与新建并列 | 破坏性操作没有警告样式 |
| 8 | 🟢 | 后端不可用时不自动恢复 | `fetchSessionList` 返回 null 后不再重试 |
| 9 | 🟢 | 无排序/搜索 | 仅按后端返回顺序 |
| 10 | 🟢 | 删除后跳到 `sessions[0]` 而非最近使用的 | `removeSession` 简单取第一个 |

---

## 二、设计目标

1. **会话可识别**：卡片式列表，含建筑名、类型标签、时间戳、构件统计
2. **消息不丢失**：切换会话保留聊天记录，刷新页面可恢复
3. **身份可靠**：session_id 由后端统一管理，不依赖文件名解析
4. **草稿可恢复**：未保存到服务端的草稿存 localStorage，刷新不丢
5. **删除安全**：有确认步骤，有视觉警告，有撤销窗口

## 三、后端变更

### 3.1 新增 Session API（`app/api/sessions.py`）

```
GET    /api/sessions              → 返回所有会话元数据列表
POST   /api/sessions              → 创建新会话（返回 session_id）
GET    /api/sessions/{session_id} → 获取单个会话详情（含消息历史）
PUT    /api/sessions/{session_id} → 更新会话元数据（名称等）
DELETE /api/sessions/{session_id} → 删除会话及其蓝图文件
```

### 3.2 Session 元数据文件

每个会话在 `storage/sessions/{session_id}.json` 存储：

```json
{
  "session_id": "sess_a1b2c3d4",
  "name": "中式庭院",
  "building_type": "chinese_courtyard",
  "created_at": 1722825600,
  "updated_at": 1722829200,
  "blueprint_file": "2026-08-05/sess_a1b2c3d4_中式庭院.wild",
  "elements_count": 25,
  "components_count": 8,
  "message_count": 12,
  "thumbnail_url": "/api/sessions/sess_a1b2c3d4/thumbnail.png"
}
```

### 3.3 改动要点

- **session_id 由后端生成**（`sess_<uuid8>`），不再由前端 `Date.now()` 生成
- **`GET /api/scenes` 保持不变**，作为兼容旧格式的 fallback
- **消息持久化**：`POST /api/sessions/{id}/messages` 追加消息，`GET` 返回历史
- 不需要缩略图生成（第一版跳过）

### 4.2 消息持久化

**分层策略**：

```
消息存储:
  已保存会话 → localStorage + 后端同步（后端为主）
  草稿会话   → localStorage only
```

**localStorage 结构**：
```
wild_messages:{session_id}  → JSON.stringify(ChatMessage[])
```

**读写时机**：
- 每次 `addMessage` → 即时写入 localStorage
- `switchToSession` → 从 localStorage 恢复消息（不从空数组开始）
- 后端连接可用时 → 启动时从后端同步，合并本地未同步的消息
- 生成完成后 → 批量同步消息到后端

### 4.3 agentStore 重构

**核心变更**：

```typescript
// 旧
function switchToSession(sessionId: string) {
  session.value = {
    session_id: sessionId,
    messages: [],              // ← 丢弃！
    connected: session.value.connected,
  }
}

// 新
function switchToSession(sessionId: string) {
  // 1. 保存当前会话消息到 localStorage
  saveMessagesToLocal(currentSessionId.value)
  
  // 2. 切换 session_id
  currentSessionId.value = sessionId
  
  // 3. 从 localStorage 恢复目标会话消息
  const saved = loadMessagesFromLocal(sessionId)
  session.value = {
    session_id: sessionId,
    messages: saved,           // ← 恢复！
    connected: session.value.connected,
  }
  
  // 4. 清除运行时状态（思考/进度等不持久化）
  clearRuntimeState()
}
```

**新增方法**：

| 方法 | 说明 |
|------|------|
| `renameSession(id, name)` | 重命名会话（同步到后端） |
| `saveMessagesToLocal(id)` | 保存消息到 localStorage |
| `loadMessagesFromLocal(id)` | 从 localStorage 恢复消息 |
| `syncMessagesToServer(id)` | 批量同步消息到后端 |
| `getSessionDisplayName(info)` | 生成展示名称（优先 meta.name → "新建筑"） |
| `getRelativeTime(ts)` | 生成相对时间字符串 |

### 4.4 SessionInfo 类型扩展

```typescript
export interface SessionInfo {
  session_id: string
  filename?: string                // 蓝图文件路径（旧字段，保留兼容）
  name: string
  building_type?: string           // 新增：建筑类型
  created_at: number
  updated_at: number

```

### 4.5 恢复流程重构

```
onMounted:
  1. localStorage 恢复上次使用的 sessionId
  2. GET /api/sessions（新接口）
     ├─ 成功 → 合并服务端列表 + 本地草稿
     │        恢复上次 sessionId 或最新会话
     │        异步拉取消息历史
     └─ 失败 → GET /api/scenes（旧接口 fallback）
              ├─ 成功 → 从文件名解析（兼容旧格式）
              └─ 失败 → 从 localStorage 恢复草稿列表
  3. 加载目标会话蓝图
  4. 恢复消息（后端历史 > localStorage > 空）
```

### 4.6 AIChatPanel.vue 变更

- **移除** `session-bar` 区域（`el-select` + 新建 + 删除按钮）
- **新增** `<SessionListPanel>` 组件引用（放在面板顶部或左侧）
- **保留** 消息列表、Thinking 面板、输入框、连接状态栏（不变）
- 新建/删除操作委托给 `SessionListPanel`

## 六、分阶段实施

- agentStore 加 localStorage 消息存取
- `switchToSession` 不再丢弃消息

### Phase 2：SessionListPanel 组件

- 内联重命名

## 七、关键设计决策

1. **localStorage 为消息主要缓存，后端为持久化**：保证离线可用、刷新不丢、切换不丢
2. **session_id 格式统一**：新格式 `sess_<8位uuid>`（后端生成），旧格式 `session_<timestamp>` 兼容读取
3. **不在此次改动中加缩略图**：需要服务端渲染管线，推迟到后续迭代
4. **保留 `GET /api/scenes` 兼容**：旧格式文件名仍可解析，平滑过渡
5. **草稿会话存 localStorage**：`wild_draft_sessions` key 存储未同步到后端的会话列表
