# 最终模型图纸 → WILD

本目录只针对本次“两层现代别墅”图纸编译，没有修改 Agent 节点或通用编译流程。

- [两层现代别墅.wild](两层现代别墅.wild)：可供项目打开的 WILD 文件，46 个原生元素、24 个组件、12 种材质。
- [02-编译设计图纸.py](02-编译设计图纸.py)：专用作者脚本，仅依赖 Python 标准库。
- [01-设计图纸.json](01-设计图纸.json)：用户最终模型回复解开文本块后的 JSON，设计数据未改。
- [00-模型原始回复.txt](00-模型原始回复.txt)：原始附件内容，保留外层文本块包装。
- [03-编译记录.json](03-编译记录.json)：派生参数、门窗世界坐标、材料实现、假设与原图问题。
- [04-资料与执行记录.json](04-资料与执行记录.json)：读取过的来源、SHA-256、工具与实际执行边界。

在本目录执行可重新生成同名 WILD 与编译记录：

```powershell
python 02-编译设计图纸.py
```

脚本依图纸建立场地、首层和二层板、外围护、14 段内墙、21 个门窗、平屋面/女儿墙、U 形双跑梯及平台、入口雨棚和台阶。整组梯井从二层板扣除；屋面使用原生 flat roof，不重复叠一张楼板。模型未给家具与室内设施，本次没有另行设计。

U 形梯按楼面 `0 → 3.6m`、步高上限 `0.18m` 计算：每跑 10 级、步高 0.18m、每跑水平长 2.8m、中间平台顶 1.8m。扶手取材于图纸中“踏步与扶手”的材质说明，具体截面和 0.95m 高度是脚本的实现约定。材料颜色/粗糙度、门窗型材尺寸、雨棚安装板和板面材料等未给定参数均记录在 `03-编译记录.json`，不冒充模型已经设计过的数值。

## 原图仍有的问题

本次用于观察模型图纸的实际效果，因此没有挪动墙、移动门或重新安排楼梯：

- `o_door_wc / o_door_util` 都在 `w5` 上，开口区间分别为 `0.5..1.4 / 1.0..1.9`，重叠 0.4m。
- 标注的楼梯间仅深 3m，实际楼梯预留区深 4.3m，并越过其西边界。
- 按本次明确的 U 形梯展开，`w14` 沿第一跑中线，`w2` 穿过中间平台。原图只检查了梯组能放进建筑体量，没有保证避开内墙。
- 上层楼梯出口回到 `Z=0` 外墙边，整组预留区又都扣除了二层板；图纸没有完整解决到达板和上层交通。
- 入口台阶按 bottom 锚点展开后顶高为 `+0.15m`，入口门底是 `0m`。
- 按 back 从东向西的定位约定，名称为“厨房北窗”的开口落在 `X=7..11.2`，厨房区域却是 `X=0..6`；改到 `w6` 的 dining_hall1 门也没有因此实现餐厅到过渡间的连接。
- 原路线和复核清单只是设计输入，未被当成真实连通或防护已通过的证明。

这些问题在 WILD 中按原数据保留，编译记录逐项标出。因而本产物适合复现与检查当前图纸，不应把脚本执行成功解释成空间布局已经正确。

## 前两轮错误与执行范围

前一轮 14 个 body 错误来自字段把内墙材质默认设为 body，但图纸没有这个角色；默认引用策略需要改进。第二轮只补了内墙材质，随后报出的门洞越界和路线宽度矛盾在第一稿已经存在，因校验提前退出而分两轮暴露。最终稿虽改正了那些越界数值，仍留下了上面的关系问题。

本次只执行专用编译脚本，并在脚本内检查 ID、材质引用、门窗边界和楼梯算式。没有运行 Agent 测试、真实模型调用、浏览器渲染或真实引擎重建；未声称完整空间检查通过。
