# 10 月 20 日：Agent 流程优化实施记录

这一轮已把“明确参数交给程序，未确定的设计交给模型”接入现有执行入口。尚未达到稳定生成整栋精细别墅的目标。

## 改了什么

- `compilation.py` 增加原生参数转换，`run_marker_generate` 在检索和模型调用前使用它。已明确的普通门窗、矩形板、box，以及参数完整的其他原生构件可以直接转换；特殊形态、缺少参数的构件继续使用原流程。转换结果仍经过原来的完整片段校验。
- `project_drawing` 复用现有空间检查，提前发现显式通路与墙、门洞的冲突。未知墙厚只检查中心线穿越，未知门洞继续待复核，不冒充物理净空验收。
- 灯具材质检查按引擎实际使用的 `body` 材质和回退关系判断；远处球体、圆柱体不再让每条通路都变成待复核，无法计算的形态仍保留待复核。
- 普通门窗、灯具的模型任务减少无关的编程协议上下文。原生参数冲突保留失败证据并阻止交付，不让模型静默改掉已批准设计。

仍使用现有节点、设计字段、构件注册表和引擎 Schema；没有增加节点、重试额度或第二套设计协议。本轮代码净增加，主要是必要的转换与校验；没有宣称完成整体代码精简。

| 14 项回归 | 通过，含不同墙向、宿主改名/反向、标高、尺寸冲突、缺参回退、失败保留及灯体材质 |

| 图纸前置检查 | 同一历史图纸的入口路线与门、内墙矛盾在执行前被检出；没有重新批准错误图纸 |
| 真实引擎检查 | 历史主体加上述 4 扇转换窗的局部候选，编译/重建均 0 错误；这不是整栋建筑验收 |
| 一次完整生产图试跑 | 标准粒度，实际调用分类器与图纸模型，共 4 次；约 60 秒后因图纸通路冲突停止，未进入材质、构件生成和渲染，没有产生新的完整别墅 |
| 静态检查 | 修改的 Python 文件语法检查、`git diff --check` 通过 |

真实试跑使用独立会话 `codex_flow_check_1792459663` 和内存 checkpoint。脚本预设的诊断自动确认没有触发，实际确认次数为 0。首次检索索引后台初始化报错，原有后台重试随后完成同步；没有为此改动检索代码。它不改变此次明确的图纸冲突结论，但不能据此宣称检索链全部正常。

## 还差在哪里

当前最明显的瓶颈是模型起草的图纸本身仍会出现入口、门洞、隔墙不一致，原有两次局部修订也可能解决不了。主体和特殊构件还需要模型实现，不能把这次 4 扇窗的零调用回放换算成整栋生成的调用节省。

接下来应围绕这份失败图纸讨论如何减少设计的重复表达、让关系更容易一次写对；本轮没有增加模型调用、缩窄通路或删除要求来制造通过。
