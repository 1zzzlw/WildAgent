## 已确认的实现不足与本轮修改

1. **工具参数只写了 dict。** 之前完整字段约束只在系统提示词，工具的 design 参数本身是宽泛对象。现在直接从 DesignFacts 生成完整工具 JSON Schema，根部放置 $defs，保留引用和数组长度等约束；提示词中的重复 Schema 删除。Schema 给模型明确字段边界，后台仍严格校验，不保证供应商强制生成合法参数。
2. **计算依据在反馈时被丢掉。** 首稿工具已经算出梯井 `[3.5,6.5,4,7.76]` 和上层到达区域 `[5.4,6.6,2.8,4]`，但发给模型的摘要只保留问题、实体 ID 和检查范围。现在失败反馈附 derived.stairs / derived.voids；路线冲突同时给出墙起终点、门洞 ID、所需区间和可用区间。上面的坐标仅用于说明这次 trace，不写入程序规则。
3. **格式错误遮住实体保留检查。** 现在对可读取的集合先检查原实体/楼层 ID；坐标等类型检查通过后才检查净距和步高。格式错误也附 error_type、实体和实际值，不再只给 Field required。
4. **重复反馈与无关改写。** 工具报告在 ToolMessage 中保留一次，不再整份重复进下一条用户消息；修订明确只改相关设计、保留完整未改坐标。仍采用整张图纸提交，不恢复旧分块框架或新增补丁工具。因此整稿修订的漂移风险仍需继续观察。

没有改图纸字段、自动猜补坐标、丢弃未知字段来接收图纸、放宽条件、增加模型调用轮数或迁移后续节点。
