# 修复不合理的修订锁定

输入 trace 为 `01a15873-5945-7800-be1c-7f5a5d689cde`，用户仅要求“生成一个别墅”。本轮只修复两处已确认的误拦，并改善缺失 ID 反馈，没有改图纸字段或几何校验器。

## 两处误拦如何处理

**楼梯级数：取消首稿数值锁定。** 原代码把模型自行写下的 steps_each=9 当成必须保持的要求，导致改成 10 级也失败。该相等检查已删除。模型未得到用户明确级数要求时应省略该字段，由现有程序按高差和步高上限计算；修订也可去掉自行填写的级数。用户明确要求仍传给模型遵守，本轮没有新增自然语言约束解析或字段来源系统。

例子中的总高 3.3、两跑、步高上限 0.18，对应每跑 ceil(3.3/(2×0.18))=10 级，步高 0.165。原来的 9 级会使步高约 0.1833，仍应被现有检查拒绝。这里是对原始数据的解释，不是本轮运行回放结果。

**重复墙：允许有证据的合并。** 被删除墙与另一面保留墙在旧稿中已经完全相同，保留墙在新稿中也保持相同，才允许删除冗余项。比较使用现有 Wall 类型及默认值，要求楼层、墙顶设置、厚度、材质角色、端点一致；端点允许反向。没有增加坐标容差，也不允许把另一面墙移动过来掩盖删除。关联开口仍须引用保留的真实宿主，原有宿主检查继续生效。

这份 trace 的 `wall_1f_a / wall_1f_f` 是同层同材质同厚度的反向重复墙；名称只用于说明证据，源码没有这些 ID 或坐标。

## 继续保留什么

- 必要实体和楼层 ID 的保护、已选净距、楼梯步高上限。
- 踏步/平台占地、开口重叠、墙梯冲突和所列路线的过墙等原有检查。
- 其他构件改变形态或宿主时保留原 ID。缺失 ID 和新增 ID 改为分别报告，避免模型从整份长清单中寻找差异。本例开口替换时改名，仍需沿用原 ID，不取消全部实体保护。

修改入口为 `design_workflow.py` 和建筑提示词函数，没有恢复旧模块或增加模型调用轮数。原始图纸依然有真实几何冲突，本轮不保证它能通过。
