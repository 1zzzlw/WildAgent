## 2. 这次究竟用了什么

### 2.1 工具与执行方式

- 当前对话中的 Codex 负责设计、读取资料、写脚本和检查图像。没有另外调用供应商模型 API，没有运行 WildAgent 的 classifier/architecture/execute 等图节点，没有进行多 Agent 委派。
- PowerShell、`rg`、Python 用于项目扫描、JSON/Schema 与关系检查。使用项目 `.venv` 中现有的 `jsonschema`，没有安装依赖。
- `apply_patch` 写入本目录下的设计事实、生成脚本、检查脚本和记录。
- `mcp__node_repl.js` 提供可用的 Node 执行入口，通过 `child_process.execFile` 运行现有引擎、渲染脚本和 Python。每次执行的参数、起止时间、退出码、stdout/stderr 保存在过程证据中的 JSON。
- `view_image` 实际查看保存的 PNG。未使用图片生成工具、外网建筑搜索、浏览器登录或第三方建筑模型。
- 阅读并采用 `building-blueprint-diagnostics` 技能的设计/产物/渲染分层核对方法。浏览器技能只作工具能力核对，实际出图使用仓库现有渲染脚本，没有使用 browser-use CLI。

普通终端 `node --version` 成功，但 `node -e` 触发 `ncrypto::CSPRNG(nullptr, 0)` 启动断言；独立 Node 工具中的同类进程能正常运行。这是本次环境入口差异，不能写成项目几何引擎失败，也没有为此改源码。

实际运行版本：Node 22.21.1；项目 Python 3.12.13；jsonschema 4.26.0；已安装 Vite 8.1.4、Three.js 0.160.1；Chromium 153.0.8010.12。终端默认 Python 是另一个 3.13.9 入口，主要验证使用项目 `.venv`。精确命令与浏览器/源码摘要见阶段记录和 manifest；现有脚本使用系统临时目录及工具缓存，用户交付文件均在本目录。

## 3. 实际设计与推导

先保存 [设计事实](汀院别墅-过程证据/01-设计事实.json)，随后编写 [生成脚本](汀院别墅-过程证据/02-生成汀院别墅.py)。先保存的是主要边界、标高、功能与空洞；具体窗组、廊架细部和家具位置在脚本编写时继续细化。庭院访客路线是在独立复核阶段补入的，并经历了显式修订，不能称全部设计一开始就已确定。

| 设计事实 | 本次选择 | 实体落实 |
|---|---|---|
| 主次体量 | 主楼 X=0～18、Z=6.6～14.4；西侧书房翼 X=0～6、Z=0～6.6 | L 形围护与分区板，共享书房/餐厅界面只建一面墙 |
| 楼面 | F0=0.36，F1=3.78，板厚 0.24 | floor 的输入 Y 为板顶减板厚；家具使用板顶作底面 Y |
| 屋面 | 主楼支承标高 7.02；书房屋面支承标高 3.54 | 两片真实 flat roof，书房屋面顶恰为 F1 |
| 挑空客厅 | X=11.4～18、Z=6.6～14.4 | 上层楼板不覆盖该范围；上方仍由主屋面覆盖 |
| 双跑楼梯 | 两跑各 10 级，每跑升高 1.71、行程 2.8 | 步高 0.171、步深 0.28；平台顶 2.07；二层梯井留空，梯口保留到达板和防护 |
| 可达露台 | 书房屋面为露台，二层走廊连通 | 连接门底=3.78；外缘 U 形栏杆，靠主楼一侧保留通行口 |
| 廊架 | 柱顶 5.72，梁顶 5.95 | 梁底=柱顶，条板底=梁顶，零件按边界推导中心 |
| 立面 | 公共空间朝院落开大玻璃，书房有木肋，实墙承担石材分区 | 真实门窗宿主与开口、框扇、玻璃和独立木肋实体 |
| 庭院 | 浅水庭、种植床、绕行入口 | 庭院板按区留空；水池底、边、水面分开表达 |
| 室内 | 一层客餐厨、书房及卫浴；二层两卧室、卫浴与走廊 | 家具落地，座椅朝使用目标；入口、餐厅、楼梯与露台保留所声明路线 |

材料不是“全部套一个暖色”：主体粉白、石材脊柱、地面砂石、木作、青铜框、玻璃、织物和水面各有独立材料 ID。重复条板、拉手、植物和椅子由循环展开，不逐个心算坐标。文件只保留 WILD 数据，生成程序在证据目录中单独保存。

初稿 WILD 到最终 WILD 只改变 `garden_bench` 的位置与朝向。路线是本次设计事实中的复核依据，不是 WILD 格式中的字段。r1 快照是补入庭院路线后的复核前状态，不伪称首次落盘时的原始设计文件。

这轮过程没有“一次写对”。有用的闭环是：保留初稿 → 检查真实文件 → 找到具体关系冲突 → 显式修订 → 重跑原检查。生产检查发现自己工具的漏检，直接说明应复用已有能力，不能把新写检查脚本当成更可靠的替代品。

## 5. 检查做了什么，没覆盖什么

[独立检查脚本](汀院别墅-过程证据/06-独立检查.py) 检查 Schema、ID、材料、正尺寸、门窗边界与重叠、梯段与平台、上层空洞、屋面覆盖、露台门底、家具名义占地支承以及指定路线抽样。它没有完整测试转弯扫掠、门扇开启、家具突出名义尺寸的零件或任意曲面。

[生产检查适配脚本](汀院别墅-过程证据/11-复用项目空间复核.py) 只向现有 `review_spatial_use` 提供楼面标高和六条路线，回放初稿及最终稿。它没有构造完整的生产 DesignDocument，也没有运行整个 Agent；`needs_review` 原样保留，没有改成通过。

渲染采用现有 `wild-web/scripts/render-baseline.mjs`。最终 manifest 绑定交付文件哈希、源码摘要、灯光、相机、浏览器及输出；[剖切包装脚本](汀院别墅-过程证据/08-剖切渲染.mjs) 只复用这一入口增加检查视角。图片检查确认了院落、挑空、楼梯及露台的可见布局，没有给建筑打伪精确的审美分数。

未运行项目测试全集、全站构建、后端服务、真实 Agent 模型生成或 RAG；也没有可用于这次通用 Agent 对话的精确输入/输出 token 账单。离线引擎检查内部使用了现有 Vite 打包入口，这不等于完成前端应用构建或全仓测试。
