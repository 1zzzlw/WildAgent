# architecture 的计算、检查和局部修订

> 已回退：本文的三个工具与局部修订协议属于已撤销的实验实现，保留为历史参考。见[回退记录](10-代码回退记录.md)。

本轮纠正的是交接方式：模型不再猜楼梯占地后等待校验打回，也不再为修改几处坐标重抄整张图纸。之前首稿 ID/楼层锁定、重复墙特殊豁免、整稿对比规则已经删除；没有提高调用上限。

## 三个工具

| 工具 | 输入 | 程序负责什么 |
| --- | --- | --- |
| calculate_stair | 起止楼面高差、梯形、方向和选用尺度 | 用共享算法求级数、尺寸和相对出口，供布局前使用 |
| inspect_design | 完整 DesignFacts | 补齐默认值，检查并展开整图 |
| revise_design | changes 数组 | 在当前图纸副本执行局部改动，然后使用同一整图检查入口 |

修订用实体 ID 定位，例如 {"op":"set","path":"/routes/entry_to_living/height","value":2.1}。这是实体路径，不是用数字定位实体的 JSON Pointer；只有实体内部的坐标数组使用数字下标。append 的路径指向集合，value 是新实体；remove 指向实体 ID，删除实体需写 reason。整批路径操作成功才应用，路径错误保留原图纸。不能整体替换或删除实体数组。

第一轮真实模型测试暴露了“人工数错开口下标”：模型将其他门当成目标门修改。现在实体数字下标会明确拒绝，检查报告的 edit_paths 提供可直接使用的 ID 路径；路线问题的 focus 也包含实际相关门洞，而不只给墙和路线。

未触碰的数据由程序保留，解决重抄导致屋顶编号丢失、无关门窗改名的问题；不再通过“首稿每个实体永久不可删除”锁住设计。删除最后一座楼梯但仍保留跨层使用空间，会被层间连接检查拒绝。程序没有自然语言需求提取器，局部修订仍不能证明模型保持了所有用户要求。

## 设计和计算的分界

模型负责用途、造型、体量、标高选择、楼梯连接和位置、内墙门窗动线、材料意图。程序负责引用、默认值、级数与占地、平台高度、梯井、楼板扣洞、门窗定位以及已覆盖关系检查。

例如楼面高差 3.3、U 梯、步高上限 0.18，程序求每跑 10 级；模型只安排其位置。用户未指定级数时不填写 steps_each。明确选定的级数若步高超限仍会报错，不会偷偷改成合格尺寸。

## 检查范围

- 字段、ID、楼层与材料引用，体量及用途分区边界、屋面选择。
- 门窗真实宿主、长度和高度范围，同宿主开口重叠。相接体量共墙上的通行洞口通过世界坐标投影识别，无需两侧重复开门；独立内墙不自动视为同墙。
- 楼梯计算占地、平台、步高，墙段穿入占地；直梯/U 梯到达板楼面支承。
- 已声明使用楼层之间的楼梯连接；非楼梯挑空、自动梯井及楼板扣洞。
- 所列路线过墙所需的净宽高、沿墙行走，以及中心线穿过楼板洞口。
- 修订不能降低首次形成图纸时选择的通路净距下限。

报告包含 valid / issues / coverage / defaults；有可推导结果时提供 derived，focus 按 ID 路径给当前相关实体。issues 包含字段路径、可修订的 edit_paths、实体与适用的实际值/期望值，模型按当前值集中修改。

这些检查不证明美感、所有房间可达、楼梯全程净高、防护构造、路线与所有障碍物的碰撞或构造配方可编译。L 梯只检查参数与矩形预留，不证明真实转向和到达板。共墙两侧分别声明开口的重复冲突目前未完整合并检查。待核事项不算已通过证明。
