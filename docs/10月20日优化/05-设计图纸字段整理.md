# 设计图纸字段整理

> 这是上一轮只整理文件的历史记录，已被[新版设计事实重构](06-新版设计图纸与architecture.md)替代。新建筑图纸从 `app/design/facts.py` 的 `DesignFacts` 阅读。本文涉及的旧字段和配套模块随后已[清理删除](07-design包清理.md)，删除前代码保存在[压缩快照](设计包清理证据/清理前-design.zip)。

本轮先整理字段定义的阅读方式和职责，不改节点、提示词或编译流程。

上一轮整理的入口是旧 `ArchitectureDecisions`：文件开头是旧建筑字段总表，每项有中文注释；下面是体量、房间、内墙、门窗、楼梯等子类型。以下内容均描述当时的实现。

| 文件 | 内容 |
| --- | --- |
| `app/design/architecture.py` | 建筑设计字段及其子类型 |
| `app/design/materials.py` | 建筑、物件共用的材质意图和材质方案 |
| `app/design/objects.py` | 物件图纸，不混入建筑字段 |
| `app/design/contracts.py` | 需求、版本审核外壳、修改协议和程序解析结果；保留旧导入入口 |
| `app/design/base.py` | 共用的类型配置与时间格式 |

这是一份图纸类型的重新组织，没有建立第二份设计协议。继续使用 Pydantic 做运行时校验。重复的开放字段配置归到共同基类，字段只定义一次。

`ArchitectureDecisions` 底部标出了旧链路仍在读取的字段：细部包、配额、必需构件和阳台参数。本轮保留它们；后续逐项合并、删除时，需要同步处理消费者。不能把移动文件当成已经减少了图纸的实际字段。

同时修复了上次评审确认的两个兼容问题：

- 房间和楼层布局按原输入保留字段存在性，不再自动写入空的 `rooms/walls`，也不删除原来的 `void:false`，避免无设计修改却改变哈希。
- 旧房间边界 `x_start/x_end/z_start/z_end` 仍能读取并保留原格式，不偷偷转换为新的空间设计。新图纸仍采用 `x/z/width/depth`。

房间坐标拒绝 NaN、Infinity 和非正宽深。建筑、楼梯、材质和审核的既有校验没有移除。

验证：31 项离线回归通过。扫描 98 份本地图纸，97 份可读，并与职责收敛版逐份对照，设计内容和哈希一致。剩余一份原有测试存档把 `floor_layouts` 写成对象，仍报告格式错误。未调用真实模型或生成新建筑。
