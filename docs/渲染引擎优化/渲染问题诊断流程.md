# 渲染问题诊断流程

> 快速判断问题是 Agent 生成的 WILD 蓝图有误，还是渲染引擎实现有问题

---

## 问题背景

渲染效果不理想时，可能有两个根本原因：

1. **Agent 生成问题**：Agent 编写的 `.wild` 蓝图文件参数不合理
   - 例如：墙体厚度 0.01m（太薄）、屋顶高度 0.5m（太矮）、位置重叠等
2. **渲染引擎问题**：蓝图参数合理，但渲染引擎实现有 bug
   - 例如：法线缺失、几何空心、材质错误、Z-fighting 等

**本文档提供系统化的诊断流程，快速定位问题根源。**

---

## 一、快速诊断流程（3 步）

### 步骤 1：检查蓝图文件（1 分钟）

**目的**：确认 Agent 生成的参数是否合理

**操作**：
```bash
# 打开蓝图文件，检查关键参数
cat wild-web/lantu/generated_*.wild | grep -A 5 '"type": "roof"'
# 或者用编辑器打开蓝图文件
```

**检查清单**：

| 参数类型 | 合理范围 | 常见错误 |
|---|---|---|
| **墙体厚度** `wall.thickness` | 0.18-0.30m（住宅），0.24-0.50m（公建） | < 0.15m 太薄，> 0.60m 太厚 |
| **楼板厚度** `floor.thickness` | 0.15-0.30m | < 0.10m 太薄，> 0.40m 太厚 |
| **屋顶高度** `roof.height` | 屋顶坡度 25-45° → height ≈ span×0.25~0.5 | < span×0.1 太平，> span×0.8 太陡 |
| **屋顶厚度** `roof.thickness` | 0.15-0.30m | < 0.05m 看不见，> 0.50m 太厚 |
| **层高** `wall.to[1] - wall.from[1]` | 2.8-3.6m（住宅），3.6-5.0m（公建） | < 2.4m 太矮，> 6.0m 太高 |
| **柱子半径** `column.bottomRadius` | 0.20-0.60m | < 0.15m 太细，> 1.0m 太粗 |
| **位置冲突** 墙/楼板/屋顶的 position | 各构件 Y 坐标应递增（地板 < 墙 < 楼板 < 屋顶） | Y 坐标混乱、重叠 |

**判断标准**：

- ✅ **参数在合理范围内** → 继续步骤 2（检查渲染引擎）
- ❌ **参数明显不合理** → **Agent 生成问题**，需要优化提示词/知识库

**示例（参数不合理）**：
```json
{
  "type": "roof",
  "roofType": "gable",
  "span": 12.0,
  "depth": 9.0,
  "height": 0.8,        // ❌ 太矮！12m 跨度只有 0.8m 高，坡度约 7.6° 太平
  "thickness": 0.05,    // ❌ 太薄！5cm 厚度基本看不见
  "position": [6, 3.2, 4.5]
}
```

---

### 步骤 2：运行几何验证脚本（30 秒）

**目的**：确认渲染引擎生成的几何体是否正确

**操作**：
```bash
cd wild-web
node ../.workbuddy/diag/verify-roof-solid.mjs
```

**检查输出**：

```
【gable 12x9 h=2.6 t=0.2】 tri=16  V=10 E=24 F=16  V-E+F=2 ✅
  水密(每边恰好1正1反) = 24/24 ✅   退化三角形=0
  体积 = 162.0000  期望 = 162.0000 ✅
```

**判断标准**：

| 指标 | 正常值 | 异常症状 |
|---|---|---|
| **欧拉特征** `V-E+F` | = 2（闭合实体） | ≠ 2 表示几何不闭合 |
| **水密性** | 每条边恰好 1 正 1 反 | 有边不共享 = 有孔洞/裂缝 |
| **退化三角形** | = 0 | > 0 表示有零面积三角形（会导致法线 NaN） |
| **体积** | 与期望值一致 | 差异 > 5% 表示几何计算错误 |

**结果判断**：

- ✅ **所有指标正常** → 继续步骤 3（检查渲染效果）
- ❌ **有指标异常** → **渲染引擎几何生成问题**，需要修复 `geometry/*.ts`

---

### 步骤 3：检查渲染效果（视觉对比）

**目的**：确认视觉问题的具体表现

**操作**：
1. 在浏览器中打开建筑
2. 从多个角度观察（正面、侧面、俯视、山墙端面）
3. 切换时间档（白天/黄昏/夜晚）
4. 切换环境档（极简/草地/雪山等）

**常见问题对照表**：

| 视觉问题 | 可能原因 | 问题归属 | 解决方向 |
|---|---|---|---|
| **屋顶是空心框架**（中间无填充） | 缺少法线/UV | 渲染引擎 | 添加 `generateArchitecturalSurfaceAttributes` |
| **屋顶太平/太陡** | 高度参数不合理 | Agent 生成 | 调整提示词中的坡度范围 |
| **屋顶看不到厚度** | thickness 太小（< 0.1m） | Agent 生成 | 提示词建议默认 0.2m |
| **墙体与屋顶闪烁**（Z-fighting） | 墙顶与屋顶底面共面 | 渲染引擎 | 屋顶底面下移 thickness |
| **建筑"悬浮"在地面** | 阴影太淡 | 渲染引擎 | 提升 shadowOpacity |
| **颜色全黑/全白** | 法线错误或材质未应用 | 渲染引擎 | 检查法线生成和材质映射 |
| **墙体太薄像纸片** | thickness < 0.15m | Agent 生成 | 提示词建议最小 0.18m |
| **构件位置错乱/重叠** | position 参数冲突 | Agent 生成 | 优化 Agent 的空间规划逻辑 |
| **门窗洞口未开孔** | 组件未正确编译 | 组件引擎 | 检查 compiler 的洞口处理 |
| **材质完全相同无层次** | 所有构件用同一材质 | Agent 生成 | 提示词要求区分外墙/屋顶/门窗材质 |

## 二、详细诊断方法

### 2.1 Agent 生成问题的诊断

**特征**：蓝图参数本身不合理

#### 诊断方法 A：人工审查蓝图

```bash
# 提取关键参数
cat blueprint.wild | jq '.geometry.elements[] | select(.type=="roof")'
cat blueprint.wild | jq '.geometry.elements[] | select(.type=="wall") | {id, from, to, thickness}'
```

**重点检查**：
1. **数值范围**：厚度、高度、跨度是否在合理范围
2. **空间关系**：构件位置是否合理（不重叠、不悬空）
3. **材质分配**：是否为不同构件分配了不同材质
4. **组件参数**：门窗尺寸、位置是否合理

#### 诊断方法 B：对比同类建筑

**操作**：
```bash
# 查看既有的优质蓝图作为参考
cat wild-web/lantu/generated_modern_villa.wild
cat wild-web/lantu/bieshu.wild
```

**对比要点**：
- 同等跨度的屋顶，高度是否相近？
- 同类型建筑的墙厚是否一致？
- 材质定义的数量和类型是否相似？

#### 诊断方法 C：查看 Agent 日志

**操作**：
```bash
# 查看 Agent 生成过程的日志
tail -f wild-server/logs/agent.log
```

**关注**：
- Agent 是否理解了用户需求？
- Agent 选择的参数有什么依据？
- Agent 是否有"我不确定"/"可能有问题"的提示？

---

### 2.2 渲染引擎问题的诊断

**特征**：蓝图参数合理，但渲染效果不对

#### 诊断方法 A：运行诊断脚本套件

```bash
cd wild-web

# 1. 几何水密性验证
node ../.workbuddy/diag/verify-roof-solid.mjs

# 2. 共面检测（Z-fighting 风险）
node ../.workbuddy/diag/check-coplanar.mjs

# 3. 材质覆盖统计
node ../.workbuddy/diag/material-impl-histogram.mjs

# 4. 空心检测（山墙端面穿透）
node ../.workbuddy/diag/detect-hollow.mjs
```

#### 诊断方法 B：检查法线和 UV

**代码检查**：在 `geometry/*.ts` 中搜索返回的 `MeshData`

```typescript
// ❌ 错误：缺少法线和 UV
return [{
  geometry: geo,
  indices: new Uint32Array(indices),
  transform: { ... },
  materialRef: material || 'default',
}];

// ✅ 正确：包含法线和 UV
const attributes = generateArchitecturalSurfaceAttributes(geo);
return [{
  geometry: geo,
  indices: new Uint32Array(indices),
  normals: attributes.normals,    // 必须
  uvs: attributes.uvs,            // 必须
  transform: { ... },
  materialRef: material || 'default',
}];
```

#### 诊断方法 C：浏览器开发者工具

**操作**：
1. F12 打开开发者工具
2. Console 标签页查看错误/警告
3. Performance 标签页查看渲染性能
4. Three.js Inspector 扩展查看场景树

**常见错误提示**：
- `NaN in normal` → 法线计算出错（零面积三角形）
- `Texture not found` → 材质贴图缺失
- `Material [name] not defined` → 材质未定义

## 五、决策树（一图判断）

```
报告渲染问题
    ↓
【步骤 1】蓝图参数是否合理？
    ├─ 参数明显不合理（太大/太小/重叠）
    │   → ✅ Agent 生成问题
    │   → 优化方向：提示词、知识库、空间规划逻辑
    └─ 参数看起来合理 ↓
    
【步骤 2】几何验证脚本是否通过？
    ├─ 欧拉/水密/体积有异常
    │   → ✅ 渲染引擎几何生成问题
    │   → 修复方向：geometry/*.ts 的几何生成算法
    └─ 验证全部通过 ↓
    
【步骤 3】视觉问题是什么？
    ├─ 空心/黑色/无法线 → ✅ 渲染引擎实现问题（法线/UV/材质）
    ├─ 闪烁/穿模 → ✅ 渲染引擎问题（Z-fighting/水密性）
    ├─ 悬浮/无阴影 → ✅ 渲染引擎问题（光照/阴影配置）
    ├─ 比例/尺度不对 → ✅ Agent 生成问题（参数选择不当）
    └─ 位置/朝向不对 → ✅ Agent 生成问题（空间规划错误）
```

## 六、常见组合问题

### 组合问题 1：Agent + 渲染引擎都有问题

**症状**：既有参数不合理，又有渲染 bug

**诊断**：
1. 先看蓝图参数 → 如果参数明显不合理，先修复 Agent
2. 修复 Agent 后重新生成蓝图
3. 再看渲染效果 → 如果还有问题，再修复渲染引擎

**原则**：**先修复 Agent（因为渲染引擎基于合理参数设计）**

---

### 组合问题 2：参数边界模糊

**症状**：参数在"勉强合理"的边界

**示例**：
- 屋顶高度 1.8m，跨度 12m → 坡度 17°（偏平但不算错）
- 墙厚 0.16m → 偏薄但不是完全不可接受

**诊断方法**：
1. 对比既有优质建筑的参数
2. 查阅建筑规范的推荐值
3. 询问用户预期（如果是用户主观感受）

**处理策略**：
- 如果用户明确不满意 → Agent 生成问题（调整默认值）
- 如果只是渲染效果不佳 → 可能是渲染引擎需要适应边界情况

## 八、总结

### 判断原则

1. **参数问题优先排查**：先看蓝图，参数不合理直接归 Agent
2. **几何验证是分水岭**：验证通过 = 渲染引擎，不通过 = 几何生成
3. **视觉问题看类型**：尺度/位置 = Agent，效果/材质 = 渲染引擎
4. **有疑问时提供完整信息**：截图 + 蓝图 + 脚本输出

### 协作模式

**你（用户）**：
- 提供问题描述和截图
- 指出"哪里不满意"
- 运行诊断脚本（可选）

**我（AI）**：
- 快速判断问题归属
- 定位具体根因
- 提供修复方案

### 目标

**让每个渲染问题都能在 5 分钟内定位根因，10 分钟内给出修复方案。**
