## 二、档 C 的核心：檐口 = 屋面朝上面的边界环 × 一个截面

### 2.1 算子结构（零 roofType 分支）

```
任意屋顶的主体三角面
   ↓ extractEaveLoops   只取朝上面(ny>0.05)，无向边配对，配对失败的边=边界边，串成环
檐口环（gable 是含博风板的六边形轮廓 / hip·flat 是矩形 / dome 是圆 /
        chinese_curved 是带四角起翘的曲线环）
   ↓ splitEaveRuns      转角 >75° 处切段，各段独立端封（避免斜接尖刺）
   ↓ sweepEaveRun       沿段扫掠同一个 8 点截面（封檐板 + 滴水线）
檐口线脚（若干互相独立的闭合实体，合并成一个网格）
   ↓ orientSolidOutward 逐构件算有向体积，为负就整体反绕 —— 不手推绕序
```

三个此前踩过的坑，都被这条链路自然吸收：

- **转角**：不再靠 `endOverhang` 让四条盒子互相重叠遮挡，而是斜接 + 端封；
- **屋脊/山墙端**：`chinese_curved` 的环在两端是"沿斜边爬到屋脊再下来"，扫掠出来**就是博风板**，
  不必再写中式专用翘角逻辑；
- **外法线**：由有向体积判定，不再依赖手推绕序（`chinese_curved` 正是在这里出过错）。

### 2.2 `buildRoof` 变成纯查表

```ts
const ROOF_TYPES: Record<string, RoofTypeSpec> = {
  gable:          { eaveTrim: true,  gableEndPanels: true,  body: … },  // 双坡：多两块山墙饰面
  hip:            { eaveTrim: true,  gableEndPanels: false, body: … },
  flat:           { eaveTrim: true,  gableEndPanels: false, body: … },
  dome:           { eaveTrim: true,  gableEndPanels: false, body: … },
  chinese_curved: { eaveTrim: true,  gableEndPanels: false, body: … },
  chinese_pagoda: { eaveTrim: false, gableEndPanels: false, body: … },  // 重檐逐层成环，套扫掠会在每层顶部多长一圈
};

export function buildRoof(params: RoofParams): MeshData[] {
  const spec = ROOF_TYPES[roofType];
  if (!spec) throw new Error(`Unsupported roofType: ${roofType}`);
  return appendEaveTrim(spec.body(params, ctx), params, ctx, spec);   // ← 无一个 roofType 分支
}
```

**新增一种屋顶 = 加一行表项**（主体生成器 + 两项能力声明），檐口代码一行不用碰。

### 3.3 体积参照量：从"硬编码解析值"改成"面积 × 水平路径长"

旧门禁把体积写死成"板面积 × 板长"逐块相加；通用扫掠后转角是斜接、屋脊处两段共用剖面平面，
闭式解不再成立。新参照量：

```
体积 ≈ 截面面积 × 檐口环**水平**路径长  (+ gable 的两块山墙饰面)
```

用**水平**路径长而不是斜边长，是因为沿折线扫掠时相邻两截面共面、只差一个平移，
平移里**落在截面平面内**的分量不改变体积，**垂直于截面平面**的分量才贡献体积 ——
那恰好是水平位移。已实测：gable / hip / flat / chinese_curved 四类**精确到小数点后 4 位**，
只有穹顶那种"每段法线都不同"的光滑环有 0.6% 偏差（门禁容差 2%）。

另外修正了探针库的两处**判据缺陷**（都曾给出误导性结论）：

1. `-0` 归一化：`(-0).toFixed(4)` 得到 `"-0.0000"` ≠ `"0.0000"`，几何上同一个点被算成两个顶点。
   穹顶赤道线里有 `cos(π/2)` 反号后的 `-0`，配不上对就被误判成边界 → **线脚顺着经线一路爬到极点**
   （这就是"穹顶线脚顶到顶点"的真凶）。归一后穹顶的环从 38 顶点/含极点，变成 **16 顶点、全在 y=0 的圆环**。
2. χ 判据：闭合环扫掠出来的是**环面（χ=0）**，不是球面。旧判据 `χ===2` 会把穹顶圈梁误判为破面；
   改成"偶数且 ≤ 2"（2=球面、0=环面），仍然拒绝奇数 χ 与多孔连通。

## 五、顺带发现（4 项）

### 5.1 已修：`buildFlat` 顶/底面绕序反转（A 类）

薄板顶面法线朝**下**、底面朝上（实测 `y[0.30] n=(0,-1,0)`）。后果：水密性失败（未配对边 8）、
体积 8 ≠ 24、开背面剔除后**可见顶面被整片剔掉**。同属档 B 那类"绕序/法线"缺陷，已顺手修正
（俯视 XZ 时 (x,z) 逆时针得到 -Y，朝上面必须顺时针给点）。

修后：未配对边 0、χ=2、体积 24.0000 = 解析值 ✅

### 5.2 已定性、未改：`buildDome` 是单面开口壳

`buildDome` 只生成上半球面，且**忽略 `thickness` 参数**。它本来就是一张单面开口壳（从外/上方看正常），
不属于"闭合实体"，因此不参与闭合性与体积断言。若期望它成为闭合实体（带板底/内表面），
是一次独立的设计变更，需另行确认。

### 5.3 已定性、未改：`chinese_pagoda` 过不了重建校验

合成蓝图下 `buildRoof` 能返回 15 块网格，但 `reconstructWildEntity` 全部丢弃并报
`RECONSTRUCTION_MISSING_MESH: [r] 源对象没有生成任何可定位网格`（`tiantan.wild` 里那份却能过，
差异不在檐口）。**与檐口无关**，已单独定位，见 §六待办。

### 5.4 已定性、未改：核心筒外凸（Blueprint / Agent 侧）

中式别墅顶层外墙轮廓为 `X[0,12] Z[0,8]`，而贯通全高的核心筒是 `X[4,8] Z[4.5,8.5]` ——
**Z 方向外凸 0.5m**，立面上会直接看到核心筒的混凝土面。`roof_main` 的材质清单只有
`roof` + `wall_finish`，**不含 concrete**，所以这块灰不是屋顶引擎造的。

按《渲染问题诊断流程》属**构件位置错乱（Agent 生成问题）**，引擎无法修正，需在 `.wild` 或
Agent 提示词侧约束（如"贯通全高的核心筒不应超出所在楼层的外墙轮廓"）。

> `dump-walls.mjs` 原先的结论逻辑是拿核心筒跟"全部顶标高墙"比 —— 而核心筒本身就在这个集合里，
> 于是**恒为"未超出"**，把真正的外凸掩盖掉了。已改成跟"**顶层外墙（剔除贯通全高墙）**"比。
