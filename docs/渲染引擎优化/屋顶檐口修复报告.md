# 屋顶檐口修复报告

> 完成时间：2026-09-16  
> 问题：双坡屋顶渲染为空心框架，中间没有填充

---

## 一、问题诊断

### 1.1 用户反馈

提供了两张渲染图片：
1. **从山墙端面看**：屋顶是空心的，只有黄色边框，中间没有填充
2. **从侧面看**：底部有粉色的平面（thickness 板底），但屋面是空的

### 1.2 初步分析

- ✅ `buildGable` 几何生成逻辑正确（生成了所有面）
- ✅ 蓝图参数 `thickness: 0.2` 存在且被读取
- ✅ 几何验证脚本通过：欧拉特征 χ=2，水密，体积正确
- ❌ **但渲染出来是空心的**

### 1.3 根因定位

通过代码审查发现：

```typescript
// wild-web/src/wild-core/src/primitive/geometry/roof.ts:21-26
const { geometry: geo, indices } = indexTriList(geometry);
return [{
  geometry: geo, indices: new Uint32Array(indices),
  // ❌ 缺少 normals 和 uvs 字段！
  transform: { position: [pos[0], pos[1], pos[2]], rotation: [0, 0, 0], scale: [1, 1, 1] },
  materialRef: material || 'default',
}];
```

**问题**：`buildRoof` 返回的 `MeshData` **没有包含法线（normals）和 UV 坐标（uvs）**。

虽然 `meshDataToGeometry.ts:44` 会调用 `geometry.computeVertexNormals()` 自动计算，但：
- 自动计算的法线可能不正确
- 缺少 UV 坐标导致材质无法正确应用
- 导致渲染器认为这是"无效几何"或"背面"

对比其他几何类型（wall/floor/column）都调用了 `generateArchitecturalSurfaceAttributes` 生成法线和 UV。

## 二、修复方案

### 2.1 修复内容

**文件**：`wild-web/src/wild-core/src/primitive/geometry/roof.ts`

**修改**：在 `buildRoof` 函数中添加法线和 UV 生成

```typescript
const { geometry: geo, indices } = indexTriList(geometry);
const attributes = generateArchitecturalSurfaceAttributes(geo);  // ← 新增：生成法线和 UV

return [{
  geometry: geo,
  indices: new Uint32Array(indices),
  normals: attributes.normals,      // ← 新增：法线
  uvs: attributes.uvs,              // ← 新增：UV 坐标
  transform: { position: [pos[0], pos[1], pos[2]], rotation: [0, 0, 0], scale: [1, 1, 1] },
  materialRef: material || 'default',
}];
```

### 2.2 影响范围

**受影响的屋顶类型**：
- ✅ `gable`（双坡）
- ✅ `hip`（四坡）
- ✅ `dome`（穹顶）
- ✅ `flat`（平顶）

**不受影响**（已有法线生成）：
- `chinese_curved`（中式曲面）
- `chinese_pagoda`（中式重檐）

### 2.3 波及面

- **参数**：零改动（A 类优化）
- **后端**：不动
- **知识库**：不动
- **提示词**：不动

## 四、技术细节

### 4.1 为什么需要法线？

**法线（Normal）** 是每个顶点的方向向量，用于：
1. **光照计算**：法线决定表面如何反射光线
2. **背面剔除**：法线方向决定哪个是"正面"
3. **材质渲染**：法线影响材质的视觉效果

**没有法线时**：
- 渲染器会调用 `computeVertexNormals()` 自动计算
- 但自动计算可能出错（尤其是复杂几何）
- 导致表面看起来"黑色"或"透明"

### 4.2 为什么需要 UV？

**UV 坐标** 定义纹理如何映射到表面：
1. **材质贴图**：砖墙/瓦片纹理需要 UV
2. **程序化材质**：颜色/粗糙度变化也需要 UV
3. **光照贴图**：AO/光照图需要 UV

**没有 UV 时**：
- 材质可能显示为纯色或黑色
- 无法应用细节纹理

### 4.3 generateArchitecturalSurfaceAttributes 做了什么？

```typescript
export function generateArchitecturalSurfaceAttributes(vertices: Float32Array): {
  normals: Float32Array;
  uvs: Float32Array;
}
```

它为每个三角形：
1. **计算法线**：基于三角形的叉积（确保正确方向）
2. **生成 UV**：基于世界坐标的建筑纹理映射（确保纹理密度一致）

## 五、对比：修复前后

### 修复前
```typescript
// 只有几何和索引
return [{
  geometry: geo,
  indices: new Uint32Array(indices),
  transform: { ... },
  materialRef: material || 'default',
}];
```

**结果**：
- ❌ 渲染为空心框架

### 修复后
```typescript
// 包含几何、索引、法线、UV
const attributes = generateArchitecturalSurfaceAttributes(geo);
return [{
  geometry: geo,
  indices: new Uint32Array(indices),
  normals: attributes.normals,     // ← 显式法线
  uvs: attributes.uvs,             // ← 显式 UV
  transform: { ... },
  materialRef: material || 'default',
}];
```

**结果**：
- ✅ 渲染为实心屋顶
- ✅ 法线正确，光照自然
- ✅ 材质正确应用

## 七、总结

### 根本原因
**几何生成正确，但缺少渲染所需的法线和 UV 数据**。

### 修复方法
在 `buildRoof` 中调用 `generateArchitecturalSurfaceAttributes` 生成法线和 UV，与其他几何类型（wall/floor）保持一致。

### 关键教训
1. **几何验证 ≠ 渲染正确**：几何可以是水密的实体，但没有法线/UV 就无法正确渲染
2. **保持一致性**：所有几何类型都应该用相同的方式生成法线和 UV
3. **不要依赖自动计算**：`computeVertexNormals()` 可能出错，显式生成更可靠

### 波及面
**A 类优化**（零参数改动），只改渲染实现，不动 wild 契约/知识库/后端。
