# S0 实施报告：光照与环境链路收进引擎

> 上游：《[渲染引擎现状评估与照片级路线](渲染引擎现状评估与照片级路线.md)》§2.3 / §7 的 **S0**。
> 分类：**A 类**（纯渲染实现，零 WILD 契约参数改动，无需事前审批）。
> 范围：`wild-web/src/renderer/`（新增 3 个运行时）+ 两个消费方（编辑器视口、`lantu/viewer`）。

## 一、S0 要解决的问题（回顾）

| 级别 | 问题 | 后果 |
|---|---|---|
| 🔴 P0 | **IBL 没有 `src/renderer/` 入口**：`pmremGenerator.fromScene()` 与 `scene.environment = …` 内联在 `CanvasViewport.vue` | 别的渲染方拿不到 `scene.environment` ⇒ 材质层按"有 IBL"设计的玻璃（`transmission`/`ior`）与金属（`envMapIntensity`）全部失效：**天空黑、玻璃死蓝、金属发暗、无反射** |
| 🔴 P1 | **AO / 接触阴影同样只活在 Vue 组件里** | 别的渲染方完全没有接触阴影，建筑与地面"贴"在一起 |
| 🔴 红线 | 查看器为自救只能**自己造 3 盏灯**（`HemisphereLight` + `AmbientLight` + `DirectionalLight`） | "查看器不自实现引擎行为"被破坏 —— 看到的不是引擎行为，而是本地代码的行为 |

## 二、实施内容

### 2.1 新增引擎运行时（`wild-web/src/renderer/`）

| 文件 | 职责（机制） | 不负责（策略） |
|---|---|---|
| `environmentRuntime.ts` | 离屏环境场景（`Sky` + 太阳精灵）→ `PMREMGenerator.fromScene()` → `scene.environment`；签名去重（量化 1/32）+ 前后沿节流（120ms）；旧纹理释放 | 当前是白天还是黄昏、用哪个环境档 |
| `lightingRuntime.ts` | 半球光 + 关键光（平行光）的构造；**阴影正交框 / 光位 / `bias` / `normalBias` 的推导**（`fitToBounds`）；阴影贴图尺寸切换 | 各预设的颜色与强度数值 |
| `postProcessingRuntime.ts` | `EffectComposer` 链路（RenderPass → SSAO → Bloom → Output → FXAA）；SSAO 半分辨率包装；合成 RT 的 MSAA；FXAA resolution uniform | 哪个画质档开 SSAO / Bloom |

同时把 `createCelestialBody`（日月精灵）与 `syncSkyPreset`（天空 uniform 改写）从组件**上移**到 `environmentRuntime.ts`——它们本来就是"同一套太阳"的两处用法（主场景里看得见的太阳 / 环境贴图里的高光点），必须同源。

### 2.2 两个消费方改造

- **编辑器视口**（`CanvasViewport.vue`）：删掉内联的 PMREM/环境场景/`rebuildEnvironment`/`scheduleEnvironmentRebuild`/`environmentSignature`/`applySceneMsaa`/`applySsaoScale`/光源构造；改为持有三个运行时。约 **-230 行**净删。
  `hemisphereLight` / `directionalLight` / `composer` / `ssaoPass` / `bloomPass` / `fxaaPass` 保留为**只读别名**，让既有"按预设改数值"的策略代码不必大改 —— 构造与机制已不在组件里。
- **查看器**（`lantu/viewer/main.ts`）：删掉自建的 `HemisphereLight` + `AmbientLight` + 自配阴影的 `DirectionalLight`，改为 `WorldLightingRig` + `WorldEnvironmentMapRuntime` + `WorldPostProcessingRuntime`。
  新增 `?time=day|sunset|night` 与 `?env=minimal|meadow|alpine|desert|autumn` 两个查询参数，直接复用引擎的 `TIME_PRESETS` / `ENVIRONMENT_PRESETS` / `deriveWorldAtmosphere`，使"查看器出的图"与"编辑器看到的"是同一套光照。
  渲染入口从 `renderer.render()` 改为 `postProcessing.render()`（与编辑器同链路，因此拿到 SSAO 接触阴影）。

### 2.3 一个刻意的不对称

查看器**没有**搬编辑器的 `shadowGround`（阴影贴花）、`presentationGround`（展示地面）、`builtInEnvironment`（内置环境）与雾。那是编辑器的**场景道具**（观察辅助），不是光照机制；搬过来会让"查看器反映引擎产出"变成"查看器复刻编辑器界面"。

## 四、残留问题与后续

1. **白天画面偏白/偏灰（关键"观感"问题）**：IBL 挂上之后，漫反射环境光是真的了，而 `TIME_PRESETS.day` 的曝光（1.08）与光强（关键光 2.68 + 半球 0.62）是按"没有 IBL"的年代调的 ⇒ 现在叠加后白墙接近过曝、对比度下降。
   **这正好是路线里的 S1（环境/曝光标定）**：不是 S0 没做完，而是 S0 把问题暴露出来了。
2. **编辑器侧只做了静态与构建验证**：本机无法用本地 HTTP 起一个可用的 `vite preview`（响应被截断），所以编辑器视口的**运行时**没有真图证据。降级替代证据 = 三个工程门禁 + 类型检查 + 生产构建 + 查看器端同一条运行时的真机验证（两个消费方共用同一个类，差异只在预设喂入与场景道具）。
3. 查看器仍未搬编辑器的 `shadowGround` 贴花与内置环境——按 §2.3 的判断，这属于"该不该让查看器长得像编辑器"，是产品问题，不是 S0 的欠账。
