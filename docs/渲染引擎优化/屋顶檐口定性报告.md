# 屋顶檐口"没有厚度"定性报告

> 触发问题：`simple_villa.wild` 渲染出来的屋顶很简陋、"没有屋檐厚度"。
> 用户问：**这是渲染引擎的问题，还是 wild 文件编写的问题？**
> 诊断时间：2026-09-16　样本：`D:\Backup\Downloads\simple_villa.wild`

---

## 一、结论（一句话）

**都不是"引擎 bug"。**

- **three.js 渲染层无责**：屋顶实体、法线、UV、绕序全部正常，檐口立板确实被生成并渲染了。
- **主要责任在 `.wild` 编写侧**：这份文件**一个 `cornice`（檐口）构件都没写**，而"檐口线脚"在 WILD 契约里**早就是既有能力**。
- **次要责任在 `wild-core` 的屋顶生成器**：`buildGable` 只会发"裸板 + 一个材质"，不会生成线脚，也不会把山墙端面从瓦色改成墙色。

一句话概括病根：**檐口的"厚度"其实已经有了（0.20m），但它和屋面同色同材质，所以在视觉上根本读不出来。**

---

## 二、三层归因

| 层 | 判定 | 证据 |
|---|---|---|
| three.js 渲染层<br>`CanvasViewport` / PBR / 阴影 | ❌ **无责** | 屋顶 `tri=16`、`normals=Y`、`uvs=Y`、`avgN≈[0,1,0]` 朝外；檐口立板被生成并光栅化（见 §三-③）。不是之前那种"空心壳"问题（那次 P0 已在 `屋顶檐口修复报告.md` 修完） |
| `wild-core` 几何生成器<br>`primitive/geometry/roof.ts` | ⚠️ **部分责任（能力缺口）** | ① 檐口只有 `thickness` 一个数字，没有封檐板/滴水/线脚概念；② **整个屋顶（含山墙端面）只发 1 个 mesh、1 个 `materialRef`** → 前后山墙被涂成砖红瓦色；③ 11.6×9.8m 的屋面只有 **16 个三角面**，无细分 |
| `.wild` 文件 / 上游生成器 | ⚠️ **主要责任（但契约已支持）** | `geometry.components` 中 **`cornice` 数量 = 0**；而 `cornice`（二维截面沿路径扫掠）是既有契约（`docs/specs/WILD_BLUEPRINT_SPEC.md` §5 组件表 + §5.4），实现见 `wild-compiler/components/cornice.ts`。`roof_tile` 也是纯色材质 `surface.default.v1`，无瓦面纹理 |

> 注意区分：这不是"作者违反契约"，而是"契约有、作者没用"。所以**修它不需要改引擎**。

## 三、为什么"有厚度却看不出来"

`.wild` 里 `thickness: 0.2` 是真写了的，几何也真生成了。逐条量化：

| # | 现象 | 实测值 | 后果 |
|---|---|---|---|
| ① | **檐口和屋面同色同材质** | 屋顶整体只有 1 个 `materialRef = roof_tile`（`#9e472e` 砖红） | 0.20m 的檐口立板与屋面糊成一片，看不出"檐口"这个构件 |
| ② | **可见厚度 = `thickness` = 0.20m** | 两侧檐口竖直立面世界 Y`[3.00 .. 3.20]`，高 **0.20m** | 对 11.6m 跨度来说太薄（真实封檐板常见 0.30–0.50m，且做成有进出的线脚） |
| ③ | **板底是一整块水平平底，不是等厚斜板** | 法线 `-Y`、面积 **113.7㎡**（= 11.6×9.8，铺满整个投影） | 从檐下看是一整块平顶天花板，檐口只呈现为一条 0.2m 的平板边 |
| ④ | **山墙两端是整面五边形封板，且是瓦色** | `z=±4.90` 端面 3 个三角面，世界 Y`[3.00 .. 6.10]`，高 **3.10m**，`materialRef=roof_tile` | 站在正面/背面看到一大块**砖红色三角**坐在米白墙上——这一条对"简陋/幼稚"的贡献比檐口本身更大 |

出檐量本身**没问题**（`span 11.6` / `depth 9.8` vs 墙外皮 10.24×8.24）：

```
X- 左檐 0.68m   X+ 右檐 0.68m   Z- 山墙端 0.78m   Z+ 山墙端 0.78m
```

## 四、修法三档

### 档 1｜只改 `.wild`，零代码（最便宜）

在 `geometry.components` 里补 `cornice` 构件：沿两条檐口线各扫一个封檐板截面（例如高 0.35m、带 0.06m 滴水），材质单独给一个亮色 `fascia`。

契约已在，不用动引擎。**但有一个必须知道的坑**：

`profile` 的 u 轴 = **右手系下"行进方向的右侧"**（`wild-core/src/primitive/geometry/primitive.ts:252-259` 的 `createPathFrame`）。所以绕檐一圈必须统一绕向，否则半圈剖面朝内插进屋面。脚本实测：

```
X- 左檐 沿 +Z 走 → profile u = [+1,0,0] → 朝内（+X）❌ 会插进屋面
X- 左檐 沿 -Z 走 → profile u = [-1,0,0] → 朝外（-X）✅
```

绕屋顶一周想一次画完四条边，还要处理山墙斜边，手写坐标量不小；**每份 .wild 都靠手补，成本不可持续**。

### 档 2｜改 `roof.ts`，不改契约（B 类，推荐）

让 `buildGable` / `buildHip` 自动产出檐口线脚，并把山墙端面拆成**独立 mesh**、用墙材质：

- 檐口：沿檐口线生成本封檐板（带滴水收口），可加一个渲染器私有参数 `_eave: { drop, outset, trim }` 控制线脚尺寸与材质；
- 山墙端面：从合并的大 mesh 里拆出来，`materialRef` 指向宿主墙材质（或新增 `_gableEndMaterial`）；
- 屋面细分：按 `span` 增加坡度方向分段，为将来的瓦楞/法线留出承载。

改 1–2 个函数、**零契约面影响**，所有既有 `.wild` 自动受益。这就是 `docs/渲染引擎优化/渲染引擎优化指南.md` 里 B 类待办清单中"**屋脊瓦 / 檐口线脚 / 山墙通风口**"那一条。

### 档 3｜改契约（C 类，最贵）

给 `roof` 加 `eave: { outset, thickness, cornice }`、`gableEnd: "wall" | "roof"` 等字段，走六步全链（schema + 校验 + 提示词 + 后端 tool + 前端 + 基线与回归）。

最灵活、面向 Agent 生成最友好，但要动后端 schema、G7 校验和提示词，得单独排一轮。

### 建议

**档 2 为主 + 少量档 1 验证。** 理由：「山墙端面是砖红瓦色」「檐口无层次」是**所有**双坡屋顶的通病，靠在每份 `.wild` 里手写 `cornice` 补不完；而档 2 是纯几何增强，零契约风险。瓦面纹理属于材料系统，单独另开一轮。

> ✅ **档 2 已于 2026-09-16 实施完成**，见 §八。

## 八、实施结果（档 2，2026-09-16）

按 §四 的档 2 落地，**零契约改动**（`roof` schema 未加字段，后端与提示词不动）。

### 8.1 改了什么

| 文件 | 改动 |
|---|---|
| `wild-core/src/primitive/geometry/roof.ts` | 新增 `resolveEaveTrim`（尺寸规则）、`buildEaveTrim`（几何）、`pushBoxSolid` / `pushPrismZ` / `earClipTriangles` / `polygonSignedArea`（闭合实体工具）。屋顶在 `_eave` 存在时额外产出一块**线脚网格** |
| `wild-core/src/primitive/resolver.ts` | `resolveRoofBoundary` 为 `gable/hip` 注入渲染私有字段 `_eave = { material }`，材质取承托墙众数材质（新增 `dominantMaterialOf`） |
| `.workbuddy/diag/verify-roof-solid.mjs` | 升级为**逐连通分量**水密 + χ=2 + 体积断言，屋面/线脚分别校验，并加"无墙回退"保护性用例 |
| `.workbuddy/diag/audit-eave.mjs` | 重写为檐口门禁 |

### 8.2 生成物

- **屋顶元素产出 2 块网格**：屋面实体（`roof_tile`）+ 线脚网格（宿主墙材质，本样例 `wall_stucco`）。
- 线脚网格 = **8 个互相独立的闭合实体**：2 封檐板 + 2 滴水线 + 2 博风板 + 2 山墙饰面。
- 本样例（span 11.6 / depth 9.8 / h 2.9 / t 0.2）实测：

```
推导尺寸    drop = 0.340m   outset = 0.136m   embed = 0.030   top = 0.020
封檐板高度  0.360m  ← 改造前可见厚度只有 0.200m（= thickness）
檐口最低点  世界 y = 3.20 − (0.340 + 0.050) = 2.810
线脚体积    3.3264 m³（几何实测 == 独立解析值）
线脚分量    8 个，每个 χ = 2，整网格水密、无退化面
山墙饰面    覆盖到屋脊（高 2.900m），与端面留 2mm 间隙避免共面
```

- 尺寸规则随尺度缩放，避免小体量屋顶被巨型线脚压垮：
  `drop = max(1.5×板厚, clamp(0.04×短边, 0.10, 0.34))`、`outset = clamp(0.4×drop, 0.05, 0.16)`。

### 8.3 为什么不能更简单

| 看似更省事的做法 | 为什么不行 |
|---|---|
| 只加粗 `thickness` | 板底是**水平平底**，加粗只会让整块屋面整体下坠，檐口仍然与屋面同色 |
| 把山墙端面拆成独立网格给墙材质 | 端面是双坡实体**闭合的必要面**，拆走 ⇒ 屋顶漏水 + 逐分量 χ 校验失败。正解是保留端面 + 叠加一层向外偏移 2mm 的独立薄板 |
| 用顶点色把檐口染亮 | 顶点色是**乘法**，基色 `#9e472e` 之上做不出白色檐口；且与程序化纹理烘焙相互干扰 |
| 给所有屋顶硬编码线脚尺寸 | 小体量屋顶（如 2.4m 门廊）会出现比屋面还大的线脚 |
